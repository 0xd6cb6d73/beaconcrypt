# Actual later-parent address alias

`PqxdhLaterParentAlias` proves a separate `2^-256` upper bound for the actual later-record sampler's parent self-address event. The event compares the selected ratchet input address, formed from the sampled parent's next-chain coordinate, with the parent address that was already fixed before that full output draw. It is not assumed impossible, and the protocol experiment is unchanged on that event.

`target_address` identifies the literal native input encoding and source ratchet domain with the maintained input-address function. `full_alias` then consumes `RawCtxFirstParentRisk.full_inputs` for the single fixed address. This uses the existing full 76-byte output/projection law: the parent material and its next-chain coordinate remain in one draw. It does not replace their joint distribution by unrelated marginal samples.

`prepared_alias` carries that event through the complete original `PqxdhErasedParentMaterial.prepare` computation, including all actual preparation, parent output, nonce and next-chain draws on both common and pending branches. Its address is fixed by the reached source packet before the parent draw. `certified_alias` transports the bound using the proved exact source erasure of the richer actual sampler, with generated callback parameters and the reached shared cache retained. `component_prefix_alias` identifies the same event in the ordinary CTX component's actual prefix execution for every explicit selected key.

`suffix_alias` proves syntactically that the saved continuation can only return a pending carrier that it actually received. Optional source failure, nonce refusal and all later callbacks cannot create a different sampled carrier. `client_alias` consequently bounds the parent-address event in the complete ordinary component execution of `PqxdhLaterExecutableCompletion.client` by `2^-256`. The source game includes its actual selected-key draw and the full continuation; no successful, fresh, honest or separated-execution premise appears in this bound.

The Boolean `outputAlias` is a private analysis event. It is false on common outputs because those outputs have no pending carrier; this does not replace the client's original common/cached decision with false. Complete common true mass remains covered separately by the original event analysis. All source randomness and work remain governed by the existing executable resource ledger; these read-only event projections add no oracle request or sampler.

This term is deliberately separate from the earlier material-normalization and chronological collision terms. Reusing an earlier charged event would require a proved inclusion across the exact same sampler and hybrid; this package makes no such reuse. It does not yet close original Gate/Fresh-to-message-key-disclosure correspondence, actual nonce-refusal probability or the final primitive-security event reduction. The original finite-lineage event already includes the record material key; its exact transport to the saved message-key disclosure history remains to be proved. Chain freshness alone would not suffice, and this alias bound does not make an allowed key disclosure negligible.
