# Source frame logs do not affect operational replies

`PqxdhRecordFactsOriginLogs` proves ten operational statements that remove only the source's `produced` and `pending` frame logs. `clearPrivate` blanks those two lists, and `clearCtx` applies that projection to the base of the full coordinate state. Neither projection changes native, effect or uniform counter fields, the shared hash cache, the directional seed state, the complete evolving-chain table, or any coordinate dictionary and private suffix cache. This projection is a proof interface for the unpublished-record argument, not a protocol operation or a change to the observable security experiment.

`logged_program_forget` uses the literal native frame logger and proves that discarding its output log leaves exactly the same full adaptive native program, result and primitive poststate. The primitive interpreter is arbitrary, so its actual KDF, hash, AEAD and writer effects remain present. `withNative_logs` lifts this fact through the source's record-state adapter while preserving the chain and seed state. `withNative_clear` concludes that clearing only initial frame logs cannot affect the projected output of that complete record continuation. This includes actual caller-known sends and receives and every optional writer outcome.

`interpreter_clear` checks the counterless source base interpreter, for any chain-replacement policy, on all eight constructors other than hidden opening and hidden sealing. Allocations keep the actual sampler and seed poststate; coins, hashes and charges retain their replies and instrumentation; lookup retains the exact native KDF charge and whole correlated output table; caller-known records use the complete native continuation theorem. Publication still appends the actual pending frames to the actual produced log and clears pending: after the stated output projection, this write-only work cannot change any retained field. No callback is assumed independent of arbitrary state, and no unrestricted base-state read is treated as log-blind.

`clearPrivate_idempotent` and `clearCtx_idempotent` check that the projections stabilize. `clearCtx_retained` explicitly lists the retained primitive state, seeds, table and coordinate states. `clearCtx_keys` shows that the projection commutes with any explicit replacement of the coordinate-state function, so a separate selected-dictionary/cache projection can be composed without assuming a key-independence result. `onBase_clear` frames the private-state law with the unchanged coordinate state, and `base_clear` exposes the resulting exact reply/poststate equality for the actual counterless CTX base endpoint.

The counterless endpoint already removes uniform instrumentation through a separately proved earlier law; this module does not repeat that transformation or claim an equality of its cost with the original counted execution. Its own projection removes only the two logs and keeps every other field literally equal. No sampler, primitive query, source callback or permitted reply is omitted by the frame-log law. The generic native theorem preserves actual native programs, not merely marginal returned values.

All ten statements have exact guarded axiom checks, each using only a subset of `propext`, `Classical.choice` and `Quot.sound`. There is no new primitive, codec, source-correctness or security premise. Hidden opening/sealing, the combined selected-record projection, chronological publication, writer-result leakage and the final unpublished-acceptance probability bound remain separate consuming proofs. No Rust, registration, ProVerif, snapshot or persistence behavior is changed.
