# Real registration finish in the common native command

`PqxdhBoundaryRegistrationFinish` carries the reviewed candidate-local registration executor into the actual `PqxdhRegistrationSchedule.finish` and frozen `PqxdhDeploymentNative.handler` finish command. Its five guarded statements preserve the complete normal-return value and state distribution. The only result wrapper is the existing `RustM.ok` at the extracted executor boundary.

`callbacks_withReader` proves that replacing the codec's frame reader with the existing shared complete reader changes none of the registration callbacks. Preparation, root extraction, initial KDF, application getter, hash and AEAD therefore run through the original native interpreter. The root request and response remain at their original CE interpreter point. No functional fixed-root correctness is substituted for a ROM response, and no new codec or primitive contract is introduced.

`executeFinish` performs the actual owner lookup. An absent owner returns unchanged state. A present owner runs `executeRegistration` on the original complete shared state, then reinstalls exactly the returned owner at the addressed index. `finish_exact` equates this with the real registration scheduler, preserving the entire owner registry and both shared caches. The local receive still uses the finish's candidate ratchet; it is not a receive on an already installed owner. Active failure abort, inactive no-op, preparation and pin checks, and successful publication are inherited through the exact real owner theorem.

`executeNativeFinish` lifts that same operation into the full CE native state. `native_finish_exact` identifies it with the actual `.finish index raw` branch for arbitrary checks, router and server seed. The Server raw-attempt counter, every owner raw-attempt counter and the complete produced-frame list are retained exactly. They are not discarded from the equality or assumed unavailable to a continuation. The primitive request transcript is preserved by the imported source program equality; any transcript represented in the native state is retained in full.

`finish_complete` and `native_finish_complete` make the continuation scope explicit. Any probabilistic continuation receives the same optional reply and complete state together, including the shared caches, owner registry, counters and produced frames. The theorem concerns the joint evaluated program, not equality of separate marginal distributions.

The all-sequence and rejection scope comes from `PqxdhBoundaryRegistrationReceive`: the complete receive precedes `afterOpening`'s sequence-one gate, uniformly for sequence 0, 1, 2 through 51, 52 and larger, malformed frames, absent application data, short or wrong-binding plaintext, and commitment or AEAD failure. There is no successful-finish or honest-owner premise. The same root and native callbacks run even on the rejected branches that reach them.

Existing `PqxdhDeploymentHiddenEntry.finish_accounting` remains the registration lane's receive-subprogram accounting: at most 51 chain-step KDF requests and one opening, and at most one hash in its stated factored interface. These are not total finish costs. This wrapper introduces no additional primitive call and adds no statistical or query-bound theorem. Preparation, root extraction, the initial KDF, native, base, uniform, codec and runtime work remain charged at their existing interfaces.

The public Rust finish loop, owner registry adapter and complete decoder remain the existing reviewed transcription and shared-reader boundaries; this module does not mechanically extract the Rust container or codec implementation. Primitive implementations, compiler/runtime/allocator and normal-return ownership remain external under the existing contracts. Snapshot and persistence reasoning is excluded. No Rust source, primitive assumption, registration budget or frozen CE interface changes.

Validation consists of a direct Lean check, five exact axiom guards allowing only `propext`, `Classical.choice` and `Quot.sound`, direct-reference and declaration-statement scans, and live negative controls for the PB-06 exclusions. The scans inspect this module's direct declarations and proof references, not all transitive imports. The reviewed real registration receive dependency remains frozen separately.
