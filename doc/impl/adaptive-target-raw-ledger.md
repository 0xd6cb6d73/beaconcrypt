# HB-114: adaptive target comparison and raw receive accounting

This checkpoint connects a final adversarial target choice to the authenticated root/evolving-chain reductions and supplies the complete raw receive compiler's resource ledger. It adds thirteen modules and 37 guarded declarations. It does not yet compose those reductions with CTX record security or establish one global symbolic/computational experiment.

The adversary's original post program returns an optional target choice and a decision bit. It runs once, after the original source-ordered private generation and candidate selection. For every catalogue entry, the existing fixed-target actual game is proved to equal a projection of that one execution. Filtering the final result changes neither the prior source work nor any query bound. The catalogue maps each choice to an actual role owner, positive record number, ancestor list and prior disclosure list. It is fixed before the experiment; arbitrary dynamically assigned peer identifiers still require a proved session-allocation map.

Writing A for this common actual execution, I_t for the explicit target-specific ideal and L_t for its constructed reduction loss, the checked bound is `|Pr[A wins] - Σ_t Pr[I_t wins]| ≤ Σ_t L_t`. Each L_t uses the original joint Ed25519/X25519 authentication, one-key ML-KEM, actual fixed-salt Extract and HMAC reductions, evolving-chain input-recovery testers and collision/guessing terms from HB-112, with that target's filtered original continuation. The different I_t are distinct experiments. Their sum is not asserted to be the success probability of an experiment that randomizes all owners together. The underlying source generator still designates one fresh Phase-1 root; earlier owners and common candidate branches remain present.

The ordinary evolving endpoint includes the private initializer value-alias comparison. The coordinate endpoint instead exposes the ordered source's actual full76 table and complete saved continuation, before that separate comparison; its loss therefore omits the initializer value-alias correction. It supplies the sampler needed by a one-key CTX consumer. Such a consumer must still externalize the selected first32 message key, retain the correlated second32 next-chain and final12 nonce, handle cached keys and aliases, and derive stopping or gating from the original freshness event.

Both endpoints are comparison events. Ineligible or attacker-owned common branches can retain a true original decision with probability one. They cannot be bounded as whole authentication winning probabilities by a small CTX advantage. A privacy comparison may cancel identical common branches. Authentication needs a derived honest-origin/freshness event across those branches; no premise requiring the adversary to return false there is added.

## Query accounting and contracts

Target selection sums separate reductions; it does not multiply the queries inside an individual reduction. The coordinate endpoint's complete sampling bill is `qPrior + 64 + U`, with `U = (7 + 67*qPost) * max(76, qPre, qApplication, 32, qSelector, qAux)` using the existing helper's nested maximum. This includes the actual preparation and every supported callback, even failure or repetition. Support annotations are erased by exact syntax equality; they do not condition or resample the distribution. Primitive and codec deterministic runtime costs remain outside the logical query count and are not declared free.

The raw compiler uses opaque chain values and private material labels. Its selected raw request contains the adversary's original bytes, and the original optional plaintext returned by the component reaches the extracted receive finish. The source driver keeps skipped slots, target consumption, successful kernel publication and failure rollback. No primitive call is needed on parser or validation rejection; every such call still consumes a source API attempt. The derivation oracle has an explicit bill and requires a later concrete interpretation. This checkpoint does not assert independent message keys or nonce uniqueness.

The permanent contracts remain correct primitive implementations and the existing exact joint-use, full-HKDF, optional KEM and codec interfaces. The security terms name actual games on the constructed samplers; they are not inferred from primitive names. Public HKDF evaluations stay real. Native compiler/runtime behavior remains external. Snapshots, persistence and restoration are outside the proof. No production Rust, ProVerif query, negative control or existing mutation matrix changes in this checkpoint.
