# Dynamic CTX modes for the record lift

`PqxdhRecordLiftCtxModes` extends the existing dynamic known-key compiler so that other keys may already be in the replay-checking hybrid. The actual private simulator supplies each known key, decoder, history index and mode adaptively. It can perform real CTX operations or replay-dictionary operations under that key while sharing the selected challenger's public BLAKE2b cache. No fixed family of independent other keys is assumed. Equal key bytes are permitted. This is a private compiler interface, not a capability exposed to the network adversary or CE environment.

The selected key is absent from `reductionImpl`, `wrapped` and `decisionClient`. `selected_step` retains the selected oracle's actual optional plaintext; `known_step` simulates the requested real/replay operation and retains its full private dictionary, public history and common hash cache. `linked_step`, `linked_schedule` and `schedule_interpretation` preserve the entire represented source state for arbitrary adaptive continuations. No recovered plaintext is inserted into a supplied target. `real_step` and `real_schedule` prove that all earlier real-only dynamic clients embed unchanged.

`sourceGame` samples exactly one uniform selected key, then runs this interface. `source_view` identifies its Boolean decision with the same constructed ordinary one-key CTX client. This is the ordinary endpoint distribution. The theorem does not establish that a production evolving key has this distribution: the persistent chain-table/source compiler and selected-input simulation must discharge that later.

`PqxdhRecordLiftCtxModeBounds` gives separate bounds for actual selected seals, every selected raw attempt, shared public hashes, explicit random requests, private replay-cache fills and selected plaintext bytes. Known-key work issues no selected seal or raw query. Real known-key seal/open operations may issue a shared hash query. Replay-mode private fills may issue 64 uniform byte queries instead. `private_not_uniform` proves those fills are disjoint from original explicit random requests, and `uniform_bound` and `decision_budgets` charge at most `qUniform + 64*qPrivate` forwarded uniform queries. `plaintext_step`, `plaintext_bound` and `decision_plaintext_bound` retain the weighted selected plaintext-byte cap. All bounds apply to adaptive callers and retain failed attempts; local AEAD, decoding and dictionary computation remain actual work, not a claim of zero running time.

For `qSeal < 2^96`, `selected_integrity` reuses the existing modified nonce-AEAD endpoints to bound the absolute Boolean probability difference between the selected real and replay modes by the sum of the validation IND$ advantage, `qHash/2^128`, twice the sum of the indexed INT-CTXT advantages over all `qRaw` possible selected raw attempts, and `qRaw/2^512`. The ordinary reductions are explicitly `validationReduction` and `indexedReduction`, instantiated with `decisionClient` and its raw wrapper. The factor two is inherited from the existing integrity comparison and is retained explicitly; no sharper primitive reduction is claimed.

`selected_privacy` adds the existing IND$ `viewReduction` advantage and reaches `AdaptiveCtxPrivacyGuard.randomView` for that same decision client. This endpoint is not yet a globally defined world of random records. Other replay-mode keys still seal using their real AEAD and a private tag dictionary; replacing all such ciphertexts and proving the final plaintext-hiding event require further adjacent simulations.

Both comparisons use the existing BLAKE2b random-oracle interpretation and modified nonce-AEAD INT-CTXT/IND$ games. They add no cryptographic assumption and do not prove primitive implementations. The source queries supplied to these games, selected key distribution, per-key nonce refusal probability, dynamic record and session selection, public versus produced frame events, and the final global budget transport remain obligations of the record-world compiler. Nonce equality across unrelated keys is not treated as nonce reuse. These modules alone establish neither global record authenticity nor the computational interpretation of ProVerif.
