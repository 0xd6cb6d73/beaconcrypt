# Paired source/context interpretation obligations

Status: design for review, not a proved abstraction. A one-world existence-of-trace or knowledge-preservation argument does not suffice to transfer observational equivalence. Any eventual source claim must construct one simulator/context that works in both worlds without knowing the hidden choice bit.

## Public host routing state

Allocate the comparison labels for source Beacon objects, Server objects, accepts and pending values when their public host handles are created, using a bit-independent injective analysis-name supply and a private bookkeeping map. The mapping uses object lifetime and actual caller-selected handle routing, never a cryptographic root, challenge plaintext or a future successful origin event. Retain distinct private pending continuations even when source-visible numeric labels repeat. If source labels are scoped to objects, encode a unique comparison label and translate its public reply back to the original scoped host label through the bookkeeping map. Native/source equality of host labels is evaluated on the original values; it is not inferred from equality of the auxiliary analysis labels. All token consumption and failed build paths must update that map identically in the two worlds.

The shared symbolic channel permits more worker schedules than the source. Merely choosing a convenient accepting worker independently in each world is insufficient. The comparison context must use its per-object/per-token mapping to request the actual selected worker at each source call, or a reviewed paired operational simulation must show that the common reduction schedule preserves this routing. Public caller labels identify replies but do not by themselves prove private worker selection. This is a concrete remaining obligation; a stronger-adversary slogan is not a substitute.

## Primitive and application calls

All pre-test key generation and root inputs keep the same paired randomness, source order and private state. The challenge interface maps its ordinary input to left/left and an eligible test input to left/right; it supplies equal-length nonempty messages under the abstract byte contract. The eligibility predicate depends only on exact signing identities and ghost target selection, not an assumed authentication event or the hidden bit. Failed seals consume allocations as before. Any abstract host failure allowed in the model must be supplied by the same public/bit-independent environment in the paired source interpretation; native allocator or arbitrary secret-dependent side channels are not proved here.

Every retained receive is run on the actual paired raw input, preserving the parser/open computation, sender/AD selection, entry state, rollback/cache updates, slot consumption and public Some/None result. The private application receives the true plaintext internally and has the explicit no-echo/no-secret-dependent-public-action contract. No challenger plaintext is inserted into an adversarial target. The source reduction cost still includes every operation, including computation performed by the simulator to reproduce omitted steps.

## Omitted public computations

The opposite/post-near chain outputs are already available in both worlds. A discarded opposite-direction or far call must expand to one fixed public recipe/program applied to those exact paired values and the original paired input. It may test public destructor success and return the corresponding result bit. If the recipe fails in only one world, that difference is itself a public observation available to the comparison attacker; it cannot be erased from the relation. Likewise, if its plaintext enters any permitted later public action, the context must use the original computed value in that action, subject to the application observation contract.

Thus inlining an omitted call requires operational public computability and the same bookkeeping program, not only separate membership in two deduction closures. The first-far-success cutoff remains part of the selected experiment. Subsequent target-direction calls are not silently simulated beyond that bound.

## Earlier initial-origin seam

Where an omitted selected opposite-direction send needs the selected finish's root, the previously proved initial-origin result may identify an earlier retained source build in each world. The lookup must yield the same source accept/build record in the simulator's bit-independent ledger, or a separate paired proof must show that differing records are indistinguishable at all subsequent recipes. Individual root-origin facts alone do not automatically provide that paired record equality. A source call identifier retained from the actual selected finish/build chronology may provide the needed link, but it must be established without reading the bit or assuming the desired secrecy conclusion.

This seam is therefore an explicit proof obligation. One-world initial-origin plus ordinary message secrecy is not a proof of the paired simulation.

## Scope after a successful solver result

The experiment selects one fresh Beacon signing identity. Other honest identities are exposed in the comparison as in the source profile, and their sends use the left message in both worlds. A global experiment challenging every honest identity needs adjacent identity/record hybrids with explicit counts and selection factors. A selected-identity solver verdict is a component statement, not an unrestricted replicated-session secrecy theorem. Reveal/compromise profiles, raw optional plaintext, computational reductions and exact query accounting remain separate until joined in the common experiment.
