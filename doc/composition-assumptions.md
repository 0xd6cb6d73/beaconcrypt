# From component reductions to a ratcheted protocol

The repository proves component inequalities and extracted-core state properties. Applying them to authenticated, KDF-derived keys across sessions requires a further experiment and simulation argument. This document names those missing arguments, instead of treating a list of primitive names as their justification.

## Historical exact-origin claims and the corrected projection

The production protocol cannot satisfy the three historical exact registration-origin correspondences retained in `exact-registration-origin-queries.pvl`. The [checked Phase 2 counterexample](impl/phase2-x25519-alias-counterexample.md) changes only the high bit of the received server ephemeral key, which X25519 masks before evaluating the same valid input coordinate. Rejecting invalid points and assuming perfect primitive implementations do not exclude this permitted alternative encoding. The same root and unchanged authenticated sequence-one record are accepted, while the raw decoded response differs from the server's response.

`BeaconCommitted` to `ServerCommitted` compares that raw field and the complete response. The two `BeaconRegistrationCompleted` correspondences to `ServerRegistrationSessionCommitted` and `RegistrationRecordSent` also retain the raw field in their `establishment_session` argument. All three queries are TRUE in the original ideal theory and FALSE with reconstructed traces in the added alias interface; the native test and checked Lean protocol congruence independently establish the concrete boundary and wiring. Record bytes alone retain their genuine origin in this witness, and no secrecy break is demonstrated.

The attack uses one honest response observation, one public bit flip and one candidate delivery, with zero reveals or extra primitive-oracle queries. It needs no identity/session selection loss or cryptographic forgery. Its success follows from the functional alias whenever the honest registration would succeed. Injectivity of accepted X25519 encodings cannot be introduced as a new primitive premise to eliminate it: the actual interface contradicts that premise. Comparing equivalence classes of encodings would change the stated correspondence and needs a new checked representation map; requiring canonical response encodings would change production admission. Neither change is part of this finding. HB-89 instead compares the retained authentication values directly: both identities, authenticated Phase-1 fields and origin, actual root and associated data, pinned server ID, and separately the accepted authenticated record. It does not choose normalized X25519 representatives or assume injectivity of DH. The traffic-session label also uses actual root bytes, avoiding an inverse-Extract implication. The revised symbolic queries do not discharge computational same-root session binding, collision bounds, target selection or joint-use simulation; those remain obligations of the common experiment. See the [projection record](impl/registration-event-projection.md).

The remaining reductions and source obligations below stay open at their documented scopes. Correcting the event projection and retaining the refuted historical conjunction do not prove evolving-chain secrecy, adaptive multi-session receive security or the common computational/symbolic experiment.

## The experiment a composition theorem must cover

A protocol adversary must be able to create and schedule sessions, register attacker-owned identities, deliver arbitrary wire bytes, request honest records, observe public transcripts and permitted outputs, and reveal explicitly chosen identity, root, current-chain or skipped-key state. Session identifiers used only in a proof are not extra KDF domain bytes. The production KDF uses exactly two public labels; directional separation comes from opposite selections of the initial split, and every later key, nonce and next chain is derived together from the current chain.

A freshness rule must exclude disclosures that reveal or derive the target message key at any point before the adversary’s final decision, including after the challenge. It must separately record permitted later chain disclosures that cannot recover already erased past material. Revealing the current chain compromises its descendants: there is no post-compromise recovery. A restored snapshot or retained skipped key can expose a past target that the live ratchet otherwise erased. Integrity of state ownership and replay history is an execution premise, not a consequence of key secrecy.

For a justified finite hybrid chain, the triangle inequality sums the adjacent distinguishing distances; it does not bound any distance by itself. If a reduction guesses one of `s` eligible sessions or `q` target records, the corresponding guessing loss is at most `s` or `q` only after proving that selection distribution and simulation. Adaptive stopping, compromise filtering, and multiple accepted attempts can change the counting. We therefore do not publish a numeric network-forgery bound obtained by multiplying existing component advantages by informal session counts.

Similarly, random-table collision bounds count distinct canonical `(domain, input, projection)` identities. Repeated observations and the intentional initial/step prefix alias at the same input are not independent samples. Distinct 32-byte coordinates yield the usual pair-count term divided by `2^256`, while distinct 12-byte nonce coordinates yield a pair-count term divided by `2^96` in that ideal experiment. Transferring those bounds to fixed production HKDF is precisely where the unsupported public-table hop must not be used. Nonce uniqueness across unrelated keys is also different from the per-key nonce discipline required by AEAD.

## Primitive guarantees, additional assumptions and idealizations

ML-KEM IND-CCA concerns hiding an honestly encapsulated secret under a target public key despite permitted decapsulation queries. The symbolic equation `mlkem_shared_secret(public_key, coins)` additionally treats that constructor as injective in the public key: equality of secrets forces equality of selected public keys. This is a stronger cross-key statement. To see why generic IND-CCA cannot imply it, append an ignored public tag to an IND-CCA KEM's public key and leave the encapsulation algorithm unchanged. The independent tag adds no information about the challenge secret, yet two differently tagged public keys with the same underlying key and coins produce the same secret. This separation is mathematical reasoning, not a machine-checked security reduction for ML-KEM. The repository's strong/weak re-encapsulation controls expose reliance on the stronger equation. A concrete ML-KEM binding analysis must state how keys and coins are chosen, account for invalid keys and implicit rejection, and bound cross-key collisions in that interface.

Ordinary Ed25519 EUF-CMA gives the adversary signatures but does not automatically give it DH computations using the X25519 scalar derived from the same identity seed. A protocol authentication reduction must simulate that extra interface while retaining the signing challenge. Conversely, an X25519 assumption must tolerate the correlated signing public key and signature transcript. The maintained `PqxdhJointIdentity` family exposes the exact correlated public-key, signature and converted-DH interface and its ordinary fresh-valid forgery event. The current actual-source authentication reductions use that explicit joint-use contract; the earlier stopped one-session reduction alone does not simulate every related use. The KEM reduction generates the identity locally, and the source server computes DH with its own seed/ephemeral and public conversion of the beacon identity. Replicated related uses and compromises still require the same joint interface throughout the common experiment. The global proof must supply a matching joint-use interface or a reduction that avoids every unavailable secret; see the reviewed [deployment contract](deployment-boundary.md).

ProVerif free constructors and destructors supply perfect opacity, constructor injectivity and exact equalities. BLAKE2b collision resistance is a concrete additional assumption for collision-witness bounds; treating its outputs as a programmable classical random oracle is a stronger modeling idealization for privacy/authentication hops. Neither collision resistance nor a standard AEAD primitive name alone supplies that random-oracle behavior. None of these classical experiments proves quantum-random-oracle or post-quantum authentication security.

The cryptographic assumptions are therefore attached to particular distributions, interfaces and winning events. The remaining composition task is to define and reduce the above multi-session experiment with those interfaces intact, not to assume that every ratchet key is fresh independent uniform data or that every public hash behaves as an ideal constructor.

Compiler correctness, allocator/OS behavior, native primitive implementations, physical erasure and foreign-runtime copies remain permanent external contracts. Persistence additionally requires integrity and provenance of stored payloads, rollback resistance, linearizable durable CAS, defined crash behavior and exclusive ownership; the unkeyed snapshot digest supplies none of those guarantees. No primitive implementation proof or strengthening of these deployment contracts is claimed by the encoding counterexample.
