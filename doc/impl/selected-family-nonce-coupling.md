# Adaptive selected-family nonce coupling

`RawCtxSelectedFamilyNonceCoupling.executable_distance` compares the entire original hidden-read-stopped source execution with the interpretation of the concrete adaptive CTX program from `RawCtxSelectedFamilyLiveCompiler.client`. Its loss is exactly one times the probability that the same instrumented source run encounters a selected send whose nonce was already used. It does not assume that this probability is zero, small, or independent of the source prefix.

The executable program has no explicit selected-message-key argument. Arbitrary supplied private state, preceding derivation tables and known-byte aliases remain allowed by these operational statements; input secrecy must be established at the actual source selection point. The selected key is an explicit parameter of the mathematical component interpreter and original-source comparison. Every accepted optional plaintext comes from the component reply and flows through the original continuation.

`optional_client` is a monadic translation of the original client into internal optional replies. It stops exactly when the existing OptionT interpreter stops. This translation neither adds a public capability nor returns a stopping value to a continuing adversary. `compiled_client` uses the reviewed complete state-interpreter law to prove that the interpreted callback schedule equals interpretation of one executable CTX program. Every original client reply, role state, reveal history, ambient value and component poststate is retained.

The analysis source `augmented` carries the original front state, complete ambient state and full dynamic CTX ledger. Until a selected-nonce refusal, it executes precisely the complete interpreted compiler transition. At a refusal, it executes the original source callback and installs the actual resulting original state and shared cache while retaining the added bookkeeping. `augmented_step` proves that removing only this bookkeeping yields the original source callback for every state. `augmented_client` lifts this equality through the entire adaptive client. The post-refusal bookkeeping need not be a new source invariant: the sticky event is already true, and the exact original state/cache projection continues to hold.

`marked_step`, `marked_client`, `marked_sticky` and `marked_hit` establish that the analysis flag records a reached refusal without changing any callback output or ledger state. `marked_agree`, `marked_distance` and `unmarked_distance` apply the existing identical-until-bad theorem. The generic agreement premise is discharged for this protocol by the literal `augmented_nonstop` equation; it is not an assumed cryptographic or source-simulation endpoint. `source_distance` compares the two complete adaptive callback runs, and `executable_distance` substitutes the actual executable reduction. These are full-distribution bounds, so subsequent events may retain the original adversarial decision and all authentication/secrecy gates.

The refusal predicate is the concrete reached `FamilyLiveCompiler.Stops`, inherited from the source-shaped send compiler. Empty input, exhausted sending state and other gates do not become refusals. Rejected raw records and hidden-key reads retain their existing behavior and observations. Public HKDF calls remain real fixed-source evaluations. Only a repeated nonce under the selected component key is charged here; nonce equality under unrelated keys is not itself this event.

The executable retains the previously proved adaptive bill: at most one dynamic record/public call per attempted source request and zero for a reveal, across all six budget coordinates, and at most the initial candidate count plus the reveal budget. This coupling adds no executable oracle call. Source uniform work, parsing, derivation and private lookup costs remain separate explicit bills; in particular, the raw receive lookup cap is 51 and the send lookup cap is one.

This module closes the adaptive record/public/reveal compiler comparison conditional on an explicit measured refusal term. Source attribution and a bound on that term, the distribution and nonexposure of the selected key, the original native-event/freshness corollary, the outer registration/installation schedule and final session/record selection factors are separate obligations. The initial ledger is arbitrary in these statements, so its refusal probability can be one. No cryptographic advantage bound or protocol nonce invariant follows merely from the analysis instrumentation. Snapshot and persistence behavior are outside the experiment.
