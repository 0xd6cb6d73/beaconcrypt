# Raw receive provenance in saved source descriptors

The selected CTX receive compiler consumes the original raw bytes. To resume a receive already stopped at a private KDF request, it needs evidence that those bytes decoded to the retained frame, passed the actual owner validation, and supplied the pending target sequence. An arbitrary value of the existing `OwnerContext.receive` datatype does not provide those facts. These proofs derive them from the source compiler that constructed the actual saved descriptor.

`RawCtxForwardOwnerScope.Valid` records nonempty raw input, exact decoder output, validation against the original expected sender and associated data, the retained associated data itself, and equality of the pending target with the decoded sequence. `begin_scope` and `resume_scope` reuse the existing complete extracted receive semantics to preserve the target and immutable context across every typed derivation reply. `receive_valid` carries the certificate through the actual skipped-key loop, including rejection and the eventual optional opening. `send_valid` preserves later certificates; a send descriptor does not use this raw receive interface and therefore has no receive-specific condition.

`program_valid` derives the certificate through every actual parser, validation, empty-input, send and public-service branch of an arbitrary adaptive owner program. It assumes neither an honest owner nor an accepted opening. `carried_valid` applies the existing forward scanner theorem to the exact descriptor returned by a supported scan. It does not replace that descriptor with an existential value having an equal continuation.

`RawCtxForwardRoleScope` lifts the same certificate through the actual Server peer lookup and associated-data selection, complete Server schedule, indexed Server publication, established and inactive Beacon dispatch, mixed role-family schedule, and adaptive record/reveal schedule. Its scanner corollary retains the literal selected role context and disclosure history. Every callback reply and original outside continuation remains available; there is no query-budget assumption in this provenance argument.

`PqxdhInitialDescriptorScope` extends the argument through the origin-aware registration builder and complete Post continuation. Records consume the concrete family proof. An attempted Beacon finish runs the actual preparation, audited initializer, application getter and raw owner, so only descriptors produced after that owner’s actual admission carry the receive certificate. Selector and other unannotated calls preserve the certificates of their full continuations. The first Server builder send retains its complete sealing, erasure, serialization, publication and post schedule; its own descriptor has no raw receive obligation. The final scanner theorem concerns the actual saved descriptor, reached private state and installation-origin trace together.

`PqxdhPreparedDescriptorScope` applies the construction certificate to the actual audited native cut, missing-parent preparation, concrete source-shaped `sampleOne`, full parent sampler and final material preparation. Its normalization lemma checks that discarding the unused earlier cache field cannot change the saved descriptor. The full material sampler preserves its parent output, nonce and next-chain draws in source order and keeps completed and cached outcomes. No source support condition is invented: the pending certificate follows from support in these existing executable samplers.

These are operational source facts, with zero probability loss and no additional oracle query or primitive assumption. They do not change the source compiler or assert that descriptor construction, parser work or local state operations are free. Existing query and local-resource bounds remain separate. They do not establish a complete CTX simulation by themselves: the consumer must resume the saved receive/send continuation, use the exact target response and actual optional challenger plaintext, retain full state, and carry the selected-nonce and disclosure accounting through the remaining program. No key independence, constructor injectivity, freshness, successful opening, identity agreement or global security conclusion is inferred. Snapshots, persistence and restoration remain outside scope.
