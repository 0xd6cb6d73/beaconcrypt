The fixed public-key quotient used by the sibling HB-92 diagnostic does not describe the entire production public experiment: it forces an equality when a caller reuses coins under different keys. This component instead records actual supplied values in a private append-only table. A value may coincide with any previously represented value or be new. Neither public-key equality nor inequality determines that choice, and no primitive input or output injectivity is assumed.

`classes_eq_iff` compares two values in the same retained table, and `sequential_classes_eq_iff` covers values inserted in source order. Equal values reuse a class, including coinciding results of different primitive inputs; distinct values have distinct classes. This is a derived property of the ghost representation, not an assumption that cryptographic operations are injective. Two independently extended tables can assign the same new numerical index to different values, so they are deliberately outside these statements. `branch_eq` preserves both equality and disequality continuation choices after the corresponding lookup relations are established.

No hidden plaintext or unavailable secret is passed to the client. It does not promise success or change malformed-input handling. `intern_length`, `record_length` and `optional_pair_length` bound growth by one class per recorded field and two per optional pair. `annotated_query_bounds` proves exact equivalence of every selective underlying-oracle cap, including all failures, rather than assigning opaque primitive work zero cost.
