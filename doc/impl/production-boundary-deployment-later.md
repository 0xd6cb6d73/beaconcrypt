# PB-D: LQ-F source join of the later-quantum deployment game

`PqxdhBoundaryDeploymentLater` closes survey row PB-13 for the later-quantum common deployment game LQ-F. It defines the adaptive LQ-F source step `laterStep` and the adaptive source game `laterSourceGame`, and proves seventeen guarded statements: the per-command joins with the LQ-F logged handler and snapshot handler, the whole-program join, the equality of the source game with the frozen LQ-F game `PqxdhDeploymentLaterServerGame.game` at the production codec on the full returned value, an index-0 instance, a normal-return statement, and generic continuation, observation and event transfers for item 8 (the event transfer both in the evaluation-measure form `𝒟[·]` and in the deprecated `Pr[·]` form). They are exact operational equalities; they add no security game, primitive contract or cryptographic conclusion, and no ghost is projected away.

The step. The run-phase state is that of `PqxdhDeploymentLaterServerGame.snapImpl`: the finish snapshot, the complete deployment state and the private ephemeral log (`RunState`). `loggedStep` mirrors the LQ-F logged handler `PqxdhDeploymentLaterServerGame.handler`: a raw accept runs the source-collected logged acceptance `PqxdhBoundaryLoggedAccept.deployment` (PB-03 under LQ-F, increment A), which reinstalls the accepted shared state and appends one optional Server-ephemeral entry to the log, and every other command runs the classical per-command source step `PqxdhBoundaryDeploymentStep.sourceStep` (increment I3, `doc/impl/production-boundary-deployment-step.md`) on the deployment state and keeps the log. `laterStep` mirrors `snapImpl`: before each command it computes `snapshotAt` from the pre-command owners, which for a `finish` captures the addressed owner's prekey and one-time fields (the cut of `PqxdhDeploymentLater.snapImpl`) and for every other command keeps the snapshot, and then runs `loggedStep`. The three shapes of the lane plan are stated as lemmas: `laterStep_finish` (capture from the pre-command owners, then the classical source finish of PB-06, log kept), `laterStep_accept` (the W4 logged acceptance, snapshot kept) and `laterStep_quiet` (every command that is neither a `finish` nor a raw accept runs the classical source step and keeps the snapshot and the log). As in the step module, codec′ is `PqxdhBoundaryRecordPrelude.withReader codec reader` and route′ is `RawCtxFrameDecoding.sender reader.model` (decision D-2, message #511).

The source game. `laterSourceGame setup codec reader erased checks ensureInit identityIndex bounds mode first second` runs, from a runtime state, the source-ordered Server birth `PqxdhBoundaryBirth.serverBirth setup.joint ensureInit identityIndex setup.serverKeyId` (runtime initialization, then one generated identity seed; a failed initialization returns no outcome with the runtime it returned and draws nothing). On a created Server it runs `laterSourceExec` from `PqxdhDeploymentNative.initial created`: `PqxdhBoundaryProgram.execute` of `laterStep` on the run-phase adversary `A₁` wrapped by CE's own secrecy layer, `PqxdhDeploymentSecrecy.wrap setup.source.crypto codec′ setup.serverKeyId bounds (asModeO mode first)`, from the empty snapshot and the empty log; then, through `PqxdhBoundaryProgram.resume`, only a successful run continues with `postPhase`, the modeled reveal and post phase of LQ-F: `A₂` (`second`) receives the run's output and the reveal `(revealOf owners snapshot, (some seed, log))` of the final owners, the snapshot, the Server identity seed and the log, and runs against `PqxdhDeploymentLater.postImpl setup codec′ checks seed` (fresh coins, and the native public HMAC and BLAKE2b commands on the final caches). The ledger, the snapshot and the log of the run are kept, and the post phase changes only the final deployment state.

Its returned value has type `Outcome KemSK Out × A`: on a successful birth, the encoded created Server, the literal Rust result (on success `A₂`'s output together with the run's final ledger, which is where `wrap` returns it) and the run state (the finish snapshot, the final deployment state after the post phase, the ephemeral log), then the runtime. `okMap` turns an LQ-F game value `(created, output, (ledger, (snapshot, (state, log))))` into `(created, ok (output, ledger), (snapshot, (state, log)))` and keeps the runtime; `unwrap` reads a source value back and is a left inverse of `okMap` (`unwrap_okMap`), so no part of the game value, in particular no ghost, is lost.
