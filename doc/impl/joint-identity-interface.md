# HB-90 joint identity interface and bounded selection

This checked component gives the Ed25519/X25519 seed reuse an explicit computational interface. It connects a finite family of adaptively used identity services to constructed single-identity weak-EUF reductions. It does not yet close the global protocol experiment, native adapter, production identity lookup or event-relative compromise policies. The checked follow-up below adds actual identity reveals with freshness through the final signature test. No production primitive or protocol choice changes.

## Exact primitive contract

`PqxdhJointIdentity.Primitives` takes one 32-byte seed to its Ed25519 public key and converted X25519 public key, deterministic signatures, and optional converted-static-DH replies at exact typed 32-byte peer encodings. `sampleSeed` draws 32 independent uniform bytes. The signing and DH services retain the same seed for their entire lifetime. Every request and actual reply is appended to one chronological history, including rejected DH requests. The seed stays inside the challenger interpreter.

The security endpoint's winning event is only ordinary weak-EUF: a valid signature whose message was never submitted to the signing service. Signing freshness is over the complete identity history, not one session's three source signatures; returning another signature on an already signed message is not a win. The adversary additionally receives a chosen-input raw optional-DH service. Security of this joint interface is an explicit assumption stronger than plain Ed25519 EUF-CMA. Ordinary EUF-CMA alone is not said to simulate this service. The endpoint contains no BeaconCrypt authentication, root, record or acceptance predicate.

The auxiliary DH service exposes more than the source protocol's root-derived outputs, which makes it a suitable authentication overapproximation after a source wrapper is proved. It is not a secrecy endpoint: it permits direct requests at every validated peer and has no target-DH exclusion. It keeps actual DH output bytes and their rejection distribution; no uniform-32-byte DH assumption is introduced. `PeerEquivalence` can supply an exact public equivalence relation with identical optional replies for equivalent encodings. The game neither assumes public-key/encoding injectivity nor silently identifies different raw request bytes. Native validation and functional encoding aliases remain correct-primitive interface facts, not implementation proofs.

`SourceWiring` states the narrow functional correspondence to `Pqxdh.Crypto`: the same seed-derived 64-byte native secret representation supplies its Ed25519 public key, attached signature, verification, converted X25519 public value and static DH. `jointPublic_conversion` proves the public conversion equation. `serverDhsFromAux_eq` and `beaconDhsFromAux_eq` reconstruct the exact four-DH tuples using one auxiliary reply for the seed-dependent server coordinate or beacon coordinate and three locally available DH operations. Successful replies preserve the exact byte string. The byte model represents a rejected DH result by its all-zero check. Instantiating this relation with native optional conversion/invalid-peer errors and the exact native seed-to-secret generator remains an adapter obligation. Source server constructors also accept a supplied seed; this uniform honest-family theorem does not assert freshness or randomness for arbitrary caller-supplied seeds.

## Full continuation and identity selection

`PqxdhJointIdentityFamily.sampleFamily` samples independent identity seeds in index order. `sampleFamily_target_first` moves any selected identity's seed to the challenger position while quantifying over the whole evaluated continuation. It generates exactly the remaining seeds, with no discarded placeholder key or equality of marginals substituted for a program equality.

The source family interpreter stores a complete history for every generated identity index. The reduction holds only the non-target seeds and their histories. It forwards all target signing/DH requests to the joint challenger and answers other identities using their locally generated seeds. `targetRouting_step` proves actual reply and complete history equality for every query, including forwarded randomness, and `targetRouting_complete` lifts that equality to any adaptive client from arbitrary prior local and target histories. The state combination retains the challenger's earlier signing and DH observations; the target secret never enters the reduction.

`targetGame_eq_reduction` identifies the source execution tested at one generated identity with the actual single-identity challenger running `reduction`. The reduction returns the adversary's unchanged message/signature, including when the adversary finally labels another identity. Any accidental additional win in that case only enlarges the upper bound. `family_advantage_le_sum` bounds an adaptively selected final identity's weak-EUF event by the sum of these constructed single-identity advantages. `family_advantage_le_count` gives `N * epsilon` when all N reduction advantages are bounded by epsilon. No public-key collision assumption is used: identity indices remain distinct even when public bytes collide. Connecting production byte lookup to generated indices still requires a checked lookup relation and any necessary public-key collision term.

`PqxdhJointIdentitySessions` maps a finite set of session labels to their owning generated identity indices. An arbitrary adaptive schedule of session requests uses the owner's shared identity service. `route_complete` preserves the complete continued execution and identity histories, and the selected session's unchanged forgery is mapped to its owner. `session_advantage_le_identity_sum` therefore pays the identity sum with no extra session factor. This depends on freshness against every signature requested under that identity, across all its sessions. It is not a claim that a message absent from one session's local log is fresh globally. Session creation, source signing policy, attacker-owned registrations, dynamic identity lookup and the later identity-reveal wrapper are not instantiated by this fixed owner map.

## Query and computation ledger

For N generated identities, a constructed reduction uses at most `qUniform + 32 * (N - 1)` uniform-oracle requests, `qSign` signing-oracle requests and `qDh` optional-DH requests when the whole source client has those class bounds. `reduction_query_bound` proves each class separately, and `session_reduction_query_bound` retains them under arbitrary session interleaving. Source random queries may request any finite uniform range; the additional 32-per-seed requests specifically draw bytes. `reductionGame_uniform_bound` additionally charges the target challenger's 32 seed draws, giving `32 * N + qUniform` for the complete interpreted game.

Non-target signatures and DH calls are evaluated locally, not declared computationally free because they are deterministic functions. Each corresponding source request triggers at most one such local primitive evaluation, so their counts are at most `qSign` and `qDh`, respectively. Forwarded target calls share those same source budgets rather than adding independent budgets. Seed generation evaluates N joint public maps. Final ordinary verification costs one verification. Retaining/routing histories, public lookup, signature byte processing, the three remaining source DH coordinates and later root/record computation retain their actual local work; uniform-oracle counts do not prove a runtime bound for them.

`familyRun_history_bound` checks source history class counts from arbitrary prior histories. `rejectedDhCount_le` and `familyRun_rejectedDh_bound` explicitly count invalid-point and other rejected DH replies within all `qDh` attempts. Rejection does not erase a query from the ledger. No opaque ambient computation is assigned a zero runtime by these statements.

## Remaining composition boundary

The joint-use advantage must be used explicitly when a later reduction preserves converted-DH observations before selecting an identity. The earlier stopped Phase-1 theorem may continue using plain weak-EUF when its reduction stops before any unavailable converted-secret operation. Neither endpoint supplies the other automatically. The follow-up global identity-reveal service below keeps freshness outside the primitive endpoint. Event-relative compromise after an earlier protocol target still requires its own freshness simulation. Root/current-chain/skipped-key reveals, copied snapshots, runtime identities, adaptive registration, public-byte collision accounting, record secrecy and the common ProVerif experiment remain separate obligations. Native primitives, compiler, storage and deployment contracts keep their stated external status. This milestone establishes no new ProVerif event by itself and does not claim full computational-symbolic closure.

## Follow-up: actual seed reveals and final-test freshness

`PqxdhJointIdentityFreshness` adds the actual reveal service to the finite generated-identity family. `sourceImpl` returns the requested identity's real seed and appends its index to the chronological reveal log, including repeated requests and a request for the identity the adversary later selects. Signing and optional-DH services keep their complete identity histories. The source imposes no oracle restriction that silently withholds the target secret. `Fresh` is the explicit final-test condition that the selected identity does not occur in the reveal log; ordinary weak-EUF message freshness is still checked against its complete signing history. This is a final signature experiment, not a theorem about compromise after an earlier root or record event.

`stopBeforeReveal` executes the original adaptive client with actual replies until the first reveal of the reduction's selected target, where it returns `none` before releasing that seed. `sourceRun_revealed` proves reveals cannot be forgotten. `fresh_probability_eq_stopped` then proves equality of every complete-result/state observer event conjoined with target freshness between the source and the stopped execution. A target-reveal branch contributes zero to that fresh event even if the original adversary continues arbitrarily after learning the seed. The statement does not identify the entire post-compromise execution with an aborted run. `stopBeforeReveal_no_target` checks the transformed client makes zero target-reveal queries; `stopBeforeReveal_query_bound` retains each source query class cap.

`revealRouting` locally answers the other identities' reveals from their sampled seeds while delegating every signing/DH/random service. Its total handler contains a default target reply, but the checked zero-target-query theorem makes that branch unreachable for the constructed reduction. No default seed is presented as an actual target reveal. `revealRouting_complete` and `reductionWork_complete` identify every returned option, all local and target identity histories, and the full reveal order with the stopped source execution, from arbitrary prior states. The reduction knows only the non-target seeds. The target seed stays inside the existing joint-use challenger, whose ordinary weak-EUF winning event and additional static-DH interface are unchanged.

`globalRun` samples the complete family in source index order, runs the unrestricted reveal-capable client, and lets that client choose its final target identity. `freshExecution_le_reductionWork` maps each fresh successful source forgery to the unchanged message/signature returned by the actual reduction. An aborted run returns one caller-specified fixed ordinary forgery; any accidental win on that branch only enlarges the bound. `targetEvent_le_jointAdvantage` applies the existing complete-continuation sampling interchange to the full observer, so it does not assume an honest selected public value or replace a joint distribution with a marginal. `global_advantage_le_sum` sums the constructed target reductions; `global_advantage_le_count` gives `N * epsilon`. Non-target identities may be revealed adaptively before or after signing/DH observations. Generated indices remain explicit, including if public values or seeds collide; no production byte lookup is inferred from index equality.

`globalReduction_query_bound` keeps the bounds `qUniform + 32 * (N - 1)`, `qSign`, and `qDh` for each reduction. `globalReductionGame_uniform_bound` charges the challenger's own seed and gives `32 * N + qUniform`; `globalRun_uniform_bound` gives that same bound for the actual source. These are uniform-oracle requests, with the added seed requests specifically byte-valued. `sourceRun_history_bound` and `sourceRun_rejectedDh_bound` preserve service counts around reveals and include failed DH replies. `sourceImpl_reveal_count` and `sourceRun_reveal_bound` explicitly charge every source reveal attempt to a separate `qReveal` cap. Repeated reveals count repeatedly. The stopped client performs at most that many reveal inspections and at most `qReveal` actual non-target seed replies; a target inspection stops locally before its unavailable oracle call.

Seed copying, each list append or membership test, history routing, and local deterministic primitive evaluation remain real work. Each returned reveal copies a 32-byte seed and updates its log; the log has at most `qReveal` entries from the empty state. Locally evaluated non-target signatures and DH operations remain bounded by the corresponding source class counts `qSign` and `qDh`; final verification costs one ordinary verification. The proof does not assign this work a zero runtime merely because reveal and non-target primitive handlers make zero challenger queries. It does not yet link runtime public-byte lookup, supplied seed distributions, native optional errors, secret aliases, dynamically created sessions, or an event-relative protocol compromise policy to this generated-index experiment.
