# Exact source requests as private material labels

This milestone realizes the complete generic owner interpreter using the actual KDF request as each material label. The native counterpart is the existing fixed-source HKDF and shared CTX backend. All previously explicit decoded-KDF and selected primitive equations are discharged by the constructed backend; no new local realization hypothesis remains in its source schedule theorem.

The label retains the exact original 32-byte input and 41-byte info. The same functional HKDF produces the original 76-byte response. Its actual extracted decoder selects key bytes 0–31, next-chain bytes 32–63 and nonce bytes 64–75. The generic KDF callback retains that next chain and returns the unchanged request as the material label. Equal requests can recur, and different requests may produce equal material values. No inverse lookup, key table or distinctness assumption is used.

Selected sealing and opening reconstruct material from the same request and call the existing native adapters. Original sequence, send target and encoded sender, plaintext or protected record, owner associated data and raw opening context remain unchanged. Both routes retain the same complete auxiliary state and CTX cache. The sender still publishes its advanced kernel after an active failed seal; failed receives retain their real primitive effects while the source controls owner rollback. All original empty-input, parser, pin, shape and capacity rejection paths remain.

## Computation and private-state scope

The native KDF callback remains the same fixed functional source throughout the execution. HKDF-SHA-512 is distinct from the BLAKE2b commitment table; no additional HKDF random table is introduced. The original structural source ledger still charges at most `qSend+51*qRaw` KDF callbacks. Uniform-query accounting treats the supplied HKDF as deterministic, so only possible commitment misses contribute the displayed 64-byte terms.

Reconstructing a selected label's material repeats real local HKDF and decoding work. Source execution, interpretation, slot copying, parser work, AEAD and table operations remain computation. The exact underlying oracle equality does not claim equal native execution time, allocations or physical memory effects.

Request labels retain earlier chain input bytes. They are private analysis state and are excluded from network, reveal, snapshot and persistence interfaces. The label representation is not a proposed native storage layout and supplies no physical-erasure claim. Any later compromise or restore interface must preserve the actual source disclosure policy explicitly. Concrete chains and counters remain in the owner, but this request-label law does not prove distinct source positions or an independent evolving-key distribution.

The backend uses the already explicit total functional AEAD and CTX random-oracle interpretation plus an optional functional writer. It preserves that interpretation's actual optional results, including writer failure after hashing. It does not identify every arbitrary optional native primitive error or prove the native crypto library, compiler, allocator, timing or deployment contracts. Public-service, reveal, multiowner and lifecycle extensions, root/registration distributions, evolving-key/challenger realization, restored-state policy and the global computational-symbolic reduction remain separate compositions.
