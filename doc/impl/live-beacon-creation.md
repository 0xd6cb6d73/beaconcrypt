# Live Beacon creation and dynamic owner indices

`PqxdhLiveBeaconBirth` formalizes the successful normal-return path of `Beacon::try_new` after initialization and the 32-byte length parse of the pinned server key (libsodium-rs `PublicKey::from_bytes` checks only the length). Production generates an Ed25519 identity, an X25519 prekey and an ML-KEM pair in that order. The one-time key is absent from the resulting Fresh object; `get_registration_bundle` generates it later if that object is still Fresh. An arbitrary live API schedule can run between those calls. Primitive implementation correctness remains a contract; reported constructor failures and binding parsing remain outside this normal-return module. No primitive internals are proved.

The model's private Created value stores the seed, complete prekey and complete KEM pair. The native Fresh state stores those same private values, the exact server public key and server identifier. The dynamic pool appends this entire object and returns only its index. Earlier owners keep their indices. Later requests are sent to the actual indexed owner together with the same common primitive/application state. An uncreated index returns none without a callback. A created index returns the actual callback reply and reinstalls its complete owner and common state. The callback is a parameter so the existing checked native services can be installed; this parameter is not an assumption about their cryptographic security.

The pool is an operational allocation interface, not the whole common experiment. It does not yet replace the fixed Fin-indexed source families used by the root theorem. Dynamic Server creation and registration-assigned peer identifiers require their own embedding. The initial pool and common state may be arbitrarily correlated and are retained in full; their earlier generation is not made free. A full experiment must charge its actual initial sampler separately. There is no assumption of independent public keys, distinct key bytes, honest selected candidates or unobservable failed calls.

| Statements | Meaning |
| --- | --- |
| `adjacent_complete` | When construction is immediately followed by one-time generation, the entire subsequent computation equals the earlier atomic Phase-1 generator. This is literal program equality including all private state. It does not move any intervening call or reveal across a draw. |
| `create_uniform`, `complete_uniform` | Creation costs at most 32 + qPrekey + qKeygen random queries; the later one-time draw costs qOneTime. Each primitive callback's full evaluated random work is an explicit input to the ledger. |
| `create_key_support` | The retained KEM public/secret pair is in the support of the actual KEM generator. It imposes no condition on a later adversarial choice. |
| `fresh_fields`, `fresh_handles` | The complete native Fresh fields are exact, and mapping only identity/KEM representations to generated handles recovers the existing source Fresh object. This mapping is independent of the later one-time sample. It is not a secret-free simulation of future owner services. |
| `allocate_continuation` | The newly created full object is installed before an arbitrary subsequent private continuation. The returned public value is only the index. |
| `install_prior`, `install_new` | Allocation preserves all existing indices and adds exactly one complete Fresh object at the returned index. |
| `owner_missing`, `owner_present` | Missing indices have no callback or state effect. Existing indices receive the original request and actual shared state, then publish the complete returned owner before continuation. |
| `step_uniform`, `schedule_uniform` | An adaptive schedule with qBirth births and qCall owner requests costs at most `(32 + qPrekey + qKeygen)*qBirth + qOwner*qCall`. qOwner bounds the actual owner callback, including its primitive work and failed paths. Further native instantiation must derive this callback cap; it is not zero or a whole-experiment bound. |
| `step_length`, `schedule_length`, `selected_index` | Only a creation increases the pool length. Its final length lies between the original length and original length + qBirth, and any actually present owner chosen afterward has index below that upper bound. Starting empty therefore yields the actual finite catalogue of at most qBirth owner positions, even with adaptive creation and selection. This says nothing about cryptographic origin or the distinctness of the owners' public bytes. |

The source audit also records obligations for the consuming live registration service. `new_onetime_keypair` generates before checking the phase, so even an inactive rejection must pay that draw. `get_registration_bundle` can be retried after serialization failure; all attempted signatures must be counted, and a Fresh failure discards only its local one-time pair. `FreshWithCoins` is a live compatibility state, not evidence that persistence belongs in scope. Its helper and bundle transitions, complete signing-log origin and repeated-call accounting still need to be installed in the dynamic source service. The single-attempt three-signature theorem cannot be used as a global signing cap. Snapshots, persistence and restoration remain excluded.
