# Source-factor receive through the selected CTX interface

`PqxdhServerAuthCtxCalls.lean` connects the source's selected first-record factor to a concrete receive client of the existing ordinary dynamic CTX interface. Its fifteen guarded statements preserve the actual optional plaintext and complete receive state. The client takes the 76-byte residual `(nonce, next chain, other directional chain)` and requires no selected-message-key argument. This is a functional compiler result; arbitrary supplied context or known bytes may still alias the selected key. It does not itself prove independence or a security bound.

`initial_source` maps the exact zero-counter, empty-cache constructor through the private material interpretation. `step_source` gives the literal joint KDF response: a hidden initial chain returns the known next chain and a marker carrying its nonce; a known chain performs the actual fixed HKDF and returns its complete concrete material. Both branches agree with the existing full 108-byte factor after interpreting the marker with the selected key. No public HKDF evaluation is replaced and no byte-alias branch is excluded.

The executable `receive` forwards an actual reached opening to `RawCtxSelectedOpenConsumer.service`. Its `opening` conversion fills only chain fields that the original getters never read. The selected route supplies the original raw context and public nonce to the ordinary raw oracle; the returned optional plaintext comes from that oracle. The known route keeps the original known-key opening and shared hash cache. Neither route supplies a recovered plaintext as an adversarial target.

`scope_chains`, `begin_scope` and `resume_scope` derive the requested sequence and immutable raw context through the complete opaque-chain driver. `program_projection` therefore requires callback equality only for reached openings at that target and context, instead of asserting simulation of arbitrary native opening capabilities. `opening_project` consumes the actual native adapter and existing selected/known source theorem, including absent material and failed opening. `derive_project` retains the complete deterministic KDF response. `receive_project` transports these concrete callback equalities through the entire cached/future driver, including all skipped-key steps, rollback and the original finish.

`receive_material` uses the reviewed material-map driver to reconstruct the complete value-side computation under the selected 108-byte factor. `receive_source` combines that reconstruction with the CTX interpretation and erases only the added component bookkeeping. The resulting native material slots, private chain coordinates, original optional plaintext, unrelated ambient state and shared commitment cache are retained. This is still the selected-factor computation; the actual separately sampled factor distribution and preceding KDF hybrid are separate consumers.

`raw_source` includes the original `RawCtxChainOwner.rawReceive` prelude. Empty input, decoding failure and validation failure keep their original rejection and attempt-count update. The reached branch derives its nonempty/decoded/valid conditions directly from that prelude and returns the same actual plaintext and complete updated owner. The receive-only call records have an unused send field; this theorem never invokes it and does not implement the Server send service.

`receive_callback_bound` and `receive_bound` give at most one dynamic component query per complete receive. `raw_bound` extends that cap to arbitrary raw delivery, including unsuccessful attempts. The separate original KDF callback allowance is at most 51, supplied by the existing chain-driver resource proof; each known-chain derivation keeps its real deterministic HKDF work. These are component-oracle bounds, not a zero-runtime claim for local processing or a global one-opening theorem.

The actual hidden Server build, logged writer behavior, nonce-refusal handling, and the adaptive service mirror remain separate work. Successful sequence-one registration must additionally consume the exact sequence-one empty-material theorem after proving that the API reply's sequence comes from the reached raw frame. The full authentication reduction must derive its one-selected-session seal allowance from actual source marks and the collision event, retain known-key aliases and all public observations, use the proved key-first factor sampler, and connect the original event to the ordinary CTX observer. None of those distribution, event or schedule obligations is assumed by this package. Serialization, persistence and primitive implementation proofs remain outside the approved scope.
