# Native source interpretation of the Server authentication experiment

`PqxdhServerAuthNative` connects the approved R1 authentication experiment to the existing native source transcriptions. Its independent native experiment executes actual preparation, extracted acceptance, registration building and Beacon finishing. Only zero-salt Extract on the actual 192-byte root input uses the approved shared random-oracle table; root Expand, all public HKDF and all other HMAC calls retain their original implementation contracts. The existing shared CTX/BLAKE2b random-oracle interpreter is retained as well; the restricted Extract table is the only patched KDF interface. Primitive correctness is trusted, and the existing abstract codec boundary is unchanged.

## Root and source operations

It preserves the old family history and cache and appends exactly the original derivation and Expand observations. `romRoot` supplies the literal Server pending token's input; `romRootReply` supplies the literal Beacon candidate's input and source array wrapper. `root_rom`, `client_rom` and `server_stage_rom` preserve the complete Server preparation and acceptance sequence: raw decoding, three verifications, admission, fresh ephemeral generation, arbitrary-key KEM encapsulation, conversions, DH operations, extracted acceptance, shared-input clearing, root derivation, input clearing and registration consumption. Reference facts come from the original supported prefix. `beacon_root_rom`, `beacon_tail_rom` and `beacon_stage_rom` preserve the actual prepared candidate, conversion and expected-binding gates, initializer, application getter, raw receive, sequence-one and registration-binding checks, all optional failures and the complete continuation. The generic lemmas state their operational callback conditions; the concrete experiment discharges them from its actual callbacks and source invariant.

The concrete native functions do not interpret an executable symbolic experiment in their definitions. ## Constructor order and resource scope

The approved R1 experiment samples Server identity, Beacon prekey, Beacon identity, one-time scalar, and KEM keypair. Rust's Beacon constructor instead samples identity, prekey and KEM, followed by the Phase-1 one-time generation. `constructor_order` proves both interchanges for an arbitrary complete evaluated continuation using the actual interpreted KEM program. `sourceOrderedState` runs this literal constructor order and then the unchanged Phase-1 and adaptive native execution; `actual_source_order` preserves the entire resulting state distribution. `source_order_game` carries the same original authentication event through that source-order execution. The proof neither asserts syntactic commutativity of oracle programs nor infers a whole execution equality from marginal key distributions.

All source samplers, KEM programs and their base-oracle interpretations remain explicit. The exact experiment-order program equality adds no oracle call and transports the existing complete source/reduction resource statements. The constructor-order presentation executes all the same actual samplers and complete continuation, including unused or rejected results. This module does not claim deterministic callbacks or ambient primitive work have zero runtime, and it adds no new cryptographic reduction, query cap or loss.

The result applies only to the approved R1 experiment and its stated reveal policy. It does not establish the later CTX reduction, close the headline authentication bound, add replicated-session security, or prove assigned-ID equality, KCI or unrestricted secret reveals. Existing extracted-core and adapter-transcription contracts, the functional primitive contracts, and the approved restricted Extract ROM are unchanged. Serialization, primitive implementation correctness, compiler behavior and deployment are outside these operational statements; snapshots and persistence are outside this proof's scope.
