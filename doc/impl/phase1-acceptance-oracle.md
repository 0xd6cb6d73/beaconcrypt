# Optional Phase-1 source acceptance (HB-90 continuation)

This focused component extends `PqxdhJointPhase1Reports` from report observations to an actual optional acceptance interface. Every candidate query returns the complete decoded Ed25519 public key and prekey/one-time/ML-KEM tuple, or rejection, to its original adaptive continuation. A separate public monitor recognizes accepted unissued fields against the complete prior signing/reveal history. Erasing that monitor preserves the full source result, private seed prefix, dynamic transcript and signing/DH/reveal histories. This is a typed source interface after four-field decoding; native Cap'n Proto, byte-based ownership, full registration/root processing and global record composition remain open.

The source accepts a candidate independently of its claimed generated index. That index labels only the origin event. Malformed candidates, attacker-owned public keys, previously signed fields, prior compromise and later compromise remain in the same experiment. The theorem does not assume honest target selection or infer native ownership from equal public bytes.

## Exact source and monitor interfaces

`SourceSpec` retains all previous dynamic identity operations and adds `CandidateReport → Option AcceptedInput`. `AcceptedInput` is the actual parsed Ed25519 public key paired with the three parsed Phase-1 public keys. `acceptanceImpl` computes the existing `sourceAccept` attached-verifier/parser result, performs the public origin instrumentation, then returns that entire optional value. The primitive implementations remain opaque correct functional contracts. The source verifier checks identity width, then PQ, prekey and one-time attached signatures, then the core identity/tag/width parsing. No rejected candidate is replaced by a fabricated accepted tuple.

`instrument` forwards exactly one original request into the reviewed report interface. After a candidate's Unit report it returns the detached endpoint's complete optional result to the original continuation. `acceptanceImpl_eq` proves equality of complete per-query stateful computations under `HasAttachedVerificationAdapter`; `actualRun_eq` lifts this through every adaptive continuation and retains all monitor and private source state. The adapter premise is the existing ordinary attached-signature format equality, including the fixed signature prefix and short-input rejection. It is not an authentication or secrecy assumption. The previously checked `source_attached_adapter` explains its production functional instantiation.

`bareImpl` independently specifies the uninstrumented typed source. It forwards dynamic identity operations to the actual on-demand generated source with its complete history, and candidate requests simply return `sourceAccept` while retaining that source state. `erase` removes only the field monitor and the underlying signature-report monitor. `sourceCandidate_erase` proves that candidate monitoring changes no underlying dynamic identity state; `sourceIdentity_erase` proves identical identity-service replies and poststate after that projection. `acceptanceImpl_erase` combines both branches, and `actualRun_erase` lifts the exact projection through the entire arbitrary source continuation. These four erasure statements do not require attached-verifier compatibility: even a disagreement between the public classifier and the actual verifier cannot change the uninstrumented source's optional replies or private state. Compatibility is needed only when transporting the event to the established reduction.

The two local Lean elaboration options in the erasure proofs resolve dependent oracle-range aliases during rewriting. They change no theorem statement, executable definition or kernel assumption. Persistent guarded dependency reports check all seventeen statements.

## Authentication event and reductions

`acceptance_advantage_le_sum` connects the same report-time field-origin event to the existing concrete family of joint weak-EUF reductions. For `N = count + 1`, at most N generated creations, and arbitrary complete source continuation, it proves:

```
Pr[an accepted fresh generated-identity field was never signed before that acceptance]
  <= sum(target < N, AdvJointWeakEUF(constructed reduction target)).
```

The reductions are the unchanged `globalReduction`, `routedAdversary` and `reportExtractor` applied to the exact `instrumentedClient` and reviewed public field translator. One first-unissued original attached field is selected deterministically against the complete signing history. There is no field, acceptance-position or additional session factor. The joint endpoint still samples one uniform 32-byte Ed25519 seed, derives its correlated public identities and offers ordinary signing plus the explicitly stronger chosen-peer optional converted-static-DH service. Its winning event is ordinary fresh-message weak-EUF. No new primitive endpoint, algorithm proof or protocol conclusion is inserted into its assumption.

`actualRun_occurred` identifies the retained sticky event with an accepted original candidate observation and its recorded source position. The actual source continues after that event, including subsequent creation, signing, DH and compromise. Event freshness is evaluated at acceptance, not incorrectly required through the final source return. The existing single-bundle changed-field corollary still requires the independently checked exact three-message log; the optional interface does not infer a once-only signing policy from a successful bundle return.

## Query and computation ledger

`instrument_query_bound` and `instrumentedClient_query_bound` retain each declared source query class through every possible optional reply and continuation. `instrumentedClient_total_bound` also preserves the total source request cap. The classes include generation, explicit uniform requests, signing, optional DH, reveals and all candidate attempts. Invalid indices, rejected DH and repeated reveals remain actual requests.

`reduction_query_bound` gives each selected reduction the same signing and DH caps, and `32*(N-1) + qUniform` uniform-oracle calls. `reductionGame_uniform_bound` adds the target challenger's private seed and gives `32*N + qUniform`. `actualRun_uniform_bound` instead charges the actual on-demand source `32*qCreate + qUniform`; `bareRun_uniform_bound` preserves that cap after monitor erasure. These sampling statements use the same functional adapter to reuse the exact reviewed source translation; no security premise is needed to remove the monitor. Each seed byte costs one byte-valued uniform request; a separately counted source uniform request may use another finite range.

`actualRun_attempt_bound` counts every original candidate by `qAttempts`, including malformed, attacker-key, already-signed and compromised candidates whose monitor forwards no fresh forgery. `actualRun_request_bound` charges every original slot by `qQueries` and retains the ordering of candidates among all identity services. The N-way reduction sum does not represent N primitive queries within one chosen reduction. The retained source bundle's separate three-signature cap remains unchanged, while the global interface permits the caller's explicitly bounded prior signing history.

Parsing and public signature verification are local computation. The bare source performs up to three attached verification operations on a candidate. Instrumented executions additionally evaluate the public field translator and signature-report predicates, potentially repeating public verification, input parsing and history membership scans. Those operations are not free because they are pure Lean functions or absent from a signing-oracle count. The qAttempts/qQueries caps bound invocations, not total input bytes, native verification runtime, allocator work or copied history size. A complete global runtime statement must additionally supply those input/service byte and local-work budgets. This component does not discard that remaining obligation or call opaque work free.

## Remaining composition

The entire state/result equalities are checked after the four raw fields have been decoded. Native outer decoding and complete-input behavior, field provenance, attached implementation correspondence, the generated-index/native-owner map, caller-supplied honest identities, and composition with known-seed imports require their existing explicit boundaries. The decoded candidate's public key is returned unchanged regardless of the event label; production byte lookup and collisions must not silently convert that label into ownership or freshness.

The source continuation may now consume the actual optional tuple, but this component does not itself execute registration replay reservation, optional ML-KEM encapsulation, the 192-byte root input, symmetric initialization or record publication. Existing one-session root and evolving-chain components still need the common protocol experiment, exact correlations, reveals and query accounting. This checkpoint does not establish assigned-ID equality or the computational soundness of symbolic constructor injectivity. Primitive implementations, compiler behavior, physical erasure, native/foreign copies, allocator/OS behavior and durable storage stay external contracts; persistence integrity, rollback resistance, linearizable CAS, ownership and crash behavior remain deployment premises.
