## Scope and reading conventions

The governing sources are [the October 6 handoff, item 7](handover/pause-2026-10-06/README.md), [the CE plan, sections 3, 5, 8, 13 and CE-14](common-deployment-experiment-plan.md), the current [CE guide](common-deployment-experiment.md), and the task-v3 decision of 2026-10-09. Later sections of the CE plan supersede its early estimates and open-status prose. In particular, D5 was accepted, LQ-F replaced the temporary D6 profile, and failed registration receives remain in the CE/registration lane by the owner decision recorded in plan section 25.

In the tables, **L** means a proposed Lean statement over extracted definitions and already approved abstract interfaces; it does not mean extraction of the public Rust adapter. **T** means an identified existing finite check or a clearly labeled proposed check. **RT** means reviewed transcription: no Rust-to-Computational declaration check currently pins that link. **E** means an existing external contract or an explicitly accepted model deviation. An entry may require an L join and a T check while retaining E for the compiler or codec implementation. This plan changes no Rust code and authorizes no new assumption, primitive theorem or threat-model extension. Proposed fidelity tests are future work, with their own review and mutation rows; they are not evidence already available.

All proposed equations must retain the actual optional reply and complete in-scope protocol state, including failure effects and the shared hash cache. Where proof instrumentation adds counters or traces, its relation must be explicit. LQ-F specifically requires retaining the joint law of its final state and private reveal ghosts; projecting away those ghosts does not prove the later boundary. A distributional statement must quantify over the whole continuation. The survey does not identify distinct sessions from equal bytes, infer publication from cryptographic production, assert assigned-ID equality, or infer primitive security from an operational equality.

Snapshots, persistence, saved-state restoration, physical erasure and running-code compromise are excluded. The word “rollback” below means the result of one failed in-memory receive on the same live object. `ReceiveTransition` is inspected only through the ordinary `decrypt_message` result and its accepted/rejected distinction; serialization and durable update APIs are not brought into scope. LQ-F's private proof logs are analysis instrumentation for the approved post-run reveal, not a production saved-state API.

The compiled-core transcript test checks exact domain labels, padding, root contributions and CTX transcript bytes. Free-schedule checks pin the reviewed symbolic vocabulary/source annotations and runner roster. These checks are useful maintained evidence, not proofs of arbitrary Rust execution or of the codec implementation.

There is already substantial negative coverage in this test file. Item 7 should add only checks needed to pin newly relied-upon adapter transcriptions or CE join declarations. It should not re-run or recreate the complete mutation campaign for Lean/documentation-only changes. No test or Lean build was run for this survey; the evidence here is inspection of the named source at the stated hash. The survey scratch manifest records the exact inspected file hashes and declaration anchors so that review can distinguish this basis from later central changes.

An important asymmetry must remain explicit: the record decoder requires complete input, while the two registration readers are the abstract registration codec interfaces in the source transcription. The record complete-input theorem must not be generalized to Phase-1/Phase-2 byte parsing without source evidence and the already approved codec contract. Likewise, `FrameReadBack` guarantees the approved readback relation for successful writes; it is not canonical serialization, general parser correctness, injectivity, or writer totality.

## Required shape of the final boundary result

The final artifact must identify one explicit in-scope adapter execution or reviewed transcription, the same raw/caller inputs, the complete primitive callback schedule, its exact CE interpretation and a state relation that keeps the live Server, owners, pending tokens, consumed-registration set, ratchets, replay history, ghost counters and shared hash state in their respective roles. It should give per-command equalities followed by a whole adaptive-program equality. It must state when it relates extracted functions directly and when it relies on the reviewed unextracted adapter correspondence.

Each claimed source effect has to have a consumer. In particular: the root theorem names the actual 192-byte input and approved backend; receive names the actual optional challenger plaintext; send names the produced frame before the writer; publication names the successful API/wire result; registration names the bound eight-byte prefix and sequence-one acceptance; routing names the claimed sender and actual lookup; state publication names the exact returned kernel. Neither a list of unused bridge conjunctions nor a test manifest alone closes these joins.

The permanent boundary is the PB-E contract ledger: approved primitive games/idealizations, codec interfaces, legal-input HKDF behavior, allocation/OS/compiler/runtime/extraction contracts and integrity of live state ownership/replay history. This work proposes no new primitive, codec, runtime or deployment contract. If an intended equation needs a stronger property than those interfaces provide, the incremental proof must expose that gap and request an owner decision rather than place the desired CE conclusion in a new assumption.
