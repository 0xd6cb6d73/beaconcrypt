# Complete selected builder source equality

`PqxdhServerAuthBuildSource.compiled_source` closes the local nonce condition in the complete executable selected Server builder. The theorem compares the literal logged source factor builder with `PqxdhServerAuthBuildProgram.compiled`, interpreted using the ordinary selected/known-key component. Its only additional starting-state requirement is that the selected endpoint's used-nonce list is empty. It does not require a nonce-freshness assertion at every reached callback, successful admission, a successful writer, a source callback simulation premise, or a particular final response.

The comparison is equality of the complete probability programs after the established source projection. It preserves the actual optional or diagnostic native result, complete returned Server state, original successful-frame context log and full shared cryptographic cache. The executable side retains its entire private component state before that projection. Outer `OptionT` refusal remains distinct from the native optional writer or response failure: the source result is wrapped in `some`, and the proved equality shows that the executable builder cannot refuse under the stated initial condition. The explicit selected-key parameter occurs only in the mathematical evaluation and source comparison; the executable builder takes no selected-key argument. This does not exclude arbitrary correlations or equal known-key bytes.

`evaluated_bind`, `evaluated_pure` and `evaluated_program` show that evaluating the executable optional stateful computation commutes with the complete continuation and the actual service program. They retain both the local log and the component state, including the state reached before any outer refusal. `auxValue` records the literal deterministic outcomes of the existing identity check, allocation checks, erasure and response writer. `source_aux` and `evaluated_aux` prove that both actual auxiliary interpreters return those same outcomes without changing any log, cache or selected-nonce bookkeeping. No abstract callback-independence condition is inserted.

`projected_bind` is the exact composition step for an optional interpreted prefix and its full continuation. It retains a refused prefix's reached state and projects only the existing private component bookkeeping. `bounded_source` then inducts over the complete service program with an attempted-seal bound of at most one. Before that seal, all auxiliary calls preserve the initially empty nonce list. At the seal, the initial condition supplies the local freshness fact needed by the already proved concrete sealer equation. Every continuation then has a zero seal-query bound, so it requires no freshness invariant on the post-seal state. This counts attempted seals and covers every possible reply, including native frame-writer failure.

`compiled_source` supplies the actual complete builder's `program_bound` and `program_logged` equations to that induction. All original next-ID allocation, pending-token binding, peer availability, candidate validation, authenticated prefix construction, first send, erasure, both optional writers and successful peer publication remain in the compared execution. The actual source chain/material settlement and same shared-cache interpretation are inherited from the reviewed builder modules; the proof does not replace them with an arbitrary equivalent marginal distribution.

This package adds no oracle call, randomness, selection factor or probability loss. The complete executable builder retains the existing `BuildProgramBounds.compiled_bound` and `compiled_bills`: at most one total component call, selected seal at most one, hash at most one, selected raw opening zero and uniform zero. Local HKDF, parser, validation, native callback computation and component interpretation retain their separate existing resource bills; this is not a claim that those operations are free.

The enclosing stopped scheduler must still establish that its selected endpoint is unused when this builder begins. The published second-selected-accept monitor and pending-token potential supply the relevant at-most-one-build discipline, but that concrete full-handler consumer is separate. Literal sealing-session provenance, acceptance snapshot chronology, the actual challenge distribution and the final ordinary CTX event reduction also remain separate. The existing programmable Extract ROM and shared CTX/BLAKE2b ROM interpretations are unchanged. This theorem is an operational source equality, not a new primitive assumption, a standalone authentication theorem or a general computational-soundness theorem. Serialization implementation, saved-state restoration and persistence remain outside the approved proof scope.
