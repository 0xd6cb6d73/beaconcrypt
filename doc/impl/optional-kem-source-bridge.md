# Optional ML-KEM source boundary for HB-82

This follow-up closes the optional encapsulation seam in the typed authenticated-root experiment. It extends the reviewed authenticated-root checkpoint `1dbe09d7e6283deb9a8b040d7aeba8a22ef2fed2`. Production source is unchanged. It does not establish the remaining complete native adapter relation, replicated experiment, evolving-chain freshness, or adaptive receive composition.

The source server first verifies the selected registration fields and checks replay status, then generates its ephemeral key before decoding and encapsulating under the selected ML-KEM public key. `beaconcrypt/src/server.rs` propagates native key decoding and encapsulation failure through `Option` before identity conversion, DH processing, root derivation, registration consumption, or response publication. The former total typed encapsulation interface could not express this arbitrary-key rejection. `SourceKemInterface.encaps` now accepts the exact 1,184-byte public-key type and returns an optional 1,088-byte ciphertext and 32-byte shared secret through the existing uniform/base oracle interface. Its optional operation includes public-key decoding and the encapsulation call; no success guarantee is imposed on arbitrary submitted public-key bytes.

`acceptedCommon` and `allCandidateCommon` preserve rejected, attacker-owned, accepted unchanged, and accepted changed candidates in the same game. Replay and initial validation rejection occur before ephemeral generation. Optional encapsulation failure retains the already generated ephemeral, records no ciphertext, and passes the unchanged registration and server state to the complete observer. A successful encapsulation reaches the existing conversion/all-zero checks, exact `FF^32 || DH1 || DH2 || DH3 || DH4 || SS` input, and root-dependent record construction. No root-dependent record exists before the supplied root is consumed. As in the earlier typed model, `.badEncoding` represents the failure branch and the public observer projects it to the native API's `None`; this is not a claim that native callers receive typed internal error reasons.

`HonestKeyCompatibility` is a functional primitive contract separate from IND-CCA security. For each public/secret pair in the evaluated distribution of the actual ordinary ML-KEM key generator, the interpreted optional encapsulation output distribution equals `some` mapped over the interpreted ordinary encapsulation distribution for that public key. It refers only to the exact primitive interface and honest input distribution. It contains no registration authentication event, no root indistinguishability conclusion, and no claim about arbitrary submitted keys. `honestEncapsulation_no_failure` derives the absence of native rejection at those generated keys from this functional contract. Ordinary IND-CCA security itself is never used to infer this property. Under the permanent correct-primitive assumption, this contract connects two views of the same ML-KEM operation; algorithm internals and native implementation correctness remain external.

The reduction's `sourceProtocol` retains ordinary total encapsulation only in its internally identified authenticated unchanged branch. Its non-target callback uses the optional operation for every actual submitted key. `directTargetContinuation_eq_total` lifts honest-key compatibility through the whole source target continuation, including generated ephemeral, abort state, real DH input, root-dependent record construction, and complete observer. A successful fresh target uses the same postchallenge decapsulation interpreter that blocks exactly the challenge ciphertext. Failed encapsulation and conversion/DH abort observers retain the unrestricted prechallenge interpreter. The generated KEM secret is confined to the enclosing interpreters; no protocol or adversarial observer callback receives it.

`sourceGame_eq_actualGame` proves equality of the complete evaluated games. It uses the existing generator-order theorem for the complete continued distribution, then the borrowed prefix's proved target-field equality, to establish that the retained target belongs to the actual key-generation support. Thus no hypothesis says that the attacker selected an honest key. Arbitrary candidates still execute their optional source behavior. The equality is evaluated-distribution equality for every complete observer after fixing the existing stateless base interpreter; it does not assert syntactic equality of two opaque primitive programs or identical internal query traces. Source and reduction resource bounds are therefore stated separately. Stateful global primitive interfaces still require the later global composition layer.

`actualRootAdvantage_le_euf_add_kem_add_extract_add_hmac` transports the existing four-term reduction to that actual optional source game. Its explicit reductions remain the stopped three-signature Ed25519 weak-EUF-CMA adversary, the one-key ML-KEM IND-CCA adversary, the fixed-salt Extract distinguisher for the exact conditional secret-input sampler, and the one-query uniform-secret-key HMAC PRF adversary. Each coefficient is one. There is no new statistical loss for the optional bridge, no public-HKDF/random-table term, and no honest-candidate assumption. Same-identity accepted field substitution is charged exactly once by the retained EUF theorem. Rejected, attacker-owned, and completed abort decisions remain real; only the eligible unchanged pending root is replaced.

The conditional sampler and all ghost operations remain explicit. A completed branch has already produced its full decision before the ordinary challenger performs its unused encapsulation and the sampler draws a uniform 32-byte contribution. That completed branch's dummy `FF^32 || 0^128 || uniform32` input is ignored by the stored decision. A pending branch uses the actual 192-byte source input. Neither dummy draw nor source encapsulation on an abort branch is removed from query accounting. Every public HKDF evaluation stays real.

For a chosen uniform, base, or logical-decapsulation resource class, the actual optional accepted continuation has cap `qEphemeral + qNative + qObserver`. Rejection after an optional attempt is covered by the same cap. The reduction's prechallenge cap is `qSigned + qEphemeral + max(qTotal, qNative) + qObserver`, where `qTotal` bounds ordinary total encapsulation and `qNative` bounds the optional native operation. `qSigned` includes identity generation, prekey generation, one-time generation, all three actual signing computations, and selector work. The KEM challenger's key generation and challenge encapsulation are additional interpreted work, not part of that adversary prechallenge cap. The specialized logical-decapsulation theorem gives `qSelector + qObserver`; optional parsing, ephemeral generation, and either ambient encapsulation interface add zero logical CCA requests but retain explicit uniform and base budgets. The postchallenge cap is the corresponding complete observer cap, separately for uniform, base, logical decapsulation, public root-KDF, and public symmetric-KDF queries. Blocked challenge-ciphertext attempts count.

The retained EUF signing cap remains three. The Extract endpoint performs one fixed-salt extraction on the exact joint sampler; its uniform-PRK challenger draws 64 bytes. The HMAC reduction makes one challenge query and at most `qPrefix + 32 + qPost` public uniform-oracle queries, using checked full interpreted-prefix and complete-observer budgets. These budgets include all opaque base/primitive work and the completed-branch ghost encapsulation. The HMAC challenger itself draws a 64-byte secret key or random reply, separately from reduction-side draws. Logical query caps do not erase the local runtime of real HKDF, DH, parsing, source record construction, or other protocol computation.

The remaining native boundary is narrower but still explicit: this proof consumes the typed primitive/verification/setup contracts and the existing byte-model `Pqxdh.serverEmit`. It does not prove the entire Cap'n Proto decoder, complete-input handling, native call graph, allocator/OS behavior, compiler correctness, storage integrity, rollback resistance, CAS, crash behavior, or ownership. It does not strengthen primitive internals. The X25519 equivalent-encoding fixture remains a model-fidelity regression; it does not end the broader computational/symbolic bridge effort or justify a protocol change.
