## Equivalent query decomposition if direct injectivity is expensive

The direct selected injective query was inconclusive within its cap. The maintained proof instead uses two formulas in this identical Kr3 process, without changing its inputs, replies, candidate classes or continuations: (i) each selected `FsReceived(S,B,kid,root,t,m)` has a preceding `L2Published(S,B,kid,root,t,m)`; (ii) two `FsReceived` occurrences with the same `S,B,kid,root,t` have equal occurrence times, even when their plaintext variables differ. The second is exactly the selected-key C3 no-replay formula, not merely same-ciphertext uniqueness. It is established by the independently reviewed T0 paper argument below; its timed-out solver run supplies no verdict.

To derive injectivity, choose one preceding matching publication for each selected receive occurrence using (i). If two receives choose the same publication occurrence, equality of its fixed fields forces equal Server identity, Beacon identity, actual assigned ID, root and sequence for those receives. Formula (ii) then forces the receives to be the same occurrence. The choice is therefore injective and preserves the preceding-time condition. This argument needs no new primitive assumption and no independence of ciphertexts or keys. The model-to-source reflection above still applies separately to both formulas and to every chosen publication.

Finally, each actual source send allocation can produce at most one successful return/publication, because the retained seal result is consumed once and the native send call returns a single optional frame. Thus distinct matching source publications give distinct actual allocation occurrences as required by the original C2 conclusion. A failed source seal remains an allocation with no publication, and cannot supply a fictitious match. Proving only the first formula would be insufficient; the same-process C3 fact must also be established by the scoped replay argument before using this decomposition.
