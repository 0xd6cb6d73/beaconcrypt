# Charging selected nonce refusals to the actual source event

`RawCtxSelectedNonceSourceEvent` turns the selected component's nonce-refusal term into a chronological event in the same augmented source execution. It builds on the actual ledger provenance in `RawCtxSelectedLiveAuditLedger`. The new result preserves the complete adaptive source-to-CTX comparison and charges the resulting event with coefficient one. It does not yet bound that source event by a small number.

`values` extracts the selected nonces from actual sealing occurrences in the private source audit. `Repeated` means this list contains a duplicate. The list retains positions: two sends with identical recorded values are still two occurrences. `mem_values` identifies the actual sealing occurrence behind each nonce. `values_append`, `repeated_pair` and `repeated_append` establish that a shared nonce between the earlier history and the current trailer is a repetition and that later events cannot remove it. Only nonces of the selected sealing interface are extracted; equal nonces under unrelated known keys are not prohibited.

`step_repeated` uses the actual supported augmented callback and its proved ledger invariant to attribute a refusing request to that duplicate event. `marked_step_consistent` and `marked_program_consistent` carry the implication through every adaptive record or reveal request, optional reply, stopping decision and final output. They also preserve the full ledger invariant. The source callback still executes after a nonce-refusal condition in the augmented experiment, so subsequent source effects and event occurrences remain present.

`marked_step_erased` and `marked_program_erased` erase only the added source event history. They recover the complete existing marked nonce game, including its private state, role state, cache, disclosure history and sticky refusal flag. Erasing the flag instead recovers the exact event-recorded source run. These two equalities ensure that the probability argument compares events in the same execution and retains all conditioning and correlations.

`nonce_event_bound` starts with the ordinary empty component nonce ledger and proves `Pr[actual selected nonce refusal] ≤ Pr[Repeated actual source history]`. It uses the supported-execution implication above and probability monotonicity. It adds no uniqueness, independence, successful-send or honest-owner premise. `executable_distance` substitutes this coefficient-one charge into the existing whole-distribution comparison between the original hidden-disclosure-stopped source and the actual executable selected CTX client. All optional replies and complete source poststates remain in that comparison.

The instrumentation adds no oracle call; the preceding ledger proof preserves the exact uniform allowance, and the existing compiled client retains its complete per-class source bounds and every verification attempt. No local computation is declared free. This remains the retained selected-KDF hybrid, with actual public HKDF evaluations. Known-key byte aliases and key exposure require their existing candidate/freshness accounting and are not ruled out by this nonce event.

The probability of `Repeated` still requires source installation origins, directional chain initialization, actual path ancestry and crossings, retained-parent priority, permitted reveals and target-selection accounting. It can be one for arbitrary initial roles or source continuations; no negligible claim is made for that unrestricted case. The comparison is not a production security theorem and adds no primitive assumption. Saved mid-derivation continuation, registration installation and global symbolic-event composition remain further consumers. Primitive internals, snapshots, persistence and restoration remain excluded.
