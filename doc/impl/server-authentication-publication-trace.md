# Exact registration publication observations

`PqxdhServerAuthPublicationTrace` adds private observations to the existing complete executable registration builder. It preserves the full optional native result, the original successful-seal context log, every component query and every adaptive continuation. The generic `observe_program` theorem erases observations after the actual handler runs once, including when that handler refuses and terminates the continuation. `compiled_erase` applies this equation to the literal material builder with arbitrary supplied pending registration, payload, metadata and complete Server state.

The two observation kinds retain different source operations. A sealing observation contains the actual pending request and its nested optional result. The outer `none` is component refusal; `some none` is a native optional rejection, which can include an inner frame-writer failure. It does not by itself certify that the writer was reached. A successful inner reply retains the actual encrypted value and appends exactly the original seal context. A separate outer-writing observation contains the actual response fields and the actual optional `write2` result. `seal_run` and `write_run` establish these concrete callback equations. An ordinary component-query monitor must still supply the actual CTX record when the inner writer fails; this module never reconstructs that record by decoding writer output.

`annotated` brackets one actual builder execution with private begin and completion messages. The completion message contains the observed trailer and is emitted before returning the original result, including a component refusal or native failure. Its coordinate is supplied by the caller, not inferred from keys, bytes or frame equality. No uniqueness or session-origin theorem is asserted for that coordinate. The annotation interface returns only `Unit`; `annotated_erase` removes both annotations and recovers the identical original executable builder. No selected-key argument is required by these executable definitions. Arbitrary correlations and byte-equal known keys remain allowed.

`compiled_bound_iff` preserves any predicate-based component query certificate exactly. This is a query-count statement, not a runtime bound: receipt allocation and the two private annotation operations remain local bookkeeping. The annotations add no cryptographic oracle request. The existing builder's source derivations, codec work and interpreter costs retain their previous separate accounting.

These eight theorems establish an operational receipt boundary, not a publication-security result. Ordered association with the component seal, whole-handler receipt transport, the cutoff before the first selected raw request, the unconditional random-tag argument and the new event's R1 partition and five KDF comparisons remain to be proved. In particular, conditioning tag uniformity on a failed writer is not justified. The completed R1 authentication theorem and all maintained ProVerif queries are unchanged.
