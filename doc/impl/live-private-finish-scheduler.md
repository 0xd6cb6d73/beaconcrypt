# Native live-finish scheduler and the private KEM router

`PqxdhLivePrivateFinish.lean` connects the actual indexed native finish operation to the ordinary one-key CCA interface throughout an adaptive schedule of record requests, public primitive requests, current-chain disclosures, skipped-key disclosures and repeated finish attempts. Its source service uses the original complete native owner, callback dispatch, registration state and installation operation. It preserves optional rejection and plaintext replies, every owner, the shared primitive cache, the joint identity state and the complete ordered history of indexed KEM decapsulation attempts.

The schedule uses the original `PqxdhPhase2LiveFinish.Spec`. Its finite family of owners already exists when this continuation starts. Creation, identity/KEM/root disclosures and target selection are separate operations that still have to be composed with this continuation. This theorem does not silently add those capabilities or charge them as free ambient work.

The reduction keeps each owner's original public KEM creation handle at the service boundary. Only the private implementation of a finish temporarily encodes the selected handle as a marker and other handles as explicit other-index values. Publication decodes the resulting owner before the next original API call. The selected handle's secret is absent from the required executable arguments. The mathematical source comparison supplies the actual selected secret to the primitive interpreter and reconstructs the source pool. Arbitrary initial histories, caller closures and equal secret bytes at other indices are not excluded by these operational statements.

`restore_append` and `restored_install` prove that a new finish's private attempt log is appended exactly once to the existing source history, in order, while publishing exactly the original whole owner and primitive state. `finish_source` then compares one complete native finish against that restored source state. `old_source` proves the same statement for the original record/public/reveal service; its public HKDF evaluations remain real. `step_source` combines both branches without assuming that a request succeeds.

An indexed pool ownership invariant connects each retained native KEM handle to its actual source-created slot. It says nothing about secrecy, authenticity or public-key uniqueness. `finish_owned`, `shared_owned`, `map_owned` and `private_owned` prove that the concrete finish preserves this invariant, including rejection, already-finished owners and erasure. `retained_owned`, `role_owned` and `original_owned` prove preservation by the existing record/public/reveal operations. `support_interpretation` transports support through an interpreter; `step_owned` uses it to establish preservation for each compiled service request. Consequently the complete adaptive comparison does not require a caller-provided premise asserting that every future request preserves ownership.

`schedule_source` is the full-state equality for an arbitrary adaptive client over this original interface. The client may branch on every actual optional reply, interleave record/public/reveal calls, retry finish attempts, stop early and choose its final result. The invariant starts from the actual indexed ownership supplied by creation and is propagated by the proved service implementation. The equality retains the entire joint identity history and all earlier KEM observations, rather than comparing only the marginal plaintext result.

`post` is the concrete public continuation: it returns only the original client's final result and keeps native roles, joint state and the added private log inside its interpreter. `post_source` composes the complete source comparison with the existing blocked-challenge router. The exact challenge ciphertext stays unavailable to the public selected-key decapsulation oracle; the challenger-supplied shared secret is consumed through the private root interface. This is an exact operational comparison, not an IND-CCA bound or a global nonexposure proof. In particular it does not assert that arbitrary callback closures or starting state are independent of the selected secret.

`supported_post` discharges the routing agreement using the existing ordinary ML-KEM recipient correctness contract with functional decapsulation and actual generation/encapsulation support. It does not require injectivity of public keys, ciphertexts or shared secrets. It does not manufacture an authentication premise or assume a selected candidate is honest; a later authenticated selection consumer must connect the chosen source handle and challenge to the supported branch before applying this comparison.

Query accounting is deliberately separate from operational equality. The already checked `PqxdhLivePhase2PrivateBounds.private_owner_classes` charges at most 69 native callbacks per complete finish, at most one selected logical decapsulation and at most one private root call. For local callback cap `qLocal` and other-index decapsulation caps `uDecap` and `bDecap`, the finish bounds are `69 * max (max qLocal 64) uDecap` uniform calls and `69 * bDecap` base calls. The full adaptive schedule must add all repeated finish costs and the actual original record/public work, then the actual creation, prefix and reservation bills. None of those missing sums is implied by an equality of output distributions.

Still required for a complete production theorem are the source constructor and authenticated selection consumer, event-specific identity/KEM/root disclosure policy, the exact target-root context and key nonexposure argument, full pre/post source scheduling, combined query bounds and target/session losses. Chain-only freshness is insufficient to discharge those disclosure conditions. No snapshot or persistence semantics is introduced here.
