# Actual accepted-record production event

`RawCtxSelectedProtocolOriginCases` and `RawCtxSelectedProtocolOriginEvent` connect the actual finite Beacon/Server record and reveal schedule to the existing ordinary authentication observer. They concern one selected record-key interface in the retained private KDF-table hybrid. They do not identify that uniform selected key with an arbitrary production root, evolving chain or initial role state.

The cases module consumes a supported execution of the complete source production audit under the real CTX interpreter. For an actual accepted Beacon record, it recovers the reached established phase and exact owner reinstallation. For a Server record, it recovers the original sender route, associated-data lookup, repeated peer lookup and full publication. In either case, the record reaches known message material, the existing all-attempt observer wins, or the exact accepted plaintext has a strictly earlier selected-key cryptographic production. The third case includes the same associated data, sequence, encoded sender and decoded payload. It also preserves any explicitly supplied initial seal history. No `SelectedFresh`, honest-peer or successful-seal hypothesis is inserted into this classification. The original receive callback supplies its actual optional plaintext; the construction does not recover plaintext and insert it into an adversary request.

`BeaconFailure` and `ServerFailure` are concrete source events over accepted positions in that audit. They assert that the reached receive material is not the known-material case and that no matching earlier selected-key production has the accepted fields. `Failure` is their union over every role index and every stored record position. This scope matters: the event does not include acceptance under a known key, even if its bytes happen to equal the selected key. Such aliases remain part of the source nonexposure and key-selection analysis. The finite role counts and supplied adaptive program are explicit parameters; the event itself selects no raw attempt and assumes no fresh-tuple predicate.

`beacon_wins`, `server_wins` and `failure_wins` derive the actual ordinary observer win from these events. `decision_exact` erases the private protocol audit and obtains exactly the existing executable authentication observer applied to the same compiled record/reveal client. Its final decision only examines its actual selected-interface seal and raw-reply history. It is not an arbitrary predicate over private protocol state. The executable requires no selected-message-key argument, but that statement alone supplies no independence result for arbitrary input state or equal known-key bytes.

`game_decision`, `game_wins` and `probability` consume the ordinary game that samples the selected key uniformly and starts the component and observer histories empty. The required functional plaintext-history invariant is proved for that empty state using the primitive's ordinary seal/open correctness contract. Arbitrary frontend contents remain arbitrary. The actual failure probability is at most the unchanged observer probability with coefficient one. The source event includes all accepted positions of both role families, so this comparison adds neither another receive-attempt factor nor a role-selection factor within this one-key game. Selecting this game from all production record keys and sessions remains a separate reduction obligation.

`authentication_bound` applies the existing concrete validation IND$ reduction and the existing raw INT-CTXT reduction at every possible raw-attempt index. Writing `D` for `AdaptiveCtxDynamicKnownKeys.decisionClient c (decision decode (base p original front))`, its bound is:

- the advantage of `AdaptiveCtxPrefixValidation.validationReduction decode c D qHash` in the modified nonce-AEAD IND$ game;
- `qHash / 2^128`;
- twice the sum, over `i < qRaw`, of the modified nonce-AEAD INT-CTXT advantages of `AdaptiveRawNonceAead.indexedReduction (baseDecoder decode) fallback (AdaptiveCtxReceive.wrapped decode D) i`;
- `qRaw / 2^512`.

The theorem requires `qSeal < 2^96` and the displayed shared-hash, selected-seal and selected-raw budgets for the same compiled client. These are the inherited ordinary CTX terms, not security assumptions introduced by the source event. Every rejected, repeated or successful adaptive raw query remains charged in the existing indexed reductions. The source caller's actual bytes and optional replies are unchanged.

`reduction_budgets` proves separate uniform, shared-hash, selected-seal and selected-raw caps for that exact ordinary client. The observer introduces no calls. Known-key cryptographic work is executed by the existing dynamic interpreter, with its actual hashing included in the shared-hash cap; it is not an independently sampled family. `source_budgets` and `source_bound` discharge all these premises conservatively from the original six-coordinate source budget. If those coordinates are sends `S`, raw attempts `R`, explicit coin requests `U`, public hash requests `H`, public HKDF requests `K` and reveal attempts `E`, the component fallback is `q = S + R + U + H + K`. Each component class is at most `q`, and all `E` reveals remain in the original source schedule even though they make no component call. This fallback is deliberately conservative; the separate class theorem accepts sharper caps.

These component caps do not erase the source's remaining work. The previously checked source interpreter retains native KDF, seal, open, hash and writer caps `S + 51R`, `S`, `R`, `S + R + H` and `S`, and uniform cap `U + 64(S + R + H)`. The complete source operation count includes `E`, and preparation, initialization, public HKDF evaluation, parsing, lookups, copying and byte processing remain in their actual enclosing source/resource contracts. This package introduces only deterministic audit and decision computation. It does not declare those costs zero or close the enclosing setup costs.

An earlier cryptographic production can still have a failed optional writer. It can also belong to a different required protocol installation or cryptographic session. This theorem does not equate typed-field origin with canonical wire-byte equality, successful publication or the eleven-field symbolic session origin. The normal-return native Vec serializer contract, concrete initializer/installation history and full Phase-1/session lineage must close those separate cases. The later assigned-ID relabel behavior remains unchanged.

The original Gate/Fresh events are not assumed to imply a forgery. They can restrict this proved production-error event, but establishing that an advertised symbolic authentication failure belongs to it still needs the actual source-origin and exposure analysis. The private-table-to-real-KDF hop, selected-key distribution, known-key alias/probe accounting, nonce-refusal transport, registration/installations and global key/session selection losses remain outside this package. No snapshot or persistence behavior is modeled here, and no primitive implementation theorem is attempted.
