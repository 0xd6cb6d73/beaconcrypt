# Actual Server root input and acceptance

`PqxdhServerRelatedRootInput` consumes the complete ordered prefix from `PqxdhServerStaticDhSource`. Every successful prefix supplies its actually received prekey bytes and the locally computed DH2, DH3, DH4 and KEM values. The executable related-root request contains those values and a public reference to DH1; it contains neither the selected Server seed nor the unavailable DH1 output.

The source correspondence realizes that reference only inside the primitive interpreter. It proves that the resulting family address is exactly the extracted core's 192-byte root input: the 32-byte all-ones prefix followed by the five actual 32-byte shared-secret values. Different encodings and different requests may denote equal complete inputs. The existing family cache continues to coalesce by actual full input; no encoding, key or request injectivity is used.

The existing joint primitive `SourceWiring` rejects all-zero static-DH results. Together with the public optional-availability law already stated in the prefix guide, this derives the source's static nonzero check at a reached request. The other three DH checks are computed from actual locally available values. Their success proves the literal extracted `server_accept` result, exact registration ID, pending public fields and pending root-input address. Their failure proves its `InvalidDhOutput` result. This uses ordinary functional primitive correctness; it does not assume that the registration authenticates any honest party.

The real root-service equality uses the existing functional `SourceRootCorrect` law for HKDF-SHA-512 without salt. It retains the entire real Extract/HMAC history and memoization cache. Accepted pending fields then enter the existing complete response-building program; its equality reads exactly the fields whose source uses remain. It does not equate a shortened private pending state with the original pending state or claim physical erasure.

`PqxdhServerRootQueryBounds` proves selective bounds for the original raw prefix, including all failure paths. Verification takes at most nine ordinary callbacks. Following verification there are at most twelve ordinary callbacks and one unavailable static-DH position. The entire prefix therefore has at most 21 ordinary callbacks and one selected-call instrumentation callback. Under actual per-callback bounds `qAux` and `qVisit`, any chosen primitive query class costs at most `21*qAux + qVisit`. Rejected registration, parse, conversion and DH paths keep every prior effect. Callback costs are explicit; these logical counts do not assert that deterministic work or local cryptographic operations are free.

The [complete root consumer](server-related-root-consumer.md) now connects the full prefix/root/RID-consumption program and retained response tail; concrete native callback interpretations remain consuming obligations. In particular, private conversion must use the ordinary generated-identity correctness law rather than a protocol-success assumption, and the native parser, attached-verification and field getters must be supplied with their exact source semantics. The additional related-DH Extract endpoint remains explicit and unbounded; neither ordinary Gap-DH nor EUF-CMA is claimed to establish its pseudorandomness. No snapshots, persistence model or primitive implementation proof is added.
