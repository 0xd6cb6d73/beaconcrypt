# Raw receive adapter fixture followup

This followup synchronizes the reviewed ProVerif/source fidelity metadata and Rust source-mutation matrices with the integrated adapter at `59d8ddb`. The adapter source used during development was a temporary unstaged copy of the workstream's stable file; it was saved under `/tmp`, removed before the normal integration merge, and checked byte-for-byte against the committed file. This followup commits no production or Lean implementation changes.

The source checks follow all three new private boundaries: `decode_crypto_frame` must read the supplied bytes with the configured reader options and reject trailing bytes; `OpenFrameContext::from_frame` must enforce the nonempty-body bound and derive the AEAD, tag, and commitment views from one payload; and `execute_open` must take its material, sequence, and context from the same owned core request, verify commitment before AEAD, construct output from the actual recovered plaintext, and call the same request's `finish`. The outer driver must perform its prechecks before taking the kernel and restore the returned kernel before returning either plaintext or rejection. Additional checks prohibit shadowing the executor's selected material/context/sequence/plaintext/result bindings.

All existing mutation matrices remain enabled. Mutations whose source moved to the decoder, factory, or executor now require an exact anchor in one of those receive helpers and cannot silently mutate an unrelated send call. The old explicit missing-material branch was eliminated by the adapter's closure followed by unconditional `finish`; its dropped-kernel and return-before-publication cases now exercise the shared completion path, while missing-material cases still require normal rejection. This is a retargeting to the implemented interface, not deletion of the original rollback or provenance obligations.

The CryptoFrame matrix increases from 223 to 229 cases. Six new cases deliberately bypass trailing-byte rejection, substitute the decoder input, alter the commitment split boundary, select tag bytes from the commitment, shadow the recovered plaintext, and return a claimed plaintext after primitive rejection. The original 409 later-registration, 163 Phase-1, 242 endpoint-context, 154 ratchet-driver, 1,230 finite-receive, 177 registration-lifecycle, and 223 initial-ratchet matrix counts remain unchanged.

All 14 tests in `cargo test --locked -p beaconcrypt-core --test proverif_transcript_fidelity` pass on the integrated sources, including all positive fixtures and mutation matrices. Formatting, `git diff --check`, and `cargo clippy --locked -p beaconcrypt-core --test proverif_transcript_fidelity` pass; existing core lint warnings remain. The integration agent runs full repository proof verification, inventory checking, linting and the complete implementation mutation suite. These source fixtures remain maintenance tripwires; they do not prove semantic Rust-to-Lean or Rust-to-ProVerif correspondence.
