# Retained Extract-table chronology

`PqxdhServerAuthCtxChronology` proves sixteen operational statements for the actual factor-side Server-authentication experiment. Its final result, `root_suffix`, says that after a source derivation returns an ordinary root, that derivation's exact input cannot later become the omitted selected input during any adaptive continuation. This is a deterministic support property of the existing retained-table game. It adds neither a security assumption nor a probability term.

The table is the already approved programmable fixed-salt Extract endpoint used by the authentication hybrids. These statements do not replace public HKDF evaluations with a random table and do not establish a new pseudorandomness property of HKDF. All off-domain public HMAC calls and the ordinary native KDF callbacks retain their existing definitions.

`Retained` records preservation of occupied table inputs. `oracle_retained` proves that an actual lazy table read keeps every old occupied input and records its queried input. `real_retained` carries this through the complete ordinary derivation, including rejected source inputs. `real_root` shows that a returned ordinary root has its actual source input present in the resulting table. No output injectivity, independent-key property or success-conditioned sampling is used.

`table_history` treats both actual derivation routes. Lazy reads retain all existing entries and keep the hidden input absent. Designated reads either reject an invalid input, retain the real cache-hit refusal branch, or omit the actual fresh selected input. The same omission invariant holds in every case. `table_root` identifies the occupied source input when either route returns an ordinary root; the designated route cannot produce that reply. `public_history` also preserves the invariant at the actual public request that raises refusal, as well as at ordinary on-domain public reads.

`services` is the literal original factor service, optionally wrapped by its actual designated-operation service. `services_derive` identifies its concrete table callback with the checked lazy or designated callback. Both native tail services remain unchanged and use the supplied complete factor value. The results quantify over arbitrary such values and contexts; they do not infer how those values were sampled or whether they are independent.

`accept_history` includes the full Server prefix, all failed admissions, local DH rejection and any actual derivation. `finish_history` includes complete raw Beacon preparation, every table reply, both ordinary and selected tails, final source binding checks and publication failure. `build_table` proves that the actual complete response builder keeps this Extract table identical while its original native, CTX-cache and source-log effects remain in their separate state. `hmac_history` retains real off-domain evaluation and the exact on-domain table/refusal behavior. None of these statements removes optional results or equates table preservation with preservation of the other source fields.

`skeleton_history` covers every original capability, including public hashing, actual coin draws and kernel reveals. `handler_history` carries it through the real one-shot designation and sticky refusal wrapper. `program_history` proves preservation along arbitrary adaptive source continuations. `run_clean` supplies selected-input omission from the literal empty retained table of `hiddenRun`; its caller does not provide an omission premise for that initial run.

`root_suffix` joins a reached ordinary-root derivation to an arbitrary later source program. The exact input remains occupied by `program_history`, while the final omitted input is absent. Hence those inputs cannot be the same. The initial omission condition in the intermediate suffix theorem is an operational invariant supplied for actual reached prefixes by `run_clean` or `program_history`. The theorem makes no claim that a successful acceptance has already been shown to use the selected callback: the next consumer must connect the real acceptance observation, final entry-owner event and this suffix fact.

The entire original source and callback state remains in every supported execution. These proofs introduce no additional calls, coins, selection factor or loss, and preserve the existing source and reduction budgets. They do not make native KDF, codec, callback or interpreter work free. The complete component-observer origin invariant, first-acceptance chronology, transport of the frozen acceptance observation, final event implication and sampled CTX reduction remain separate consumers. Known-key aliases remain allowed. Primitive implementations, compiler/runtime behavior and abstract codec contracts retain their existing scope; saved-state restoration and persistence are excluded.
