# Binding persistence parity

Expose the same application-supplied snapshot storage contract through C, Go, and Python that Rust provides through `PersistentServer<S>`. Every successful state-changing call must complete the store's compare-and-swap before returning its output. Restoration must win an activation CAS; stale or failed owners must be fenced. A normally rejected receive must preserve state and perform no CAS.

The C ABI accepts context-bearing load and compare-and-swap callbacks with explicit context destruction. Load transfers bytes synchronously through a copying sink, so foreign allocator ownership never crosses the ABI. Snapshot-head and successor-validation helpers let applications implement the exact Rust comparison contract. Per-handle status codes distinguish ordinary protocol rejection from persistence failure, including output encoding after an accepted receive.

Go wraps the C ABI with a `SnapshotStore` interface and callback handles; Python implements the Rust trait around a Python storage object. Both preserve structured persistence errors and expose snapshot heads and poisoned-owner state. Existing checkpoint-only constructors remain available for compatibility. Wire messages and the version-2 snapshot representation remain unchanged.

Acceptance coverage includes creation, restoration and activation fencing; durable commit before registration, send and receive results; failed CAS suppressing output and poisoning the owner; rejected receives skipping CAS; stale owners and concurrent restorers; malformed loads; callback exceptions and panics; and callback-context lifetime. Validation includes Rust feature builds, Clippy and formatting, language binding suites and examples, and a complete workspace mutation run with no missed or timed-out viable mutants. This work does not change or run formal proofs.

The implementation retains the existing checkpoint constructors and the version-2 snapshot and wire formats. C uses synchronous copying sinks and context destruction on both constructor failure and server release. Go preserves callback errors through `PersistenceError.Cause`, recovers callback panics, copies buffers using pointer-width lengths, and releases its callback handle on explicit `Close`. Python raises `PersistenceError` with the native code and chained callback exception, rejects mutable reentry, and participates in Python cycle collection. Snapshot export reads the authoritative store and rejects a head belonging to another owner instead of exporting uncommitted local state.

The C header was regenerated with the existing cbindgen build step to expose callback structs, snapshot-head helpers, durable constructors and stable status constants. The Python stub describes the new store protocol and immutable snapshot heads. The C regression fixture is compiled and executed in the Rust CI workflow, alongside the C-feature Rust unit tests. Independent reviews checked commit ordering, status translation, callback ownership, malformed load handling, owner fencing and the documentation contract.

Validation passed: `cargo test --workspace --all-features --locked --offline` (289 tests), `cargo clippy --workspace --all-targets --all-features --locked --offline`, formatting and whitespace checks, both role-specific Rust feature builds, the direct C callback tests and strict C11 fixture build, a fresh release `gobinds` build followed by `go test -race -a -count=1 ./...`, and a fresh Python extension build followed by all 64 Python tests. The checked-in mutation exclusions remain unchanged: C/Python adapters and binding-store-only helpers are exercised through their explicit binding suites rather than claimed as covered by the default-feature mutation run.

Final complete mutation verification passed with `cargo mutants --workspace --jobs 8`: 1,197 mutants tested in 12 minutes, with 820 caught, 377 unviable, zero missed and zero timed out. The existing C, Go and Python examples also built and ran successfully in isolated temporary working directories. No core source, proof artifact, test-vector fixture or snapshot encoding changed.
