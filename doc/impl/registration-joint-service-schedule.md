# Executable registration schedule over the private services

`PqxdhRegistrationJointBundleCompiler` and `PqxdhRegistrationJointServiceSchedule` contain fourteen guarded statements. The executable client runs one Server and any finite number of dynamically created Beacons through the same public typed registration interface as `PqxdhRegistrationSchedule`. Beacon identity seeds and KEM secret keys remain inside the existing indexed private services. Each client owner retains its actual private prekey and one-time fields, public identity/KEM bytes and exact service creation indices. Erased native phase fields remain absent in the encoded owner. The historical private pools are analysis state; this interface does not expose them to the adversary.

The bundle compiler's `compiler_interpreted` and `program_interpreted` retain the actual local one-time draw, three ordered signing requests and optional codec writer on both complete private pools. `bundle_source` identifies that compiled execution with the full literal source trace, including signatures emitted before a writer returns None and all prior service history. The writer remains the original deterministic optional codec callback. These equations add no codec or cryptographic correctness theorem.

The scheduler backend contains the existing private identity/KEM interface, the complete native finish-tail interface and five explicit native Server/public operations: accept, build, public HMAC, public hash and current Server kernel read. `pool_program` preserves the whole native state while interpreting private-service programs; `finish_program` preserves the existing complete finish interpreter. The Server/public operations retain their full original source implementations and shared primitive caches. Their internal Server joint-use compilation remains open; naming a backend request does not make that work a primitive assumption or remove its cost.

`create_source` proves equality of the entire encoded constructor distribution. Identity generation, the actual local prekey draw and KEM generation remain in source order. The client's syntactic None branch is total but absent under the existing real lazy identity interpreter, as shown by the literal source equation and the prior `client_present` result. This typed constructor always creates; raw constructor rejection is outside this typed scheduler theorem. `bundle_source` and `finish_source` prove the same complete equality for the selected live owner, including optional failure replies, all other owners, both private pools, the shared caches, logs and actual returned plaintext. Their slot conditions come from `JointSchedule.Invariant`, which is preserved by every original source request. `shared_source` preserves each full original Server/public operation, and `query_source` joins all nine public request classes without adding an admission filter.

`execute_bind` proves equality under an arbitrary full client/backend continuation after reassociating the owner registry and backend state. `program_source` then proves exact OracleComp equality for an arbitrary adaptive public program: the ownership invariant is obtained after each actually supported source step, and every caller reply and final result is retained. `generated_source` starts with the actual empty owner registry and discharges all ownership premises internally. There is no honest-target, successful-finish, accepted-origin or selected-key premise. Public owner addresses remain separate from identity/KEM service creation indices, and no public-key injectivity is assumed.

`program_uniform` transports the existing full evaluated source allowance to the compiled schedule. For all-reply caps on the nine source classes it charges `qCoin + (64 + G) * qCreate + 32 * qBundle + (96 + E) * qAccept + 64 * qBuild + 69 * max(64, D) * qFinish + 64 * qHmac + 64 * qHash`, where `G`, `E` and `D` include each KEM operation's direct uniform draws and all interpreted base-oracle draws. Current Server kernel reads make zero uniform queries; their local work remains real. Runtime initialization and Server seed creation lie outside this typed interface and keep their existing separate source bills. This transport adds no reduction loss and does not establish a cryptographic security bound.

The [global service-query ledger](registration-joint-service-ledger.md) now gives explicit all-reply counts of emitted identity creation, signing, joint DH, KEM creation, decapsulation, uniform, native-tail and Server/public service requests. Additional identity, KEM and chain reveals must consult the current live owner fields before using any retained index; the historical private pools must not create an erased-key reveal. Server internal joint-use compilation, multi-Server imported pending handles, raw runtime initialization, freshness and target selection, the primitive reductions and the common computational/symbolic experiment remain separate obligations. The existing restricted downstream consumers keep their original restrictions until these operational results are connected to them.

All fourteen public statements have exact axiom guards allowing only `propext`, `Classical.choice` and `Quot.sound`. Both changed modules are checked directly under Lean 4.34.0 with one thread and the shared resource lock. No Rust, ProVerif, primitive implementation or snapshot/persistence change is included. Central imports, inventory and aggregate validation belong to the separately reviewed integration step.
