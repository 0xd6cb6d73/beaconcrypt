# Material interpretation inside the private-chain driver

`RawCtxChainMaterialMap.lean` supplies the operational map needed to use the ordinary CTX selected key inside the existing source drivers. The drivers already keep each chain as a private payload. This module additionally interprets material payloads without converting the chain requests to bytes. A hidden material marker can therefore coexist with an opaque chain marker, while known byte aliases remain possible. No equality test on a dummy chain or key is used to decide the source path.

The 13 guarded statements generalize the existing material interpretation laws to the private-chain driver. `receive_resume` preserves every original target, gap, cache-window and staged-slot branch, including rejection and continuation to another derivation. It uses the existing extracted validation and array-map laws. `receive_begin` preserves the complete admission and cached/future choice. The three normalizer statements retain exact complete states and optional plaintext, and `receive_rank` preserves the original termination measure. `receive_program` and `receive_execute` lift those facts through every stateful callback in the full skip/open computation.

The sending statements preserve sequence exhaustion, original admission and advancement before the optional seal. `send_begin`, `send_normalBegin` and `send_ready` retain all previous receive slots and the exact fresh material. `send_program` and `send_execute` retain the full advanced kernel even when the sealing callback returns no ciphertext. Neither the material map nor these theorems change any callback's actual optional result.

The complete program equations work in any lawful monad, including the complete source state transformer and an oracle-backed compiler. Their KDF and open/seal equations are explicit functional obligations. The CTX compiler must discharge them using its actual selected and known services; these hypotheses are not security assumptions and do not establish arbitrary native-client simulability. In particular, original raw parsing and context provenance remain necessary before applying the selected raw-opening callback equation.

The material interpretation may be noninjective. It preserves slot presence and sequence tags without inferring key independence, key inequality or confidentiality from the marker representation. The maps add no oracle calls, but these statements assign no free cost to supplied callbacks. Concrete primitive query bills and the adaptive one-selected-seal/one-opening argument remain separate obligations. They also do not discard material left in skipped-key slots: the actual sequence-one registration observer must establish the narrower successful-publication property needed to hide that material.

All 13 guarded statements use only the standard Lean axioms, with no primitive-security premise. This supports the B9b compiler; it is neither the CTX endpoint reduction nor the final Server-authentication theorem. Primitive implementations, serialization and persistence remain outside the approved proof scope.
