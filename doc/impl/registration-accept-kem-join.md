# Raw-accept cut joined to the initialized report compiler and the Phase-1 EUF bound (stage A)

Status: stage A of the accept/KEM join plan. Four modules and 33 statements pass direct single-module Lean 4.34 checks with empty logs and exact `#print axioms` guards that permit only `propext`, `Classical.choice` and `Quot.sound`. The root module checks against the retained artifacts. The change has not been independently reviewed and is not pushed. Stage A is the authentication half of handoff item 1 ("What has not been proved", item 1): it joins the raw-accept cut to the initialized report compiler and to the ordinary joint-use weak-EUF family, and it classifies every reached cut. It does not reach the KEM challenge; stages B, C and D, listed at the end, remain open.

## What is proved

**Tag (M0).** `AcceptCutTag.tag work index` is `AcceptCut.scan work index >>= tagFinish` (`tag_split`, by definition). `tagFinish` resumes a pending cut exactly as `AcceptCut.finish` does, issuing the same raw accept and passing its reply to the original continuation, and additionally returns `some (raw, reply)`; a complete cut returns `none`. `finish_erase` and `tag_erase` show that forgetting the record gives `AcceptCut.finish` and the original program `work`, so the tag adds no request and changes no reply. `tag_bound` and `decision_bound` carry every `IsQueryBoundP` cap of `work` to `tag work index` and to `decisionClient decision work index`, the Boolean client `decision result && accepted tag` that later stages run. `accept_lt` shows that a reached pending cut has `index < cap` for any all-reply cap on raw accepts, and `accept_source` instantiates it at `qAccept = budget (.inl 3)`. Rejected earlier accepts are counted, so this bounds the raw-accept ordinal, not the encapsulation ordinal of `PqxdhRegistrationJointKemCut`; the two are different handles.

**Report split and naturality (M1).** `resume` restarts the reported command compiler from a recorded initialized outcome with the same Server, owner registry and native state, and `continuation` runs that resumption under the same identity reduction, from the reached local KEM/runtime state and source registry, and under the same report interpreter, from the reached monitor and reporting state. `commands_initialized_bind`, `initialized_bind` and `run_bind` show that the reported commands, the initialized report compiler and the report run of `program >>= next` are those of `program` followed by this resumption; the identity-reduction step is `TerminalReports.compiler_bind`. `cut_split` instantiates `run_bind` with `AcceptCut.scan_finish`: the report run of `work` is the report run of the raw-accept scan followed by `continuation … AcceptCut.finish`. `split` couples the two runs of the tagged program: it draws the reached outcome `r₁` of the scan and then the final outcome `r₂ ← continuation … tagFinish r₁`. `split_snd` is the program equality `Prod.snd <$> split … = RR (tag work index)`, so the final component is exactly the report run of the tagged program. `ReportSource.initialized_source` already identifies the source projection of that run with the actual initialized source execution of the tagged program, which by `tag_erase` issues exactly the requests of `work` and receives the same replies. `split_fst` shows that every countable observation of the cut component has the same distribution as under `RR (scan work index)`; the continuation is an ordinary probabilistic computation and cannot fail. `commands_initialized_map`, `reduction_map`, `initialized_map` and `run_map` are naturality in the program result, and `selected_run` gives `RR (AcceptCut.selected work index owner fallback) = mapChoice owner fallback <$> RR (scan work index)`, where `mapChoice` replaces only the program-result component by `AcceptCut.choice` and keeps local state, registry, monitor, snapshot and reporting state. `sourceResult_map` and `raw_eq` push the map through the source projection: a pending cut with raw bytes `raw` maps to the final choice `(owner, raw)` with the same Server and encoded state.

**EUF instantiation (M2).** `selected_certified` discharges the fourteen source caps of `AcceptCut.selected work index owner fallback` from `certified`. `selected_report_bound` is the address-free half of `native_origin_bound` at that program: under `capacity : (if supplied.isNone then 1 else 0) + qCreate ≤ count + 1`, the probability in `RR (selected …)` of `PqxdhRegistrationJointFinalReportEvent.Failure setup.joint codec` is at most `∑ target : Fin (count + 1), advantage setup.joint (NativeOriginBound.reduction … (selected …) … target)`. The proof is `FinalReportEvent.transport`, `FinalCandidate.reported_bound` with `ReportCosts.initialized_creates`, then `PqxdhJointPhase1Reports.fieldOrigin_advantage_le_sum`, the same chain as `native_origin_bound` after its first step. The five bills are `selected_service_bound` (at most `3 * qBundle` signing and `qFinish + qAccept` converted-DH requests per reduction), `selected_reports_bound` (at most `(count + 1) * (qAccept + 1)` public candidate reports), `selected_client_uniform` (the complete client uniform bill `total caps qInit budget`), `selected_reduction_uniform` (`32 * count + total caps qInit budget` per reduction) and `selected_game_uniform` (`32 * (count + 1) + total caps qInit budget` for the endpoint game); the uniform bills take the existing `qInit`, `initBound`, `caps` and `KemBound setup caps` premises of `NativeOriginUniform`. Each is a direct instantiation of the existing theorem with `certified` from `selected_certified`.

**Protection, classification and authentication bound (M3).** `ProtectedAt kemIndex r₁ encoded raw next value address owner target publicKey` says that the reached outcome is a pending raw cut on `raw`, that `RawSignatures.verified setup codec checks raw = some value`, that `address` locates `owner` in the public owner registry `encoded.2.2.owners`, that `owner.2.1 = kemIndex.val` (the public KEM creation index), that the owner's identity index routes to `generated target`, that the source identity key of that index is `publicKey`, that `value.identity = publicKey.ed25519`, and that `revealedAt owner.1` is false in the transcript reached at the cut. `Protected kemIndex r₁` is its existential closure. `KeyMatchCut kemIndex r₁` says that the verified PQ key of the pending candidate is the public key at index `kemIndex` of the native KEM pool at the cut; `HonestTuple` adds to protection that the verified tuple occurs in the witness owner's chronological signing history. `attached_detached` is the attached-to-detached step: from `RawSignatures.verified … raw = some value`, `RawSignatures.verified_origin` gives `candidate codec raw = some value.candidate` and `RawSignatures.verified_detached` gives `acceptPhase1Candidate setup.joint.verify value.candidate = some (value.identity, value.keys)`; the latter uses the inherited `shortRejects` premise and `setup.wiring` through `PqxdhJointPhase1Reports.source_attached_adapter`. `protected_origin` applies `AttemptReports.owner_origin` to the program `scan work index`, to the reached outcome `r₁` itself and to the witness address, with `accepted` from `attached_detached` rewritten by `value.identity = publicKey.ed25519`: either the verified tuple occurs in the owner's history and `KeyMatchCut kemIndex r₁` holds, through the owner's fixed receipt and `owner.2.1 = kemIndex.val`, or `FieldOriginFailure setup.joint ⟨target, value.candidate⟩` holds in the snapshot reached at the cut. `chosen_mapped` shows that `FinalCandidate.selected` of the mapped outcome is `some value.candidate`, by `raw_eq`, `NativeKemOrigin.selected_source` and `verified_origin`. `protected_report_failure` combines them: `Protected ∧ ¬KeyMatchCut` implies `FinalReportEvent.Failure` of `mapChoice owner fallback r₁`, whose snapshot is the one reached at the cut. `classify` (T1) shows that every supported `r₁` satisfies at least one of `CutComplete` (constructor failure, or fewer than `index + 1` raw accepts), `VerifyRejected` (attached verification `none`), `VerifiedSome ∧ ¬Protected` (attacker-owned, imported, revealed, missing owner, other identity or other KEM index), `Protected ∧ HonestTuple ∧ KeyMatchCut` (honest unchanged or honestly re-issued tuple) and `Protected ∧ FinalReportEvent.Failure (mapChoice owner fallback r₁)` (honest identity, changed tuple). The cases are not exclusive: two generated owners with equal identity public keys can place one cut in the honest case through one owner and in the failure case through the other, and the failure case is address-free. `protected_bound` (T2) states that the probability in `RR (scan work index)` at `count + 1` positions of `Protected kemIndex ∧ ¬KeyMatchCut kemIndex` is at most `∑ target : Fin (count + 1), advantage setup.joint (NativeOriginBound.reduction … (AcceptCut.selected work index owner fallback) … target)`, by `protected_report_failure`, `selected_run` and `selected_report_bound`. There is no honest-target premise.

## Target designation and freshness reading

The target is designated by the public pair `(index, kemIndex)`: the zero-based raw-accept ordinal and the KEM creation index. The owner is located existentially in the public owner registry by address, and every comparison in `ProtectedAt` and `KeyMatchCut` is between public values: the verified identity against the owner's public identity key, the owner's public KEM index against `kemIndex`, and the verified PQ key against the public half of the native KEM pool entry. The source key lookup `sourceKeys … seeds` is an analysis projection, exactly as in `NativeKemOrigin.key_or_failure`, and is never evaluated by a reduction. No secret key is compared.

This is an intentional deviation from the recipe in the [raw-accept cut guide](registration-joint-accept-cut.md), which suggested passing a designated owner address as the owner argument of `AcceptCut.selected` and using `key_or_failure`, whose `found` premise is tied to the address `encoded.2.1.1` returned by the program. Stage A instead uses `AttemptReports.owner_origin` at the witness address and the address-free `FinalReportEvent.Failure`. `FinalCandidate.selected` reads only the raw bytes of the choice, the terminal report batch goes to all `count + 1` positions, and `FinalReportEvent.Failure` has no address, so the owner constant of `AcceptCut.selected` is never read and no owner-selection factor arises. The plan fixes that constant to `0`; the statements here are stated for an arbitrary constant `chosenOwner`, of which `0` is an instance. The deviation is owner decision 6 of the plan and needs the owner's confirmation.

`Protected` reads the identity freshness of the owner at the cut, in the report state reached immediately before the selected raw accept is issued (option (a) of owner decision 1 in the plan). The definitions `ProtectedAt` and `Protected` are isolated in the section `CutProtection` of `PqxdhRegistrationJointAcceptOrigin`. A whole-run reading (option (b)) or a public cut-time observable recorded by the tag (option (c)) would be new predicates with their own theorems; the statements proved here would not change. The owner has not yet chosen between the options. The plan's stage C combines this cut-time horizon with the whole-run KEM freshness `GoodKem` (no disclosure of KEM key `kemIndex` over the whole run). The two horizons differ by design, and the planned main theorem is an event of the `split` coupling, whose final component is the report run of the tagged program; nothing in stage A states that theorem.

## Assumptions and accounting

No primitive game, contract, axiom or premise is added. The only inherited contracts are the functional attached-format premise `shortRejects` and the `setup.wiring` contract, both used through `RawSignatures.verified_detached`, as `KemOrigin.raw_selected` and `AttemptOrigin.raw_origin` already do. The bounds additionally take the existing creation-capacity premise `capacity` and the existing uniform-bill premises. The loss is one sum `∑ target : Fin (count + 1)` of ordinary joint-use weak-EUF advantages with coefficient one; there is no factor for the owner address, for a field or report position, or for the raw-accept ordinal, which is designated. `scan`, `selected`, `tag` and `decisionClient` forward every query exactly once, and every all-reply cap of `work` carries over; omitted continuation work is neither charged nor used to offset earlier work. A reached raw cut has `index < qAccept`, so an adversary-chosen raw ordinal would range over a family of at most `qAccept` handles; no such selection is made or charged here. No statement takes `MlKem768RecipientCorrectness`, and no KEM, Extract, HKDF or root-input statement appears, so the candidate and the KEM value enter no KDF context.

## Deviations from the plan

The probability statements use the repository's form `𝒟[(fun r => decide (P r)) <$> RR …] {true}` under `Classical.propDecidable`, as `native_origin_bound` does, instead of the plan's `Pr[P | RR …]`: the VCVio revision in use deprecates `probEvent`, `probOutput` and `evalSPMF`, and the report outcome type has no measurable-space structure. For the same reason `split_fst` is stated as an equality of the measures `𝒟` of every countable measurable observation of the cut component, which contains every cut-time event through a Boolean observation, instead of an equality of event probabilities. M2 and M3 are generic in the owner constant, as explained above. The plan's step label `rawEq` is the theorem `raw_eq`. Five helper statements are added and guarded: `finish_erase` (M0), `run_bind`, `commands_initialized_map` and `reduction_map` (M1, the last two from the scratch probe), and `selected_certified` (M2). `PqxdhRegistrationJointAcceptOrigin` imports `PqxdhRegistrationJointNativeKemOrigin` directly, because that module is outside the import closure of `PqxdhRegistrationJointAcceptCut`. No planned statement turned out false or unprovable, and none was weakened.

Stage C (modules M4, M9a, M9 and M10): key-list monotonicity along the continuation, KEM-side client-result naturality, the bridge from the actual source to the raw KEM real game (`good_source`, `active_raw`, `coins_stopped`, `router_split`, `real_split`), and the main theorem T5 with its bills companion T5b, which combine `split`, `split_snd`, `split_fst`, `protected_bound` and the KEM hop. Stage D (lane port L2 and module M11): the opaque form of the KEM-ideal continuation. Owner decisions 1 to 6 of the plan remain open, in particular the freshness reading and the confirmation of the owner designation. Handoff item 2 (the Extract/HKDF hybrid at the actual joint sampler, including context secrecy of the candidate), items 3 to 8 and the final validation matrix are untouched. Persistence, snapshots, attacker access to running code and codec internals remain outside the experiment, and primitive implementations remain trusted.
