# Arbitrary-position record composition: source reuse and first consumer

Historical design audit at e22e83d5e0231bb16bfc9af02202f1c124a3b9e0 on codex/evolving-record-composition. This records the plan before focused checks resumed. The checked retained-source completion and its precise remaining executable/event obligations are now described in `doc/impl/later-saved-source-completion.md`; prospective language below is not a claim of completion.

This work extends Milestone C beyond the first Beacon-owned send. It retains the HB111/112 experiment and its documented resource, initial-context and noSign/noCreate scope; it does not claim to close F10's dynamic global adversary. The new joint registration scheduler and withheld-initial-publication proof belong to separate lanes. Primitive implementations and source codec contracts remain the existing ones. Snapshots and persistence remain excluded.

## Smallest concrete missing theorem

The first consuming theorem should be an exact **sample-supported saved-descriptor completion equation**. Its input is the pending value actually returned by `PqxdhErasedParentSample.sample` (or its source-supported carried form), the retained parent entry and the same child key/nonce/next-chain projections. Its conclusion identifies the complete native resume with a key-free selected-material program under the ordinary dynamic CTX interpreter, retaining the complete front, original publication/origin trace, source-local/private state and reached shared cache.

The proof has three source cases, not three new schedulers:

1. A saved record request: apply the existing pending role compiler to the exact supplied parent reply, reinstall the returned roles and history, then run the saved outside Post continuation.
2. A saved Beacon finish: apply the pending receive owner compiler to the exact first opening; keep optional plaintext and all failure effects, execute the original sequence-one/binding/pinned-server checks and finish publication, then resume the saved outside client.
3. A saved initial Server builder: resume the actual pending send, run erase/write/publication and reinstallation in source order, then resume its original Post client. The scope includes writer failure and already-completed work.

Ordinary source comparison must retain unrestricted reveal replies. Hidden-disclosure stopping can be joined only after proving that the original byte-level Fresh event excludes it. Selected-nonce stopping remains a separately charged event until its probability bound is proved. No conditional “no alias”, “nonce unique”, “selected target honest”, or whole-observer source-equality premise should enter the eventual consuming theorem.

There are six preserved uncommitted files in /tmp/beaconcrypt-descriptor-callbacks concerning this exact boundary. They are audit material only, not approved dependencies: `PqxdhSelectedPostNative`, `PqxdhSelectedDescriptorCompiler`, `PqxdhSelectedDescriptorEvents`, `PqxdhSelectedOwnerOrigin`, `PqxdhSelectedOriginPost`, `PqxdhSelectedOriginDescriptor`. Their Post helper overlaps the now-maintained `PqxdhSelectedFirstRecord.post_program`; reuse the maintained theorem where possible. Preserve the old worktree unchanged. Port only proof bodies genuinely needed by the concrete sampled consumer, under independent review, without creating a parallel family or scheduler.

## Required joins after that consumer

First, connect the saved completion to `PqxdhErasedParentMaterial.observe`, including its original finite lineage checker and exact Gate/Fresh decision. The completed/cached outcomes keep their actual bits. In particular, an inner common value may be the entire earlier-stage cached continuation rather than a rejected registration. Its contribution to the target forgery event must be derived from source publication/lineage facts or charged via the actual cached-risk theorem; it cannot be silently set to false or counted as a selected-key observer win. `PqxdhInitialNativeRisk.cached_risk` supplies the source probability endpoint, while `PqxdhInitialNativeParentEvent` and `PqxdhInitialPublishedEvent` connect reached cache paths to the actual target event. Any additional use of that collision bound must remain visible in the final coefficients. The pending mass split used by `PqxdhFirstRecordTarget` is generic before its first-record specialization and can be reused to avoid counting an arbitrary completed true bit as a forgery.

There are three separate non-pending cases in that argument. The cached-risk theorem covers an actual pending cut whose selected address was already cached. It does not cover a fully completed carried scan, and it does not cover a true bit returned by the outer prior sampler. Those latter cases require their own original source-event or pending-mass argument. No bound on their contribution follows merely from packaging them into the same common sum branch.

Second, derive the nonce-stop bound on the actual later sampler. The selected child input is `nextChain parent76`; it is correlated with the retained predecessor response. The retained entry stores the parent address and material, so an exact material44/next32 split can expose a fresh chain draw without treating the entire predecessor response as independent. Move a draw only through equality of the complete continuation. Reuse the generic target-free tagged interpreter and candidate-count machinery from `PqxdhFirstRecordStopTagged`, but discharge its actual initial tag/role invariants from the saved pending cut. Its first-Beacon start lemmas cannot simply be reused for an arbitrary Server or later record. Charge repeated known inputs and byte aliases; do not assume them absent.

Third, generalize the actual record event and observer receipt from sequence one to the designated positive number and both sender directions. Preserve Server peer routing and Beacon phase/associated-data selection, prior sent-frame history, canonical decoded frame equality under the existing ReadWritable contract, failed writers, and replay rejection. A local owner/install token must not be mistaken for cryptographic-session equality.

Finally, compose the same HB112 reductions, final-material alias charge, full prefix/suffix resource bills, nonce/candidate statistical terms and actual CTX reductions. For confidentiality retain an explicit equal-length challenge and justified receive/reveal restrictions; Milestone C's plaintext-suppression wrapper is a concrete replayable-CCA-style experiment, not unrestricted receive confidentiality. Adaptive target/session/record selection remains the exact same-run finite partition from the existing selector modules, with its explicit catalogue provenance and selection factors.

## First implementation boundary after aggregate release

Start with the complete saved record/Post case under actual descriptor support and publication trace; then add the saved finish and first-builder cases needed by the very same sampler. Review and publish only once the endpoint consumes the concrete sampler, all final public statements have standard-only axiom guards, and plain-English analysis records its exact remaining nonce/event scope. Direct changed-module checks will be serialized under /tmp/bc-arc-scratch/lean.lock; no full build will be used for each proof fix.

The maintained source bridges remove the need to recover an additional generic-Origin Post implementation. `PqxdhSelectedFirstRecord.post_program` already preserves the complete Boolean publication trace, for arbitrary retained parent, target and material. `low_program` preserves the original source-local state and shared cache, and `prepared_lifted` instantiates preparation, application, retained initializer, selector and auxiliary callbacks with the actual prepared source. None of these three results depends on position one; the position-one specialization occurs later in that module. The new saved-prefix comparison can consume those results directly.

The sampler conditions also have existing source proofs. `PqxdhInitialNativeAuditCarried.carried_fits` obtains the exact remaining outside allowance and quiet pending completion from the original bounded program, while `PqxdhInitialPreparedParent.supported_pending` transports actual prepared support to that carried descriptor. `PqxdhPreparedDescriptorScope.material_valid` supplies raw provenance for the complete later-material preparation, including proof erasure and normalization. The first new public endpoint should instantiate these facts from supported source output rather than expose Fits or Valid as new caller obligations. This leaves the actual three-case saved-prefix completion and its original finite lineage checker as the next proof boundary.

Independent read-only review confirmed these seams and identified two accounting details to retain explicitly. Raw provenance does not itself imply Fits: the original all-reply post bound and support transport must establish that separate certificate, and normalization must preserve the carried descriptor rather than invent support under a changed initial state. The existing later-prefix bill already includes complete cached continuations and all 184 sampled bytes on common branches; a subsequent pending-suffix bill applies only to a pending outcome, without charging the completed branch a second time. This is a design review, not approval of an implemented or checked theorem.
