# Selected Beacon finish through the actual raw-opening interface

`PqxdhServerAuthFinishMaterial` compiles the selected Beacon post-root callback into the existing dynamic CTX interface. Its executable `program` takes the fixed HKDF source, the ordinary codec, the residual factor material and the actual prepared response. It requires no selected-message-key argument. It calls the original application getter and passes its actual optional bytes through the complete raw parser, frame validation, receive state machine, opening and registration checks. It returns the original optional staged result. The mathematical source interpreter still takes the selected key explicitly; arbitrary correlated input values and equal known-key bytes remain permitted. This operational equation is not a selected-key independence theorem.

The central difficulty is the final material interpretation. A failed or wrong-sequence receive can retain private material markers, so a blanket claim that every final kernel contains only ordinary material would be false. `finish_reply` preserves the original optional opening result. `opening_wrong` obtains the sequence of the returned plaintext from the actual prepared opening arguments. `program_wrong` carries that fact through every skipped-key continuation. These equations retain all oracle effects before the existing sequence-one gate rejects the result; they do not move rejection earlier or silently remove attempted openings.

`execute_material` handles the two actual source cases. For sequence one, the literal empty initial kernel reaches one uncached opening and its final kernel contains no cached material, using the checked `BeaconFirstOpening.execute_one_material` theorem. For every other sequence, the original post-opening registration gate discards the staged result after the unchanged receive computation. Consequently, any two material maps give the same final registration observation. `raw_material` proves this for arbitrary input bytes, including empty, malformed and invalid frames. It does not assume that the decoder succeeds or that an opening is accepted.

`observe` uses a fixed material resolver solely in the final registration observation; no primitive request uses that resolver. `raw_observation` combines the material-map equation with the existing concrete raw-source simulation. It preserves the actual optional challenger plaintext, original sequence and binding checks, staged native kernel when present, and complete shared cache after component bookkeeping is projected away. `native_labels` identifies the actual primitive callbacks used by the source Beacon factor. `program_source` then supplies the literal original application getter and cleared prepared candidate, proving equality of the complete selected callback with the executable program. There is no residual callback-simulation, successful-opening, sequence-one or material-settlement premise in this theorem.

`program_bound` counts at most one dynamic component request across the entire callback, including rejected attempts. `program_other` proves zero selected sealing and uniform requests. `program_bills` exposes selected seal zero, forwarded hash at most one, raw opening at most one and uniform zero. The stronger total cap of one means the hash and raw limits do not assert that both calls occur. These are component-interface bounds: real local HKDF evaluations and their up to 51 receive derivations, parsing, validation, deterministic known-key cryptography and component-interpreter sampling remain in the separate source and reduction bills. Public HKDF evaluations remain real.

This closes the concrete selected Beacon callback needed by the B9b handler. The complete adaptive handler, second-selected-session stopping proof and global call bounds, actual key-first factor/context distribution, and original entry-event implication into the ordinary authentication observer are separate consumers. This package makes no session-origin, assigned-ID-equality, nonce-uniqueness or final advantage claim and introduces no cryptographic assumption or reduction loss. Snapshots and persistence are outside this proof.
