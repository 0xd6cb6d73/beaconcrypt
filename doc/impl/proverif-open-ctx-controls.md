# Open symbolic CTX differential controls

The two `fs-aead-differential-*` targets test the role of the symbolic CTX equality with attacker-supplied inputs. Neither target is a protocol security theorem or a computational reduction. The committed-frame target is a definitional check; the deliberately uncommitted target is a differential control. Existing closed controls and all protocol queries remain unchanged.

Each replicated worker accepts six arbitrary public context inputs (two keys, two nonces and two associated-data values) and one arbitrary raw frame term. It parses the same frame shape used by `crypto.pvl`, retaining the ciphertext, detached tag, commitment, sequence and sender identifier. Both openings use that exact ciphertext and tag. The worker obtains each plaintext from the existing deliberate weak-AEAD opening destructor; it never substitutes a privately recovered plaintext into an attacker request. The event occurs only after both opens succeed and the `(key, nonce, associated_data)` tuples differ. Public frame fields are shared because both attempts use the same frame. A public sender constant supplies a known identifier without restricting the attacker's input choice.

`FsAeadWithCtx` first checks the supplied commitment against each complete context with the actual symbolic `ctx_commitment` operation. Constructor binding makes distinct context tuples incompatible with those two equalities, so absence of the event is definitional in this theory. This result does not establish that ChaCha20-Poly1305 itself commits to its key, or that BLAKE2b collision resistance alone gives a random oracle. The existing computational modified-CTX proofs and their explicit collision/ROM assumptions retain their separate scope.

`FsAeadWithoutCtx` removes exactly those two commitment comparisons. Its attacker still supplies both contexts and the same full frame, and both opening destructors must succeed. The weak-AEAD fixture already used by the closed controls deliberately has left and right opening labels with different context tuples and a common ciphertext and tag. A reconstructed attack demonstrates that this uncommitted experiment can reach the event. It says nothing about finding such a collision in the production primitive.

The exact target roster is `CTX-open` (definitional, TRUE) and `CTX-open-no-commitment` (differential, FALSE with exactly one confirmed trace). The checker pins the query/process pair, complete open process tokens, and existing weak fixture declarations. Model changes require explicit review and a refreshed digest; digest comparison is a drift guard, not a semantic proof. The checker rejects unknown verdicts, missing summaries, wrong formulas, unexpected warnings, missing traces and source changes during execution. Each target runs under the shared ProVerif lock, separately from the original correspondence group's budget and within the approved 1,800-second and 10 GiB limits. The default direct control timeout is 30 seconds; the Make target uses the same configured maximum as the other separate groups.

The focused Make gate passed both exact verdicts, with a confirmed reconstructed trace for the uncommitted worker, in 0.02 seconds of total verifier time. It also passed all 25 transcript-fidelity tests and nine checker regressions, followed by the reviewed inventory check. The independent semantic review verified both the constructor contradiction and an explicit public multi-opening witness. The initial Make run correctly rejected a bound-variable shadowing warning; renaming that variable removed the warning without changing a process operation, query or result. Strict warning rejection remains enabled, and the initial diagnostic logs are retained separately. Final source hashes and complete logs are archived with the publication receipt. No production Rust, primitive implementation or snapshot/persistence change is included.
