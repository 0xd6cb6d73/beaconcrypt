# Later-record challenge and actual source provenance

`PqxdhRecordConfidentialityChallenge`, `PqxdhRecordConfidentialityTrace` and `PqxdhLaterSelectedSendPrivacy` provide twenty guarded operational statements for the later-record confidentiality composition. They retain a literal two-world challenge, rather than interpreting an arbitrary Post Boolean as a secrecy or authentication failure. These statements do not yet bound the difference between the two worlds.

The challenge fixes a source owner and a wire sequence. An owner is either a Server object together with its requested peer ID, or a Beacon object. The adversary may perform any earlier request already present in the original Post interface and may then submit two equal-length plaintexts. The wrapper forwards exactly one ordinary send of the chosen plaintext through that owner. It does not inspect or restrict a private counter, chain, origin label or selected-key marker. An actual failed send still consumes the single challenge. Later challenge attempts and unequal-length alternatives receive the same explicit refusal used by the challenge interface.

The final target test requires an actual returned encrypted record with the requested sequence. It also requires that no ordinary forwarded send returned that same owner and sequence. This is an observation of actual public send replies, including earlier replies; it does not suppress source operations. The original optional writer result, all source effects and all later adversarial requests remain present. Raw receive replies use the existing explicit challenge-plaintext screening from the first-record experiment. Beacon finish replies remain unchanged, so a selected opening through finish still needs its separate collision/event analysis. Initial Server registration sequence one is produced by the enclosing builder, not by a later Post send, and is not a challenge route claimed by this wrapper.

## Wrapper and resource statements

`send_bound` charges the literal Server or Beacon send to its actual source predicate. `query_bound` transports any adversary predicate budget through the complete wrapper on every reply path, counting a challenge whenever either of its two possible sends belongs to that predicate. `post_bound` includes the final target Boolean, and `post_bounded` supplies every coordinate of the original scheduler budget. The `certificate` definition changes only the original certificate's Post and its proven Post budget; all source callback, primitive and prefix fields are retained. In particular, this does not remove the enclosing experiment's existing no-sign/no-create prefix restrictions or add arbitrary dynamic identities.

`challenge_step` identifies the exact source send and returned optional record for an equal-length challenge at any reached wrapper state. `single_output` checks that a sole challenge yields precisely the adversary's guess conjoined with the actual returned-sequence test. `observe_target` identifies the sticky competing-publication flag exactly. `Kept.trans`, `query_kept` and `run_kept` prove that the chosen challenge pair and its actual optional reply cannot be overwritten and that a competing-publication flag cannot be cleared by any suffix. These properties hold for every possible source reply, including rejection and failure.

These are source-interface counts, not runtime or ciphertext-byte bounds. Primitive interpretation, local deterministic cryptography, KEM/base work and the existing component overhead remain governed by their original ledgers. The wrapper adds no separate oracle service and the proof-only trace adds no query. Owner and sequence are fixed parameters here; adaptive identity, session or record selection must be connected explicitly to the enclosing experiment and its reduction factors.

## Actual source trace

`Trace` observes the unchanged wrapper interpreted by its original source implementation. Each node retains the complete source state, original dependent query, actual supported reply and full adaptive continuation. `Reaches` is a proof relation for a prefix of that same execution; it is not another executable scheduler. `run_trace` constructs the full trace from actual support. `interpreted_kept` and `Trace.kept` carry the all-reply bookkeeping facts into this exact source execution without discarding the source state.

`Trace.origin` proves that a true target event from a state with no challenge has an actual reached challenge request. Its witness contains the equal-length plaintexts, complete pre-send state, original successful send reply, complete post-send state and the exact remaining client trace leading to the same final result. The source record's sequence is the requested sequence. `run_origin` consumes the literal empty wrapper state, and `post_origin` retains the witness even after the wrapper returns only its Boolean. No caller supplies an honest origin, a successful source path or a selected-key condition.

`forwarded_excluded` separately identifies the original source reply at an ordinary forwarded operation and proves that it did not publish the target if its exact continuation reaches the final target event. It distinguishes the source reply used for publication bookkeeping from any screened raw reply observed by the adversary. Thus matching a final sequence number alone is never substituted for the actual challenge send.

## Retained-parent send relation and remaining composition

`derive_target` retains the original predecessor-priority rule: at the selected address, the child route agrees with the existing selected response only when the retained parent address differs. `send_selected` lifts this to literal equality of the complete send oracle programs, preserving exhaustion, the outer selected-nonce refusal, optional writer failure and the entire advanced kernel. `send_twin` then consumes the existing checked two-plaintext relation. At the same actual selected input, both challenge plaintexts use the unchanged selected seal interface and identical complete continuations. The statement is independent of the send counter and role metadata.

The parent-address inequality is an explicit case split, not a new security assumption; `PqxdhLaterParentAlias` already bounds that actual sampler event separately by `2^-256`. These local statements do not infer the selected input from a sequence, role, ciphertext, key equality or an arbitrary origin label. The next consumer must derive that input from the actual directional path at the reached challenge and connect the full wrapper to the existing sampled saved-descriptor continuation. It must then prove the complete two-world suffix coupling, retain original finite-lineage/message-key freshness, and pay actual nonce recurrence, finish-opening, known-key alias and primitive terms. Other owners' publications and equal known-key bytes are not prohibited by this wrapper. All original common/cached decisions and their existing mass bounds remain part of the enclosing composition; no branch is forced to false to manufacture secrecy.
