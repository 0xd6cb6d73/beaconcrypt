# Lean 4.34 composition branch migration

This work merges `vcvio-lean-4.34` at `7e996e5015898f3b0b175e9fabcb646c3af6c453` into `codex/full-proof-composition`, whose reviewed predecessor is `46af78732c7475ae064c7f29139526ca93910f5a`. The upgrade branch already descends from that predecessor. The user authorized completing its remaining ports and required the larger security proof to stay paused. The separate unfinished-proof recovery branch is not part of this merge.

The dependency baseline is Lean and Mathlib 4.34.0, VCVio v4.34.0 at `98dc1089129086b776129c79d88c0c561b8d8d1a`, Aeneas at `6852e6474ec508930acba4df79977b3483a10d10`, Hax-Lean at `b49608d5e402577b400569ee989c3f1b69e4aaf3`, cargo-hax 0.4.0 and Charon `nightly-2026.09.02`. Two source patches adapt the pinned Aeneas and Hax-Lean libraries. The preparation script checks exact configuration, dependency revisions, checkout roots, clean unpatched dependencies, patch hashes and resulting diff hashes before the maintained build. No upstream branch head substitutes for an immutable dependency revision.

VCVio's general evaluation interface now returns measures. The migration retains `evalSPMF` for discrete subdistribution arguments and uses checked conversion lemmas where public games expose `evalDist`. Explicit singleton evaluation supplies the same Boolean probability. The Ed25519 runtime's map law is now part of the upstream runtime interface; the reductions still use that law. Atomic KEM support uses nonzero singleton mass with the discrete measurable structure. This is not a replacement by topological support or a new assumption that a chosen target is honest. Review retains the original experiments, loss coefficients, challenge restrictions, freshness events, correlated samplers and query bounds.

Some generic library interfaces change explicitly. The three `CtxPrefixIsolation` support helpers require upstream `MonadAttach` and `ExactMonadAttach` laws, supplied by the canonical `OracleComp`/`ProbComp` instances at production uses. Measure-facing eager-table wrappers require the corresponding measurable and discrete-measurable instances; the full-continuation discrete reorder law remains available without those extra interfaces. These are representation and library-law requirements, not new cryptographic, honest-target or freshness premises. The eleven ideal-model files keep every definition and theorem statement; only the three reviewed proof bodies change.

The remaining source proof repairs make elaboration explicit. The initial response builder now names its actual computation and transports its result through the nested state maps before applying the original reinstallation equation. All optional success/failure/divergence branches retain their full protocol, primitive, identity and cache state. Callback, native audit, terminal Beacon, origin-context and ordinary-cache proofs similarly apply existing `StateT.run_map` or unfold the original monad lift. Private one-query lemmas explicitly name `OracleComp.IsTotalQueryBound` to avoid field lookup on the underlying free-monad representation. Printed axiom guards are updated only to the actual kernel reports; none permits an additional project axiom or admission. Local elaborator transparency settings affect proof search, not theorem statements or kernel checking.

Downstream initializer consumers use the same repairs: explicit nested state maps preserve erased-root, private-alias, prepared-prefix and root-event continuations; original empty-cache annotations only resolve Lean inference. Freshness and secrecy wrappers identify the same Boolean singleton with its point probability. Where a distribution bind helper was removed, an existing equality of the full computations supplies the same evaluated equality directly. Explicit sampler maps retain every context field and the original `qPrior + 32` bill. These downstream ports preserve existing heartbeat limits, events, losses and query allowances. Generic complete-state sampling equalities retain their original discrete SPMF meaning, now written `𝒮`; Boolean consumers derive measure equality through `evalDist_eq_of_evalSPMF_eq`. This includes the full76 split with its arbitrary complete continuation and original nonce, next-chain and selected-key ordering. Adaptive final-choice and first-material consumers use the same supported preparation and existing losses.

The Aeneas patch retains every original `BvTac`, `BvTac.Tests` and `Bvify` regression proposition. The upgrade checkpoint had commented out scalar examples and suppressed two failures; the integrated repair restores them. A small tactic step generalizes scalar BitVec projections while retaining defining equalities, so Lean 4.34 can reify them consistently. Lean checks the resulting proof terms. The original `BvTac.Tests` file is now byte-identical to the pinned dependency, and neither an error-dropping guard nor an admitted theorem substitutes for a test. The pinned dependency regression build passes all 1,646 jobs.

These are ports of existing proofs. They do not complete the opaque selected-record compiler, later-prefix resource consumer, dynamic KEM/freshness router, global selection losses or computational-symbolic event map listed in the [pause handoff](proof-toolchain-upgrade-handoff.md). The extra related-DH Extract endpoint remains explicit and unbounded. No primitive implementation, snapshot or persistence proof is added, and no stronger end-to-end security conclusion is claimed.

Fresh cargo-hax extraction under the locked environment reproduced all six tracked extraction files byte-for-byte. The complete Makefile verification, restored dependency regressions, policy gates and refreshed reviewed inventory pass. Independent semantic review covers theorem scope, primitive interfaces, query accounting, source preservation and inventory integration. HB-124 records the validation receipts. Mutation testing is omitted because no Rust source changed. The larger proof remains paused.
