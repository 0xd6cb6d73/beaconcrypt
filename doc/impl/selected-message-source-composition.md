# Selected-message freshness, adaptive aliases and raw opening

HB-117 connects the actual native disclosure checks and raw opening callbacks to the selected-message-key endpoint. Ten modules add 106 guarded statements. These are exact local source correspondences and an adaptive alias reduction; the complete mixed source compiler, selected-key nonce-use proof and replicated symbolic trace connection remain separate obligations. All primitive implementations remain trusted contracts, and snapshots and persistence are excluded.

## Adaptive candidate-hit reduction

`RawCtxSelectedKeyProbes` handles known key candidates that can depend on the entire earlier ciphertext and optional-plaintext interaction. It appends one shared-ROM query per candidate only after the original client stops, retaining repetitions. The returned digest is ignored and the original result, including the candidate list, is returned unchanged. This is internal reduction instrumentation; it does not add a network disclosure of private candidates.

`finish_result` preserves the exact original stopped-result distribution. `probes_public` records the entire candidate list in the actual public-query history. `finish_candidates` and `finish_hit` show that every selected-key equality is a secret-prefix hit on that same execution. `candidate_probability_finish` preserves the retained key/candidate correlation, and `candidate_le_prefix` derives the corresponding probability inequality. None of these statements assumes that adaptive candidates are independent of the key.

`canonical_prefix_bound` transfers the prefix event from the real shared-cache experiment to the existing independent-prefix experiment and pays for that event transfer. `candidate_bound` therefore bounds the original candidate-hit probability by

```text
2 * (Adv_validation_IND$(finish(client))
     + (qHash + qCandidates) / 2^128
     + sum_{i < qRaw} Adv_INT-CTXT_i(finish(client))).
```

The factor two is explicit. The reductions are the existing `AdaptiveCtxPrefixValidation.validationReduction` and `AdaptiveRawNonceAead.indexedReduction`, instantiated with the actual instrumented client. Every adaptive raw attempt has an indexed integrity term. The theorem retains the component's `qSeal < 2^96` precondition and its nonce-rejecting interface. It introduces no independent `qCandidates / 2^256` guessing claim and does not yet justify using that nonce interface for arbitrary native sealing schedules.

`probes_bound` charges each classified probe. `probes_bills` specializes this to one public hash and zero selected seals, raw attempts or explicit random calls per candidate. `finish_hash` adds the entire terminal candidate allowance; `finish_uncharged` retains every category excluding these probes. `candidate_validation_bills` gives at most `qSeal + 1` primitive seal calls and `qUniform + 64 * (qHash + qCandidates + qSeal + qRaw)` reduction byte-samples, plus the challenger's separate 32-byte key. `candidate_integrity_bills` gives the same reduction sampling allowance and at most `qSeal` seal calls for each indexed integrity reduction. Hash evaluation, callback work and candidates are accounted for in their original interfaces; zero explicit random calls in a probe does not make its ROM implementation free.
