# Actual joint source for the dynamic KEM router

`PqxdhDynamicKemJointSource` connects the selected KEM disclosure monitor to the original combined source service. That service contains joint Ed25519/X25519 identity operations, explicit local random choices, and indexed KEM creation, decapsulation and reveal requests. The source interpreter retains the complete joint identity state and KEM observation history. It still returns the actual selected secret on a successful reveal and permits the client to continue afterward. This module is the ordinary source comparison, so its interpreter has the actual reserved secret pairs; the executable CCA reduction must use the separate redacted router.

`reveal_source` identifies every ordinary optional reveal reply with the original private pool, including an existing selected secret and rejection of missing or future handles. `step_source` extends that exact comparison to each original combined request. It reconstructs only the already-created private prefix. Joint identity generation, signing, converted-DH operations and their complete seed/log state execute through the existing `lazyImpl` in their original order. Explicit local coin requests remain actual random queries.

`step_answer` distinguishes an artificial outer reservation failure from ordinary optional protocol rejection. The actual creation allowance rules out that outer failure. `step_capacity` proves that only KEM creation advances the active prefix, while all other joint or private operations preserve its size. The proof remains valid when the source has returned the selected secret and continues handling later requests.

`program_source` follows the entire bounded adaptive source program. After projecting away only the added disclosure monitor and inaccessible reserved future, its result is exactly the original `LiveKemReservation.reserved` oracle program, including the complete joint state, private created keys and both service histories. This is syntactic equality of the interpreted oracle computations, not just equality of a final Boolean or marginal key distribution. `program_uniform` therefore transfers the original complete uniform-query allowance exactly. It does not erase joint generation, ordinary decapsulation, local coins or interpreted ambient primitive costs.

`selected_source` starts the original on-demand source with its actual empty KEM pool and arbitrary retained joint identity state. It consumes the existing checked complete-continuation generator interchange to sample the chosen creation ordinal first, then samples every other reserved key in source index order and runs this monitored source. The equality retains every adaptive continuation and full final source state. No public-key injectivity, distinct-secret-byte condition or selected-candidate honesty premise is used. This remains an ordinary source distribution equation: it does not reveal the chosen secret to an executable CCA adversary.

The existing generator ledger charges one actual key generation for the chosen slot and `count` actual generations for the other slots, including unused reserved slots. If a key generation takes at most `qKeygen` interpreted uniform queries, this prefix costs `qKeygen * (count + 1)`; the complete source suffix keeps its separate `program_uniform` allowance. The source creation cap is `count + 1`. The later CCA interpretation must retain the previously proved logical decapsulation, local uniform/base and joint identity charges; no ambient callback is declared free here.

These seven statements close the actual combined source side of the reservation boundary. The next consumer must lift the stopping and pre/post CCA interpretation through the same combined interface, derive the target's KEM disclosure condition from the original global freshness decision and retained owner handles, and establish the protocol boundary that prevents direct disclosure of the challenge candidate. They do not establish whole-protocol authentication or secrecy on their own. No snapshot or persistence behavior, new primitive security assumption, or primitive implementation proof is introduced.
