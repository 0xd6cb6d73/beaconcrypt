## Exact observable capabilities

The client can call `send(plaintext)`, `openRaw(raw)` or `deliver(raw)` in any adaptive order and can stop with an arbitrary result. Sending returns the actual optional encrypted record. The raw-opening capability returns the original optional decrypted record, including its actual plaintext, sequence and source metadata. Delivery is an additional network observation interface: it runs that same source receive and exposes only its success bit. The raw-opening capability is preserved in full; it is not replaced with the less informative delivery interface.

Both receive modes pass the original arbitrary bytes to exactly one original source call. Parser failure, rejected sequence or sender, failed commitment or AEAD, successful consumption and rollback retain their original source behavior and full primitive effects. Nothing inserts recovered plaintext into the adversary's input. The interface returns only the challenger/source-produced optional reply. A successful raw-opening response discloses its actual plaintext, so a later confidentiality experiment must account for that disclosure in its explicit target freshness policy.

`send` is a chosen-plaintext application request: its requester supplies and already knows the plaintext. The public transcript records that request. This interface does not silently turn a private honest application's unknown message into a public request; a common experiment with such messages needs an explicit private application service and a matching public request projection. No private owner, current chain, cache, callback history or primitive state is included in the final public observation. The complete state is retained in internal simulation equations so it remains available to subsequent protocol execution.
