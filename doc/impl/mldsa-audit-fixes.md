## Reviewed proof and source changes

The regenerated complete extraction adds the `authentication` definitions already present in the isolated cohort and adopts the production AD281/CTX357 layout. Independent review compared the authentication type/function cohort against the isolated extraction byte for byte. After accounting for that addition and the reviewed width/offset substitutions, the remaining generated changes are the relocated associated-data constant and the AD constructor's reserved-zero branch. The generated external templates and forwarding files are unchanged, so this repair introduces no new external implementation hole.

The pure PQXDH AD model retains the original 153-byte prefix and appends 128 zero bytes, matching the deterministic core constructor. The CTX layout becomes `key32 || nonce12 || AD281 || tag16 || LE64(sequence) || LE64(sender)`, with 357 total bytes, a 325-byte key-free suffix and a 293-byte nonce/AD envelope. The new offsets preserve the order and width of all other fields. Independent review of 106 changed model/computational modules found 100 containing only width substitutions; the remaining six account for the zero suffix, suffix lengths, raw decoder framing and trailing-64-byte example. No added security premise, relaxed event definition or weaker cryptographic assumption was found. The core and commitment refinements separately adapt array bounds, offset proofs and the new zero branch.

The three `TranscriptAuth` refinement modules now use the global `beaconcrypt_core.authentication` definitions. The isolated six-file `AuthenticationExtraction` cohort remains a pinned reproducibility check but is no longer imported alongside the complete generated root, avoiding the duplicate generated root instance. `PanicFreedom/Authentication.lean` supplies eleven unconditional certificates for the transcript constructors, ordered parts, signature input, AD overwrite, LE64 encoder, role clone and static width assertions. The regenerated aggregate and manifest contain 290 non-helper operations. Within the twelve-file ideal-model set, only `Pqxdh/Kdf.lean`, `Commit.lean` and `InstanceCommit.lean` change; the reviewed aggregate digest is `c7acbc9e3aa1b262a31fdcc68838de236bd6f52294e8e53f5ee9c3134f917518`.

The source-pin changes preserve every legacy ProVerif process, query, expected result and verdict class. Seven checker families now enforce the existing classical-projection marker, and 39 classification rows explicitly state that the mandatory ML guards and AD fingerprints are omitted from those profiles. Scope-removal and scope-change regressions accompany the refreshed source hashes. The symbolic name-order and getter checks retain their narrower classical scopes. [The separate correspondence review](mldsa-source-pins.md) explains the reviewed Rust behavior and records the independent Python checks. The complete solver matrix subsequently passed every configured group.

The current higher-level PQXDH model still uses the core's zero-filled fingerprint slots. Exact construction and overwrite refinements do not globally compose the adapter's mandatory ML verification, actual hash values or source signing histories with the existing computational deployment games. The bounded ML-DSA symbolic profiles and conditional trace bounds retain their explicit primitive assumptions and schedule limits. The maintained [verification analysis](../formal-verification-analysis.md), trusted-boundary summary and Lean README explain this distinction. Earlier AD153/CTX229 and 279-operation receipts are preserved as history.
