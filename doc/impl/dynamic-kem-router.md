# Dynamic indexed KEM routing

`PqxdhDynamicKemRouter` removes the selected KEM secret from an executable dynamic creation/decapsulation/reveal service. Its reservation contains the challenger public key at one chosen creation ordinal and actual locally generated pairs at all other ordinals. `selected_reservation` proves equality of this complete public-key-only table with redaction of the original selected-first reservation. Public-key and shared-secret byte aliases do not change ownership: the source creation index is authoritative.

A reservation is private future data, not an already-created key. The router advances its activated-prefix count only when the source creates the next owner. It first checks that a requested handle exists in that activated prefix. A reveal of a missing or future selected index returns the original ordinary rejection and continues; a successful selected-key reveal stops before returning unavailable secret bytes. The stop has an explicit `forbiddenReveal` flag and does not fabricate a secret or record a false ordinary rejection. The complete stopped result retains the original returned-value history, creation count, and both disclosure/exhaustion flags. `empty_source_pool` establishes the real empty starting pool and history.

`program_source` compares every adaptive prechallenge program with this same concrete stopped source. Its statement retains the entire optional result and private bookkeeping, including rejected paths. The executable reservation requires no selected-secret input; the source comparison supplies it to the CCA interpreter and source-state reconstruction. Arbitrary input histories and equal other-key secret bytes are not excluded by these operational statements. `PqxdhDynamicKemPost.program_source` gives the corresponding complete postchallenge equality when the supplied candidate is the real recipient secret. The postchallenge router returns that candidate to the source client for the exact selected challenge ciphertext and forwards every unequal selected ciphertext through the ordinary CCA interface. The generic source-client type does not prevent a caller from returning those bytes; candidate nonexposure must be established by the later native source/adversary boundary. Other owners retain their original local optional outputs. `supported_source` derives the special-ciphertext equation from the existing functional primitive-interface contract and ordinary recipient correctness on actual key-generation/encapsulation support; it assumes neither public-key injectivity nor a protocol authentication result.

`PqxdhDynamicKemSource.created_pool`, `decapsulation_source` and `other_reveal_source` connect the private reservation representation to the original source pool's appended key, decapsulation and permitted compromise operations. `schedule_capacity` consumes the original syntactic creation cap and proves that exhaustion cannot occur when the reservation covers that cap. `empty_capacity` specializes this to the empty source state. `selection_sum` accounts for adaptively choosing an actually created owner by an explicit finite sum over the same source creation allowance, preserving the complete original event and execution in each summand. It is probability accounting, not yet a sum of instantiated cryptographic reductions.

`PqxdhDynamicKemBounds` counts the original source decapsulation attempts, including missing handles, rejected outputs and stopped continuations. A source cap `qD` gives at most `qD` selected logical CCA requests in each phase. If each local other-key decapsulation has uniform cost `uD` and base cost `bD`, the corresponding phase costs are at most `uD * qD` and `bD * qD`. `challenge_blocked` gives zero postchallenge queries at the selected exact challenge ciphertext for the complete adaptive program. Source creation uses a previously paid reservation; it is not free key generation. `PqxdhLiveKemSelection.family_uniform` and `selected_uniform` retain the actual local generation bill `qKeygen * count` plus the selected challenger generation. No deterministic lookup, transcript copying, outside callback or full protocol scheduler work is asserted to have zero runtime or oracle cost.

`PqxdhDynamicKemLiveRead` checks the actual native retained prekey/KEM field before requesting the private pool. Its `disposed_routed` theorem shows that a disposed native KEM field rejects without a pool request or a freshness stop, preserving complete router state even when the trusted interpreter keeps historical pairs. A retained live field requests exactly its creation index. This concerns logical native-field availability; snapshots, persistence, physical erasure and restored-state behavior are outside scope.

These modules establish a dynamic operational CCA-routing interface. They do not yet prove that the complete protocol's final freshness event allows stopping after every selected reveal, or that an arbitrary caller-supplied initial history is simulatable. The intended source initialization is empty. The full joint identity/KEM/native protocol scheduler must consume the source reservation/order laws, native ownership relation, live-field read restriction, stopped-event argument and global session/record selection losses in one experiment. The final protocol IND-CCA term must use that constructed reduction; these equalities alone are not an end-to-end secrecy claim.
