# Phase-1 native bundle boundary

`PqxdhBoundaryPhase1Native` consumes the existing `RegistrationSchedule.bundle` and `DeploymentNative.handler` operations. The six checked equalities and bound describe their actual complete result and state; they impose no successful-writer or successful-bundle premise.

`native_prepared` computes the unchanged prepared role with the exact identity, prekey, one-time key and KEM public key. It uses the existing joint signature callback on the prekey, one-time and PQ messages and passes their complete attached-signature buffers to the existing optional `codec.write1`. A failed preparation or writer returns the original owner. A successful writer publishes the exact prepared material and original identity into InitSent. The arbitrary optional callback failures remain covered by `PqxdhBoundaryPhase1Source`; this native specialization uses the already-defined total typed signing contract and uniform scalar sampler.

`owner_source_order` keeps the one-time scalar draw exactly before the Fresh preparation. FreshWithCoins uses its retained scalar, and other phases return without a draw. `source14_bundle` reinstalls precisely the returned owner at the requested index while retaining the complete shared state and other owners. `native_bundle` lifts the same execution to CE's literal bundle handler, preserving the complete native state, both raw-attempt counters and the produced-record log. `native_continuation` substitutes this source execution before any continuation of the full reply and deployment state. No distribution interchange or marginal-key equality is used.

`native_uniform` retains the existing cap of 32 uniform byte queries for every native attempt, including failed writers. The source service caps remain one generation request, three signing attempts and one serialization request. The signatures and byte processing are deterministic local work under the defined primitive interface; the uniform bound is not a zero-cost claim for that work. Repeated failed requests retain separate attempts and draws.

The reference adapter is `beaconcrypt/src/beacon.rs`, `get_registration_bundle` (lines 300–396 at base 3d212990). Its generator, builder arguments, signature order, setter order, writer and publication were reviewed. The existing `validate_phase1_source` fidelity check anchors selected source strings, buffers and ordering. The unextracted Rust adapter remains reviewed transcription (RT), while these Computational equations are checked Lean (L). Native primitive implementations, compiler/runtime behavior and allocation errors remain external contracts. This stage changes no Rust source, security assumption or protocol property.
