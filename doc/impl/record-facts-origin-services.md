# Record origin service witnesses

`PqxdhRecordFactsOriginServices` proves five support and functional facts about the actual `PqxdhRecordLiftIdeal.ctxInterpreter`, using the previously reviewed replay and dictionary witnesses. This is a service-level step toward `OriginStatement`, not the global origin or unpublished-record theorem.

`opening_frame` says that every successful hidden opening in replay or random mode has an actual material coordinate returned by the source opening getter, an actual frame decoded from the original network bytes, and a pre-existing seal dictionary entry at that coordinate. The decoded frame has the entry’s exact sequence, sender and encoded payload, and the source returns that entry’s plaintext. The proof follows the payload parser, the source argument getter and the 153-byte associated-data check before projecting the actual counted, shared-ROM keyed execution. It introduces no alternative plaintext and makes no assumption that a supplied target frame came from an honest send. The theorem does not yet prove that this coordinate belongs to the receiver’s opposite-direction peer.

`keyed_raw_seals` and `opening_seals` prove that raw receives leave every coordinate’s successful-seal dictionary unchanged. These statements cover successful and rejected requests, including parser, argument and width rejection. They assert preservation only of the dictionary: shared hash caches, private suffix caches and attempt counters remain part of the real execution and may change.

`hiddenSealing_call` is an equality of the hidden sealing client with its one selected keyed query and its full pure continuation. The continuation retains the writer’s actual optional result and the pending frame log. It is stated for the validated associated-data width and retains plaintext replacement, selected nonce, sequence, sender and target fields.

`sealing_trace` proves the exact dictionary, produced-log and pending-frame effects for every supported ideal hidden seal. An invalid width or refused repeated nonce produces no record, leaves every dictionary unchanged and leaves the pending log unchanged. Otherwise the selected coordinate adds the exact selected input and returned CTX record to its dictionary, and the pending log appends the literal source frame. This append happens even when the frame writer returns `none`; consequently the proof cannot silently treat an unpublished record as nonexistent. The already tagged produced log stays unchanged until the later source publication callback. Preservation of other coordinates on successful seals is separately available from the existing `PqxdhRecordLiftCtxHybrid.sealing_other` theorem.

These theorems assume only the explicit ideal-mode restriction (`replay` or `random`) where dictionary acceptance is needed, and the width premise of the functional call equality. They use no `FrameReadBack`, decoder-agreement, injectivity, freshness, guessing or primitive security assumption. The exact primitive record and actual decoders remain arguments of the source execution. In particular, pre-seal private-cache entries created by raw queries are preserved; no seal is assumed to draw a fresh commitment. No probabilistic loss or query bound is claimed at this stage, and no field of the source private state is discarded by a new game construction.

All five statements have checked exact axiom guards permitting only `propext`, `Classical.choice` and `Quot.sound`. Focused direct Lean checks and independent semantic review passed. Attribution of dictionary entries to actual sending handles, publication of pending frames at owner boundaries and adaptive schedule induction are now established by the source send, buffer and [global invariant](record-facts-origin-invariant.md) modules. The accepted-transcript join and unpublished-frame probability bound remain open.
