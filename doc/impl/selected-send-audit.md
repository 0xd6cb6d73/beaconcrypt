# Actual parent-retry candidate accounting

`RawCtxParentRetryAccounting` consumes the literal `PqxdhInitialParentPrivateObserver.observed` interface used by the evolving-chain source proof. Its seven statements connect private send derivation requests to the existing candidate ledger, preserving the full primitive, auxiliary, root-cache and disclosure-flag state.

`known_logged` proves the complete state equation for a known send-chain request. Its actual 32-byte input is appended once before private byte-alias routing. If those bytes equal the protected input, the request uses the same hidden child response but the candidate is still recorded. `hidden_logged` proves that a genuinely hidden request uses the same full child response and appends no invented known candidate. Both equations retain the exact existing disclosure flag.

`parent_retry_logged` distinguishes a retry at the exact retained predecessor address. On the branch where predecessor and protected child inputs differ, this request appends the predecessor bytes and returns the hidden child with its original material. The inequality is a branch condition for this exact equation, not a global freshness or no-collision premise. The equal parent/child branch remains covered by `known_logged` and is recorded as a protected-input candidate.

`retained` proves candidate-prefix inclusion for every supported full adaptive continuation under that actual observer, including reads, public evaluations, rejected operations, later initializer callbacks and all optional results. `known_followed` therefore puts the original known send input in the final candidate list after the same arbitrary typed continuation. It does not stop at the immediate KDF callback or erase later disclosure behavior.

`hidden_next` classifies the pure retained-table step: only a known request at the exact predecessor address can create a hidden next-chain slot. `source_hidden` consumes the actual supported audited request and its returned slot. It derives that same predecessor branch, distinct protected input and complete appended-candidate poststate. No final history equality, absent alias or successful seal is supplied as a premise.

These equations expose the local facts needed by the full family send trace. They do not infer that a caller-supplied request was reached by the native owner frontend, prove initial owner construction, or claim that every repeated seal has already been assigned to a source-supported ancestor test. Those consuming obligations remain separate. Existing known-input candidate bounds retain the original publication gate and freshness rule; this accounting adds no new compromise exclusion. One known derivation request contributes exactly one candidate and a hidden request zero; all original primitive calls remain, with no additional oracle query introduced by the private audit. The same original deterministic lookup/KDF work remains computation. No primitive algorithm, snapshot or persistence proof is added.
