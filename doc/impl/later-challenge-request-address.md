# Later challenge request addresses

The four modules `RawCtxNativeSendSequence`, `PqxdhLaterChallengePaths`, `PqxdhLaterChallengeOrigin` and `PqxdhLaterChallengeAddress` connect the literal later-record challenge to its selected directional KDF input. The final `material_request` consumes support of the existing full material sampler and the actual saved-descriptor completion. For a true unchanged challenge Post with the original marked target publication, it produces the reached challenge request, its complete source suffix, its pre-send kernel and its exact selected input. The request-time marker, counter and directional path are conclusions rather than supplied certificates.

## The returned number comes from the pre-send kernel

`RawCtxNativeSendSequence.primitive` follows the actual send adapter through its capacity check, KDF, sealing and optional writer result. A returned record has sequence equal to the old kernel counter plus one; the advanced kernel has that same counter. `native` consumes the literal generic native callbacks. The owner, Server, Beacon and LIVE statements carry the pre-step kernel through the existing dispatch and publication code. The generic frontend statements state their operational send law explicitly, and the concrete challenge consumer discharges it with `native`.

A Server peer selected by the public request must therefore have existed in the actual pre-send state. A Beacon must have been established at that same point. Neither conclusion is reconstructed from the final role map, which later source operations can change. Optional rejection, failed writes and unrelated callbacks keep their existing behavior.

## The marker belongs to this challenge request

`PqxdhLaterChallengePaths.sourceHandler` reassociates the existing installation-annotated source state; it invokes the original occurrence compiler and concrete retained callbacks. `source_records` identifies its record branch with the full original LIVE API. `source_step` preserves the previously proved selected-initializer and occurrence-path invariants, and `source_program` preserves the entire operational result and backend state through an arbitrary Post. These are proof annotations over the existing source, not a second adversary scheduler.

`builder_absent` handles the initial Server Builder before the Post. Its literal supplied initializer starts at zero, and its only possible published record is the actual first send at sequence one. It cannot account for a target at any number at least two. Failed publication and arbitrary preexisting unlabelled roles remain permitted; the original publication annotation starts empty and asserts no provenance for those old roles.

`PqxdhLaterChallengeOrigin.source_publication` records the installed marker read before each actual published send. A finish may change an installation marker but cannot add a record publication. `unused_publication` and `used_publication` follow the unchanged challenge wrapper and its sticky competing-publication flag through the whole prefix and suffix. Rejected challenge attempts remain in the trace. An unscreened competing target publication would invalidate that original wrapper event, so it cannot supply the marked target publication in the true branch being analysed.

`marked_request` consequently attributes the final target publication to the actual challenge send and recovers the marker at that request. `request_facts` joins that marker with the source-preserved path and the literal returned-sequence law at one state. `sequence_request` discharges the initial absence and path conditions using the real first Builder, retaining the exact chosen plaintext, public record, adaptive continuation and complete final source state. It does not infer an earlier marker from a later installed owner or identify distinct installations by equal key bytes.

## The enclosing sampler supplies the path

`PqxdhLaterChallengeAddress.sampled_request` consumes the complete annotated source execution for the actual sampled pending cut. At target number `depth + 2`, the returned record gives pre-send counter `depth + 1`. The maintained `LaterSendAddress.marked_address` joins this same-state source kernel with the sampled cursor through one retained parent/child table. It therefore identifies the actual native send input with the next-chain coordinate of the full sampled parent response. Repeated chain bytes are allowed; deterministic walks through one table suffice.

`pending_request` obtains that annotated execution from the literal saved-descriptor resumption and its complete outside Post. `material_request` then consumes the existing `ErasedParentMaterial.prepare` distribution, including the full parent, nonce and next-chain draws. Its result retains the actual pre-normalization source draw, proof that this draw belongs to the original prior, and its complete challenge witness. The normalized earlier cache field is never treated as evidence that a reconstructed starting state was reached. Common and cached outputs keep their existing decisions; this conditional pending theorem does not replace or bound those branches.

The input-alias complement is exactly the existing `LaterInputAlias.collision = false` on this full sampler. It retains absence from the actual earlier-input log and separation from the current parent address. Its previously established probability charge remains separate. These support theorems neither introduce a new security assumption nor cancel any earlier normalization or collision loss.

Focused checks preserve the same source callbacks, optional replies, original Boolean decision, disclosure state and complete shared/private cache. The theorem does not supply a global target/session/position selection reduction.
