## Cryptographic and global limits

The ordinary contracts are the stated joint primitive functional wiring, the native public-point availability/nonzero law on generated scalar inputs, exact native public conversion, logical source erasure, source/codec behavior and the perfect primitive implementations. The source-root comparison with the ordinary real related-Extract endpoint additionally consumes the existing `SourceRootCorrect` fixed Extract/Expand functional equation. These are interface equalities, not new security conclusions or implementation proofs.

The [related-DH Extract game](joint-dh-related-extract.md) remains an explicitly additional security endpoint with an unbounded advantage. Its protected class is actual DH equality and its cache coalesces complete actual input bytes, including alternate encodings and aliases. Public fixed-HKDF/HMAC evaluations and off-class side roots remain real. Gap-DH input recognition, ordinary weak-EUF, collision resistance or uniform-secret-key HMAC PRF does not justify this endpoint's smallness. The new source equations do not change that distinction.

Full dynamic birth and selected-owner routing, source generator order, other Server registration output requests, selected-secret compromise/reveal stopping, the later HMAC hop, global target/session/record losses, ordinary shared-ROM prefix execution and the computational-symbolic event map remain consuming obligations. The primitive game does not expose selected-secret reveals, so the complete source compiler must derive its stopping or freshness treatment before using the endpoint. The stage's optional plaintext remains part of the actual receive interface; confidentiality still requires the appropriate target-plaintext and key-reveal exclusions. Later assigned-ID equality is not inferred. Snapshots, persistence and primitive internals are outside this proof.
