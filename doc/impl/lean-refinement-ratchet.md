# Ratchet observable refinement workstream

The branch audit read the actual extracted phase interfaces, `RatchetExecution`, `RatchetReceiveDriver`, `RatchetEffectRefinement`, `RatchetReceiveIdeal`, `RatchetRoleReachability`, `RatchetLifetime`, and the unchanged `Model/Ratchet`. The positive-sequence receive theorem already relates complete driver results to `Ratchet.recvStep`, including the complete represented poststate and exact rollback on rejection. The send phase theorem relates successful encryption, and its seal-phase invariant already describes the successor state before sealing finishes. The previous mixed-history theorem records arbitrary optional outputs but concludes only lifetime reachability and output length. It provides no ideal observable history.

The remaining behavioral gaps are therefore mixed send/receive trace correspondence, complete send outcome classification, bounded-counter exhaustion, invalid wire sequence zero, and a property-transfer result whose observation abstraction is explicit. Failed sealing is a real semantic distinction: the extracted `SendSeal.finish` retains the advanced state even when returning no ciphertext. The unchanged ideal sender always emits a ciphertext when it advances. The refinement boundary must consequently represent a failed seal as one ideal send whose ciphertext is withheld, while retaining a failed-seal annotation with the consumed index. Treating failure as an ideal stutter would be false. Exhaustion is instead a real stutter, and zero has no valid predecessor in the model's zero-based message space.

`RatchetTraceRefinement` defines complete synchronous API actions, a driver using the existing extracted-phase compositions, an ideal API wrapper, observations derived from actual results and input counters, and finite trace refinement. Successful send observations retain the complete message index and ciphertext; successful receives retain plaintext; receive errors retain the core API's absent-plaintext granularity. Failed seals retain the consumed index; exhaustion and invalid sequence zero are explicitly distinguished. The ideal wrapper must visibly call the unchanged `sendStep` or `recvStep` for substantive operations and may stutter only at the two explicit API boundary cases.

Acceptance requires a theorem for every finite action list and represented entry state, termination and exact equality of the observation list, and the full `KernelRefines` relation for the terminal ideal state. A corollary must apply to arbitrary actual driver evaluations, rather than only a chosen existential execution. Property transfer covers universal finite-trace properties under the documented observation abstraction, together with state predicates transported through `KernelRefines`. Model properties concerning ciphertexts deliberately withheld after seal failure, distinctions among rejection causes unavailable through the API, timing, and unrestricted liveness are outside this transfer class.

The legitimate boundary interpretation consists of one fixed pure KDF request interpreter, the existing AEAD interpretation and decryption-correctness law, successful seal replies equal to that interpretation's encryption, and open replies equal to its decryption on actual extracted request material. Each send may independently succeed or fail. These are primitive contracts, not a premise asserting state or trace refinement. The theorem covers completed synchronous admission/resume/finish operations. Existing cancellation proofs retain their separate coverage; adapter scheduling and actual cryptographic implementations remain outside this workstream.
