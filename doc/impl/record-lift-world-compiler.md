# Dynamic private record source compiler

`PqxdhRecordLiftWorldCompiler` executes the frozen record-lift program with caller-known concrete kernels and private labeled kernels in one dynamic Server peer map and Beacon owner list. A hidden record stores its installation slot and actual labeled source kernel; it does not retain a second concrete hidden kernel. The private state also retains the complete original World seed cache, used-role markers, shared ROM cache, primitive counters, independent raw-attempt counters and produced-frame log, together with a persistent table of complete 76-byte ratchet outputs.

The main result is `initial_schedule_erasure`: interpreting any adaptive `WorldSpec` program from the actual empty compiler state and erasing its private labels/table equals the existing World computation, including its complete result and full native poststate. `run_erasure` applies this equation to the actual frozen `Interface.program` in either mode, retaining environment state `E` and the world-owned ledger. No caller-supplied reachability, noninterference, freshness, key-independence, successful-opening or security-event hypothesis appears in these initial-state theorems. This is an operational source equality, not a cryptographic inequality or a claim that arbitrary predicates on private state are permitted security events.

## Actual storage and installation

`StoredKernel.known` retains a caller-known concrete kernel unchanged; `.hidden` retains the slot and labeled kernel. `resolve` uses the existing persistent lazy seed sampler for a hidden slot and installs the literal role-directed source initializer. Server installation checks initialization, vacant assigned handle and unused role before resolution. Beacon installation checks the actual `initSent` phase and unused role before resolution. Refused requests do not allocate a seed. Successful installations retain the exact Server identity or Beacon shell and preserve every previous record interpretation when the seed cache grows. The private constructor imports its original caller-known peers without imposing a hidden-kernel certificate.

The internal `cachedSeeds` function totalizes the actual partial cache for interpretation, private lookup and opening/sealing. It does not sample or store an independent family. The derived `Scoped` invariant proves that every live hidden label belongs to a sampled slot. `TableScoped` proves the same for every stored full76 answer, and `StoredReady` retains available live-chain/skipped-material references together with the checked source control, counter alignment and material attribution certificate. Those facts exclude the unused-slot default and unavailable-reference fallbacks at actual reachable hidden callbacks. Seed-cache extension and table extension preserve the interpretation of every unselected peer and owner.

The `origins` map is computed from the actual stored kernel constructors. The existence lemmas tie each hidden tag to an actual peer or established owner. Local owner execution preserves the slot tag. This package does not yet prove a complete compiler-schedule equality with the separate `Origins.annotate` wrapper or transfer its global per-role uniqueness theorem to these derived maps. `Good` records common slot membership, not the physical Server/Beacon direction orientation of every later live coordinate; that additional global orientation theorem must follow from installation and the existing local coordinate-preservation laws.

## Literal ordinary-record execution

Hidden sends and receives execute the existing labeled `ChainCompiler` drivers over the complete source control state and skipped-material cache. Caller-known kernels execute the literal original native source adapters. `nativeKdf_real` discharges the local compiler's functional KDF response law directly from `World.primitives`; no new KDF contract is assumed. `realPolicy` invokes that actual charged native KDF on every callback, including repeated coordinates, and records the complete returned 76 bytes. Aliasing or equality of concrete keys at different logical coordinates is allowed and supplies no independence premise.

`ownerRun_real` retains the actual optional reply, complete primitive poststate and exact `Native.logged` frame list. A failed opening retains the original source rollback behavior. A send retains source advancement before sealing, including a failed seal. A frame handed to the writer is logged even if the writer returns failure. Hash calls in either direction and public/environment hash calls share the original World ROM cache.

`serverStep_erasure` proves the complete original dynamic Server routing equation. The header router selects the assigned handle before full raw decoding, and the same peer identity supplies AD in the original Server/Beacon order. The immutable local sender remains distinct from the selected peer ID. Uninitialized Servers reject without an attempt increment; missing peers and unroutable raw input increment only an existing Server's raw ghost and perform no primitive work. Selected publication changes only that peer's whole kernel and the Server raw count, preserving every identity and other peer.

`beaconStep_erasure` covers absent handles, all existing inactive tags and established owners. An absent owner has no raw increment. An existing inactive owner rejects raw input with one independent ghost increment and performs no primitive work. Established calls retain the outer identity-key ID as sender, the authenticated control binding as receive target, the stored AD and full source kernel. Publication preserves the shell and every other owner. Inactive registration metadata remains environment-owned and irrelevant to ordinary-record dispatch; exact registration shell installation and transient registration receive remain the existing CE-side source obligations.

## Complete adaptive program and permitted observations

Initial-state source simulation therefore derives its local prerequisites from execution, rather than assuming a well-formed future trace.

`handler_erasure`, `schedule_erasure` and `initial_schedule_erasure` retain the complete original World fields, including hidden seeds and kernels internally.
