# Complete live-finish continuation query accounting

`PqxdhLivePrivateFinishBounds.lean` consumes the concrete scheduler in `PqxdhLivePrivateFinish`, rather than an arbitrary auxiliary post-handler. Its bounds cover the complete adaptive original record/public/current-chain/skipped-key/finish client, every optional reply, repeated requests and adaptive stopping. Native roles, shared cache, joint identity state and private decapsulation history remain inside the interpreted state.

The source client has seven explicit budgets: sends `qSend`, raw receives `qRaw`, caller coins `qCoin`, public commitment/hash requests `qHash`, public fixed-HKDF requests `qKdf`, current-chain/skipped-key reads `qRead`, and native finish attempts `qFinish`. `Bounded` quantifies over every reply continuation for each class. It is an ordinary source query cap, not a premise that accepted requests are honest, that targets are fresh, or that a security event is false. Rejected, inactive and repeated finish attempts all spend the finish coordinate.

`old_uniform`, `old_excluded` and `old_classes` preserve the original source service's exact uniform-query allowance and prove that these record/public/read operations introduce no KEM or private-root request. Public HKDF remains the real fixed function. Its lack of a uniform-oracle request does not erase its source API call or deterministic computation. The same distinction applies to copying a retained chain key and to public byte parsing or lookup.

For a native local-callback uniform cap `qLocal`, and ordinary other-index ML-KEM decapsulation caps `uDecap` and `bDecap`, define `C = max(max(qLocal,64),uDecap)`. `service_classes` combines the original per-operation costs with the checked complete-owner allowance of 69 callbacks, at most one selected logical decapsulation and at most one private root. Every local callback and permitted other-index primitive program retains its own cost; no opaque ambient work is declared free.

`uniform_bill` and `finish_bill` evaluate the seven-class sums. `schedule_classes` applies those exact step bounds throughout the original adaptive scheduler, preserving its arbitrary result and complete final state. Its uniform allowance is `qCoin + 64*(qSend + qRaw + qHash) + 69*C*qFinish`, its ordinary base allowance is `69*bDecap*qFinish`, and its separate selected-decapsulation and private-root allowances are each `qFinish`. The latter are separate source-interface classes, not a claim that every attempt uses both.

`ordinary_step` consumes the previously proved concrete owner routing theorem, which charges at most one ordinary selected-key decapsulation per finish and does not add a second query for its private root. `ordinary_post` then proves the complete public CCA continuation has the same uniform and base bills above and logical-decapsulation cap `qFinish`. This tighter bound comes from the actual routed owner program; it is not inferred by adding the separate selected and private-root caps. The challenge ciphertext remains blocked by the ordinary CCA interpreter, and matching private-root requests consume the supplied candidate internally through the existing routing function.

`total_bound` and `source_queries` count all original API calls, including classes that require no new random draw. The total is `qSend + qRaw + qCoin + qHash + qKdf + qRead + qFinish`. Thus public fixed-HKDF evaluations and every compromise attempt stay explicitly counted even though they do not contribute to the uniform or KEM oracle bill. The ordinary source send/receive derivation, AEAD, commitment and serialization limits remain the earlier record-service bounds; this module does not substitute these uniform/KEM counts for those distinct component budgets.

These are syntactic oracle-program bounds under all replies. They do not transport a budget through a mere equality of evaluated marginal distributions. They require no key independence, public-key injectivity, freshness or cryptographic assumption. The callback and primitive caps refer to the actual supplied programs, and the theorem keeps their costs visible.

The continuation begins with the same already-created finite owner family and private pool as the operational scheduler theorem. Actual owner creation, identity creation/signing/conversion, preconstructor and registration work, private identity/KEM/root disclosures, generator reservation and all challenger sampling still require their separate enclosing source bills. No creation work is included in `qFinish`. Full interleaved creation/reveal/decapsulation history, target-slot selection, authenticated challenge origin, source input/context nonexposure, and the global common experiment remain consuming obligations. No snapshot or persistence semantics is added.
