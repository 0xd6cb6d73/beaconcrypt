# Actual plaintext from matching source production

`RawCtxSelectedPlaintextOrigins` closes the functional plaintext step left by the accepted-record classification. The ordinary integrity observer detects an accepted fresh full CTX tuple. When a tuple matches an earlier seal, arbitrary oracle replies alone do not establish that the returned plaintext equals the earlier input. This module uses the actual dynamic CTX interpreter and the existing ordinary AEAD opening-correctness contract to prove that equality. It does not assume a protocol-origin theorem or introduce a security advantage.

`HistoryCorrect` records ordinary opening correctness for each issued ciphertext. `AttemptCorrect` says that every successful optional reply matching a seal in that attempt's saved history returns the same plaintext. `LocalGood` and `Good` additionally align the observer's seal history with the actual selected interpreter history. These are functional invariants over the executed source, not authentication, freshness or secrecy assumptions. `initial_good` proves them for the ordinary empty observer/component state for every selected key. The continuation theorems accept the same invariant at an arbitrary nonempty prefix, whose actual initialization must supply it.

`matching_open` recovers the typed nonce, AD and retained ciphertext fields from the full tuple equality. A successful commitment check then uses the existing `Pqxdh.Crypto.aead_open_seal` functional contract through the issued-ciphertext invariant. The returned plaintext is the actual opening result. No hidden plaintext is added to the adversary's target and no primitive implementation or internal algorithm is proved.

`raw_good` proves that the concrete selected raw service preserves these invariants. Malformed requests still record their actual rejected attempt. Parsed requests perform the original shared-cache commitment lookup and retain its result, including failed checks. Successful matches use `matching_open`; every earlier attempt keeps the history that existed at its own time. `seal_good` proves that a real successful seal adds the same ciphertext/plaintext pair to both histories, while nonce refusal changes neither. The full optional result, local state and cache are preserved.

`step_good` covers every branch of the actual dynamic-key component: selected raw delivery, sealing, randomness, public hashing and known-key work. Known keys may have equal bytes; the theorem does not exclude aliases or infer independence. `schedule_good` preserves the invariant through the complete adaptive schedule. `monitored_good` consumes the exact existing executable-monitor interpretation, retaining its full observer and selected/known-key source state. `audited_good` then consumes the concrete production audit's erasure theorem, so the result applies to the original adaptive record/reveal client with its actual optional stopping and source observations.

`trace_attempts` proves that the chronological source audit retains each earlier opening receipt. `current_correct` combines that fact with the actual interpreted run: at any stored source-query position, all attempts through that call have correct matched plaintext, and all seals available before the call came from the retained initial prefix or a strictly earlier actual source send. The support of that source trace is derived from execution through the concrete interpreter, rather than assumed as a separate callback or origin premise.

`record_payload` verifies that the component target retains exactly the decoded `C || T || commitment` payload. It says nothing about uniqueness of the enclosing Cap'n Proto serialization. `matching_plaintext` takes the matched branch produced by the actual acceptance classification and recovers an earlier entry with the exact returned plaintext, AD, sequence, encoded sender and decoded ciphertext payload. `current_matching` combines that conclusion with the actual adaptive source audit and supplies that same entry's strictly earlier source-production witness or retained-prefix witness. Thus plaintext and source origin refer to one entry, rather than independently chosen equal-looking records.

The resulting origin is still inner cryptographic production. The earlier send witness retains the actual optional writer, including `None`; the native codec contract is described in [the seal production guide](selected-seal-production-receipts.md). The source receipt does not identify installation, session, direction, API target or receiver merely because key bytes and CTX fields match. The corrected eleven-field registration session and successful publication remain separate source-lineage obligations, and injective correspondence still requires the original consumption/replay result. Claimed routing IDs are not equated with server-assigned IDs.

These thirteen statements add no oracle operation or reduction loss. They retain all attempts and do not select another raw target, so they add no second `qRaw` factor. Existing exact monitor/audit query equivalences and the separate private KDF, known-key, setup and initialization bills remain unchanged. The selected-key distribution in the complete context, known-key alias/probe and reveal accounting, retained private KDF-table to real fixed-HKDF hop, nonce-risk charge and finite global selection reductions are still required for a production security bound. Public fixed HKDF evaluations remain real. Snapshots, persistence and primitive internals are outside this work.
