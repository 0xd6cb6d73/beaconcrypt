# Private installation provenance for the executable record world

`PqxdhRecordLiftOrigins` adds a private provenance map to the executable `PqxdhRecordLiftWorld` without changing its interpreter. Each Server assigned handle and Beacon owner handle may carry a hidden slot label. The wrapper first runs the literal World query, then updates provenance from that original request and its actual reply. Successful hidden installation records its slot; successful caller-known installation records no hidden slot; refused installation leaves both maps unchanged. Appending an owner clears the returned new handle's hidden annotation. A `none` annotation means no hidden provenance, not that the record object is absent.

No key-byte comparison classifies an object as hidden. The two roles may share a slot, as intended by the persistent paired seed. Within one role, two different handles cannot carry the same hidden slot. This property follows from the World's executable unused-role check: each successful hidden installation consumes its role marker, and later operations preserve that marker. `reply_facts`, `annotate_marked`, and `annotate_unique` expose these steps. `initial_schedule_facts` proves consumed-role attribution and per-role uniqueness for every supported result of every adaptive WorldSpec program from the initial state, without a reachability or secrecy hypothesis. Arbitrary-state versions state their initial marker and uniqueness premises explicitly.

`handler_erase` identifies the entire query reply and full original World poststate after dropping provenance. `schedule_erase` lifts that equality through every adaptive continuation, including the frozen Interface program. It retains seeds, kernels, shared ROM cache, exact optional replies, produced frames, raw-attempt counters, effect counters, and underlying uniform instrumentation. The wrapper adds no oracle query and replaces no sampler or primitive. These equalities concern the internal execution; provenance and the full private state are not additional adversary observations. The permitted security projections remain World.observed/analysis and the eventual source event definition.

`server_success`, `beacon_success`, `server_refused`, `beacon_refused`, and `append_result` give exact annotation updates from actual supported replies. The successful hidden-install laws additionally tie the installed initial source kernel to the very seed stored under that slot, while retaining the supplied Server identity or Beacon shell. This is an installation-time fact. Ordinary record evolution can subsequently change the kernel.

This module does not yet replace private concrete kernels with logical chain or material coordinates. It does not prove that all tagged objects still exist or remain established after an arbitrary later schedule, a source compiler simulation, a source target-freeness condition, or a record-security game bound. Those joins must track actual record evolution and source observation erasure. The existing World and CE boundaries also remain unchanged: C1 source-game equality and exact registration shell correspondence are separate obligations; C5 session selection remains on the CE side. No equality of seed bytes or ciphertext bytes discharges provenance or declassification obligations.
