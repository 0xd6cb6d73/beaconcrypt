# Source send attribution for record origin

`PqxdhRecordFactsOriginSend` closes the local selected-coordinate attribution obligation left by the buffered-origin helper. Its seven statements cover actual source kernel sends, actual owner sends and the complete source owner-send command through its publication callback. They do not yet prove the global adaptive origin theorem.

`Claims control label tag` means that the tag names an actual handle whose currently installed hidden slot and physical sending direction agree with the label. `sending_claim` derives this relation for the actual selected sender coordinate from `handleKernel`, the real control lookup, and the existing source `Safe` invariant. It does not assume that a selected record has an honest origin or that an attacker-selected key is honest. `claims_step` proves that later source control transitions retain established claims by preserving installed slots and physical handle roles.

`kernelSend_buffered` follows the actual hidden source send through its exhaustion decision, source lookup, sealing callback and optional writer result. It uses the source admission theorem to identify the selected coordinate with the kernel’s current sending coordinate. The actual lookup keeps dictionary and writer-log fields, while the actual sealing callback supplies the exact pending frame and dictionary entry. `kernelSend_source_buffered` discharges the local coordinate/tag premise using the real handle lookup and `sending_claim`.

`knownSend_closed` proves that a send on caller-known material retains all previously attributed hidden dictionary entries. The native send still executes and retains its primitive effects and writer buffer; the proof only observes that the hidden dictionaries and already tagged produced log remain unchanged. `ownerSend_buffered` combines the hidden and known paths with empty-plaintext rejection, using the actual owner kernel. `ownerRun_send_closed` then follows the source’s publication callback: every newly generated hidden dictionary entry has a matching frame in the produced log with the actual caller’s handle tag, and the literal pending log is empty afterward. Writer failure still generates the pending and then produced frame when the sealing callback generated a record; it does not become a successful public ciphertext.

The preconditions are the local induction invariant for existing dictionaries, the source control `Safe` invariant, the actual stored owner/kernel lookup, and replay/random ideal modes where dictionary semantics are used. These are explicit induction inputs. The [global source invariant](record-facts-origin-invariant.md) establishes and preserves them from initialization; no theorem here treats them as primitive security assumptions. Caller-known sends require no ideal-mode premise. No new primitive or codec contract is introduced, and no freshness, collision, publication-probability or query-budget premise is used.

All seven declarations have exact checked axiom guards permitting only `propext`, `Classical.choice` and `Quot.sound`. The proof reuses the independently reviewed replay, dictionary, service, buffer and handle modules, plus the checked exact source lookup-preservation helper from `PqxdhRecordFactsOriginReceive`. Global handler preservation and actual kernel receive-origin witnesses are established by the companion modules. Accepted-transcript retention and the probability bound for never-published frames remain separate obligations.
