# Review of the ML-DSA source pins

The source-fidelity repair reviews the changes from `248953c9` through `57292b04` before renewing the seven legacy ProVerif drivers' whole-file source hashes. The classical models and their query formulas remain unchanged. Their source pins are tripwires for the reviewed projection, not a semantic proof that the current ML-DSA implementation has exactly those traces. The shared checker now requires the existing `legacy_profiles.scope=classical_projection:MLDSA_guards_not_globally_lifted` marker, and the seven drivers' verdict-classification rows explicitly carry this limitation. Removing or promoting that scope fails a regression test even though ProVerif ignores its comment syntax.

## Reviewed correspondence

| Source change | Preserved projection | Additional current behavior outside the legacy model |
| --- | --- | --- |
| `Beacon::get_registration_bundle` | The three Ed25519 signing calls still sign the typed prekey, one-time key and ML-KEM public key in that order. Successful serialization still precedes publication of `InitSent`; the original single-use lifecycle remains. | Independent ML-DSA identity, transcript construction, signing, public key and signature fields, retained request digest, and their failures. |
| `Server::get_shared_secret` | After the added ML gate, typed Ed25519 decoding and signature checks, the identity/one-time replay identifier, four DH contributions, ML-KEM input, root-input ordering, root derivation and replay-set insertion are unchanged. | Self-presented ML key verification and both public-key fingerprints precede the classical projection. Admission does not bind that key to an enrolled Ed25519 identity. |
| `Server::build_registration_response` | Candidate validation, available assigned ID, initial ratchet derivation, nonempty key-ID-bound plaintext, CTX sealing, and installation only after successful encoding retain their order. | The token's server-ML fingerprint prevents retargeting, the AD contains both fingerprints, and the response is signed before encoding or publication. Failure of these added steps prevents publication. |
| `Beacon::finish_registration` | The original terminal-abort lifecycle, DH/KEM root-input construction, pinned Ed25519 check, initial ratchet, sequence-one receive, authenticated assigned ID and establishment retain their relative order. | The pinned ML server key and retained request digest authenticate the whole response before DH/KEM. The same two ML fingerprints enter its AD. |
| `pqxdh.rs`, `shared.rs`, and the core AD builder | Classical public-key encodings, KDF domains and the first 153 AD bytes retain their values and order. The adapter's ratchet callbacks, counters, receive windows and failure rollback are unchanged. | Current AD is 281 bytes and CTX is 357 bytes; the appended ML-key fingerprints are used by both AEAD and CTX. Legacy symbolic AD omits these fields. Native known-answer changes are independently tested, not justified by the symbolic projection. |
| `EstablishedRemote` | The existing peer identity and ratchet getters retain their meanings. | A public ML-key fingerprint is retained with the peer and exposed by the server's new getter. It is public authentication metadata, not a KDF secret. |

The seven renewed driver families are registration provenance, delayed response, near record origin, tasking origin, trusted-application secrecy, exact-interface strong secrecy, and exact-far material. The latter's core ratchet/refinement inputs are unchanged; only its adapter source tripwires changed. No model constructor, equation, reduction, process, query, expected polarity, replay argument or security assumption is changed by this pin review. In particular, an attack or reachability witness in the classical projection is not asserted to be executable through the new mandatory ML-DSA guards. Conversely, a successful projected security query alone does not establish full-implementation ML-DSA security or a trace simulation.

The `symbolic-name-order.py` pin is renewed for the unchanged placement of ephemeral-key generation and encapsulation after the classical admission checks and before their first DH/KEM use. Its complete-continuation comparison still concerns the two unchanged symbolic server macros. The new ML checks execute before this source boundary; no reordering across them, no native sampler equivalence, and no failure or timing equivalence is inferred. Its checker also requires the explicit classical-projection scope.

The separate getter-profile pin is reviewed against the four declared secret fields: Ed25519 identity, ML-KEM key, prekey, and one-time key. Their signatures and complete state-dependent bodies are unchanged; the existing exhaustive 20 beacon-phase cases and live server-identity case still apply. C and Python changes add constructor inputs and public ML-key getters, without adding a secret-field getter. The new ML-DSA private identities and persisted seeds are outside this four-field table, which is not an exhaustive inventory of all secrets or a compromise theorem.

## Validation

All 22 `beaconcrypt-core/proofs/pro-verif/test-*.py` suites pass, totaling 387 tests, and all nine getter-profile tests pass. This includes the new scope-removal and scope-promotion regressions. The classification checker accepts all 3,236 expected verdict rows with unchanged formulas, statuses and class counts; only the 39 reviewed legacy rows gain the explicit scope prefix. Both complete symbolic name-order continuations and the exhaustive 21 getter-availability rows pass their direct checks. Black formatting and `git diff --check` pass.

Existing mutation controls continue to reject changed source bytes, signature purposes, publication lifecycle, model terms, query formulas, and verdicts. The coordinated full run supplies passing Rust transcript-fidelity, regenerated-proof and complete ProVerif receipts. It completed every pre-Lean gate before exiting with status 2 on thread-creation resource failures; a subsequent locked toolchain, Lean and inventory retry passed without source changes. [The audit repair record](mldsa-audit-fixes.md) records the combined receipt. This review does not replace the independent ML-DSA authentication/joint-session ProVerif results or the deterministic AD/CTX source-refinement migration.
