# Actual source callbacks in the selected CTX interpreter

The saved source continuation needs more than record opening and sealing. It may prepare another Beacon registration, retrieve its optional application data, initialize a new ratchet, query the private identity/KEM selector, allocate storage, erase a temporary buffer, or serialize a response. `PqxdhSelectedCallbackCompiler` keeps these as an explicit external service beside the dynamic CTX interface. Its executable lowering never accepts the selected message key. That key appears only in the evaluated component interpreter used to state the source comparison.

`local_native` identifies each external callback with the original audited source callback. `callback_source` then compares its complete evaluated reply and source state through the same CTX interpreter. The projection removes only added component bookkeeping. It keeps the shared auxiliary state, private KDF store, chronological input log, private identity/KEM state, retained root cache and root/two-chain audit. Initialization uses its dedicated audited operation: projecting only its optional kernel without appending the actual candidates would be incorrect. Failed optional outcomes remain ordinary source outcomes.

`PqxdhPreparedSelectedCallbacks.source_step` instantiates that equation with the actual source preparation, application getter, retained initializer, private selector and publication dispatch. Preparation and application use the already proved source factorization through their cache-free interface, which retains every local/private effect and every permitted decapsulation outcome. Selectors retain their identity and root-cache effects. Publication uses the actual local validation/allocation/erase/writer dispatch. These statements do not assume arbitrary callbacks are independent of selected material or the CTX cache. Their concrete typed source factorization supplies the relevant restriction.

The query accounting is also concrete. `callback_no_hash`, `callback_uniform` and `callback_bills` forward every original uniform call and make zero commitment-hash, selected seal or selected raw-opening requests. The five source categories retain separate allowances. `PqxdhPreparedSelectedCallbackBounds` consumes the authenticated source certificate: preparation and application each cost at most `C = max(qLocal, 64) + qDecap`; retained initialization costs at most 32 uniform calls; the selector costs at most `D = 34 + qBase + qDecap`; and actual publication costs at most `qAux`. Here base and decapsulation costs are the original interpreted source callbacks, including their complete randomness. The source environment in this consumer explicitly installs `PqxdhSourceAuxiliary.server callbacks`, so the auxiliary allowance cannot refer to an unrelated environment implementation. These are per-request bills; the outer scheduler must still count each category's adaptive invocations.

This package contains eleven guarded statements across three modules. It is an operational callback simulation and resource consumer. It does not yet establish the entire saved Post/Builder continuation, the full multi-session selected-message reduction, nonce-stop probability, or the implication from the original global freshness event. The chain-label representation used by the earlier evolving-chain cut remains distinct from the opaque message-material representation used by the CTX compiler. No primitive implementation proof, public-HKDF random-table interpretation, new cryptographic premise, snapshot behavior or persistence assumption is introduced.
