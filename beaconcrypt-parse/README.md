# Beaconcrypt transport parser

`no_std` Rust codecs generated by EverCDDL/EverCBOR from [transport.cddl](schema/transport.cddl), with handwritten complete-input decoders and size-checked encoders. Exact encoded-length helpers and the complete-message size policy come from `beaconcrypt-core` and are re-exported here. The `beaconcrypt` adapter uses this crate for all transport messages.

The inclusive limit is **32 MiB (33,554,432 bytes) per complete encoded message**, including CBOR framing, authentication tags, and commitments. It does not limit plaintext snapshots or JSON state. Registration responses carry raw `ciphertext || tag || commitment`, with implicit sequence `1` and the pinned numeric server ID.

Registration messages use wire version `3`. Requests encode `[3, 0, identity-key, pre-key, one-time-key, pq-key]` as a six-element array; responses encode `[3, 1, identity-key, ephemeral-key, kem-cipher-text, app-cipher-text, key-id, signature]` as an eight-element array. The mandatory Server ML-DSA-65 signature is exactly 3,309 bytes. The remaining request fields retain their attached Ed25519 signatures. Complete requests occupy 1,490 bytes. Previous registration versions are rejected. Data frames retain their existing wire version `1` encoding.

`encoded_init_len` takes four byte lengths in identity/prekey/one-time/PQ order. `encoded_response_len` takes five byte lengths in identity/ephemeral/KEM/application/signature order and a separate numeric key ID. These helpers include every field and canonical CBOR header in the complete-message limit. The parser checks syntax and fixed widths; callers verify signatures and cryptographic identities.

Decoders apply a bounded, nonallocating flat-shape check before generated validation. Encoders reject oversized results before writing; other failures may modify the caller's output buffer and return zero.

Run from the repository root:

```sh
cargo check -p beaconcrypt-parse --locked --offline
cargo test -p beaconcrypt-parse --locked --offline
cargo fmt --all -- --check
cargo clippy -p beaconcrypt-parse --all-targets --locked --offline -- -D warnings
cargo mutants -p beaconcrypt-parse -C=--locked -C=--offline
```

Generated files reside in `src/generated/`; [provenance and regeneration commands](generated/README.md) use the pinned tool bundle through `scripts/regenerate.py`. Normal builds require no generator. Workspace mutation configuration excludes imported generated sources and includes handwritten code.

Imported sources use [Apache-2.0](generated/LICENSE); handwritten files use [0BSD](LICENSE-0BSD).
