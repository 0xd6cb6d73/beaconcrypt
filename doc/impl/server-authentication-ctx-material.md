# Exact material interface for Server authentication

`PqxdhServerAuthCtxMaterial.lean` connects the B8a key-schedule output to the source factor used by B8b and supplies the selected CTX key's exact sampling order. The eight statements are functional and distribution equalities plus a query bound; they add no primitive-security assumption or reduction loss. They are a supporting interface for B9b, not the completed authentication reduction.

The key schedule returns one complete 76-byte first ratchet-step output and the other 32-byte initial chain. `factor` converts the full response to the extracted `RatchetKdfResponse` without changing its bytes. `initializer_prefix` uses the existing fixed HKDF source's prefix contract to identify the 64-byte initializer with the first 64 bytes of the same stream. `initial_chains` retains both actual directional projections. `factor_source` consequently identifies the complete B8a result from a root with the exact `PqxdhServerAuthSendFactor.factor` used by the source build. No new HKDF call, initialization nonce or independent projection is introduced. `factor_decoded` identifies the source decoder's next chain and key/nonce material.

The executable residual consists of the 12-byte nonce, 32-byte next chain and 32-byte opposite initial chain. Only the mathematical `output` reconstruction takes the selected 32-byte key. `output_decoded` shows that decoding this reconstruction yields the known next chain and the existing hidden-material marker with the same nonce. Marker syntax does not exclude known byte aliases or establish source-context secrecy.

`key_first` reuses the existing complete 76-byte split and swaps independent uniform draws over the whole evaluated continuation. The result is exactly an ordinary uniform 32-byte challenger key followed by the residual's uniform 76 bytes. `key_first_context` preserves an arbitrary separately sampled complete context and moves that sampling after the challenger key as well. Both equalities quantify over the full continuation and every output type; they are not marginal-key equalities and do not condition on successful protocol execution. They do not justify applying the uniform hybrid to an arbitrary correlated source state: the actual B8b source factorization and selected-entry coupling must supply that distribution first.

`residual_bound` charges 12 + 32 + 32 = 76 direct uniform-byte queries to the executable. The ordinary challenger separately supplies its 32-byte key. Source-context preparation, public hash/HMAC/HKDF calls, record queries and other local work retain their own complete bills; none are declared free by this result.

The two distribution statements use the repository's existing discrete `𝒮` interface, suppressing only its deprecation diagnostic locally. All eight axiom guards remain enabled and report only the standard Lean axioms. This package does not yet compile the adaptive hidden build/receive callbacks to the CTX challenger, prove the selected seal/raw budgets, or bound the original entry-authentication event. Public HKDF evaluations remain real, and serialization, persistence and primitive internals remain outside the approved scope.
