# Completing saved later-record schedules through the CTX interface

The three `PqxdhLaterSavedPost` modules connect an actual saved record, Beacon finish or initial Server builder to the maintained adaptive Post compiler. The selected CTX interpreter keeps its complete state throughout: its shared hash cache, selected nonce history, previous opening attempts and known-key state are not reset when the saved request completes. These are operational source and query-count results. They do not establish later-record secrecy by themselves.

`PqxdhLaterSavedPostCompiler.record_evaluated` executes the saved record and then all of its original outside program in that same interpreter. `finish_evaluated` does the same for a saved Beacon opening, preserving the original binding, sequence, terminal-state and publication decisions. `builder_evaluated` retains the known predecessor seal, source erasure, optional second serialization and Server reinstallation before continuing the original Post. An optional writer failure remains a source result. The separate outer `Option` remains the existing compiler refusal and is not converted into a writer failure.

`publication_source` discharges the builder's local callback comparison using the original source callback interpreter; it does not assume an arbitrary callback preserves the cache. The complete callback poststate is retained in the executable program. Only the source-comparison projection removes component bookkeeping. `prepare` then packages each actual saved request's original outside program with its reached instrumented state. `complete_evaluated` proves that this exact state feeds every subsequent request. `source_complete` identifies its projected source continuation with the already proved `PqxdhLaterSavedContext.complete`. Neither the original Boolean result nor any later origin or publication trace is replaced.

The maintained instrumented Post implementation has an auxiliary Beacon monitor. The new compiler accepts its index explicitly. The source projection ignores those extra monitor fields, and none of these statements uses them to identify the selected record or assume it is the first Beacon record. The underlying descriptor, role, record position, complete source state and original publication trace determine the execution. No new family scheduler is introduced.

`PqxdhLaterSavedPostComparison.original_source` preserves the complete saved-source distribution after interpreting the hidden material and projecting the additional ledger. `original_good` gives exact event equality with the maintained augmented CTX interpreter when the event retains the actual absence of hidden-material disclosure. `record_post_good` is the corresponding direct record specialization. `augmented_bound` and `source_bound` charge the actual sticky nonce-refusal flag of the same reached continuation, with coefficient one. No nonce-uniqueness assumption or successful-receive premise is introduced. The event restriction is displayed explicitly; proving that the desired original finite-lineage secrecy event implies it remains a separate consumer obligation. The refusal probability is not asserted to vanish.

`PqxdhLaterSavedPostBounds.publication_bound` retains the source erasure and optional writer while proving they use none of a specified component class when the actual source-local interface has that property. `prepare_bound` gives the saved request a conservative cap of one such request. `prepare_post` obtains the full outside program's `qPost` allowance from the same descriptor's `Fits` certificate for every syntactically possible reply. `complete_bound` combines them, including attempts before failures or refusal. Finally, `component_bills` discharges the callback premises concretely for selected sealing, selected raw opening and public hash requests. Each complete continuation has cap `1 + qPost` for each of those three classes. These are conservative separate class bounds, not a total-call or running-time bound.

The forwarded source coins, native primitive calls, private lookup work, codec work and earlier preparation keep their original resource accounting. This package introduces no new random draw and does not call that surrounding work free. The previously established later sampler's 184 pre-key bytes and separate 32-byte selected key draw are unchanged. A global uniform/base ledger must still include the actual source callbacks and all of the sampler, rather than infer it from the three component-class caps.

The executable definitions have no explicit selected-message-key parameter; only their mathematical evaluation and source comparison receive that key. This interface fact permits arbitrary correlations and equal known-key bytes in other supplied values. It does not itself prove independence, nonexposure or target/parent address separation. The source descriptor's `Fits` evidence is a structural resource certificate; the earlier actual-sampler support theorem supplies it on reached source states. The enclosing ordinary reduction still needs to carry that evidence through the exact sampler without an undecidable branch or a new adversary restriction.

The remaining event composition must retain the complete/cached outcomes, apply their separately proved common-mass bound, join the original lineage/freshness checker, account for target/parent aliasing and source nonce risk, and identify the final CTX observer. The capability scope is that of the existing source Post interface and its original certificate, not unrestricted dynamic registration. No snapshot, persistence, serialization-implementation or primitive-implementation claim is made. All sixteen public statements have standard-axiom guards.
