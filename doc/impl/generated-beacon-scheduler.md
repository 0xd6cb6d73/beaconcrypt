# HB-97: generated Beacon in the native root scheduler

The computational experiment now installs its freshly generated Beacon inside the private generation continuation. It retains the original identity → prekey → ML-KEM → one-time generation order and the three source signatures, runs the optional Phase1 writer, publishes InitSent only on success, then gives the public program its actual entry reply. The same reached state feeds the original Server acceptance/root derivation, response builder and later record/public/reveal scheduler. This closes the fixed-existing-role limitation of HB-96 for this one newly generated Beacon. It does not yet add the native Phase2 completion API, dynamic repeated registration, the remaining compromise/restore capabilities or the final KDF/CTX/symbolic composition.

The eight new modules contain 59 guarded statements. The two handle-disjointness statements use no axioms. All other reported dependencies are subsets of Lean's standard `propext`, `Classical.choice` and `Quot.sound`. No primitive or protocol axiom is declared.

## Concrete loss and query ledger

The checked distinguishing bound is one constructed joint Ed25519/X25519 weak-EUF advantage plus one constructed ordinary ML-KEM IND-CCA advantage. The comparison world retains one common challenge shared secret for matching private roots and all real public fixed-HKDF evaluations. This is not yet a bound replacing the protocol root or evolving record keys by independent random values. That requires the actual-joint-sampler Extract and ordinary HMAC reductions in the same extended experiment.

The actual prefix sampler allowance is `32 + qPrekey + qKeygen + qOneTime + qSource + qWrite + Q + U + 64(S+R+H) + qBase*qB + qDecap*qD`. `Q` counts every forwarded selector request. `U`, `S`, `R` and `H` are the source coin, send, raw-receive and public-hash allowances. Using the entire compiler bill as a selective coin cap is conservative: it may overcount other requests but drops none. The source signing allowance is three; the unchanged declared-class law retains the original logical-decapsulation allowance `qD`.

The native continuation adds `uEphemeral + uNative + 64 + 5*qAux + U_post + 64(S_post+R_post+H_post) + qBase*(bEphemeral+bNative)`. Every actual generator, base handler, decapsulation, Phase1 writer and auxiliary callback has its own explicit interpreter bound. The five auxiliary handlers and all nine native response categories retain the HB-96 one-call allowances. Native record work retains the existing `S+51*R` KDF, `S` seal, `R` open, `S+R+H` hash and `S` frame-writer bounds; public HKDF requests remain real. Uniform requests are oracle calls over specified finite ranges, not entropy bits, runtime or generic byte-work. Signing, verification, DH, parsing, allocation, fixed HKDF and storage work are not thereby declared free.

## Contracts and remaining work

The primitive implementations are assumed correct at their exact stated interfaces; no primitive internals are proved. The authentication endpoint explicitly includes the Ed25519/X25519 joint-use interface, rather than inferring converted-DH access from ordinary EUF. The ordinary KEM endpoint uses explicit recipient correctness, functional decapsulation and native/ordinary honest-key compatibility. Attached-signature wiring and the actual source generator interfaces remain explicit contracts. Generation and signing here use the existing total legal-input model; this does not independently model every native optional library/entropy/allocation failure before the post-signing adapter. The optional Phase1 serialization failure itself is modeled exactly.

The packed writer is a supplied optional callback with exact signed-field arguments and ordering. Its byte relation to Cap'n Proto, and the full primitive/codec/allocator/compiler/runtime boundary, retain their explicit source contracts. The handle-erasure theorem preserves complete represented state but does not yet interpret a new private Phase2 identity/KEM service. Existing shared CTX uses the explicitly stronger classical random-oracle interpretation; it is not inferred from BLAKE2b collision resistance. Persistence integrity, rollback resistance, linearizable CAS, crash behavior and ownership remain deployment premises; an unkeyed snapshot digest supplies none of them.

The fresh generated Beacon is installed before adversarial scheduling, but the currently exposed native capability family still implements established record/public/reveal operations. Native `finish_registration` and its early abort, identity/KEM/root reveals, copied/restored snapshots, final exposure filtering, evolving input secrecy, common multi-session target selection and the persistent ProVerif projection remain required next steps. HB-95's authenticated initial sequence-one rule is unchanged. No later assigned-ID equality or full-response-byte injectivity is asserted.
