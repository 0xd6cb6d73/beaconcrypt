# HB-113: live raw-source interfaces

Five modules add 43 guarded statements connecting actual live execution to the existing raw CTX components. These are complete program, distribution and source-field equalities. They add no primitive security assumption or statistical loss. They do not yet connect the HB-112 target-key distribution to a raw-record security reduction, establish replicated registration, or give the missing applied-pi public-observation simulation. Snapshots, persistence and restoration remain excluded.

## Extracted native frame prelude

`RawCtxNativeFramePrelude.payload_exact` consumes the extracted production payload splitter and proves equality with the computational splitter, including rejection at payload length 80 or below and the exact base ciphertext, retained tag and commitment slices. `complete_exact` consumes the extracted complete-input check; nonempty reader remainder rejects. The functional reader retains the actual borrowed slices, root access and scalar getters. Cap'n Proto internals, native representation and compiler correctness remain explicit interface contracts. No canonical raw encoding or encoding injectivity is assumed.

`prepare_exact` composes those extracted operations in production order: empty-input rejection, complete framing, root access, sender pin, payload access, payload admission and sequence. `prepare_success` and `accepted_fields` recover the actual decoded frame, sender, original raw buffer and slices on success. `prepare_normal` and `prepared_exact` justify the normalized optional result from the extracted functions' totality, without conditioning on successful parsing. `prepare_context` proves that the retained native context uses the selected owner's associated data and that same decoded sender.

`continuation_exact` quantifies over the complete continuation of the normalized fields. `receive_source` instantiates it with the existing full receive program. `game_exact` then retains the complete evaluated distribution and final primitive state for any stateful primitive interpreter, with the actual owner's associated-data representation stated explicitly. These equations do not equate parser traversal, allocation, copying or runtime costs, and do not by themselves prove every native cryptographic callback realization.

## Actual selected opening and shared CTX state

`RawCtxKeyFreeDecoder.target_source`, `decoder_source` and `decoder_selected` remove the unavailable message key from the actual selected raw decoder. The target retains the selected nonce, associated data, sequence, sender, ciphertext body, retained tag and commitment. It contains no plaintext. The selected nonce is simulator-side data, not a newly public protocol field; its availability with the target key still needs the actual joint-sampler composition.

`RawCtxSharedSourceOpening.real_complete` reconstructs the real shared-cache handler's entire canonical state while preserving the unused suffix dictionary. `family_complete` retains every other family's entry and the same common hash cache. `reached_source` consumes the actual decoder, selected material and source admission facts to identify a reached opening with that real handler. These equations hold for arbitrary material values and aliases; they assume no independent key family or nonce freshness.

`RawCtxSharedOpeningConsumer` forwards the original raw bytes using only a private material label. `api_none` and `api_some` return the challenger's actual optional plaintext with source metadata. `opening_missing` and `opening_present` preserve the original slot lookup and callback choreography. `finish_source` and `present_source` retain the extracted cached/future finish, rollback, successful publication and the entire component family/cache poststate. RustM failure or divergence is never collapsed into a successful opening or ordinary rejection.

`call_bound` and `opening_bound` state each selected query-class allowance. `opening_bills` gives one component raw-query allowance and zero compiler hash, seal or explicit uniform requests. `family_raw_uniform` separately charges up to 64 uniform byte draws by the real shared hash interpreter. Parser rejection and failures before a reached opening remain source raw attempts even when no component raw request occurs. The existing source KDF, callback and local computation ledgers are retained; these local equations do not declare ambient work free or provide global query totals.

## Adaptive observations and same-run records

The sixteen statements in `LivePublicObservation` compile arbitrary finite adaptive chosen-plaintext sends and raw deliveries into the actual owner source, with separate full optional-plaintext and acceptance-bit receive capabilities. Logging and subsequent public projection preserve the original adaptive result and complete private poststate. The source consumer derives its callback history, decoded records, successful positions and consumed-position invariant from that same run. Both receive modes count as actual raw attempts, including rejection. The [detailed observation guide](live-public-observation.md) explains every statement and the distinction between chosen-plaintext requests and an unknown private honest application message.

This source-to-worker relation remains support inclusion. It is not an assertion that every worker strategy has the same probability law as the source or a proof of the separate symbolic ideal-origin event. Actual evolving-key distributions, private honest-application observations, session creation/selection, reveal-relative target freshness and the cryptographic ideal-to-symbolic simulation remain the next consumers.
