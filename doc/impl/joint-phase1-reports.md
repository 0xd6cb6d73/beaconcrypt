# Phase-1 field origin in the adaptive joint identity experiment

This HB-90 extension connects BeaconCrypt's source-facing Phase-1 field check to the existing adaptive joint Ed25519/converted-X25519 signature game. A candidate contains the four unchanged fields returned by registration decoding: tagged identity, attached prekey, attached one-time key and attached ML-KEM key. The source-facing checker parses the identity, verifies PQ/prekey/one-time signatures in actual server order and checks all signed payload tags and widths. Its event says that an accepted candidate under a created identity contains a message that this identity has never signed and that the identity had not been revealed at this report. The general theorem does not assume that the selected candidate is honest, that no earlier signatures or DH observations exist, or that a single bundle was the only signing attempt.

For at most `N = count + 1` generated identities, `PqxdhJointPhase1Reports.fieldOrigin_advantage_le_sum` bounds the probability of any such report by the sum of `N` explicitly constructed joint-use weak-EUF advantages. The constructed adversary is the existing `globalReduction`, applied to `routedAdversary`, the public first-report `reportExtractor`, and this module's `routedClient`. There is no field-selection, report-position or additional session factor. The endpoint still has ordinary fresh-message signature verification as its winning event and the explicitly stronger chosen-input optional static-DH auxiliary service. This proof neither assumes a protocol-authentication conclusion nor proves a primitive algorithm or implementation.

`candidateFields` splits the three original attached buffers in PQ/prekey/one-time order. `acceptedFields_valid` uses the existing exact acceptance witness to show that every such field verifies under the decoded identity. `selectUnissued` searches those original fields against the complete actual signing-message history; it never manufactures a message or signature. `selectUnissued_none_iff` characterizes its rejection exactly, including a new signature on an already signed message. `selectUnissued_some` retains original-field membership and full-history freshness. `selected_weak_euf` therefore gives the ordinary joint endpoint winning event for the chosen field. `candidateFields_length` bounds the search by three fields; it does not enumerate a message space.

`translateReport` uses a generated index's publicly observed key and actual signing history. It first requires acceptance under that exact key and then chooses at most one original unissued field. Missing indices, missing public keys, malformed or invalid candidates, candidates under another identity and candidates containing only already signed messages produce no forgery report. They still occupy an original source attempt. `translated_index` preserves the reported generated index. `translateReport_event` proves that the existing report-time signature predicate on the translated forgery is exactly `FieldOriginFailure` on the original candidate. `candidateAccepted_iff` exposes the same equality as a public Boolean detector. Identity freshness is checked at that report; later compromise remains allowed.

The public `Monitor` records the actual public identity/history snapshot, a sticky event bit, a counter incremented on every original query and every original candidate observation. Each observation retains its pre-request counter value, unchanged candidate, optional translation and acceptance result. These positions preserve rejected and unforwarded candidate attempts among the complete identity-operation transcript, while list order retains the order of all reports. The monitor never obtains a generated seed except through an actual source reveal request.

`wrapper` forwards every original creation, signing, optional DH, reveal and uniform request unchanged. A candidate report forwards at most one existing signature-report request and always records the original attempt. `run_complete` proves equality of the complete linked execution and the existing reporting experiment after only reassociating products. It retains the full generated private source, all signing/DH/reveal history, original candidates, positions and arbitrary later continuation. The source definition here is this explicit linked instrumentation; the theorem does not assert an independent Cap'n Proto/native protocol implementation equality.

`wrapper_source_preserves`, `sourceImpl_preserves` and `run_compatible` prove that the monitor's public snapshot and sticky event agree with the actual reporting interpreter throughout every supported execution. `run_event` transports the original field-origin event to the same signature experiment using that full-state invariant. `wrapper_observation` proves exact counter, original-observation and sticky-bit updates. `wrapper_occurred`, `wrapperRun_occurred` and `run_occurred` identify the final bit with an accepted original candidate observation, including executions that continue with later compromise.

`source_attached_adapter` derives the complete attached-verification interface from the already stated joint `SourceWiring.verifyAttached` law together with rejection of buffers shorter than the sixty-four-byte signature prefix. This extra premise is the ordinary functional signature-format behavior, not a security assumption. `sourceAccept` follows the source's verification and core-parser order on arbitrary decoded field bytes. `sourceAccept_eq` proves equality of its complete optional result with the existing detached acceptance endpoint under that functional adapter law, covering short and malformed input. Actual Cap'n Proto decoding, complete-input treatment, decoder field provenance and native optional-error instantiation remain separate adapter obligations.

`singleBundle_unissued` and `singleBundle_fieldOrigin` connect the earlier exact three-message source result to this general event. With the exact prekey/one-time/PQ signing-message log, an accepted same-identity changed key tuple contains an unissued message because the checked type/role encodings separate the three message classes. The general reduction never assumes this exact log. Its later source instantiation must use the retained writer theorem or another checked history statement. In particular, one successfully returned bundle alone does not prove that only three signing requests occurred: native signing precedes serialization and state publication, so any claim about failed attempts must account for the actual primitive, serializer and allocator behavior. Prior DH observations remain in the history and do not become signing messages.

`wrapper_query_step` and `routedClient_query_bound` preserve each original identity-operation class through every candidate branch. `fieldReduction_query_bound` gives each selected joint adversary `qUniform + 32*(N-1)` explicit uniform queries and the same `qSign` and `qDh` caps as its source, including rejected DH. `fieldReductionGame_uniform_bound` charges the complete challenger `32*N + qUniform`, including the target seed and unused reservations. `run_uniform_bound` separately charges the actual on-demand source `32*qCreate + qUniform`. No opaque ambient oracle is assigned zero cost: this source interface has explicit uniform, creation, signature, optional-DH, reveal and candidate-report operations.

`wrapper_attempt_count`, `wrapperRun_attempt_bound` and `run_attempt_bound` charge all `qReport` original candidates even when no detached report is forwarded. `wrapperRun_request_bound` and `run_request_bound` bound the exact outer position counter by an explicit total-source-query budget. These counts do not make parsing, byte comparisons, signature verification, signing-history filtering or transcript storage free. Each translation considers at most three attached fields and searches the actual finite history; public report recognition also evaluates its detached verification predicate. The imported joint endpoint and stopping reductions retain their documented local verification and non-target service work. This component does not claim a machine-runtime theorem or derive a total raw-input-byte budget from a request count.

The remaining protocol composition must connect actual native acceptance points and generated-index ownership to these reports, including byte-key collisions and attacker-owned registrations. The existing known-seed import wrapper is a separate interface and has not been merged into this generated-index candidate reporter. Honest supplied-seed generation, optional failure behavior, root and evolving-record distributions, KEM challenge routing, record/session selection, reveal freshness and persistence assumptions remain explicit global obligations. This result does not establish assigned-ID equality, secrecy of raw DH replies, full symbolic/computational correspondence or end-to-end protocol security. Primitive/compiler contracts and deployment integrity, rollback resistance, ownership, crash and storage premises remain unchanged.
