# Real source callbacks and coordinate annotations

`PqxdhRecordLiftRealTable` establishes the operational bridge needed before replacing evolving secret chain outputs. It keeps a private coordinate table containing actual complete 76-byte native replies. A coordinate names its slot, direction and source position. The chain input is the installed seed or the previous reply's next-chain projection, as defined by `PqxdhRecordLiftChainTable`; the material is the same reply's key and nonce, as defined by `PqxdhRecordLiftMaterialTable`.

`receive_store` and `send_store` generalize the earlier uniform-table callback equalities. Their only table requirements are extension of all previous entries and storage of the supplied complete reply at the actual request coordinate. They preserve the entire source rollback entry, both chains, cached skipped material, pending control and context. They do not assume how the reply was sampled, distinct key bytes, or independence of table entries.

For the real source, `Consistent` states that every stored reply equals the deterministic source HKDF output at its currently interpreted predecessor input. This is an operational invariant, not a new primitive security assumption. It holds for the empty table. `record_mono`, `closed_record`, and `consistent_record` derive its preservation when the actual output is recorded at an available coordinate. Thus a retry agrees with its old entry, and previously available chain inputs remain unchanged. `output_alias` explicitly retains equal real outputs when two distinct labels have equal native requests. No alias probability is asserted here.

`callback` makes one literal native KDF query on every invocation, including table hits and retries after a failed opening. It then retains every returned byte in the private table. `callback_bound` checks its one-query cap; the definition has exactly one unconditional query. `callback_real` interprets this computation using an explicitly supplied actual native KDF step equation and preserves the entire native poststate, including any caller instrumentation. The equation is an operational implementation premise that the concrete native handler must discharge, not a new cryptographic security game. The table lookup and byte conversion involve local deterministic work; no statement makes that work free. Public and caller-known HKDF evaluations are not replaced by this module.

`output_source`, the two byte-conversion inverse laws, `receive_real`, and `send_real` identify the stored output and the complete source callback with the original typed HKDF interface. The only source endpoint used is the existing correct fixed HKDF source object. This module proves no algorithm or implementation internals, randomness replacement, evolving-chain secrecy bound, alias bound, selected-input independence, global source simulation, or adaptive CTX reduction. The companion `PqxdhRecordLiftChainCompiler` proves full recursive receive/send execution erasure with the interpretation evaluated at the growing table; installation and dynamic handle provenance remain separate global-world obligations.
