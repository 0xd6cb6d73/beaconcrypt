# Record dictionary and writer-buffer provenance

`PqxdhRecordFactsOriginBuffers` supplies the local invariant machinery needed to link ideal replay dictionaries to the source’s tagged produced log. It has nine checked statements. It does not establish the whole-protocol origin event or a probability bound.

`Closed claims secret` means each successful-seal entry in each coordinate dictionary has a frame in the already tagged produced log, with the entry’s exact sequence, sender and payload, and a tag satisfying `claims` for that coordinate. `Buffered claims tag secret` additionally allows the corresponding frame to remain in the literal pending writer log of the current owner operation, provided that current tag satisfies `claims`. These are proof invariants over existing fields; no experiment, oracle or source operation is replaced. The `claims` relation is a parameter instantiated by [the source send proof](record-facts-origin-send.md) with actual handle, installation-slot and direction facts. It is not a primitive assumption or a completed source-origin premise.

`sealing_buffered` proves preservation under the actual ideal hidden sealing service, using `sealing_trace`. It requires the current caller’s tag to satisfy `claims` for the actual selected material coordinate. On source width rejection or CTX nonce refusal it retains existing provenance. On a generated record it places the exact new dictionary entry and literal frame in the current owner’s pending buffer, including when the frame writer fails. All existing entries retain their earlier witnesses, and the existing source theorem supplies exact preservation of other coordinate states. The source send proof discharges the selected-coordinate tag fact from actual kernel ownership and direction.

`publish_callback` gives the exact evaluated computation of the actual CTX publication service. `publish_closed` and `publish_buffered_closed` prove that publication moves pending witnesses into the tagged produced log and empties the pending buffer. They do not infer successful publication from frame production: a failed writer remains in the produced log and still requires the separate unpublished-frame probability argument.

The other five facts establish that initially empty dictionaries are closed, a closed invariant can be used within any owner operation, an empty pending buffer converts buffered provenance back to closed provenance, unchanged dictionaries and writer logs preserve buffered provenance, and widening an established tag relation preserves closed provenance. They permit arbitrary shared-cache, private-cache, counter, seed and chain changes when the explicitly named invariant fields stay equal. The actual execution still retains those fields; this module creates no erased game.

The nine declarations have exact checked axiom guards allowing only the standard Lean logical axioms `propext`, `Classical.choice` and `Quot.sound`. No new primitive correctness or security premise is introduced by these bookkeeping proofs. The actual setup and primitive record remain arguments of the unchanged service definitions. No query is added and no query-cost or statistical claim is made. The source send/receive inductions, actual handle attribution and [adaptive dictionary invariant](record-facts-origin-invariant.md) are established by the companion modules. The accepted-transcript join and unpublished-record bound remain open.
