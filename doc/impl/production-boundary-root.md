# Root requests at the native registration boundary

`PqxdhBoundaryRoot` connects the extracted root-input builder and the actual native registration callbacks at their existing R1 interpretation. The input consists of 32 bytes of `FF`, the four 32-byte DH replies in source order, and the 32-byte KEM reply. `built_input` derives this equality from a successful extracted `build_root_key_input` execution, including its nonzero-DH rejection check. It assumes no independence between contributions, honest selected key, injective public-key encoding or secret-input distribution. `input_length` fixes the request at exactly 192 bytes.

`source_built` and `source_complete` expose the literal source callback: read the existing shared Extract table at those same bytes, perform real HMAC Expand at `PQXDH_INFO || 01`, take its first 32 bytes, and return the original native representation. Only the Extract cache is updated by that callback; the complete family history and other native state are retained. The latter equality allows any continuation to inspect the optional reply and entire poststate together. There is no interchange of generators or equality of marginal distributions.

`tail_root` and `scheduler_root` identify this callback with the actual Phase-2 tail and registration scheduler dispatch. The scheduler forwards the supplied native root input without rebuilding a value from public transcript fields. The actual candidate-local finish, admission and failure paths remain in the separately reviewed registration-finish boundary. A successful builder equation is a local operational premise used by the byte-transport helpers, not a primitive security assumption or a premise that the whole registration succeeds.

`logged_complete` gives the exact Server root callback with its instrumentation retained: both the derivation entry and real Expand-HMAC observation in the family history, followed by the session touch containing the actual returned root. `logged_built_complete` places this same full continuation at the extracted 192-byte input. The supplied source descriptor is retained unchanged; this helper neither derives it from transcript bytes nor proves its provenance or alignment with the pending token. The acceptance boundary retains the original client and the point at which this callback runs.

`scheduler_root_uniform` transports the existing table bound to the concrete owner callback: at most 64 uniform byte draws for one cache miss, zero on a hit. The callback performs one logical Extract-table read and one real Expand-HMAC evaluation. Local conversion, HMAC evaluation, cache lookup, history updates and continuation work are retained work, not free or additional uniform-oracle queries. The existing `PqxdhServerAuthNativeUniformCosts.logged_root_uniform` gives the same 64-draw allowance for the displayed Server callback. Preparation, KEM, DH and all other source and reduction bills remain separate and unchanged.

`initial_complete` then identifies the actual scheduler initialization callback at the returned 32-byte root and the symmetric-ratchet domain label. It returns the real 64-byte HKDF response with the complete native state unchanged. `initial_prefix` proves that this actual response is the first 64 bytes of the real 76-byte ratchet response at the same input and label, using the existing source prefix contract. It does not replace either response with independent chain, key or nonce samples. This is one logical initializer call with real HKDF computation; it introduces no new uniform draw or extra table.

The production sites are `beaconcrypt/src/pqxdh.rs`'s root derivation and `beaconcrypt/src/ratchet.rs`'s 64-byte initializer, together with the Server and Beacon registration call sites. The byte builder itself is extracted and its correspondence is checked by `PqxdhRefinement.build_root_key_input_abs`. The public adapter, native primitive execution and codec call boundaries retain the existing reviewed-transcription and implementation contracts. R1 replaces only the approved zero-salt Extract slice by its shared classical programmable oracle; real Expand and the initial/ongoing ratchet HKDF functions retain their defined interfaces. No equality between this ROM and the fixed public HKDF is assumed or proved here, and no functional fixed-root correctness theorem is used to answer a ROM request.
