# Selected raw authentication observer

`RawCtxSelectedAuthenticationObserver` defines an executable final decision for the same dynamic known-key CTX client already used by the native compiler. It requires no selected-message-key argument. Each selected raw request is forwarded unchanged, and the actual challenger-produced optional plaintext is returned to the original continuation. The observer stores that request, its optional reply, and the successful selected seal history before the attempt. Known-key requests, public hashing and caller randomness continue through their original interfaces. The observer adds no oracle call and erasing its state gives the original executable program exactly.

The recorded request is the component request. For the native compiler this includes the existing private 165-byte framing containing nonce and associated data followed by the original network bytes. The framing is not a production message or a plaintext supplied by the adversary. `RawCtxUniversalDecoder` already proves exact recovery of the original bytes and native target. The observer never turns recovered plaintext into a forgery target.

The final Boolean is true exactly when some recorded attempt decoded successfully, returned a present optional plaintext, and its complete authentication tuple was absent from the successful selected seals before that attempt. A present empty plaintext is still an accepted component opening. Tuple comparison includes nonce, typed associated data and the complete encoded CTX record. This retains the distinction between a fresh base-AEAD ciphertext and a fresh CTX tuple that reuses a base ciphertext with a changed commitment. Later seals cannot erase a prior success because the observer retains the attempt-time history. Failed, malformed and repeated raw requests are all forwarded and charged even when their final forgery test is false.

The replay endpoint returns a plaintext only by looking up that same complete tuple. `replay_raw_good`, `replay_seal_good` and `replay_step_good` prove that the observer's successful-seal history is identical to the actual selected history and that its winning bit stays false through every concrete source operation, including known-key operations and the shared hash cache. `replay_schedule_good` proves this for every adaptive continuation. `monitored_program` and `decision_interpreted` identify the full-state interpretation with the actual executable observer. `replay_zero` then proves zero winning probability in the original replay component game, without a new cryptographic assumption.

`authentication_bound` applies the existing `AdaptiveCtxDynamicKnownBounds.selected_integrity` theorem to this concrete decision. Its real-game accepted-forgery probability is at most the ordinary modified nonce-AEAD IND$ advantage of `AdaptiveCtxPrefixValidation.validationReduction`, plus `qHash / 2^128`, plus twice the sum of the ordinary modified nonce-AEAD INT-CTXT advantages of `AdaptiveRawNonceAead.indexedReduction` for indices zero through `qRaw - 1`, plus `qRaw / 2^512`. Both reductions contain the actual observed client through `AdaptiveCtxDynamicKnownKeys.decisionClient`; no arbitrary private-state predicate is used as their winner. The sealing allowance must satisfy `qSeal < 2^96` as in the existing endpoint.

`monitor_queries` and `decision_queries` preserve every supplied query-class bound exactly. In particular the theorem consumes the original client's `qHash` bound for selected public hashes and actual known-key hash work, `qSeal` bound for selected seal attempts, and `qRaw` bound for every selected raw attempt. Explicit uniform and total bounds are also preserved by the same theorem; local parsing, table lookups and primitive execution retain their existing separate bills. The component theorem does not silently supply protocol-level session or target selection factors.

This result establishes the concrete component authentication winner. Applying it to original native authentication events still needs the actual source accepted-record observation, the selected-key distribution and its permitted reveals, the original publication `Gate` and byte-based `Fresh` conjunction, the source nonce-refusal term, and the global target/session accounting. `Gate` and `Fresh` alone do not imply a forgery. The retained private KDF hybrid still needs its separate reduction to real fixed HKDF; public HKDF remains real throughout. Snapshot and persistence behavior are outside this proof scope.

Validation: direct Lean 4.34 module compilation and 18 guarded axiom reports, containing only `propext`, `Classical.choice` and `Quot.sound`. No Rust code or primitive implementation was changed.
