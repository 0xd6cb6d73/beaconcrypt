# Dynamic signature reports and subsequent compromise

This focused HB-90 extension connects dynamic honest identity creation to report-time signature freshness. An arbitrary client may create identities, observe the complete joint signing/DH interface, request actual seed reveals, submit any number of signature reports, continue after those reports and stop adaptively. The source records whether any report was a valid fresh-message signature for an identity that was created and had not yet been revealed. For at most `N` creations, that event is bounded by the sum of `N` explicit constructed joint-use weak-EUF advantages. There is no report-position selection factor. This is a signature-interface theorem; native BeaconCrypt acceptance points and the common root/record experiment are not instantiated by this component.

The primitive endpoint is unchanged. One uniform 32-byte Ed25519 seed determines the Ed25519 and converted-X25519 public interfaces, signatures and chosen-input optional static-DH replies. Its winning event remains ordinary fresh-message signature forgery. Providing the additional raw-DH service makes this an explicit stronger joint-use weak-EUF contract, rather than plain EUF-CMA. No secrecy game for that raw-DH service is assumed, and no primitive algorithm or implementation is proved. Native seed generation, seed-to-secret conversion and optional peer-validation errors still require the previously stated exact functional adapter contract.

`PublicSnapshot` contains a natural-index map of observed joint public keys and the actual per-identity signing/DH/reveal history. `observeKeys` inserts a key only when an actual creation reply publishes it. `observe` then updates histories from the actual service or reveal reply. A rejected reveal of an uncreated index does not mark the future identity compromised. `sourceKeys_append` proves the generated public map changes at exactly the new index, even if its key bytes collide with earlier values. `source_snapshot_step` identifies this public update with the complete actual source step. It preserves all previous source state and observations; it does not infer identity equality from equal key bytes.

`reportAccepted` checks a report using only the observed public map and histories. An invalid or uncreated index rejects. At a created index the test requires no prior successful seed reveal, a message absent from the signing log and successful public signature verification. `reportAccepted_iff_source` proves that this public test is exactly the previously defined source `DynamicEvent` on the actual source snapshot. Its target-support obligation comes from actual seed-prefix lookup, not an honest-selected-target premise. The experiment permits every attempted reveal and report; freshness is part of its explicit winning event.

`ReportingState` retains the full private created prefix, complete original source query/reply transcript, per-identity histories, public snapshot, sticky event flag and all report observations. Each observation contains the unchanged candidate, the number of source queries already executed and the Boolean public-recognition result. Together with the source transcript and report list order, this records the reports' interleaving with creation, service and reveal requests. The oracle's report reply remains `Unit`; no private state is provided to the client. `reportingImpl_report` gives the exact report poststate, and normal source requests continue through the actual interpreter. Subsequent creation, services, reports and compromises remain unrestricted.

`stopAtFreshReport` is an executable client transformation. It forwards each earlier original query, computes the same public snapshot from the returned reply and stops at the first publicly recognized report, returning that candidate unchanged. It receives no private seed. `occurred_probability_le_stopped` proves that the original source's probability of ever recording the event is no larger than the stopped source's valid final event. The induction follows the complete evaluated source continuation; its source step uses `source_snapshot_step`, and its recognized-report branch uses the ordinary probability upper bound of one. An unrecognized report continues with its exact retained timestamp and result. No equality of public-key marginals or deletion of earlier observations is used.

`reportingRun_le_extractor` converts the stopped optional candidate into the existing dynamic final-forgery interface. A fixed fallback is used only when no report was recognized, and any resulting additional win can only enlarge the bound. `reporting_advantage_le_identity_sum` composes this coefficient-one capture with the already checked dynamic source reservation, routing and joint-use family reductions. Each selected reduction is explicitly `globalReduction` applied to `routedAdversary` of `reportExtractor`; none receives the target seed. `reporting_advantage_le_identity_count` gives `N * epsilon` if every one of these constructed reductions has advantage at most `epsilon`. Final freshness is required only in the stopped execution. `reportingRun_occurred` proves that arbitrary later seed reveals cannot erase an event in the original continued source.

The resource statements distinguish actual source execution, the reduced challenger and local computation. `extractor_query_bound` preserves every declared dynamic source class through stopping. `reportingReduction_query_bound` gives each selected reduction at most `qUniform + 32*(N-1)` uniform-oracle requests, `qSign` signing requests and `qDh` optional static-DH requests. Rejected DH replies remain in the DH cap. `reportingReductionGame_uniform_bound` includes the target challenger's seed generation, so the complete interpreted game costs `32*N + qUniform`, including every unused reservation. Each seed uses 32 byte-valued uniform requests; each explicit source uniform request may have an arbitrary finite range and counts once in these library units.

`reportingImpl_uniform_step`, `reportingExecution_uniform_bound` and `reportingRun_uniform_bound` prove the actual source's separate cap `32*qCreate + qUniform`, from every retained state for the execution lemma. `reportingImpl_trace_count` and `reportingExecution_trace_bound` count any original source query class in the complete actual trace, including invalid-index calls, repeated reveals and rejected DH. These supply separate `qCreate`, `qSign`, `qDh` and `qReveal` attempt budgets. `reportingImpl_report_count` appends exactly one observation per report, and `reportingExecution_report_bound` charges all reports against `qReport`, including invalid, repeated and post-compromise attempts. Reports do not require an extra cryptographic challenger query, but they still perform up to `qReport` local public verifications and map/history checks. Non-target local signing and DH evaluations remain bounded by the corresponding source class budgets. Each successful reveal copies a 32-byte seed; creation computes its joint public map. Lookup, history processing, timestamp calculation and transcript appends remain real local work dependent on the retained state sizes. No machine-runtime theorem or free opaque ambient computation is claimed.

The event concerns uniformly generated identities indexed by their actual creation order. Attacker-owned or caller-supplied identity creation is not silently treated as uniform honest creation. Native identity ownership, public-byte lookup and any collision terms needed for that lookup remain separate. The new report operator must still be connected to actual source acceptance/extraction points without manufacturing fresh-message events. Dynamic session ownership, KEM/root/current-chain/skipped-key reveals, their event-relative freshness rules, persistence/rollback assumptions and the common computational/symbolic experiment remain open. This component adds no security premise equivalent to protocol authentication and does not close the full proof goal.
