# Selected finite-family live compiler

`RawCtxSelectedFamilyLiveCompiler` connects the checked finite-family CTX frontend to the actual adaptive record/public/reveal interface. The executable `impl` and `client` receive the selected address and public context, private kernels represented with a hidden message-key slot, the preceding private derivation table, and the original adversarial client. They require no selected-message-key argument; arbitrary supplied histories and equal known-key bytes are not excluded by these operational statements. The mathematical CTX interpreter takes the selected key explicitly.

`read_step` retains the exact observation produced by the existing original reveal dispatcher before returning its optional reply. A read of unavailable selected material stops before returning those bytes. `read_not_fresh` proves that this stopping observation itself falsifies the existing byte-based freshness predicate, independently of the adversary's final decision. No new freshness definition or assertion that the final decision is false is introduced.

`step_source` proves the complete one-step source correspondence for every reached record, public query or reveal. Removing only CTX bookkeeping yields the existing `RawCtxSelectedMessageStopping.sourceRecord` and `stopping` experiment. Every original role, optional API result, history observation, ambient value and shared cache is preserved. The sole additional branch is the explicitly stated `Stops` predicate for a reached selected send whose nonce was already used. That branch retains the entry role family and cache and increments the original history position; it is not assumed impossible or fresh. The imported finite-family compiler establishes exact indexed publication and real public HKDF evaluation.

`step_queries` charges at most one dynamic CTX/public call for each record or public attempt and zero for a reveal. `client_queries` lifts that concrete bound through every adaptive continuation using all six source budget coordinates. Failed requests and stopping seals are included. This bound counts the dynamic component interface; it does not price source-side derivations, private lookups, parsing or other ambient operations. The existing separate source bills remain necessary, including up to 51 private derivation lookups for a raw receive and one for a send.

`step_candidates` and `client_candidates` retain every previously disclosed candidate and charge at most one new known candidate per reveal attempt. The complete adaptive client therefore has at most its initial candidate count plus `qReveal` candidates, including rejected, repeated and stopping reads. The theorem is a count, not a claim that the selected key is uniform or hard to guess given those observations.

The module establishes concrete source-step equality and full adaptive operational budgets. A complete adaptive source comparison with the selected-nonce stopping event, source attribution and probability bounds for that event, registration/installation changes to the live family, and final target/session losses remain separate composition obligations. The original arbitrary-final-event and byte-freshness theorem is available in `RawCtxSelectedMessageStopping`; it is not yet an end-to-end consequence of these one-step equations.
