# Complete random AEAD challenger byte accounting

This HB-85 refinement supplies the missing ciphertext-body sampling budget for the actual conventional adaptive CTX validation reduction. With a source budget `qBytes` for the sum of all submitted sealing plaintext lengths, its complete ordinary random experiment has at most

```
qCoins + 64*(qHash + qSeal + qRaw) + qBytes + 16*(qSeal + 1)
```

uniform-oracle requests. The random experiment generates no encryption key. The corresponding complete real experiment retains its separately checked 32 key-byte draws and `qCoins + 64*(qHash + qSeal + qRaw)` forwarded uniform cap. These are two exact declared experiments with different sampling operations; a seal-count cap alone cannot bound arbitrary plaintext lengths.

`NonceAeadRandomQueryBounds.randomSeal_uniform_bound` checks the ordinary random sealing handler from any prior nonce history. A used nonce rejects before drawing. A fresh request samples a body with the original plaintext length and a detached sixteen-byte tag, with a checked upper cap equal to that sum. No random CTX commitment is hidden here: those private/public digest draws are explicit uniform requests made by the existing reduction and already counted separately. This verifies ordinary challenger sampling and protocol accounting, not a primitive algorithm or primitive security proof.

`plaintextCost` assigns each ordinary seal its submitted plaintext length and assigns explicit uniform queries zero plaintext bytes. `PlaintextBound` is a weighted query budget over every possible reply and every complete adaptive continuation. Rejected or repeated sealing requests still spend their submitted byte budget, which gives a conservative cap independently of the challenger's nonce state. No plaintext-size bound is inferred from a count of requests.

`randomImpl_uniform_step` includes one actual uniform request on the coin branch, or the body/tag cap on a sealing branch. `randomRun_uniform_bound` combines the weighted byte budget with separate seal and explicit-coin bounds through the complete interpreted continuation. It proves `qUniform + qBytes + 16*qSeal` from any prior handler state. `randomExperiment_uniform_bound` instantiates the empty-state ordinary Boolean random experiment and drops only its final state projection. Its definition performs no key generation, so adding the real world's 32-byte key sampler would misdescribe this experiment.

`plaintext_bind` composes weighted payload budgets through arbitrary complete continuations. `plaintext_simulate` transfers a supplied weighted source cost through an arbitrary stateful interpreter when every actual source query proves its corresponding outgoing payload cap. `no_seal_plaintext_zero` proves zero encryption payload for a computation that cannot call sealing, and `lifted_probability_plaintext_zero` applies it to lifted probabilistic work. A zero plaintext cost is not a claim that cache sampling, parsing or local work is free.

`AdaptiveCtxPlaintextQueryBounds.SourcePlaintextCost` reads the original `CtxSealInput.plaintext.length` only on the production-shaped source seal query; public hashing, explicit coins and raw receive requests have zero submitted encryption plaintext. `SourcePlaintextBound` counts these lengths across all possible source observations, including rejected nonce reuse and adaptive stopping. It is an explicit resource precondition on the source client, not a security or authenticity assumption.

`runLogged_bind` proves exact successful-history threading through a complete continuation. `runLogged_no_plaintext` combines the existing checked no-seal predicate with the ordinary weighted bound. `sealStep_plaintext_bound` inspects the actual CTX sealing wrapper: it forwards the same original plaintext once to the ordinary seal oracle, then its private commitment lookup and complete state update submit no further encryption payload. This covers either an actual rejected response or a successful body/tag followed by the retained dictionary lookup.

`sourceStep_plaintext_bound` handles every actual source query. The sealing branch uses that exact unchanged-input proof; public hash, raw receive and coin branches use their existing actual zero-seal bounds. Private cache effects on failed or repeated raw attempts remain in the computation even though they have zero encryption payload. `loggedSource_plaintext_bound` threads the complete CTX state and successful sealing history through arbitrary source continuations, subtracting only the selected query's declared byte cost. `sourceClient_plaintext_bound` then instantiates the same existing ordinary client used by the published computational reduction, without defining a replacement adversary.

`validationSeal_plaintext_zero` checks the actual `ctxValidationInput` empty message. Its additional seal contributes no body bytes, while its random-world tag is included in the extra `16` term. `validationReduction_plaintext_bound` proves that the unchanged validation reduction preserves `qBytes` through its constructive nonce selection, bounded candidate scan and final empty-message seal. No secret plaintext is substituted into that request.

`validationRandom_uniform_bound` applies the ordinary complete-random-experiment theorem to this exact reduction, using the checked source byte lift and the existing `qSeal + 1` sealing and `qCoins + 64*(qHash + qSeal + qRaw)` uniform bounds. It does not require a nonce-freshness assumption for the cost upper bound, since rejection only reduces actual draws. The existing probability theorem still uses its stated `qSeal < 2^96` condition to prove the constructive validation nonce fresh in the real world. No advantage term, target selector, raw-attempt count or integrity-family coefficient changes.

Source explicit uniform requests may sample from arbitrary finite ranges and count once in VCVio's query units. Each digest miss uses 64 byte-valued requests, each sampled body byte or tag byte uses one byte-valued request, and the real key sampler uses 32. Local nonce search, candidate-key evaluations, parsing, payload processing, cache/history operations and storage remain actual computation. This is a complete declared uniform-query ledger, not a machine-runtime or compiler-cost theorem.
