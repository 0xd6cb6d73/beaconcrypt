# Registration builder receipts and the actual source seal log

`PqxdhServerAuthBuildReceipt.compiled_receipts` attributes every new selected component seal in the complete executable Server builder to its actual source context. It retains arbitrary earlier component history separately. Each new receipt contains the exact plaintext, associated data, sequence and encoded sender, together with the source's eight-byte assigned-key binding. It also retains the precise publication alternative: either the writer of that concrete frame returned `none`, or the same context occurs in the builder's actual returned successful-frame log. No successful admission, successful response, honest pending token or selected-key freshness condition is assumed by this attribution theorem.

The distinction between production and publication matters here. The ordinary CTX component records a cryptographic seal before the native frame writer runs. A failed frame writer therefore leaves a component receipt without a successful source log entry. Conversely, a successful frame writer appends the source context immediately, and failure of the later registration-response writer does not remove that entry. Outer selected-nonce refusal remains distinct from both native optional failures. The attribution theorem follows these cases through the unchanged complete builder rather than treating an optional response as proof that a record was or was not sealed.

## Source binding follows from the actual request

`requested_context` follows literal sending admission to show that a reached KDF request retains its caller's complete seal context. `send_context` then proves that the actual material driver issues zero requests outside any property satisfied by that context. Its real KDF step and optional sealer reply remain in the program.

`after_context` carries the same property through the first-send, erasure and optional response-writer continuation. `candidate_bound` uses the actual `candidate.key_id_binding` result and `firstContext_bound` to establish the exact little-endian eight-byte assigned-ID prefix. Every identity, reservation, nonempty-payload and allocation branch remains present. `build_bound` adds the actual next-ID, pending-token Server-binding and peer-availability gates. `program_bound` supplies the concrete executable builder, proving zero sealing requests whose context lacks the source binding. This zero bound is an all-reply syntactic invariant, not a bound on failed attempts or a claim that surrounding work is free.

## Component receipts retain the writer boundary

`FrameOrigin` records the ordinary component seal's equality to the source plaintext and AD, its exact sequence and sender, and the failed-frame-writer or successful-log alternative. It makes no statement about a session or installation identity. `sealer_receipt` derives this information from the actual selected sealer's monitored execution. Known-material calls, invalid AD and explicit nonce refusal cannot create a new selected receipt; equal known-key bytes remain allowed and are handled on the original known-key interface.

`sealer_prefix` proves that every reply retains the entire old source context log. `Receipts` tracks an arbitrary list of earlier component entries separately from newly attributed entries. `sealer_preserves` preserves that invariant through the actual optional callback. `compiler_receipts` instantiates every original auxiliary outcome: identity checks, allocation, erasure and the outer response writer create no component seal and retain the source log. `interpreted_receipts` lifts these facts through every adaptive continuation of the complete service program, preserving the reached state even if the executable stops. Finally, `compiled_receipts` supplies the actual source-bound program and starts with its literal earlier observer history; no initial receipt or source-log correspondence premise is required.

`matched_receipt` consumes an actual accepted decoded target and a prior component entry with the same full CTX tuple and the actual matching plaintext. The existing narrow `ReadWritable` abstract-message contract makes that exact decoded frame writable. It therefore rules out the failed-frame-writer alternative for this particular match. The source context is in the returned log, and its bound key ID, application payload and associated data equal the fields accepted by the Beacon. This uses the actual optional plaintext receipt and binding checks already proved in `PqxdhServerAuthFinishReceipt`. It does not require canonical wire encoding, equality with the original serialized byte string, blanket writer totality, or success of the later response writer.

## Scope and remaining consumer

All thirteen public statements concern the existing executable programs and their actual support. The observer adds no component calls; its existing exact query-preservation equations remain applicable. The builder's previous attempted-call bills remain total at most one, selected seal at most one, forwarded hash at most one, selected raw opening zero and uniform zero. Every rejected attempt remains in those bills. Local HKDF, validation, allocation, codec work and component-interpreter sampling retain their separate source and reduction accounting.

This package introduces no cryptographic security assumption, probability loss or session/record selection factor. Its final local match theorem uses the already approved abstract readable-frame contract only on the concrete matched frame. The complete adaptive protocol still has to associate each reached builder with its actual marked Server session, retain its source touch before the acceptance observation, and carry the corresponding successful context into that observation's seal log. Those chronology facts are needed to connect the original `EntryEvent` to the ordinary all-attempt CTX winner. They are not inferred from equal key bytes or a matching ciphertext tuple. The complete component challenge distribution, stopped-handler resource accounting and final ordinary CTX advantage bound also remain separate consumers. Primitive internals, serialization implementation and persistence remain outside this package.
