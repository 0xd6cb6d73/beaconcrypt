# Indexed private KEM creation

`PqxdhLiveKemBirth` connects the actual native constructor to a private indexed KEM service. The constructor client receives the KEM creation index and public key. The secret remains in the private interpreter, alongside every earlier pair and the full service history. The identity-service index, KEM-service index and later native owner index are different coordinates; no equality between them or injectivity of public key encodings is assumed.

`coins_complete` preserves both complete service states through local generation. `afterIdentity_complete` retains the actual prekey-then-KEM order. `joint_step` keeps the original joint identity service and leaves the KEM pool untouched. `create_source` identifies the full identity → prekey → KEM execution with the original source constructor, including both private histories. `create_continuation` retains the entire subsequent computation and evaluated distribution. No generator interchange or marginal-only equality is used.

`created_lookup` derives the exact generated pair at its newly returned index; `created_prior` preserves every earlier index even if public encodings coincide. `decapsulate_present` invokes the actual primitive on that indexed private pair and original ciphertext, retaining its optional reply and history entry. `decapsulate_missing` rejects uncreated handles without a primitive call, while recording the attempted query. `reveal_step` returns and records the actual indexed secret or rejection. Compromise is represented explicitly; the later freshness rule must consume those observations.

`fresh_source` maps the original complete native Fresh object to these exact service handles while preserving the server binding, prekey, phase and instrumentation. The existing `PqxdhPhase2KemHandles.native_owner_run` can then transport the complete actual Phase-2 owner through an indexed private lookup. Its use still requires the created-handle relation to be maintained by the final live owner compiler; this module does not assert that arbitrary roles own valid handles.

`create_uniform` charges 32 + qPrekey + qKeygen interpreted uniform requests. `decapsulate_uniform` charges the actual interpreted decapsulation bound qDecap for each present indexed call; missing handles use no randomness. `coins_class` and `coins_bills` preserve each local random request in its own class. `afterIdentity_bills` separates the prekey sampling bill from the one KEM creation call. `create_bills` gives at most one joint creation, one KEM creation and qPrekey local random requests. The service calls still pay their complete interpreter bills, including ambient primitive randomness. Deterministic runtime is not asserted free.

These seventeen guarded statements establish source wiring and private representation, not a multi-key IND-CCA theorem. The ordinary one-key reduction must select only the designated creation handle, keep every other owner local, simulate all permitted pre/post decapsulations and stop or invalidate the target on actual prohibited reveals. In particular, the existing single-generation `Phase2KemProvenance.encode` must not be applied to an unrestricted dynamic pool because it deliberately collapses all generated handles. Generator-order interchange, target/session loss and the complete common experiment remain separate consuming work. No primitive implementation, storage, snapshot or restoration behavior is proved here.
