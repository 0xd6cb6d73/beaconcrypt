# Joint registration source schedule and complete sampling bill

This package connects the separately checked Server admission, Server response and Beacon initial-response boundaries in one executable source schedule. Its eight new modules contain 81 statements: complete source operations, adaptive consumed-set and owner lifecycle rules, actual numeric allocation and publication counters, literal Server and raw Beacon construction, and a concrete full sampling bill. The final experiment performs actual supplied/generated Server initialization and then an arbitrary raw public registration schedule. This is an operational source milestone; it does not establish the joint ProVerif transition relation or a global security theorem.

The private state contains one complete existing native Server interpretation and a dynamically growing list of complete native Beacon objects. The Server interpretation retains consumed identity/one-time pairs, moved pending tokens, its checked identifier counter, installed peers, successful-seal history and both primitive caches. Every Beacon contains its actual seed, prekey, one-time and KEM fields only where the original source phase retains them. Completion or abort uses the original native state transition; there is no second secret-key registry that can restore disposed fields.

An owner index is a public object address. It is distinct from a claimed or assigned protocol identifier, an identity's public key, a Server acceptance index and a pending token. A missing address returns ordinary rejection before any source callback. The present-owner finish equation runs the complete original native owner and reinstalls its exact optional result and returned object. The callback preservation equation keeps every shared protocol field, while retaining actual changes to the Extract and CTX caches. The literal publication/abort function always returns established or aborted, including both outer pin and binding checks. The checked adaptive no-retry consumer preserves that exact terminal owner through all subsequent creation, bundle, Server, finish and public-primitive requests, then proves finish and bundle are pure rejections with the complete final state unchanged. This applies after an active InitSent attempt. A raw finish call made before bundle publication instead returns the original Fresh or FreshWithCoins owner unchanged; it must not close that owner or prevent a later bundle.

Creation and bundle requests are separate. The current constructor is the post-admission typed-pin body: identity generation, prekey generation and KEM generation occur in source order at that request. It appends a fresh owner and returns its index. The new raw surface executes runtime initialization first and then the exact 32-byte width check, before invoking that body. Like `Beacon::try_new`, it does not check that the pin is a valid point: a Beacon whose pin cannot be converted is created normally, a finish call before its bundle leaves it unchanged, and its first finish attempt after the bundle aborts it, because finish converts the response identity and requires it to equal the pin; the unchanged finish model refuses such a Beacon at these places by construction, which is not proved as a separate theorem. Every raw-surface statement in this package therefore also covers such Beacons. The internal typed constructor cannot be requested through the public surface. Its checked continuation equation quantifies over the complete returned runtime and protocol state, preserving all generator effects at the requested schedule position. A later eligible bundle request invokes the original live Phase-1 program. Fresh generates one-time material there, FreshWithCoins uses retained material, and the three signatures precede the optional writer. Writer failure retains the original returned phase. Repeated eligible attempts therefore require their own signing and generation bills; a single successful bundle does not justify a global signing cap of three.

Phase-1 signing and publication require separate receipts too. The maintained symbolic BeaconInitiated and BeaconBundleInitiated events precede their network output. In the source, all three signing calls precede the writer, and only writer success permits InitSent reinstallation and return of the bundle. A signing-log witness can therefore describe a failed publication attempt. The eventual event map must state whether it denotes cryptographic initiation or successful bundle publication; weak EUF alone does not turn an already signed message into a successful publication. Extending the single-attempt whole-bundle origin result across retries also requires the actual retained prekey/KEM and per-attempt one-time history, not just three independent signing-log membership facts.

Server accept and build requests use the existing complete native operations with arbitrary input bytes, selected pending handle and optional application payload. No origin annotation authorizes a request. The checked `ScheduleState` consumer lifts the actual source consumed-set, disposal and counter rules across all interleaved Beacon operations. A built allocated token remains spent under every later request; a guessed future token is deliberately outside that rule. Failed response publication retains the previous Server object while keeping separate cache and seal-log effects. Successful publication advances the same checked public counter once and returns that exact assigned ID. The `ScheduleLedger` consumer counts rejected requests as well: consumed-set growth and session-index allocation are bounded by `qAccept`, and public counter growth by `qBuild`. Its Server-operation labels classify those state changes without deleting Beacon or uniform requests from execution or granting their callback work a zero bill. The shared interpreter's old designated-Beacon coordinate and selected-prekey coordinate serve only its private analysis interface; the final projection must demonstrate their irrelevance to this dispatcher rather than introduce an unexplained additional owner or recover a secret from a public input.

An honest-identity registry may classify the target named by a later security event. It cannot authorize registration or suppress transitions for an unknown identity, a changed signed bundle or an attacker-owned key. Such requests still execute the source checks and consume the same attempt indices. Provenance for an accepted bundle under an honest identity must follow from the exact EUF and source-receipt consumer; registry membership alone supplies no bundle-origin theorem. The existing fourteen-query model remains an unchanged regression fixture while the generalized model states its own honest-target and freshness scope.

The private trace must distinguish a reached cryptographic seal, the inner frame writer's optional output, the actual outer ResponseFields and writer reply, and the public build result. A successful inner operation followed by outer failure keeps its original primitive/cache/log effects and does not publish a response or peer. The trace records those actual callback results once and must erase to the unchanged execution. It will not infer delivery from a seal-log entry, impose writer totality, or identify a session from equal root/key/frame bytes. These observations are proof instrumentation, not saved state, restored state or a disclosure capability.

The eventual joint symbolic worker must represent dynamic Fresh, FreshWithCoins, InitSent and terminal owners, including repeated failed bundle writers. Simply running the earlier standalone processes in parallel is insufficient: their local owner process starts after a single bundle publication. Public numeric slots also need a private allocation relation so nonexistent requests have the source's ordinary rejection behavior. The Server side must retain the reviewed private consumed-set mutex, one-use pending tokens and predictable checked counter, with origin tables used only for observation.

The computational schedule's pending handles are public natural numbers, allocated by every Server accept attempt, including failures. The joint process therefore also needs a monotone attempt counter and public handle encoding. The standalone response process's fresh opaque attempt name is insufficient as this interface: using it for authorization would remove guesses of future or nonexistent numeric slots. Fresh names can still distinguish private trace occurrences, while admission uses the actual allocated pending entry. Pending indices, Beacon owner indices and assigned protocol IDs remain separate counters and types.

The joint dispatcher must linearize complete live API operations and return ordinary rejection for missing or future slots. Every normal branch reissues its private serialization token, including terminal and failed calls; absence of a token cannot substitute for an admission test. This follows the live source object's exclusive mutable-owner boundary and introduces no persistence or storage premise. Oracle-query bills must remain separate from the local cost of indexing, list updates, history retention and dispatch. Those operations are not free runtime merely because they issue no primitive query; any efficiency statement needs their explicit polynomial size and step bounds.

The restricted programmable Extract table on the actual 192-byte root slice and the existing shared CTX/BLAKE2b random oracle remain explicit inherited idealizations. Public evaluations outside that Extract slice and the source ratchet operations remain the original functions. This operational work proves no primitive security law, constructor injectivity or complete applied-pi compiler theorem. The new source initialization consumes the previously reviewed constructor from commit `59f2487870ab7fc8e4199f264721eb09fd4a9840`, selectively ported with its three guarded statements and a smaller maintained dependency import. It retains runtime initialization before supplied-seed validation or the actual 32-byte seed draw. The resulting native Server has the actual empty peer map, consumed set, pending map and public counter; the dynamic Beacon registry is empty. The old single-Beacon analysis slot is a deterministic aborted value with Unit identity and no private key, rather than another generated owner. No joint dispatch targets that slot, and every adaptive operation preserves it. The checked `experiment_ledger` consumes this literal constructor: both imported and generated paths start the same empty consumed set and public counter, then derive duplicate-free admission, consumed/session counts at most `qAccept`, and final assigned counter between the supplied Server ID and that ID plus `qBuild`. Imported seed provenance remains distinct from a generated draw. The raw-surface consumer now carries these same admission and numeric-counter bounds from actual Server creation through arbitrary raw Beacon constructors, preserving the intermediate and final runtime states separately. Its complete adaptive lifecycle theorem retains terminal owners and already allocated moved tokens, while future guessed indices remain outside the spent-token predicate. Wider compromise and established-record capabilities, logical primitive-oracle instrumentation and selection accounting, the complete process relation and the cryptographic event consumers remain substantive follow-up work. Primitive implementations, serialization implementations, compiler/runtime behavior and persistence are outside this module.


## Exact source theorem groups

The eighteen statements in `PqxdhRegistrationSchedule` preserve each complete native callback and public operation. `shared_continuation`, `onShared_run`, `callback_fields` and `program_fields` retain the full shared state around arbitrary evaluated work. `finish_source`, `finish_missing` and `bundle_source` identify literal optional source executions and exact registry reinstallation. `create_source` gives the complete source generator continuation. The remaining terminality statements derive active finish closure and transport the exact terminal owner through every supported adaptive request; `no_retry` then gives both actual final rejections.

The fifteen `ScheduleState` statements preserve the original Server fields across all owner callbacks, recover the original native Server interpretation, and transport actual admission, token and counter relations. `accept_pending` retains the source index increment on every attempted accept. `build_consumes` and `no_rebuild` apply only to an already allocated pending slot, so guessed future handles remain possible ordinary calls. `build_counter` preserves both success and failure poststates; only actual returned responses advance and publish. The seven `ScheduleLedger` statements count source admission, session allocation and successful counter growth under all-reply `qAccept` and `qBuild` caps. Their labels are state observations, not a modified execution.

The seven `ScheduleInitial` statements consume the literal Server constructor and prove the otherwise unused compatibility Beacon coordinate is never publicly dispatched. The nine `ScheduleSurface` statements expose raw initialization and 32-byte pin-parse order (`parsePin_eq_toWord32` states that the parse is exactly the width check), retain every optional failure and lift complete adaptive state and count relations. `surface_lifecycle` simultaneously preserves terminal owners, allocated spent tokens and that unused coordinate. The two `ScheduleExecution` statements identify actual successful construction followed by the exact initialized-runtime continuation, then derive the empty-start consumed/session/counter ledger. Initialization failure remains in the experiment, and the operational success support used in the ledger is derived from that experiment rather than supplied as a cryptographic premise.

## Complete query accounting

`PqxdhRegistrationScheduleCosts` has eighteen statements. `create_uniform` and `rawCreate_uniform` retain both 32-byte source generators, actual KEM generation and every reached runtime initialization. `sourceRoot_uniform`, `server_root_uniform` and `server_client_uniform` retain the reached 64-byte Extract draw, full family history and actual registration consumption. `preparation_uniform`, `tail_uniform` and `callbacks_uniform` account for arbitrary-key optional decapsulation and each actual shared-table operation. `owner_uniform` and `finish_uniform` apply the existing 69-callback source bound to the complete initial-message attempt, including work before final sequence/binding rejection. `bundle_after_uniform`, `bundle_program_uniform` and `bundle_uniform` retain the three actual functional signing calls and optional writer, with at most one 32-byte one-time scalar draw per attempt. `accept_uniform` and `build_uniform` retain the entire source prefix or native response tail, including rejection and failed writers. `public_hmac_uniform`, `hmac_uniform` and `hash_uniform` retain all public primitive evaluations and their actual caches.

Let `G`, `E` and `D` be the declared complete interpreted uniform costs for KEM generation, encapsulation and decapsulation. Each includes its primitive uniform count plus `baseUniform × baseCalls`. These are ordinary interface/resource caps quantified over every applicable input, not an independence, honesty or security assumption. Let `I` bound one runtime initialization callback for every runtime state. The nine attempted-request classes have these conservative uniform bounds:

| Source request class | Uniform queries per attempted request |
| --- | ---: |
| Explicit uniform request | `1` |
| Raw Beacon creation | `I + 64 + G` |
| Phase-1 bundle | `32` |
| Raw Server accept | `96 + E` |
| Server build | `64` |
| Beacon finish | `69 × max(64, D)` |
| Public HMAC | `64` |
| Public shared hash | `64` |
| Current installed-kernel read | `0` |

`ScheduleResources.handler_uniform` and `surface_uniform` consume the concrete callback proofs for the actual internal and raw handlers. `UniformBounded` supplies a separate finite cap for each class over every possible adversarial reply continuation. `surface_program_uniform` then proves the complete adaptive interpreted program bound. `uniform_bill` expands its finite sum to

```text
qCoin + (I + 64 + G)qCreate + 32qBundle + (96 + E)qAccept
  + 64qBuild + 69max(64,D)qFinish + 64qHmac + 64qHash.
```

`surfaceExperiment_uniform` additionally charges the literal initial Server constructor: `I + 32` when no seed is supplied, or `I` when a seed is supplied. Runtime refusal and invalid supplied seeds remain actual branches. The same initialization callback's effects and bill recur on every raw Beacon-creation attempt. No constructor prefix, actual KEM work or unspecified ambient callback is outside this theorem.

These counts measure uniform-oracle requests after interpreting the primitive base interface. The source class certificate also retains a finite `qRead`, even though current-kernel reads make no uniform request. Deterministic signing, verification, DH, real HKDF/AEAD, parser/writer execution, indexing and list/history processing remain in the actual source programs; zero uniform cost does not mean zero runtime. The bound is conservative: the factor 69 is the whole native callback count, not a claim of 69 logical decapsulations or a tight logical-decapsulation theorem. Existing per-operation signing, verification and decapsulation caps still require their explicit chronological instrumentation consumer before they can be advertised as a global primitive-oracle ledger. The source/query-size and local runtime costs are not erased by the uniform bill.

## Remaining composition boundary

The constructed experiment currently has one live Server and a dynamically created Beacon family, with the listed registration and public primitive operations plus installed-kernel reads. The optional imported Server seed is a fixed experiment parameter; it is not a dynamically imported Beacon-identity operation. Identity/KEM/root/skipped-key disclosure and arbitrary established-record capabilities are not supplied by this narrower registration surface. Their concrete source services and event-specific freshness policies must be joined explicitly. The standalone symbolic gates remain unchanged; this package does not infer their joint trace relation by putting their names beside the scheduler. The next source/symbolic consumer must relate each actual operation, public numeric handle, optional reply and complete state transition, then lift the relation through arbitrary scheduling without an origin admission gate.

No primitive implementation, codec implementation, compiler/runtime correctness, saved-state behavior or persistence contract is proved here. All inherited ROM and native primitive boundaries remain as stated above. Independent review and focused standard-axiom checks cover this operational milestone; central import/inventory and aggregate verification belong to its consuming integration.
