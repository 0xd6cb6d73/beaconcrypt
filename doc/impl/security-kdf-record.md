## Findings checked against the branch

The fixed source handler in `PqxdhJointKdfGame.lean` returns `productionStream source.crypto address`, while its random handler samples and caches a uniform 76-byte stream at each public address. The adversary chooses every address and may evaluate the public deterministic source locally. One equality test therefore distinguishes them efficiently whenever the source is efficient. Naming this a joint-stream endpoint rather than a PRF does not make its advantage negligible.

The downstream problem is stronger than an overly general primitive assumption. `hiddenRootSharedRandomGame` and `hiddenRootIndependentGame` replace adversarial public KDF responses, as do the terminal initializer and initialized-chain games. An observer can ignore the honest root or chains, query an unrelated known input, and compare its response with a local HKDF evaluation. Preservation of typed query syntax is not preservation of the real public interface. Existing equalities, reductions, ROM bad-query and birthday bounds remain valid mathematical results, but they supply no negligible production bound through this endpoint.

The affected definitions and capstones are in `PqxdhJointKdfGame`, `PqxdhHiddenRoot`, `PqxdhProjectionCollisions`, `PqxdhInitializerSecrecy`, and `PqxdhInitializedChainsSecrecy`. Their explanatory comments now say this explicitly. No existing theorem statement, proof, or game has been weakened or silently replaced.

## New checked proofs and their meaning

`PqxdhPublicKdfCounterexample.lean` constructs the attack against the existing game itself. It proves that the adversary uses zero randomness queries and at most one complete-stream query, always returns true in the real world, and returns true in the lazy-random world with probability `1 / card(Vector UInt8 76) = 2^-608`. Its exact advantage is the absolute difference between one and that probability, and a separate checked theorem proves advantage at least `1/2`. This is an efficient public-evaluation control, not evidence of a production root-recovery attack. The proof charges no oracle query for local deterministic computation, consistently with the existing query model; machine-checked runtime/PPT preservation is still absent.

`PqxdhSecretInputKdf.lean` introduces a different, narrowly scoped root experiment. A joint sampler produces a public context and secret input bytes. The context may be correlated with the input. The adversary receives the context and one honest root and runs arbitrary local probabilistic code, including the real public HKDF implementation on guessed inputs. The same code and public operations exist in both worlds; only the honest 32-byte root changes to independent uniform bytes. Neither input nor PRK is passed to the observer. There are no hidden restrictions on public guesses and no programmed public-HKDF oracle.

The functional `SourceRootCorrect` premise identifies `Pqxdh.rootSecret` with the first 32 bytes of `HMAC(PRK, INFO_PQ || 0x01)`, where `PRK = HMAC(0^64, IKM)`. This is an algorithm equation, not a secrecy assumption. It remains a primitive implementation correspondence obligation; the theorem does not verify RustCrypto SHA-512/HMAC/HKDF internals. This exact Extract/Expand layout follows [RFC 5869, sections 2.2 and 2.3](https://www.rfc-editor.org/rfc/rfc5869#section-2.2).

The capstone `sourceRootAdvantage_le_extract_add_hmac` reduces this source-root game with coefficient one to two explicit primitive experiments. The first exposes the entire PRK alongside the sampled public context and compares the real fixed-zero-salt Extract output with an independent uniform 64-byte PRK. The concrete reduction receives that PRK, performs one Expand HMAC evaluation, and runs the root observer. This observation is stronger than the final-root observation and concerns the primitive extraction stage for a specified distribution; it does not assume the desired protocol result. Its smallness is an additional unresolved computational extraction obligation. A 256-bit secret input cannot give statistical uniformity over 512-bit PRKs; the endpoint would need a computational argument.

The second experiment is an ordinary HMAC PRF game with an independent uniform secret 64-byte key and a consistent random public-message oracle in the ideal branch. The reduction makes exactly the root Expand call and is proved to use at most one challenge HMAC query. It carries the original public sampler and observer as local computations. Checked distributional equalities commute independent sampling and prove that the first 32 bytes of a uniform 64-byte block are exactly uniform, using a bijection with two 32-byte halves. The final inequality follows from the triangle inequality after identifying these experiments. It contains no fixed-public-HKDF/random-table term and no ROM guess term.

Additional checked controls explain why ordinary secret-key HMAC PRF security does not discharge fixed-salt extraction. `zeroSaltPatched` changes any HMAC family only when its key is the public zero salt. Its Extract result is then constant for every input, regardless of input entropy. The complete keyed oracle is unchanged for every other key, and a uniform 64-byte PRF key equals that exceptional key with probability `2^-512`. These are structural and probability facts about a countermodel transformer, not an attack on actual HMAC-SHA-512 and not a machine-checked general PRF hybrid bound. They prevent treating the extra extraction obligation as an automatic consequence of a primitive-name checklist. RFC 5869 expressly distinguishes IKM as the HMAC message during Extract and notes the stronger analysis available with a random salt; this repository uses an absent salt.

`PqxdhComposition.lean` proves explicit finite global-hybrid accounting. The distance between the first and last whole experiment is at most the sum of adjacent distances. If separate bounds have been supplied for every adjacent global pair, their losses add; a common loss incurs an explicit `n`-fold factor. The games retain whatever correlated keys, sessions, compromise events, and observations they contain. This theorem does not equate these adjacent global experiments with independently sampled one-key component games. Such an equation or reduction must be supplied for every hop before the arithmetic applies. The result is useful loss accounting, not the missing protocol composition argument.

The new sampler game has no external signing, DH, decapsulation, compromise, persistence or other-session oracle. Those interactions are not silently encoded as local code with access to unknown secrets. A fixed prechallenge public context may carry such observations only after an appropriate preceding reduction justifies their joint distribution; adaptive external interactions require an explicit larger interface. This is the exact boundary of the new result.
