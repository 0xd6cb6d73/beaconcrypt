# Source provenance of the selected nonce ledger

The one-key CTX component refuses a second sealing request with a nonce already used under its selected key. BeaconCrypt's source does not implement that component refusal. The existing comparison therefore charges the probability of an actual refusal in an augmented run that otherwise projects to the complete source execution. These three modules establish where that run's selected nonce entries come from, before assigning any probability to repeated source sends.

`RawCtxSelectedSendAuditLedger.send_used` traces every newly recorded nonce to the sealing occurrence in the original send's exact event trailer. The result covers component refusal and failed serialization and retains the complete component state. `send_tracked` appends that trailer to the prior chronological audit. `stop_current` identifies the current source sealing occurrence when the actual compiler refuses; `stopped_pair` combines it with a prior occurrence supplied by the retained ledger. The receive and public-service lemmas show that all cached and future receive paths and all real public HKDF, hash and coin operations issue zero selected sealing queries and preserve the selected nonce ledger. Their other cryptographic work, replies, cache effects and state changes remain present.

`RawCtxSelectedRoleAuditLedger` constructs event trailers through the actual empty-send check, original owner context, every Beacon phase, Server associated-data and peer lookup, raw routing and indexed family dispatch. Its used-nonce and raw-path results supply the source occurrence for every new component entry. `tracked` preserves the previous audit while appending the current trailer. Its four refusal results attribute an actual owner, Beacon, Server or family refusal to a current source occurrence whose selected nonce was already retained. No honest-owner, nonempty-family, public-ID injectivity or unequal-key premise is added.

`RawCtxSelectedLiveAuditLedger` instruments exactly the augmented experiment from `RawCtxSelectedFamilyNonceCoupling`, retaining complete roles, disclosure history, private ambient state, shared primitive cache and component bookkeeping. `step_used` handles the actual source fallback on a refusing request as well as normal compiled callbacks and reveals. `erased_step` and `erased_program` remove only the added event history and recover the exact augmented execution. `step_tracked` and `program_tracked` prove the concrete provenance invariant through every adaptive request, optional reply and continuation. `source_program` further projects to the original hidden-disclosure-stopped source experiment used by the existing CTX comparison. This remains the retained selected-KDF hybrid; it does not replace the production KDF hop.

`initial_tracked` obtains the invariant from the ordinary component initialization with an empty selected nonce ledger, allowing arbitrary existing source roles and cache. `initial_program` then gives an actual earlier send occurrence for every retained selected nonce after the entire source program. `stopped_pair` and `reached_pair` identify an earlier audit occurrence and the current trailer occurrence with the same selected nonce whenever the next actual request refuses. They do not assume distinct occurrence values: two positions in the chronological execution can contain equal values. No source nonce uniqueness is assumed.

The instrumentation adds no oracle request, and `uniform_queries` preserves the exact uniform allowance of the same complete augmented run in both directions. The earlier source-to-component bounds continue to charge all source query classes and all adaptive verification attempts. Local instrumentation is not assigned a zero running-time cost. These are exact operational equalities and support invariants with no new primitive contract or probability loss.

This checkpoint does not bound the probability of the resulting repeated-source-send event. A subsequent argument must preserve chronological multiplicity, identify actual installation origins and chain paths, charge equal or crossing derivation inputs and permitted reveals, and connect that event to the same source sampler and explicit reduction losses. Equality of nonces under unrelated keys is not the selected-key refusal event. Chain freshness supplies no identity or KEM freshness. Registration installation, saved mid-derivation continuations, full selection factors and the final computational-symbolic correspondence remain further composition work. Primitive internals, snapshots, persistence and restoration are outside this proof.
