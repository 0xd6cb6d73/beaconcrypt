# Private monitor at the actual generated source prefix

Three modules add ten guarded statements connecting the generated pending packet to an annotated execution of its actual native source prefix. The same source requests, adaptive replies, complete states, Builder result, captured callback and ROM cache are retained. This annotation adds only the existing private request monitor and erases exactly to the original source program. It does not replace the source by the stopped CTX compiler or infer a coupling between changed interpreters from matching support.

`PqxdhLaterChallengeSourceMonitor.original` reassociates the existing challenge wrapper and native source interpreter. `original_program` proves equality with the complete original nested execution. `annotated` adds the existing `Monitor.record` at each actual pre-request state, preserving all native state and effects. `query_source` and `program_source` erase that private marker to the exact original query and adaptive-program distributions. Their equalities include the entire returned wrapper/native state, not only a public value or marginal key distribution.

`SourceMonitor.Reaches` follows actual supported steps of this annotated interpreter and retains the literal adaptive remainder. `source_reaches` lifts every original `RecordConfidentialityTrace.Reaches` path to this annotation using the same replies and native states. `query_unmarked` uses the original wrapper's all-reply semantics to show that any callback returning an unused challenge pair also started unused and preserved its arbitrary incoming marker. `Reaches.unmarked` applies that argument backwards along the actual prefix. `source_unused` joins these facts: when the original prefix ends with an unused pair, its annotated execution ends with the same incoming marker. In particular, starting at `none` ends at `none`.

`PqxdhLaterChallengeSampleMonitor.Marked` retains the original Builder support witness and the exact callback-local scan alongside this annotated prefix. The source-state view used by the monitor is universally quantified because no admitted challenge has occurred on this prefix. No particular conversion between native and instrumented component states is assumed. `reached_marked` obtains the witnesses from the same `SampleChronology.Reached` execution, and `phase_unused` derives the required absence of a challenge pair outside the used phase. This covers the prefix leading up to both before-phase and inside-phase requests; it does not establish the selected-input condition when an inside-phase callback begins.

`PqxdhLaterChallengeGeneratedPrefix.prefix_unmarked` consumes the same fully evaluated generated carrier, its recorded selection, the pending-packet shape and its captured metadata. It returns `Marked` for the exact prepared draw and adversary selected by that carrier. The not-used premise is an explicit phase condition, discharged for the original true marked-publication event by `GeneratedFrame.generated_not_used`; it is not an authentication or secrecy assumption. No challenge query, source refusal or completed/cached sampler branch is removed from the underlying programs.

This is the native source part of the prefix join. The optional compiler invariant and executable/source equations remain in `MarkerPrefix` and `MonitorSource`. Applying those equations to the same stopped sampler still requires the original-versus-nonce-stopped event comparison, including all refusal mass and the actual component state relation. The [inside-source result](later-challenge-inside-source.md) identifies the literal inside callback input and its pre-request frontend at the same generated packet. Connecting that frontend to the actual stopped component state and joining the local marker result to the successful target event remain open, together with two-world prefix coupling, the real/raw primitive hop, Fresh/event implication, selected finish/refusal accounting and the final selection/resource ledger. These ten operational/support results add no advantage term, selection factor or query allowance; none makes opaque callback work free. The existing full callback budgets and alias allowance remain in force.

Each module is checked directly with Lean 4.34.0, one thread and the shared lock. All ten public statements have exact guards admitting only the standard `propext`, `Classical.choice` and `Quot.sound` axioms. Rust, ProVerif, primitive contracts and deployment scope are unchanged. Central imports and inventory remain for the reviewed integration step.
