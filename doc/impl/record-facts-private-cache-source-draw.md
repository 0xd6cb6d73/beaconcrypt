# Actual hidden sealing with an explicit digest query

`PqxdhRecordFactsPrivateCacheSourceDraw` proves thirteen guarded statements. Its main result, `source_exact`, preserves the complete initialized erased-source computation while expressing each hidden sealing operation through an explicit digest query. The same source program, environment, adaptive adversary, replies and full private poststate remain present. This is an operational compiler equality, not the statistical origin or binding bound.

`HashInput n` is `(Label n × Bytes) ⊕ Bytes`: a private coordinate and suffix on the left, ordinary hash bytes on the right. `Spec n` is that digest interface plus the original finite-coin interface, definitionally the proposed common collision-oracle interface. `compileSeal`, `compileKeyedSeal` and `compileHiddenSeal` are actual `OracleComp` programs over this interface, available to an arbitrary future interpreter. Their private query carries the concrete coordinate and the complete outer suffix before the digest is returned.

The local `evaluate` interpreter answers a private query with a uniform whole 64-byte digest and forwards finite coins unchanged. It retains a supplied ordinary hash callback, which the sealing compiler never invokes. `evaluate_coins` checks the complete lifted finite-coin distribution. `seal_exact` relates this fresh-query interpretation to the actual erased local seal under its explicit empty-cache and unused-nonce premises, in replay and random modes only. Replay computes the original AEAD ciphertext before the digest query. Random mode retains the original body sampling, then tag sampling, then digest query. The real-mode branch makes the compiler total but is outside every source equality's mode precondition; it is not a new real-mode idealization.

`keyedSeal_exact` installs the returned local entry and shared ROM in the selected coordinate while preserving every other state field. `hiddenSeal_exact` retains the original associated-data width rejection, exact selected nonce and context, optional record reply, frame construction, writer outcome and pending-buffer reinstallation. A successful seal enters the literal frame buffer before any writer failure is observed. Neither the theorem nor its compiler assumes the writer succeeds or changes an adversary-supplied target plaintext.

`service_exact` covers every source service constructor under the actual pre-query `FreshPoint`. Its `service` endpoint delegates every non-sealing operation to the unchanged erased endpoint. `program_exact` lifts the equality through complete adaptive continuations: it derives each next fresh point from the proved `Virgin` invariant and attempted-coordinate history, and uses actual supported replies to maintain that invariant. `source_exact` supplies both initial virginity and the existing source `program_fresh` theorem. No source freshness, writer success, completion or cryptographic independence assumption is added.

Six statements expose local address and query facts. `seal_addressed` and `hiddenSeal_addressed` allow only the selected coordinate's private queries and finite coins, excluding ordinary hashes. `seal_digest_queries` and `hiddenSeal_digest_queries` give an all-reply digest-query cap of one. `seal_queries` and `hiddenSeal_queries` count every query in the explicit local compiler: one in replay mode, or the replaced plaintext length plus sixteen tag-byte coins plus one digest query in random mode. Width rejection may use fewer. The digest interpreter itself subsequently costs its separately charged 64 uniform byte queries; the original source and reductions must still pay their complete native and uniform costs. The number of whole sampled vectors is not substituted for their byte-query count.

This stage does not compile or budget ambient base/native services into the shared digest interface. Those services remain literal `ProbComp` source work in `service`, and this equality declares none of their work free. The subsequent combined compiler must preserve shared ordinary-hash memoization, establish coherent private-cache addresses when using a memoizing private oracle, prove its global request bounds, and connect the actual collision and guessing events to the statistical games. It must also consume the separate replay/random cache-observation law to return to the original counted CTX view. No primitive, codec, deployment, parser, persistence or security contract is introduced.

All thirteen public statements have exact axiom guards allowing only `propext`, `Classical.choice` and `Quot.sound`. The source and guarded module passed a bounded single-file Lean check; independent semantic review and publication metadata remain required before integration.
