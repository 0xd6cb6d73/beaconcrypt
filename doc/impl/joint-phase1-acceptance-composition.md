# One source writer followed by actual optional acceptance (HB-90)

`PqxdhJointPhase1AcceptanceComposition` connects one actual generated identity, the source-ordered signing block and the actual optional Phase-1 acceptance interface to one constructed joint weak-EUF reduction. Its `oneSession_authentication_bound` has coefficient one. It does not assume that the selected candidate belongs to an honest identity, and it does not assume the desired three-message signing log: the source execution establishes that log under explicit setup and selector signing/creation budgets.

This follows published `c4ad179f62b63610a9aeed4ebb917bb76832d158`. The new result is a typed source-interface authentication composition. It does not yet instantiate native material generation, Cap'n Proto decoding/serialization, publication/error ordering, the optional KEM/root execution, known-seed imports or the common global protocol experiment. In particular it does not assert the complete authenticated-root or end-to-end security theorem.

## Actual execution and event

`oneSession` asks the existing dynamic source interpreter to create an identity. Its private interpreter samples the same 32-byte Ed seed, publishes the actual joint Ed25519/converted-X25519 public pair at index zero and retains its complete private state and creation observation. `sessionBody` then runs setup, the prekey/one-time/PQ source signing program, the original selector and one final candidate query. That final query returns the complete actual attached-verifier/parser `Option` value. The original candidate and the returned optional decoded input are separate fields in `SessionResult`; no secretly recovered field is substituted into the candidate.

Setup and selection are arbitrary adaptive programs over the same source interface. They may request explicit randomness, actual optional converted DH, identity reveals and arbitrary other candidate checks, and they may adapt to those replies. The single-session theorem requires each setup and selector continuation to make zero additional signing requests and zero additional identity creations. These are structural `IsQueryBoundP` source-schedule conditions, quantified over every possible reply; they are not authentication or freshness assumptions. The source writer supplies the three signing requests in order. This models one such writer execution and does not infer a lifetime once-only signing policy from a successful registration: native attempts that fail later during serialization may already have signed.

Unchanged honest candidates, changed candidates under the generated identity, attacker-key candidates and rejection execute through the same interface. `SessionChanged` tests the actual final returned value: it must contain the created identity's Ed public key and a key tuple different from the source material. It additionally requires that identity's seed to be unrevealed at this acceptance. A target reveal is an allowed source request; it makes this event ineligible. Because the candidate query is last in this program, its final freshness is precisely freshness at that query. A later root/record continuation must preserve this report-time distinction; the present event does not require secrecy after arbitrary later compromise.

## Reduction and permanent contracts

`oneSessionReduction` is the existing `globalReduction` at the single generated target, composed with the dynamic `routedAdversary`, first recognized `reportExtractor`, `routedClient` and the exact `instrumentedClient (oneSession setup selector)`. The reduction receives only the joint public values and its explicit primitive oracle; the target seed remains inside the challenger. It preserves prior target DH observations, signing history, rejected calls and other candidate attempts. The final single-target sum has one term. There is no field-selection, candidate-attempt or extra session-position factor.

`oneSession_authentication_bound` bounds the probability of `SessionChanged` by the advantage of that specific reduction in the existing joint weak-EUF game. The winning event of that endpoint remains an ordinary fresh-message valid Ed signature. Its auxiliary chosen-raw optional converted-DH service is explicit and stronger than ordinary plain EUF; this composition does not claim that plain EUF automatically provides it. Functional generation/public conversion/DH/attached-signature contracts remain unchanged. The attached-format law supplies exact detached-signature splitting and short-input rejection, not a protocol-security conclusion. No primitive algorithm or implementation proof, custom axiom or new cryptographic endpoint is introduced.

## Query and local-work ledger

`liftDynamic_query_bound` preserves any source query class through embedding. `selectedProgram_query_bound` and `oneSession_query_bound` retain separate budgets for creation, setup, writer, selector and final acceptance, under every optional response. `oneSession_create_bound` derives cap one from zero setup/selector creations. `oneSession_class_bound` and `oneSessionReduction_class_bound` keep the exact ordinary joint classes: setup's cap plus selector's cap, with only signing adding three. Specializing their setup/selector signing caps to zero gives signing cap three for both actual source requests and the constructed reduction.

Let U, D, R, A and T denote the sums of the respective setup and selector caps for explicit uniform requests, optional-DH service attempts, reveal attempts, candidate attempts and total source requests. These bounds include rejected, invalid-index and repeated requests.

| Checked statement or specialization | Bound |
| --- | --- |
| `oneSession_create_bound` | One creation request. |
| `oneSession_class_bound`, `oneSessionReduction_class_bound` at signing | Three signing requests under the theorem's zero-sign setup/selector conditions. |
| The same class statements at DH | D logical optional-DH attempts; rejection remains counted. |
| The same class statements at uniform | U local uniform-oracle requests; no unused non-target identity is reserved when N=1. |
| `oneSession_reveal_bound` | R reveal attempts, independently of event eligibility. |
| `oneSession_attempt_bound` | A + 1 original candidate attempts. The existing actual-attempt theorem transfers this to the retained candidate log. |
| `oneSession_total_bound` | T + 5 original positions: creation, three writer requests and final candidate verification. The existing actual-position theorem transfers this to the complete source monitor. |
| `oneSession_actual_uniform_bound` | 32 + U for the actual source, including the on-demand target seed. |
| `oneSession_challenger_uniform_bound` | 32 + U for the entire joint challenger, including its secret target seed. |

The 32 seed draws are byte-valued uniform queries. Explicit caller uniform requests may have any finite range; the ledger counts uniform-oracle calls, not universally one-byte calls. The imported source writer's checked signing messages total 1,253 bytes. Attached signature construction, public verification (including repeated analysis checks), parser work, finite history scans, seed copying, material/context construction and all other deterministic primitive evaluations remain real local computation. Setup/selector query bounds cover their complete oracle continuations; separately supplied local functions are not thereby proved to have a native runtime or primitive-call bound. The eventual root/global interpreter must expose and charge every additional KEM, DH, Extract, HMAC, record and deployment operation in that same experiment.

The theorem's index is generated by the actual source prefix. This avoids an honest-selected-candidate premise, but it is not a native public-byte owner-lookup theorem. Supplied honest-seed distributions, byte aliases/ownership, material generators and their order, complete codecs, state publication, rollback/persistence and root/record freshness remain explicit later boundaries. Compiler correctness, native primitive implementation, physical erasure, foreign copies and durable storage/CAS remain external contracts.
