# Original native event and freshness lift

`RawCtxSelectedNativeFreshLift.native_event_bound` preserves the original native event and the existing byte-based selected-record freshness predicate. Their probability is bounded by the same completed event on the concrete adaptive CTX program plus one times the probability of the selected-nonce refusal event in the same instrumented source run. The event may include the original adversarial decision, authentication/secrecy gates and complete retained private state; the theorem does not replace it with a convenient new predicate or assume the decision is false after compromise.

The source game executes the literal `RawCtxProtocolReveals.protocolImpl` native record/public/reveal frontend using `RawCtxFunctionalFamily.backend` with the retained selected-KDF table. It is the native protocol frontend in that explicit private-derivation hybrid, not an assertion that the real production HKDF already produces uniform keys. The actual public HKDF service remains the real fixed-source evaluation. The preceding root and evolving-chain hybrid arguments are still needed to connect this game to real production execution.

`native_fresh` consumes the previously checked exact `RawCtxSelectedMessageStopping.native_event` theorem: stopping before returning unavailable selected material preserves the probability of every completed original event gated by original byte freshness. The actual attempted read is retained in history and itself makes freshness false. `mass_tv` transports arbitrary events across the full-distribution bound. `native_event_bound` then consumes `RawCtxSelectedFamilyNonceCoupling.executable_distance` without adding a query, a selection factor, or a second charge for nonce refusal.

`compiledGame` is the interpretation of the exact executable `FamilyLiveCompiler.client`; `nonceGame` is the explicit sticky refusal monitor on its augmented original-source execution. Every optional API reply, role, history observation, ambient field and shared cache remains in the comparison. The existing component-call bill and candidate cap apply unchanged. This corollary neither declares source work free nor bounds the source-side private derivation or uniform bills again.

This event comparison does not make an arbitrary event executable without the selected key. The retained predicate can inspect the key-interpreted private state, and original byte freshness can require comparison with that key. Constructing the actual key-free authentication/privacy winning predicate, justifying its freshness proxy and accounting for aliases remain separate obligations. Likewise the initial ledger and histories are arbitrary here: the nonce-refusal term can be one, and it still needs source provenance and a protocol bound. No honest-session, accepted-record, no-compromise or nonce-freshness premise is added. Full outer registration/installation schedules, selected-key distribution and nonexposure, and final session/record selection factors remain to be composed. Snapshot and persistence services are excluded.
