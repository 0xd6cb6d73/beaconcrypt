## The worlds

All worlds run the same key-free compiled client, `PqxdhRecordLiftProtocol.program`: the frozen interface program (`PqxdhRecordLiftInterface.program`, with the CE ledger wrapper and the mode projection `asModeO`) compiled to the ten private services of `PqxdhRecordLiftProtocol.ServiceSpec`. The worlds differ only in the private interpreter of those services.

`chains ideal` interprets the client with the mixed lookup policy `PqxdhRecordLiftMixedWorld.policy setup.source ideal`. A coordinate (slot, direction, position) with `ideal` false calls the actual native HKDF; a coordinate with `ideal` true reads the persistent lazy full76 table, which keeps its entries across rollback and re-derivation. `realChains` (every coordinate real) is the frozen record world: `realChains_analysis` shows that on the CE-12 analysis projection it is `PqxdhRecordLiftWorld.analysis <$> PqxdhRecordLiftWorld.run`, the projection that CE-11's C1 join `PqxdhDeploymentEnvironmentJoin.join_analysis` equates with the native deployment game, and `realChains_game` shows the same for `PqxdhRecordLiftWorld.game`. `chains_selected_zero` shows that index zero of the ordered hybrid of `PqxdhRecordLiftChainOrder` is `realChains`. `idealChains` (every coordinate ideal) is the brief's chain-ideal world (H-4).

`ctxRun modes replace` keeps `idealChains`' interpreter for eight of the ten services (`ctxInterpreter_base`: allocation, coins, public hashes, charges, table lookups, known-kernel sends and receives, publication) and changes only the two hidden-record services. A hidden opening (`hiddenOpening`) performs the source payload-parser rejection, the actual total getters on chains read from the table and the 153-byte associated-data check, then makes one keyed request `(coordinate, raw)` with the universal envelope that `RawCtxUniversalOpening.call` uses for a selected key, and returns the source API reply. A hidden sealing (`hiddenSealing`) performs the associated-data check, makes one keyed seal request with the selected input of `PqxdhRecordLiftCtxServices.sealCall`, logs the frame before the writer result and returns the source API reply. A malformed payload or a wrong associated-data width makes no keyed request (`hiddenOpening_malformed`, `hiddenSealing_narrow`). The keyed request of coordinate `c` is answered (`keyed`) by the one-key CTX local state of `c` in mode `modes c`, with the key and nonce of `c`'s table entry (`materialAt_native`: the native material of the same entry), the world's shared BLAKE2b cache and its counted coins.

The three modes (`keyImpl`): `real` is `AdaptiveCtxSharedModes.localImpl true`; `replay` is `AdaptiveCtxSharedModes.localImpl false`, which seals with the real AEAD, commits through a private suffix dictionary and accepts a raw frame only if it is in the coordinate's replay dictionary of successful seals; `random` (`randomImpl`, `randomSeal`) is the replay mode with a uniformly random body of the plaintext's length and a uniformly random 16-byte tag, intended as the seal semantics of the ordinary IND$ random experiment behind `AdaptiveCtxPrivacyGuard.randomView`. `keyImpl_modes` records that real and replay are exactly the two endpoints of `PqxdhRecordLiftCtxModeBounds.selected_integrity`, and `randomImpl_other` that random mode differs from replay mode only on sealing. No theorem here says that random mode is an endpoint of an existing bound: that the per-key hop from replay mode to `randomImpl` is the distance between `AdaptiveCtxPrivacyGuard.replayView` and `randomView` that `replay_random_advantage` equates with the IND$ advantage was an S4 obligation (closed: `PqxdhRecordLiftCtxRandom.randomTargetView_randomView` and `replay_random_target`; see open points). A hidden seal that repeats a nonce at its coordinate is refused (reply none, no frame); the native seal never refuses, so this is the explicit refusal that the refusal terms charge. That it never happens is an S4 obligation, not yet a theorem: one seal per material label in `ctxRun`, to be proved by transferring `PqxdhRecordLiftWorldProvenance.tracedSchedule_initial_nodup` through `ctxInterpreter_base` and the client-side `Control` invariant. The existing `PqxdhRecordLiftWorldProvenance.tracedProgram_nodup` is stated for the lookup-policy interpreter `tracedSchedule policy`, not for `ctxInterpreter`, so it does not apply directly.

`idealAuth` puts every hidden coordinate in replay mode. `idealRecords` puts every hidden coordinate in replay mode in observation mode O and in random mode in observation mode P (`idealRecords_O`, `idealRecords_P`); its replies are mode-projected by the unchanged `asModeO`. `randomRecords` puts every hidden coordinate in random mode in either observation mode. The plaintext map `replace` is the identity in every world except the hiding comparison.

## The view

`View` is the permitted decision view of a completed run: the adversary's output, the world-owned ledger (transcript with mode-O replies, the test session with its bit, the fresh messages), the environment's own final state, the tagged produced-frame log, the raw-attempt counters and the handle-to-slot map of installed hidden kernels (`handleSlot`, read from the stored record objects). It contains no seed, chain table, coordinate label, kernel byte, CTX dictionary, primitive counter or shared cache. The CE-12 analysis projection factors through it (`analysis_chainView`, `View.analysis`). The environment state and the slot map are additions beyond the analysis projection: the first is needed by the later-quantum post phase (R6), the second by the origin event; both make the targets stronger. Chain decisions may also read the final shared BLAKE2b cache; every other decision is cache-free, because commitment preimages contain message keys (decision D4).

For the secrecy targets, `hidingView` is the mode-P public projection that keeps the secrecy ground truth (the test bit and the fresh messages), and `publicHiding` erases that ground truth: the test session keeps its first handle and count, a fresh entry its handle and reply (`publicHiding_hidingView`). `PublicHiding` is the input of CE-LOR's public decision and eligibility.

## The targets

Every lift target has a Boolean form (`...Bool`: the `boolDistAdvantage` of the two worlds under a decision with coin cost `cost`) and an event form (`...Event`: the absolute difference of the probabilities of a Boolean event), and the statement is their conjunction (`...Statement`). The event form follows from the Boolean form (`chainLiftStatement_of_bool`, `ctxAuthLiftStatement_of_bool`, `ctxPrivLiftStatement_of_bool`, `ctxLiftStatement_of_bool`, `recordAuthLiftStatement_of_bool`, `recordLiftStatement_of_bool`, through `pure_advantage`). Each lift is quantified over every environment with `Frame env startup allowance` and every adversary with `budget.Respects adversary`, the premises that CE-11 discharges (C2a and the adversary budget). Each loss is an exact sum with coefficient one over the `hops n budget = positions budget * (n * 2)` ordered hybrid indices of `PqxdhRecordLiftChainOrder`, where `positions budget = sends + 51 * receives` is the frozen `Caps.derivations` (`positions_derivations`); the same indices enumerate target keys. Reductions are explicit parameters (`ChainReduction`, `CtxReduction`: one reduction per index, built from the environment, the adversary, the decision and the budget), and every reduction must respect a bill that is a function of `BillInput` (the budget fields, the environment's `Frame` data, the fresh bounds, the slot count and the decision cost).

`ChainLiftStatement` (item 5, `chain_lift`): `realChains` and `idealChains` differ, for every decision on the view and the final shared cache, by at most the sum of `hopLoss` over the indices (Extract on `uniform32` plus HMAC-PRF for each index's full76 observer, the right side of `PqxdhRecordLiftGlobalCut.observed_bound` and `PqxdhRecordLiftGlobalSeedCut.observed_bound`) plus the aliasing and refusal terms. Contract: `SourceFullCorrect`.

`CtxAuthLiftStatement` (item 4, integrity half, decision D1): `idealChains` and `idealAuth` differ, in either observation mode and for every cache-free decision, by at most the sum of `integrityLoss` over the indices (the four terms of `selected_integrity` for each index's one-key adversary at its hash and raw bills: IND$ validation, `qHash/2^128`, twice the attempt-indexed INT-CTXT sum, `qRaw/2^512`) plus the refusal term.

`CtxPrivLiftStatement` (item 4, privacy half, decision D1): `idealAuth` and `randomRecords` differ, in either observation mode and for every cache-free decision, by at most the sum of `privacyLoss` over the indices (the IND$ advantage of `AdaptiveCtxPrivacyGuard.viewReduction`, which `replay_random_advantage` equates with the distance between `replayView` and `randomView`; that this is the per-key hop between replay mode and `randomImpl` was an S4 obligation, closed by `PqxdhRecordLiftCtxRandom.randomTargetView_randomView` and `replay_random_target`; see open points). In mode P the right world is `idealRecords`. The mode-O instance has no consumer since the fix pass (the origin target no longer has an IND$ step); it is kept because the per-key privacy hop is uniform in the observation mode.

`CtxLiftStatement` (item 4, `ctx_lift` as the brief names it): `idealChains` and `idealRecords` differ, for every cache-free decision, by at most `ctxLoss`: the integrity loss and the refusal term and, in mode P, the privacy loss. `ctxLiftBool_of_parts` proves that the two halves give it: in mode O `idealRecords` is `idealAuth` and the integrity half alone suffices; in mode P the triangle inequality through `idealAuth` adds the privacy half, every term with coefficient one.

`RecordAuthLiftStatement` (the integrity record lift, decision D1): `realChains` and `idealAuth` differ, in either observation mode and for every cache-free decision, by at most `recordAuthLoss`: the chain loss at the decision that ignores the cache, the aliasing and both refusal terms and the integrity loss. It has no privacy reduction, so CE-OR and CE-UKS can consume it as soon as the chain lift and the integrity half are proved; `recordAuthLiftBool_of_parts` proves the composition by the triangle inequality, every term with coefficient one. Contract: `SourceFullCorrect`.

`RecordLiftStatement` (`record_lift`): `realChains` and `idealRecords` differ, for every cache-free decision, by at most `recordLoss`: the chain loss at the decision that ignores the cache, the aliasing and both refusal terms, the integrity loss and, in mode P, the privacy loss. `recordLiftBool_of_parts` proves that the three parts give it by the triangle inequality, every term with coefficient one. Contract: `SourceFullCorrect`. CE-APP and CE-LOR use it in mode P; CE-OR and CE-UKS use `RecordAuthLiftStatement`, because `recordLiftBool_of_parts` takes the privacy half.

`OriginStatement` (`idealRecords_origin`): in `idealAuth` and `idealRecords`, in both observation modes, the probability that some accepted raw receive on a handle holding hidden slot `j` carries a frame that no handle of the opposite role holding `j` ever produced is zero (`UnproducedAccept`, the replay-dictionary invariant). The probability of CE-OR's event (`UnpublishedAccept`: the frame was not returned by such a handle earlier in the transcript) is at most `publicationTerm budget = guessTerm budget = 2 · R · S / 2^512` in each of `idealAuth`, `idealRecords` and `randomRecords`, in both modes (decision D2, owner input 9). The term is purely statistical and needs no privacy reduction: in replay and random mode the commitment of a hidden seal is a uniform 64-byte value of the coordinate's private suffix dictionary (`AdaptiveCtxSharedReplay.localPrivate`), never written to the shared cache, and replay acceptance compares the full nonce, associated data (which binds the frame's sequence number and sender) and encoded record including the commitment (`AdaptiveCtxReplayDictionary.replayPlaintext`; `RawCtxFrameDecoding.fromPayload_record` makes the payload encoding canonical). A produced but unpublished seal (its writer failed) leaks at most the writer's success bit, hence the factor 2; the commitments of distinct seals are independent. `guessTerm_le` shows that the term is at most the first draft's `R · S / 2^128`. Contracts: `FrameReadBack` (a returned ciphertext reads back as its frame) and `DecoderAgreement` (Server routing agrees with the frame's sender).

`BindingStatement` (the CE-UKS part of `idealRecords_origin`): in `idealAuth` and `idealRecords`, in both observation modes, the probability of `CrossAccept` is at most an explicit cross-handle term `crossTerm` of the bill input; `BindingTarget` fixes it to `bindingTerm = (R + S + H) · S / 2^512`, with `H = sharedHashTotal` the shared-hash total `hash + S + R + envTotal allowance .hash` of `PqxdhRecordLiftWorldBudget.run_hash`. `CrossAccept` is an accepted raw receive on a handle `first` whose decoded frame some handle `second` returned anywhere in the transcript, where one of the two holds a hidden slot and they are not partners (`Partners`: opposite roles holding the same slot). Because the return may come before or after the receive, either choice of the designated handle in CE-UKS is contained. The bound rests on the private commitments, not on the frame's sender field: every Server peer seals with the same sender, the Server identity key ID (`PqxdhRecordLiftProtocol.serverStep` passes `server.sender`; in Rust `Server::encrypt_message` uses `self.identity_key_kid` for every peer and the frame's key ID is the sender), and a Beacon seals with its assigned ID `shell.identityKeyId` (Rust `Beacon::encrypt_message`), which the adversary delivers and which need not be unique, so frames of two peers, or of two Beacons, can differ only in their record bytes. A frame of a hidden handle accepted on a known handle needs a shared-cache output to equal a private commitment, and a frame returned by two handles needs two independent commitments, or a cache output and a commitment, to collide. Contract: `FrameReadBack`.

`HidingStatement` (`idealRecords_hiding`, mode P): replacing every hidden seal plaintext by one of equal length does not change the law of `hidingView`, the mode-P public projection that keeps the secrecy ground truth (output, the mode-P transcript view, the test session, the fresh messages with their replies, the environment state, produced frames, counters and slot map). `hiding_advantage` and `hiding_event` give the Boolean and event forms with advantage zero. No contract. It is the intermediate form: replacement does not touch the ledger's draws, so using it for CE-APP or CE-LOR would leave CE-12 an induction over the world's interpreter. The two final-world forms below remove that step.

`FreshGuessStatement` (CE-APP's final-world fact; mode P, every environment and adversary, no `Frame` or budget): for every claim function of the adversary's output, the probability in `idealRecords` of `FreshHit` (the claimed admitted fresh message was sent on a handle holding a hidden slot and equals the guess) is at most `2^{-min}`, where `min` is the ledger's lower bound on fresh lengths. No contract.

`LorStatement` (CE-LOR's final-world fact; mode P, every environment and adversary, no `Frame` or budget): for every public decision and public eligibility on `PublicHiding`, the probability in `idealRecords` that the run is eligible, every test the ledger admitted named a handle holding a hidden slot (`TestsHidden`) and the decision equals the test bit is exactly half the probability that the run is eligible and `TestsHidden` holds. Admission is recomputed from the transcript with the ledger's own `Admissible` and `SameSession` (`AdmittedTest`, `firstTest`) and depends only on the mode-P view (`admittedTest_view`). Putting `TestsHidden` inside both events, rather than requiring that eligibility imply it, makes the statement hold for every eligibility; CE-12 removes it on the support of the ideal world, where its eligibility implies it by C5. No contract.

Both final forms are to be proved in S5-E by a pointwise coupling. Random-mode seals of equal-length plaintexts are identical for the same coins, so resampling a fresh message, or flipping the test bit, is a measure-preserving map on runs whose secret sends all went to handles holding a hidden slot or to handles with no installed kernel; it changes only the ledger's secrets, the mode-O replies in the ledger's transcript and the CTX dictionaries, none of which `PublicHiding` or the adversary's mode-P view reads. The environment never sees a record reply (records bypass it in `PqxdhRecordLiftInterface.native`), and a handle's slot does not change after installation (a vacant peer key ID, an owner in `initSent`), so the final slot map describes every earlier send.

`ChainLiftTarget`, `CtxAuthLiftTarget`, `CtxLiftTarget`, `RecordAuthLiftTarget` and `RecordLiftTarget` fix the aliasing and refusal terms to zero (`noTerm`, decision D3), and `BindingTarget` fixes the cross-handle term to `bindingTerm`. The structural reasons for zero, which the delivering stages must prove, are recorded with decision D3 below.

A target with free reduction or term parameters is a statement shape. An artificial reduction (for example an unbounded observer with advantage close to one) satisfies it trivially, so a target is a deliverable only together with the explicit simulator-built reductions and closed-form bills of the theorem that proves it, and those are reviewed with that theorem.
