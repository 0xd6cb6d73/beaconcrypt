# Ideal-record dictionary updates

`PqxdhRecordFactsOriginDictionary` gives seven support facts used to connect local replay witnesses to the global source execution. It preserves the actual shared hash interpreter, counted sampler, and persistent per-coordinate suffix caches. It proves no distribution replacement or probability bound.

`localRaw_seals` covers successful and rejected raw inputs and proves that they preserve all earlier seals. `localSeal_step` and `randomSeal_step` cover replay-mode and random-mode sealing: nonce refusal adds nothing, and successful sealing prepends exactly the request input and returned record. This does not assume that the private commitment lookup is fresh: a previous raw input may have populated its cache entry. `key_step` combines these facts for every request of an ideal key, including public hashes and coins. Its explicit premise excludes real opening mode.

`keyed_witness` connects the actual coordinate-indexed interpreter to a supported result of its one-key program. It retains the same returned value and exact selected coordinate state. Other coordinates remain unchanged; the source chain, seeds, produced frames, and pending frames are unchanged by this keyed step. The shared hash cache and uniform counter may change and are retained by the original execution. The theorem takes a support projection for its conclusion, not a claim that these effects are absent or free.

`keyed_step` supplies the exact seal-list rule at the selected coordinate and preserves every other coordinate. `keyed_frame` applies the independently checked replay/frame witness to an actual global keyed raw request: a successful reply in replay or random mode has a frame decoded from the original raw bytes and an earlier matching entry in that coordinate's dictionary, with the same plaintext.

These lemmas introduce no cryptographic game, query, reduction loss, or new assumption. `localSeal_step` reads the functional primitive interface, including the tag-width field used to construct the record; it makes no primitive security claim. [OriginInvariant](record-facts-origin-invariant.md) now identifies each dictionary entry with a correctly tagged production in this same execution. The accepted-entry join, successful-write transcript join and stated failed-writer probability bound remain open. The whole `OriginStatement` is still open.
