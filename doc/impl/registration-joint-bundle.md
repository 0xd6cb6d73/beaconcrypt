# Native registration bundle through indexed private services

`PqxdhRegistrationJointBundle` connects the actual `RegistrationSchedule.bundle` operation to the existing joint Ed25519/X25519 identity service. It retains the locally held prekey and one-time material while replacing the identity seed and KEM secret pair in the client with public material and service indices. The identity index has an explicit created-slot lookup; the supplied KEM index is retained without a KEM ownership claim, because the bundle does not decapsulate. The public owner address and the private identity index are separate parameters; they are never equated or selected by public-key equality.

The central `client_source` equation interprets the handle client and compares its entire result against a common source trace. That trace draws the one-time scalar only in the actual Fresh branch, uses retained material in FreshWithCoins, and rejects inactive phases without drawing anything. It performs the three real signatures in prekey, one-time, KEM order and then calls the original optional writer. Both successful and failed serialization retain the entire prior identity-service history followed by those three replies. A successful writer publishes the exact source InitSent state; a failed writer keeps the original owner. The client has no separate identity-seed or KEM-secret field or argument. This representation theorem does not exclude equal bytes or correlations among its actual retained scalars and public values.

`native_after` and `native_bundle` prove that the literal native callbacks produce the first projection of that same trace for any public owner address. `native_source` reinstalls the returned owner at the exact original list address while preserving every other owner, the complete Server, pending state and both primitive caches. The two continuation theorems quantify over arbitrary continuations on the complete result and state; they are not marginal public-key comparisons or generator-interchange assumptions. The client equation retains an arbitrary auxiliary state unchanged, so the private KEM pool and other untouched scheduler fields can remain in that coordinate.

The exact created-handle lookup is a representation precondition of the local client equation, not an authentication or honest-candidate assumption. `RegistrationJointCreation.service_owns` proves it for actual newly allocated identity slots; the existing live joint service preserves the seed pool when signing. `after_seeds` proves that preservation for the complete local source result. Its preservation through the rest of the common scheduler remains a separate composition obligation. This module neither assumes that the public owner address is the identity index nor proves the whole dynamic scheduler merely from this local relation.

The logical client bounds count at most one generator attempt, three signature-service attempts and one writer attempt on every optional branch. The complete evaluated trace and handle client use at most 32 uniform byte queries. This evaluated bound uses the actual pure signing and optional writer interfaces already present in the native scheduler; it does not count their CPU work as zero or declare arbitrary external callback work free. No KEM generation or decapsulation occurs during this bundle operation. Their actual constructor and finish costs remain separate. Repeated failed publications append their three signatures again and must be charged again by the later scheduler bound.

This proof uses existing primitive functional interfaces and the abstract optional message writer. It adds no security game or assumption, does not prove serialization internals, and supplies no global forgery advantage. The full identity/KEM lifecycle, converted-DH and reveal routing, adaptive target selection, global query ledger and common symbolic event map remain consuming obligations. Existing one-session authentication results and old `noCreate`/`noSign` theorem scopes are not widened by this local operation equality.
