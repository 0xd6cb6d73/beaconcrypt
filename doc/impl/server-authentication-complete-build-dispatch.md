# Complete Server build dispatch under the dynamic CTX interpreter

`PqxdhServerAuthCtxBuild.build_source` relates the complete concrete build operation to the original `EntryFactor.buildStep`. It includes the actual pending-token lookup, marked-session dispatch, complete selected or ordinary builder, token consumption, native response settlement and session-labelled source seal trailer. An absent pending token returns failure without invoking a builder. For a reached selected builder only, the theorem requires the component's selected used-nonce list to be empty. The enclosing stopped scheduler still has to prove this operational invariant; it is not an authentication or cryptographic premise.

`complete` calls the original `afterBuild` with the actual native outcome and returned local successful-frame log. It consumes the pending token, settles the full Server state and appends every returned context under the same source session index. No filtering depends on the later response result: a successful frame seal remains logged when the later registration writer fails. `complete_restore` shows that this operation commutes with restoring the component-owned cache. All other protocol fields, table annotations and the designation flag remain intact.

`post` keeps an outer component refusal distinct from an ordinary native failure. On a normal component result, it applies the complete native settlement even if that result is an absent response or native diagnostic. On outer refusal, it keeps the reached protocol state without pretending a native reply was produced. `after_evaluate` preserves the full component state and restores its actual reached cache on both routes. Under the source-comparison theorem's unused-endpoint condition, the equality itself proves that outer component refusal cannot occur: every source result is wrapped in `some`.

`selected` starts the builder's local successful-frame trailer at the actual empty list. `selected_source` applies the checked complete selected builder equation, retaining its full native outcome, returned Server, all original auxiliary checks and both optional writers. It then uses that exact local trailer in session settlement. `known` uses the original root, real initial KDF and native tail on the same shared cache, and `known_source` proves the corresponding complete source equation. Known-key byte aliases remain permitted; no honest-token or successful-build restriction is introduced.

`build_source` combines these two equations with the actual token and mark tests. Its endpoint condition is conditional on both a present token and a marked session. An ordinary build and an absent-token attempt require no selected nonce invariant. The compared result contains every protocol field and cache effect after the existing mathematical projection; the executable component evaluation retains its complete private state before that projection. The executable receives no explicit selected-key or component-cache argument. Arbitrary correlations in its supplied local values and residual material are still allowed, so this operational equation alone is not a challenge-independence theorem.

These five equations add no oracle request, sampling, selection factor or probability loss. The selected builder retains its already checked limits of one total component request, selected sealing at most one, forwarded hashing at most one, and zero selected raw-opening or uniform requests. The ordinary builder retains its actual native/hash program and established callback accounting. Local KDF, validation, allocation, abstract writers and component-interpreter work are unchanged and are not declared free. The global source and reduction budgets must still include those costs.

This module provides the complete build callback for the adaptive compiler. The global stopped-handler simulation, unused-endpoint invariant, concrete resource ledger, actual sampled context/key distribution and seal-session-to-acceptance chronology remain separate consumers. Primitive internals, serialization implementation, saved-state restoration and persistence remain outside the approved proof scope. The existing programmable Extract and shared CTX/BLAKE2b ROM contracts are unchanged.
