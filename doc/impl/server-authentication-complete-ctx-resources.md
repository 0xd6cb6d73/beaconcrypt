# Complete query ledger for the ordinary CTX authentication client

`PqxdhServerAuthCtxResources` discharges the remaining resource obligations for the exact client constructed by `PqxdhServerAuthCtxExperiment`. The complete adaptive compiler, its actual context and residual samplers, the all-attempt authentication observer and the ordinary selected-key reduction all have explicit bounds. The proofs do not condition resource accounting on successful acceptance, a good event or an honest selected target.

Let `G`, `E` and `D` denote the existing `KemCaps.keygenCost`, `encapsCost` and `decapsCost`. Each includes the actual primitive program's direct uniform draws and its base-query allowance multiplied by the base interpreter's uniform cost. The original adversary has four bounds, for every public input: `qCoin` explicit random queries, `Q` accepts, `qHash` public shared-hash requests and `qH` patched-HMAC requests. Define the existing source bill

```text
U = entryReductionBudget caps qCoin Q qHash qH
  = 256 + qCoin + 160*Q + 64*(qHash + qH) + G + Q*E + D.
```

These primitive resource contracts and four original source caps are explicit premises. `AuthBudget` alone does not provide them. Actual arbitrary-key KEM work, rejected prefix work, table sampling, public evaluations and known-key processing are retained.

## Complete adaptive component accounting

`route_total` supplies a conservative total component-request cap for each of the seven actual compiler routes. It consumes the checked real accept, finish, build, HMAC and quiet-route bills. A finish may execute its prefix and opening before refusing; those requests remain charged. A build may fail its writer or the outer component stop; the attempted work remains charged. `handler_total` proves that the literal designation and sticky-refusal wrapper add no request.

`stopped_total` applies the existing adaptive source potential to the actual optional compiler. For every syntactically supported normal result, the concrete handler footprint supplies token consumption, allocation and phase behavior. Stopped results need no future-state invariant, but all work performed before stopping is paid. `continuation_total` instantiates this argument with the original adversary and the literal empty initial state, giving `entryRunBudget` without a caller-provided valid-state premise.

`client_total` adds the actual original-R1 context sampler and the 76-byte residual sampler. Its complete component-request cap is `U + 76`. The context has four 32-byte samplers and full KEM generation; the residual contains nonce12, next-chain32 and opposite initial-chain32. The original joint-factor projections are not independently resampled. The already checked native source-order bridge remains unchanged.

## Actual interpreted uniform work

`client_uniform` proves a uniform-query cap of `U + 76` for the complete client interpreted by the ordinary component source, including its full resulting component state. It uses `CtxExperiment.client_source`, an equality of the actual `OracleComp` programs, and the already discharged stopped-source bill. It does not transfer resource counts from equality of evaluated probability distributions, which would be insufficient.

`source_game_uniform` adds the challenger's selected 32-byte key draw, giving `U + 108` for the full ordinary source game and its full poststate. The selected key and residual remain separate parts of the same original 108-byte output. No selected-key sampling is charged twice, and no surrounding callback work is omitted.

## Client, observer and ordinary reduction classes

`client_bills` gives the exact concrete client four explicit ledgers: at most `U + 76` explicit uniform routes, at most `U + 76` shared-hash routes, one selected seal and one selected raw attempt. The uniform and hash route bounds are conservative projections of the proved total component-request bound; they are not claims that every request belongs to both classes. Known-key seals and verifications that invoke shared hashing are included by the existing `HashRoute` definition. `client_hash` exposes the same discharged hash bound directly for the final integrity consumer.

`observer_bills` consumes the actual observer's query-preservation theorem. Recording the original raw bytes, actual optional plaintext and attempt-time seal history adds no oracle call; all four bounds therefore hold for that exact observer, without synthesizing a target or assuming freshness. `reduction_bills` then invokes `AdaptiveCtxDynamicKnownBounds.decision_budgets` on that same observer. The actual constructed ordinary `ReceiveSpec` reduction has uniform and shared-hash caps `U + 76`, selected-seal cap one and raw-attempt cap one. Real known-key simulation and its shared-hash requests remain in this reduction.

## Scope and validation

These eleven statements add no cryptographic assumption, event premise, reduction loss or query. They bound oracle requests, not wall-clock time, storage size or deterministic primitive/codec computation. The latter operations remain in the actual programs under the existing implementation and efficiency contracts; they are not removed or declared free. Downstream primitive reductions retain their own challenger/query overheads.

The source experiment keeps `revealSeed=false`, the approved no-KCI capability scope, restricted programmable Extract ROM and shared CTX/BLAKE2b ROM. Primitive implementations, serialization implementation, snapshots and persistence are outside this proof. This ledger does not itself prove the original event implies an ordinary forgery or finish the global authentication theorem; those consumers use these exact constructed interfaces and bills.
