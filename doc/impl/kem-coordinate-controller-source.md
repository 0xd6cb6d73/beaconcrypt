# Source interpretation of the authentication-only KEM controller

The authentication-only abstraction gives its controller the actual KEM ciphertexts and shared-secret replies and then permits arbitrary optional KEM replies. This is an explicitly stronger observation than the production network interface. It is useful for asking which registration-origin events need DH and record authentication even when no KEM contribution is secret. It is not the Server root-secrecy experiment, and it neither asserts KEM cross-public-key binding nor changes the fixed ML-KEM implementation.

`PqxdhKemCoordinateController` defines two typed controller requests: encapsulate under the exact 1184-byte public key, and decapsulate the exact 1088-byte ciphertext using a public key and stable creation index. The descriptor contains no KEM secret, converted identity seed or DH scalar. Responses retain the actual option: an encapsulation ciphertext/32-byte secret pair or a decapsulation 32-byte secret. The concrete controller calls precisely the corresponding original native KEM callback and appends that actual optional result to an explicit disclosure history. The controller interpreter is trusted simulation code; its private-state argument is not an adversarial state reveal.

`step_source` and `program_source` establish equality of the complete original reply and native poststate after erasing only the added history. The latter applies to the entire adaptive native program, with no restriction to successful KEM results. `continuation_source` supplies the same evaluated continuation with the complete original result and private state. `uniform_iff` preserves the exact original uniform-query allowance in that same syntactic computation; it does not transfer resource bounds through a mere equality of evaluated distributions. `concrete_only_kem` shows that changing all non-KEM callback implementations has no effect on this controller, provided the two KEM callbacks are unchanged. Thus this controller does not require a separate DH or identity-secret operation.

`PqxdhKemControllerSource.server_source` consumes the literal ordered `PqxdhServerRootPreparation.collect` client. Decoding, identity checks, the three attached-signature verification positions, field tags and widths, registration reservation, point admission, ephemeral generation and KEM-key admission remain in their source positions. Every optional failure retains the effects already performed. Encapsulation precedes identity conversion and all four DH operations.

`beacon_source` consumes the actual `PqxdhBeaconPhase2Preparation.owner` client. Inactive owners reject unchanged; every active preparation failure follows the original terminal abort and outer identity-ID update. Decoding and ciphertext/ephemeral/identity getters precede both identity conversions. Decapsulation precedes DH1 through DH4, the assigned-ID getter and the extracted pin/zero-DH checks. Shared-secret clearing still follows extracted preparation on both outcomes. Short or malformed ciphertext rejection stays in the typed getter. For a length-correct invalid ciphertext, the concrete callback retains the native ML-KEM fallback result and the subsequent source computation; there is no invented public rejection flag or injective fallback constructor.

`server_root_source` goes beyond the raw prefix: it consumes the complete existing native root helper, including extracted acceptance, clearing the shared-secret temporary, deriving the root, clearing the copied input, consuming the registration ID and returning the full cleared pending token. It preserves the complete related-input family history/cache and the actual auxiliary state. The previously established `PqxdhServerRelatedRootConsumer.stage_real` supplies a separate real related-DH/Extract interpretation of this same native helper under its stated functional source contract. No smallness of that additional related-input advantage follows from the controller simulation.

`PqxdhKemControllerBounds` separates source KEM attempts from other callback work. A Server raw prefix uses at most one encapsulation and twenty-one other callbacks. Beacon owner preparation uses at most one decapsulation and twelve other callbacks, including erasure after a late core rejection. `server_interpreted` gives the selective underlying query bound `qKem + 21 * qOther`; `beacon_interpreted` gives `qKem + 12 * qOther`. Their hypotheses bound each actual stateful callback, uniformly over reached inputs and state. A local interpreter must pay the actual allowance for every reached callback, including rejected attempts and generator work. These are primitive/oracle query counts; copying or appending audit data is not asserted to have zero running time. Subsequent root/publication/record continuations retain their separately stated allowances.

This package establishes an operational source interpretation, not an authentication reduction. The arbitrary-KEM symbolic process must still be connected to its target events and exact protected joint identity/prekey freshness rules. Its public controller adds observations that must be stated explicitly. The related-DH/Extract and CTX hybrid terms, repeated-input aliases, target selection and the common global experiment remain separate obligations. The ordinary ML-KEM IND-CCA reduction continues to serve Server root secrecy; this authentication-only abstraction does not replace it. No snapshot or persistence behavior is modeled.

`PqxdhKemCreationController` supplies the additional generation interface required by the symbolic controller. Its request is the exact next public creation index and its reply is an optional 1184-byte public key. The concrete interpreter runs the original KEM generator, appends the actual private pair to the source pool, and adds only the index and public key to the explicit public audit. It neither equates nor separates distinct public-key byte strings. `generation_source` proves this full computation, `constructor_source` consumes the actual identity/prekey/KEM owner constructor in its original source order, and `program_source` preserves every adaptive joint-service, generation, decapsulation and reveal program after erasing only the added generation audit. Concrete honest generation returns a successful optional reply; the abstract controller may additionally fail or choose aliased public keys. `uniform_iff` preserves the exact original syntactic query bill, including all preceding optional failures and all generator work. The private interpreter state passed to these functions is trusted simulation state and is never an adversarial state disclosure.
