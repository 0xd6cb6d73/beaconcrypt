## Exact source and executable log simulation

`AdaptiveCtxLogSimulation.runLogged` is an explicit recursion over the adaptive ordinary nonce-AEAD interface. It forwards encryption requests and arbitrary finite uniform requests. It records supplied plaintext only when that encryption returns a ciphertext. A raw request is decoded into its unchanged nonce/AD/ciphertext tuple and answered with the recorded plaintext if that exact tuple appears in the encryption log; all other raw requests return none. The simulator has neither the challenge key nor an opening oracle. It never creates an adversary request containing secretly recovered plaintext.

`runLogged_projection` proves equality for an arbitrary complete continuation and initial state after projecting the old adaptive game's extra attempt/discrepancy monitor. The simulator does not evaluate the monitor's hidden-key opening, even as ghost computation. `runLogged_history` proves its complete returned encryption log equals the real ordinary challenger's successful encryption history. `primitive_preserves_nonceHistory` identifies the actual used-nonce list with that log's nonce projection, and `ordinary_run_nonce_count` bounds its length by all sealing requests, including rejected nonce reuse. `sourceClient_validation_fresh` combines these operational facts with `qSeal < 2^96` to prove the constructive validation nonce is fresh against the actual challenger state.

`sourceClient` instantiates this recursion at the previously checked independent-public CTX wrapper. Its returned result already contains the entire source state: public/private dictionaries, complete sealing/nonce history, public hash trace, raw-attempt counter and every private suffix lookup, including failed verification and cache hits. `retainedLoggedGame_eq` identifies that full source result exactly with the log/reject world's projection while retaining the same sampled key only in the terminal analysis. The adversary never receives this retained key.

The actual private suffix remains the source nonce, associated-data bytes, base tag, little-endian sequence and little-endian sender identifier. The ciphertext body is not added to the CTX suffix. Every well-formed raw request looks up or installs that suffix before commitment comparison, including rejection. Existing cache entries are reused after failed queries; there is no new independent sample per attempt or per honest seal.

## Constructed conventional reduction and losses

`validationReduction` runs that ordinary client, obtains the fixed `qHash`-slot candidate vector from its public input trace, chooses an unused nonce using the bounded twelve-byte counter scan, and requests one encryption of an empty plaintext with empty associated data. `validationAccept` checks the returned 128-bit tag with an explicit finite list scan against tags obtained by local encryption under the candidate keys. `validationAccept_eq` proves that scan equals the existing classical finite-existential decision; `validationCandidates_length` identifies its exact `qHash` slots and `validationAccept_no_queries` records its zero additional oracle calls, without making candidate-key evaluation free. This is the existing ordinary Boolean IND$ game, not an endpoint that tests a guessed key secretly on the adversary's behalf.

`loggedProbe_le_validationReal` proves that a real hidden-key candidate hit validates. `validationReduction_random_le` bounds the same Boolean client's random-world success by `qHash / 2^128`. If its nonce is already used, the random-world sealing oracle rejects and success is zero; otherwise the last tag is a fresh independent 128-bit sample. The candidate vector and all prior adaptive source state are fixed before that sample. `loggedProbe_le_indDollar` combines these facts into the concrete ordinary advantage plus the statistical validation term.

`independent_prefix_eq_probe` uses the proved public-trace length bound only in the actual independent source experiment. `probEvent_le_add_ofReal_tvDist` then transports that fixed vector-hit event to the executable logged world across the full retained-key transcript distance. No claim about equality with an unbounded logged trace is needed. `independent_prefix_le_indDollar_add_intctxt` therefore bounds the actual prefix event by the constructed conventional IND$ advantage, `qHash / 2^128`, and the existing sum of ordinary INT-CTXT advantages over every raw-attempt index.

## Query and computation ledger

`runLogged_query_bound` retains every ordinary query-class bound. `sourceClient_seal_bound` gives at most `qSeal` ordinary encryption requests. `sourceClient_uniform_bound` gives `qCoins + 64 * (qHash + qSeal + qRaw)` uniform-oracle requests. Each digest miss contributes 64 byte-valued requests; source `qCoins` requests may use any finite range. Failed private lookups remain included, while cache hits consume no new randomness.

`validationReduction_seal_bound` gives `qSeal + 1` ordinary encryption requests, and `validationReduction_uniform_bound` retains the same source uniform cap. The reduction makes zero opening-oracle requests. `validationReal_uniform_bound` includes the real challenger's 32 key bytes, giving `32 + qCoins + 64 * (qHash + qSeal + qRaw)`. Each integrity reduction separately has `qSeal` ordinary encryptions, the same reduction uniform cap, no opening oracle, one final verification and 32 challenger key bytes. The source shared-ROM game retains its previously checked raw/public/private counters and complete interpreted uniform ledger.

These counts do not make local computation free. The logged simulator may scan its complete successful encryption history at each raw attempt; it processes the actual raw bytes and decoded tuples. Each validation candidate can require one local AEAD evaluation, for at most `qHash` candidate evaluations, plus tag comparisons. The nonce selector constructs at most `qSeal + 1` candidates and scans the used-nonce list; its bounded-search interpretation is recorded in [the constructive nonce record](constructive-validation-nonce.md). Cache lookup, log storage and byte processing remain actual work. The random ordinary challenger additionally samples each successful requested ciphertext body of its plaintext length and a 16-byte tag; a complete bound for those challenger-private draws needs a total plaintext-byte budget. No such byte bound is inferred from `qSeal`; the [weighted plaintext refinement](adaptive-ctx-plaintext-accounting.md) now proves the explicit source-byte lift and complete random challenger bound for this exact validation reduction.

## Contracts and remaining composition

Ordinary nonce-AEAD correctness, INT-CTXT and conventional IND$ retain their exact existing interfaces and winning events. The programmable classical shared ROM remains an explicit idealization stronger than BLAKE2b collision resistance. No primitive implementation or internal cryptographic security proof is attempted. The recursive log interpreter and bounded nonce scan have concrete algorithms, while inherited abstract oracle/cache representations and native primitive functions remain the stated model boundary; the declarations alone do not establish compiler-level executability or an asymptotic runtime theorem.

An already encrypted base tuple with a changed outer context may still receive its previously supplied plaintext in the logged ordinary game. Its CTX digest is a persistent hidden dictionary value, including after failed guesses. That alias event needs its own checked adaptive guessing simulation and accounting. The one-target `2^-512` theorem cannot simply be multiplied by `qRaw` without that argument.

The decoder remains an explicit public function. Native complete-input CryptoFrame refinement, exact parser/adapter provenance, ratchet consumption and replay, rollback, evolving and correlated keys, multiple sessions, copied snapshots, permitted reveals and freshness remain global protocol obligations. Per-key nonce uniqueness supplies no inequality between nonces under unrelated keys. Compiler and perfect native primitive correctness, physical erasure, trusted persistence integrity, rollback resistance, linearizable CAS/ownership and crash behavior retain their external contracts. This milestone alone establishes no new ProVerif event and does not close the complete protocol goal.
