# Native send events and source provenance

`RawCtxSelectedSendEvents` connects the retained private audit to one literal native send driver. Its `services` definition uses the original `RawCtxSelectedMessageDriver.sendServices`: prior-table lookups return their real retained response, and sealing uses the actual native source interpreter with its full primitive state and optional writer result. The selected message key is confined to that mathematical interpreter. The executable audited driver and event construction do not receive it.

`derived` checks the exact request and response recorded after private derivation. `requested` checks the entire admitted send: the derivation event precedes the sealing event, and that event contains the actual caller, old kernel and ready sealing capability. The complete advanced kernel, optional ciphertext and shared poststate are preserved. A failed native writer still records its seal attempt and returns the advanced send state. Exhausted admission emits no event. Empty application messages are rejected by the already checked outer owner gate before this driver is invoked.

`history_exact` derives the event suffix from a supported execution of the concrete source interpreter. `recorded_sealing` then constructs the real admission and routing witness for any seal in that suffix. It identifies the suffix by position after the old history, so repeated identical event values are allowed. The theorem does not assume that the occurrence was absent from the old history or that the caller supplied a correct routing trace. `sealing_routed` retains the original caller and old kernel along with the exact ready response.

`selected_chain` attributes any hidden-material seal in that source suffix to the actual target sending-chain bytes. On a later derivation it also retains predecessor-address priority, including collisions between the target address and the saved predecessor. This uses source request construction and byte representation; it does not assume HKDF injectivity, nonce uniqueness, distinct identities or an honest target. Equal nonces under unrelated known keys do not become selected-material events.

`erased_source` removes only the private events and returns the same complete source operation. `uniform_queries` proves that the audit has precisely the original source uniform-query allowance for every budget, including unsuccessful writes. `events_length` gives at most two audit entries per invoked send driver: one derivation and one seal attempt. These are bookkeeping and oracle-query statements, not running-time claims. Retained-table lookups, parser and writer work, private state copying and list operations keep their ordinary costs and the existing separate source lookup and primitive ledgers.

The nine guarded statements add no cryptographic advantage or statistical loss. They cover a concrete send operation under its supplied correlated entry, prior table and shared state. Their whole-family source consumer, dynamic installation ancestry, repeated selected-nonce probability, reveal conditions and global target-selection losses remain subsequent obligations. A source routing witness alone is not a nonce-reuse bound. Primitive implementations, snapshots, persistence and restoration remain outside scope.
