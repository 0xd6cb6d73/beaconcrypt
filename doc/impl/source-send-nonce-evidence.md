# Source sends, nonce evidence and initial directional aliases

HB-121 derives send evidence from the original native callbacks and preserves it through their actual receive work. These results supply the source events and one initial-alias probability charge needed by the global nonce reduction; the complete multi-origin dispatcher and later path-collision charge remain required.

## Original selected send and nonce ledger

`RawCtxSelectedSendTrace` records each actual selected sealing callback using the original outer owner, original key-free entry kernel and original pending seal. The compiler never receives the selected key. Owner labels are supplied by actual dispatch, never inferred from sender IDs, associated data, key bytes or derivation addresses. The trace includes every valid-width hidden sealing attempt, including a failed optional writer and the final refused nonce attempt; known-key seals and invalid-width rejection retain their original behavior.

`erase` proves literal component-program equality after dropping only the private trace. `repeated_source` and `stopped_source` prove that the explicit outer refusal is an already-used selected nonce with unchanged complete component state. A writer returning `None` remains an inner optional result and cannot cause this refusal. `call_used` and `scalar_used` prove that each actual callback can add only its own selected nonce to the component ledger, retaining known-material byte aliases and all other state. `tracked_step` and `recorded_step` preserve the relation between the component ledger and original occurrence history for every supported result; `initial_tracked` obtains that relation from the ordinary empty initial state.

`stopped_evidence` then derives an earlier occurrence in the old history with exactly the current nonce, records the current occurrence last and retains the full unchanged component state. This is ordered actual-call evidence, not a claim that repeated derivations or receives are repeated sends. `Routed` records the actual normal send admission and literal driver-ready result before any primitive reply. `routed_chain` and `later_routed_chain` use the exact first/later private table routes to identify the original sending-chain input; retained predecessor priority is preserved.

`note_old`, `note_selected` and `note_length` preserve original order and bound new trace entries by one per scalar call. `sealing_bound` proves equivalence of every primitive query bound with the original scalar callback. Thus the existing hidden/known hash, seal, raw and uniform ledgers remain unchanged, including known local work. Tracing is pure bookkeeping, not uncharged cryptographic work.

The consuming full-family compiler must install these records from the original owner dispatch, transport the actual ready/admission witnesses and preserve the selected nonce ledger through nonsealing calls. This module does not assume or prove that repeated selected sends are unlikely. The global source ownership, chain-cycle and cross-direction/root-alias charge remains a separate required proof; arbitrary initial roles can actually repeat. No new primitive assumption, no selected-key no-hit premise, no snapshot or persistence claim is introduced.

## Preservation through original nonsealing work

`RawCtxSelectedSendLedger` discharges the nonce-ledger preservation required between recorded sends. `local_nonseal` inspects the literal actual real component's raw, public-hash and uniform branches. Raw decoding failure, commitment rejection, opening failure and successful optional plaintext all leave the seal nonce list unchanged while their actual other effects still run.

`source_nonseal` extends that result to the full dynamic known-key source. Known-key operations retain their own complete histories and the shared cache, including selected-key byte aliases; they do not modify the selected ledger. `program_nonseal` proves the same property for an arbitrary complete adaptive component program whose selected-seal query cap is zero. This is a query-class condition that actual source callbacks already prove, not a nonce-uniqueness assumption or a claim that raw/hash/random work is absent.

`tracked_nonseal` transports the earlier original-owner/send occurrence history from `RawCtxSelectedSendTrace` across that complete work, deriving the state relation from actual execution. `opening_nonseal` directly consumes the actual scalar `RawCtxSelectedOpenConsumer.service` and its existing zero-seal theorem, without a separate parse, context, getter or successful-opening premise. The optional plaintext and all non-ledger state remain those of the original component program.

Theorems add no implementation or oracle query and erase no existing query category. Existing raw, shared-hash, known-key and uniform budgets remain required. Combined with the ordinary empty initial ledger and the traced sealing callback's preservation theorem, this gives the full-family compiler an executable invariant across both kinds of operations. Original owner dispatch/routing and the probability charge for repeated source sends remain separate consuming obligations. No key independence, no selected-nonce rejection as a production rule, no security assumption, and no snapshot/persistence behavior is introduced.

## Actual source send order

RawCtxSourceSendOrder derives send-counter monotonicity from the literal source callbacks. An exhausted send preserves the counter; each nonexhausted send advances it even when sealing or writing returns no frame. Receive operations preserve send fields. The complete original finite LIVE family therefore preserves a lower bound at the same installed owner, without an assumed callback invariant.

The final source_cycle theorem starts with an actual admitted send, its exact complete returned state, and the same returned kernel installed into the original role family. An arbitrary supported original LIVE suffix that brings that owner back to its old send input has a strictly greater counter and the same root path in the complete final private cache. It therefore witnesses a real directional cache cycle. It does not assume send success or discard failed writer effects.

Scope is deliberately the no-install LIVE interface. A new registration can replace a route; the final global ledger must retain the cryptographic installation origin, not identify it solely by a public owner index. Cross-direction and cross-origin meetings and their cryptographic probability charges are separate remaining consumers. This module introduces no primitive assumption, nonce-freshness premise, or smallness claim. It adds no oracle calls; original callback and schedule bills remain in force.

## Fixed-HKDF initial directional alias loss

`RawCtxInitialSendAlias` charges the initial send-chain equality through its actual fixed-HKDF source operation. Its sampler is the original joint context and32-byte root computation supplied by the caller. It makes no independence, entropy or secrecy assertion about that sampler. `real` calls the literal `realInitial` source initializer, supplies its one complete64-byte response to both actual native role constructors, and runs the full supplied continuation before deciding whether the two initial sending chains coincide. `native_event` proves that this comparison is exactly equality of the two source sending chains when the original constructors return.

`real_source` identifies this complete source experiment with the maintained full-output fixed-HKDF component observer. `random_source` projects that component's justified uniform76 output to one shared64 response, preserving the entire evaluated continuation. It does not sample independent outputs for the two roles. `random_bound` charges the half-equality event by2^-256 only in that uniform comparison, without conditioning on source success, freshness or continuation termination.

`primitive_bound` constructs the exact-sampler Extract reduction and the ordinary uniform-secret-key HMAC PRF reduction with coefficient one each. `source_bound` then bounds the actual source event by their explicitly defined advantages plus2^-256. `reductionLoss` spells out both games and observers. The Extract advantage is for the caller's exact joint sampler; if the root is exposed or correlated in a way that permits distinguishing, this theorem does not declare that advantage small. It adds no new primitive assumption and cannot replace the authenticated-root/source-freshness argument with an independent-root premise.

The comparison reuses the maintained76-byte expansion and therefore has at most two HMAC challenge queries, even though the event sees only64 bytes. All public fixed-HKDF evaluations in the continuation remain real. `sampler_uniform`, `observer_uniform` and `hmac_uniform` charge the complete original sampler and continuation, with HMAC challenge queries separate. `game_bills` gives source qSample+qObserve, uniform Extract qSample+64+qObserve, real HMAC64+qSample+qObserve, random HMAC qSample+128+qObserve and projected ideal qSample+64+qObserve. The Extract comparison consumes one exact joint input and one PRK response by its existing game definition. No ambient work is treated as free.

The global second-selected-send theorem still must use the actual admitted root sampler, select and count source owners/initializations, preserve paired receive traversal, and account for later same-direction cycles, cross-direction meetings and cross-root aliases. This module establishes the computational cost of one concrete initial directional-alias event; it does not claim the full nonce bound or independent state across sessions. No Rust, primitive algorithm, snapshot or persistence behavior changes.
