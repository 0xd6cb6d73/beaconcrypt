# Source receipts for initial chain installation

The existing origin trace answers whether an initializer used a selected DH-coordinate family. In the production source experiment its marker is Boolean. It cannot identify a distinct local installation, and equality of this marker, a root, a chain or associated data does not identify a cryptographic session. The new installation annotation keeps that existing marker and its Gate unchanged while retaining the actual initializer return needed for directional path analysis.

`PqxdhInitialFinishReceipt` records the exact kernel returned by the Beacon initializer before the application getter and first raw receive. A receipt contains that kernel and the same actual prepared response. `prepared_erase` and `owner_erase` erase only the receipt and recover the existing origin-marked program, including every failed or inactive attempt. They are equalities of complete oracle programs, preserving source order, optional returns and all callback effects.

`prepared_origin` and `owner_origin` identify the actual supported preparation, the original initializer's successful optional return, and the complete subsequent application/receive execution, with their intermediate and final private states. The returned kernel is the receipt's literal `initial` field. For the native kernel specialization, `roots` returns this field's original `send_chain` and `receive_chain`, before any advancement. The attempted-initializer receipt is retained even when the subsequent getter, receive or publication fails. The separate `successful` projection retains it for owner installation exactly when that same finish publishes a successful application reply. All sequence-one, binding-prefix, candidate authentication, pinned-server and terminal-state checks remain inside the original finish.

This annotation belongs to the private source analysis. Its prepared value may contain secret root inputs, and its initializer kernel contains actual secret chains. Erasure does not make those values available to an executable key-free reduction or establish their secrecy. The subsequent composition must transport only the justified public observations and discharge its concrete source nonexposure obligations. The original query-class accounting remains exact because erasing the annotation gives the same oracle program; no initializer, getter, raw receive or pure native computation is declared free.

`PqxdhInitialInstallOccurrence` assigns a monotone attempt ordinal at the first Server builder and at every attempted Beacon finish, including failures and inactive phases. Every attempt that actually reaches a successful initializer return records its literal initial kernel and available source transcript fields under the actual candidate owner and attempt ordinal, even if a later seal or writer fails. Only a successful local publication updates the owner-to-installed-token map. Cryptographic seal production remains a separate source event. Counterpart roles may belong to one cryptographic session while having different local installation tokens. An empty annotation does not certify arbitrary preexisting roles: those remain unlabelled until supplied by the actual earlier construction trace or accounted for as initial candidates.

`PqxdhInitialBuilderReceipt` records the actual Server candidate and its initializer kernel after identity validation and peer reservation. `candidate_origin` and `used_origin` recover the exact supported gates, current allocation, candidate preparation, literal initializer result and later continuation. `build_initialized` consumes the complete indexed Builder under an arbitrary actual handler, including full consumed state and peer reinstallation, and recovers that same initializer return. The interpretation equations retain all handler effects. The receipt is retained after plaintext allocation failure, sealing failure or writer failure. `build_erase` and `queries` preserve the original full program and each original query-class bound.

`PqxdhInitialKernelConstruction.supplied_new` connects either typed initial64 response to the literal extracted `ConcreteRatchetKernel.new` constructor at its returned send and receive chains. `supplied_reachable` derives the original full zero-state reachability relation under any fixed ratchet interpreter. `retained_supported` applies this to the actual retained root-cache initializer, preserving its exact audit reply and auxiliary state. It does not infer initialization from an arbitrary callback support claim. `PqxdhInitialReceiptConstruction.server` consumes the full interpreted source Builder with its original supplied initializer. Its Beacon theorem consumes the full attempted finish with the actual retained initializer, after only tuple reassociation and projection of its separate audit return. Both results identify the receipt's literal pre-advance chains and full zero-state kernel, including attempts whose later continuation fails. The other preparation, application and native calls retain all their effects; no independence premise is supplied for them.

The occurrence trace uses an `Owner` and a monotone attempt ordinal. Its `receipts` list contains attempted-initializer evidence regardless of eventual publication. Its `installed` map changes only on successful publication: a Beacon success uses the actual finish reply; a Server success additionally matches the returned key ID to the actual candidate and checks the resulting peer entry. These are first-construction source checks, not a later assigned-ID agreement claim. Unsuccessful publication preserves the prior installation map while retaining any new attempted-initializer evidence. Cryptographic seal production remains in the separate original source seal audit, including seals whose later writer fails.

`step_erase`, `program_erase` and `sequence_erase` erase only the new occurrence trace and recover the original complete origin-marked first Builder and adaptive Post. They retain every frontend field, old Boolean coordinate marker, callback and public reply. `sequence_queries` preserves every source oracle-class allowance exactly. No new random draw or oracle call is introduced; deterministic annotation work is ordinary computation and all preexisting callback/primitive costs remain in their own source bills. `step_attempts`, `program_attempts` and `sequence_attempts` charge one ordinal for each attempted finish and one for the first Builder. A Post allowance of `qPost` therefore gives at most `1 + qPost` additional ordinals. All inactive, rejected and failed attempts count.

`sequence_ordered` starts only the annotation from empty and proves strictly increasing receipt ordinals across that entire source program. `distinct_tokens` then rules out equal occurrence tokens at distinct chronological receipt positions even if all their root, chain or transcript bytes are equal. This is local occurrence identity, not cryptographic session identity. The constructor consequences supply the exact initial chains needed by the separate retained-path proof. An invariant connecting the installed map to every subsequent native kernel and chronological seal interval is a consuming obligation; the ordering theorem itself does not assert it.

The complete advertised cryptographic-session projection still requires retained Phase-1 history. Neither an arbitrary receipt payload nor equality of initial chain bytes substitutes for that history. This source receipt layer does not introduce a cryptographic assumption, a root-independence premise or a session agreement theorem. Transport through the complete saved descriptor/common experiment, the installation-to-current-path invariant and final session/accepted-record attribution remain separate composition obligations.
