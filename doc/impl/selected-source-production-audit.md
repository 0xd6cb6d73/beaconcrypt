# Actual source production history

`RawCtxSelectedProductionOrigins.lean` and `RawCtxSelectedProductionAudit.lean` connect the ordinary selected CTX successful-seal history to actual source sends in the complete adaptive record/reveal client. They retain the original request, private entry roles, optional API result, resulting roles and authentication observations. An earlier receipt is kept as an earlier receipt; the proof does not reset the history at a selected continuation or infer its origin from ciphertext equality.

The source-origin predicates describe actual protocol operations. `Produced` retains the original send kernel and context, literal prepared derivation, full retained-table response, reached hidden material, challenger-produced typed CTX record, advanced kernel and optional writer result. `send_produced` obtains those fields from the checked complete send. `owner_send` adds the actual nonempty-plaintext admission gate and original owner publication, retaining sender, target ID, associated data and attempt counter. A writer failure remains a cryptographic production with an advanced kernel. An explicit selected-nonce refusal produces no new successful seal.

`beacon_send` follows the actual Beacon phase selection and exact owner reinstallation. Inactive phases supply no production. `server_send` follows the original associated-data lookup, repeated peer lookup, metadata-derived sender and exact peer publication. It keeps the caller's target ID distinct from any registration assignment. `family_produced` then identifies the actual finite-family Server or Beacon query and its indexed role update, while preserving every other role. Matching cryptographic bytes is not used to select a source role.

The five `*_no_seals` statements follow the complete receive driver and actual owner/Beacon/Server raw dispatch. Cached and future receives, arbitrary malformed bytes, rejected frames, missing or stale material and actual optional opening replies issue zero selected sealing calls. Public caller coins, public hash queries and real fixed HKDF evaluations also add no selected sealing receipt. These are selective query counts: raw verification, known-key operations, hash sampling and private derivation work retain their existing separate costs.

The executable audit wraps the actual finite-family compiler. Each record/public query appends its original request, complete private entry roles, unchanged optional family result and the authentication observer before and after that exact call. It appends the entry after obtaining the actual result. Reveals preserve this observer and retain the original reveal history and stopping behavior. There is no selected-message-key argument; arbitrary supplied private state and known byte aliases remain representable. This representation fact is not an independence or nonexposure theorem.

`step_erase` and `client_erase` prove that discarding only the added source audit recovers the actual compiled record/reveal client with its final optional result, complete private role/reveal history and full authentication observer. The final result may stop; the audit does not replace it with an acceptance or success assumption. Actual challenger plaintext remains the optional value returned through the original receive path. `client_queries` preserves every component query predicate and bound exactly before any primitive interpreter is chosen.

`step_records` identifies the actual supported source call behind every new audit entry. `step_trace` and `client_trace` prove a stronger chronological statement: the final record list is the exact initial list followed by an actually generated suffix, and that suffix links the initial observer to the final observer without gaps. Every entry in the suffix is justified by the original indexed-family call using its recorded private state and actual result. The `Recorded` predicate is therefore discharged from execution; it is not a primitive contract or an assumed source-simulation premise. `edges_append` composes adjacent pieces of this same observer history.

`trace_production` consumes those actual source calls and the concrete dispatcher theorem. Every successful selected seal in the final observer is either already present on entry or was produced by an original indexed send in the trace. `client_production` supplies both premises from the actual adaptive execution, retaining the optional publication and the private source capability. Starting with an empty observer seal list eliminates the entry-prefix case. A nonempty prefix remains explicit and must come with its actual preceding setup/source provenance in the larger experiment.

`edges_cut` cuts the trace at a list position rather than identifying occurrences by value. `client_before_production` uses that cut in the actual run: any seal present before a recorded query comes from the retained entry prefix or a strictly earlier source query. A later send cannot justify an earlier receive's origin. Chronological duplicates are preserved, and no injectivity or uniqueness premise is needed. This is the source history needed when comparing an accepted raw attempt against its attempt-time seal history.

`step_length` counts one audit position for every original record/public request, including rejections and the stopping request, and zero positions for reveals. `client_length` gives the adaptive cap under the actual source request bound. `source_record_bound` and `source_length` derive that cap from the maintained source budget: the number of new audit positions is at most `qSend + qRaw + qUniform + qHash + qPublicHkdf`. The separate reveal budget remains unchanged. This finite position count is not itself a cryptographic selection loss. The component observer already accounts for every selected raw attempt; no additional raw-attempt multiplier is introduced here. The existing separate bound of 51 private receive derivations, one send derivation and the explicit preparation/initializer costs remain outside this local audit count.

These results establish actual cryptographic production origin for the compiled record/reveal suffix. They do not identify the full symbolic session tuple, installation, direction or required receiver origin from a matching CTX tuple. They do not infer successful serialization from an arbitrary optional writer; the precise normal-return production Vec codec contract is documented separately in `selected-seal-production-receipts.md`. Multiple raw encodings may decode to the same fields. Real sealing-history correctness remains necessary to infer plaintext equality on replay.

The next authentication consumer must combine the actual accepted receipt with this earlier-production history and preserve the three possible failure classes: a fresh full CTX tuple, an unpublished matching production, or a matching publication with the wrong required source origin. Original Gate and byte-Fresh alone do not remove these classes. Installation and saved-descriptor attribution, selected-key distribution in the complete continuation, known-key alias/probe accounting, and constructed session/key selection reductions remain separate obligations. Initial registration and later initialization callbacks are outside this record/reveal audit until the enclosing concrete descriptor compiler supplies their actual trace. The retained private KDF table remains an explicit hybrid; public HKDF evaluations are real. Snapshots and persistence are excluded.

Validation uses direct Lean 4.34 checks and guarded axiom output for all 25 public statements. No primitive implementation proof, Rust modification or mutation run is involved. Central source imports, inventory metadata and complete Make verification remain integration checks.
