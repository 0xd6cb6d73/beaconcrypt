# Lean 4.35.0 dependency compatibility overlays

The Lake requirements and manifest pin Aeneas `6852e6474ec508930acba4df79977b3483a10d10` (`nightly-2026.09.03-6852e64`) and the reviewed Hax-Lean `174840bf2f633ae3bae955e08f781b3737ffc0b8` (`v0.3.30` baseline), preserving the library revisions paired with the repository's cargo-hax 0.4.2 extraction stack before the Lean upgrade. The reviewed Hax-Lean revision requires the Aeneas Lean library at `6852e6474ec508930acba4df79977b3483a10d10`. On 2026-10-22, resolving the remote `v0.3.30` tag selected `562939586572265d5a70779bb405beddcb5a48c9`; the Lake requirement and `hax.toml` now use the reviewed full revision so that tag resolution cannot change the extraction/library pairing. `hax.toml` keeps the Aeneas extraction tool at the binary artifact tag `nightly-2026.09.03-6852e64` instead of cargo-hax 0.4.2's built-in default `build-183e4f0`, so the extraction tool stays paired with that Aeneas Lean library. Charon remains pinned separately by that configuration to `nightly-2026.09.02`.

`apply-dependency-patches.sh` verifies the Lake configuration, Lean toolchain, Hax extraction configuration, every manifest dependency's revision and checkout root, patch hashes, and resulting diffs before every Lean build. It uses Lake's non-upgrading dependency resolver to materialize exact manifest revisions when a package checkout is missing, rejects local changes in every unpatched dependency, and refuses an unexpected configuration rewrite or dependency checkout change.

## Aeneas

`aeneas-lean-4.35.patch` forward-ports the official unmerged Aeneas Lean 4.33 work from [`95048d69298263591d7b406b38fb2a3b71fce6b3`](https://github.com/cryspen/aeneas/commit/95048d69298263591d7b406b38fb2a3b71fce6b3) and [`48f6fb4b57e13b95bd45899501239a7167dd8b02`](https://github.com/cryspen/aeneas/commit/48f6fb4b57e13b95bd45899501239a7167dd8b02) onto Aeneas `6852e6474ec508930acba4df79977b3483a10d10`, then retains the Lean 4.34 `bv_decide` and direct BitVec proof adaptations for Lean 4.35. The overlay retains every original `bv_tac` and `bvify` regression example with its original proposition. The symbolic bit-vector reifier does not normalize the computed width of a scalar field projection, so the adapter generalizes specialized scalar projections to bit-vector variables while retaining their defining equalities before invoking `bv_decide`. This uses the kernel-checked generalization operation and introduces no assumption. Both modular-arithmetic examples run normally, without error-dropping guards. Beaconcrypt's extracted and handwritten Lean sources contain no `bv_tac` invocations. Pinning the upstream `bump-lean` branch directly is not viable because it predates the `Result` to `RustM` transition and partial-specification interfaces used by Beaconcrypt's generated definitions.

Lean 4.35 adds a built-in `Nat.reduceLog2` simproc with the same name as Aeneas's existing simproc. The overlay renames the Aeneas declaration and its custom-set registration to `Nat.reduceLog2Aeneas`, preserving its implementation, trace class, simp sets and every regression proposition. The nested Aeneas toolchain, Mathlib requirement and dependency manifest use Lean and Mathlib 4.35.0.

Lean 4.35 also changes the representation of `Decidable`, so unfolding `ite` and `dite` no longer produces the `Decidable.casesOn` expression expected by Aeneas's branch analyzer. The overlay reads the conditional's own arguments instead: its result type, proposition, decision instance and complete true and false branches. A plain conditional has no proof argument in either branch; a dependent conditional has one. The corresponding expression reconstruction uses those same native arguments. All original `StepStar` examples and expected diagnostic messages remain unchanged.

The Aeneas artifact is stored as a plain canonical Git diff rather than a format-patch because the reviewed overlay combines those upstream adaptations with the local source-build and linter configuration; the cited upstream commits identify its inputs, not a synthetic commit containing the combined result.

## Hax-Lean

`hax-lean-4.35.patch` retains the reviewed Lean 4.34 elaboration adaptations for Hax-Lean v0.3.30: explicit fixed-array length facts and a dependent witness elimination. The pinned upstream Hax-Lean release still targets Lean and Mathlib 4.31. The original two hunks are unchanged. They were re-ported unchanged from v0.3.17 on 2026-10-18 for the cargo-hax 0.4.2 upgrade: both target regions are textually identical in v0.3.30, and only the `CoreModels/RustPrimitives/Funs.lean` hunk position (27 lines lower, after the new `slice_copy_within` model and module header) and its base blob index changed; every added and removed line is the same.

The Lean 4.35 overlay also spells out `Std.Do.WP.wp` in the hypothesis-processing helper, its quoted constant lookup and four regression proof lines. The short name `WP.wp` is ambiguous between Lean's predicate transformer and Aeneas's specification interface. Qualification selects the predicate transformer already required by those statements. Every regression proposition is retained. The negative hypothesis-processing regression still checks its complete original error and now also checks Lean 4.35's preceding `mvcgen` syntax-deprecation warning; the tactic and its error remain unchanged, and no diagnostic is suppressed.

The Aeneas overlay disables `preferReleaseBuild` so Lake cannot substitute an upstream archive built from the unpatched tag. It also disables the weak `dupNamespace`, `defProp`, and `ambiguousOpen` linters to keep upstream warning changes from failing Aeneas's warning-clean build; these are style diagnostics, not kernel soundness checks.

These overlays affect only the Lean libraries in Lake's ignored package checkouts. Their revisions match the reviewed cargo-hax 0.4.2 extraction stack so regenerated Beaconcrypt definitions and the libraries used to check them stay aligned. The Makefile runs `lake --rehash build` after preparation so Lake recomputes source hashes; direct `lake build` bypasses these preparation and assurance checks.
