## Finding

F10 remains open. The missing capability is not “finite budgets cannot describe replication.” Existing checked interfaces already describe adaptive creation, signing, converted-DH service, compromise, and final target selection with finite resource bounds. The older authenticated-root/evolving-chain headline does not consume the complete interface: it imposes zero forwarded signing and creation before target selection, fixes an earlier role environment, and has no single proved connection from all dynamic protocol operations and reveal events to its reductions. The new B theorem closes the approved R1 authentication experiment, not that broader adversary.

The smallest useful next consumer is a **complete native-scheduler-to-indexed-joint-service simulation**, using the new operational scheduler being written by the dynamic lane. It should instantiate existing dynamic identity/KEM routing and source-order laws on the scheduler's actual create, bundle, private DH/decapsulation and live disclosure callbacks, preserving the full continued distribution and actual owner-to-creation-index relation. This is a source/reduction interface obligation; it requires no new hardness assumption and is distinct from writing another operational scheduler.

## Current operational lane and smallest next proof boundary

The active, unreviewed WIP is `/tmp/beaconcrypt-registration-joint-schedule/beaconcrypt-core/proofs/lean/BeaconcryptCore/Computational/PqxdhRegistrationSchedule.lean`: shared-state definition at 23; native finish at 68; source bundle at 100; create at 112; request interface at 125; handler at 148. Dynamic owns its per-step/native projection, consumed/spent/closed-owner invariants and combined symbolic-process relation. It already uses one shared NativeState and dynamically allocated Nat owner slots; it does not yet establish empty initialization, attacker-owned seed import, later-record calls or wider disclosures. Do not call this WIP a checked global experiment.

The next security consumer should preserve that exact scheduler and replace only primitive access by the indexed joint services:

1. Construct the actual owner→identity-creation/KEM-creation map from successful source allocation, keeping source order, bundle one-time generation and all three actual signing replies. Prove complete native/source callback equality, including aborted/writer-failed operations, shared Extract/CTX caches and public replies.
2. Supply concrete source report/disclosure positions and untouched continuation. Apply existing identity reporting and KEM stopping only to their actual events. Never identify owners by equal public bytes or assume ordinary EUF supplies the joint interface.
3. State the resulting security-interface program's explicit source-class caps. This removes the need for the obsolete zero-sign/zero-create caller restrictions for that consumer; merely deleting those fields from the old certificate would not prove anything.

After that local bridge, the broader remaining consumers are still substantive: attacker-owned/imported identity policy; actual common identity/KEM/root/current/skipped reveal history and target freshness; dynamic installation-to-session catalogue; chosen-session/record reduction in that same run; and common ProVerif event projection. The closed B theorem is reusable only after its exact input/context and cross-session shared-cache distribution are supplied—one cannot multiply its bound by a session count and skip that simulation.

Historical `/tmp/beaconcrypt-dynamic-kem-composition` retains broader `PqxdhLiveRegistry`, `PqxdhLivePendingRegistry`, and `PqxdhLiveCreatedServers` operational prototypes. They are not current central endpoints and are not recommended for wholesale recovery; dynamic explicitly chose the new scheduler. Their local statements can be considered only with exact source/contract comparison.

No saved-state/persistence capability is requested or added. Private ghost “Snapshot” records in B record an acceptance observation and are not state restoration APIs.
