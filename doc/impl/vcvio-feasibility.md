# VCVio feasibility and native Lean computational reductions

## Decision

VCVio is feasible for computational proofs over beaconcrypt's handwritten Lean ideal models and is a better integration fit for the `lean` branch than adding a second proof assistant. The current objective is not to reproduce the tracked SSProve branch theorem by theorem. It is to prove computational reductions for security events stated directly over the ideal PQXDH, CTX, and ratchet components and then connect those models to extracted production code through explicit refinement theorems.

That conclusion is deliberately narrower than “VCVio replaces SSProve.” VCVio does not provide a drop-in equivalent of SSProve 0.2.4's complete typed package/validity layer, heterogeneous location heap, or mature package-algebra surface, but matching that framework surface is no longer an acceptance condition. Neither the present SSProve suite nor VCVio supplies the full multi-session, active, extraction-linked end-to-end proof specified in [`computational-security-proof-plan.md`](computational-security-proof-plan.md), and VCVio has no quantum random-oracle or QPT adversary model.

Recommendation: continue with small, theorem-driven reductions against the current ideal Lean models. Use the model's real event and transition definitions, import the narrowest applicable VCVio hardness assumption or game library, and state every missing implementation-refinement and primitive-security premise explicitly. Retain the SSProve work as comparison evidence rather than a porting target.

## Reproducible baseline

The investigation was performed on branch `vcvio` in worktree `/tmp/beaconcrypt-vcvio`. The worktree was recreated from its previous signed feasibility commit, `origin/lean` was fetched at `3bf16a3ffdd34c964d501ff74e3e940269dc623b`, and that exact state was merged as signed commit `0957f7d`. The main worktree and its unrelated local changes were not modified. The SSProve comparison below records the earlier feasibility investigation, but it no longer defines the implementation roadmap.

VCVio is pinned by immutable commit `cbd4144b51d92da00dd50f05e068b2348fa6e529`, the commit behind its `v4.31.0` tag and therefore compatible with this project's Lean/Mathlib 4.31 line. The checked-in Lake manifest also locks VCVio's inherited `PolyFun` and `loom2` dependencies. The authoritative upstream descriptions are the [VCVio repository](https://github.com/Verified-zkEVM/VCVio/tree/cbd4144b51d92da00dd50f05e068b2348fa6e529), which documents `OracleComp`, denotational probability semantics, oracle simulation, logging/caching, and its proof logics, and the [VCVio paper](https://eprint.iacr.org/2024/1819), which presents the oracle representation, forking lemma, Fiat-Shamir proof, and Schnorr-like case study.

The comparison uses three distinct targets:

- Target A is the accepted repository-owned surface at tracked `ssprove` commit `926983273ae5ff7bcd302631fb743844a6d44290`: thirteen proof modules covering bounded ROM infrastructure, CTX binding and privacy, finite PQXDH/ratchet games and hybrids, one-step forward secrecy, record integrity, one state-separated composition slice, and an exact restricted one-call result-and-final-heap certificate with public-view probability and advantage equality.
- Target B is the SSProve 0.2.4 framework surface itself: valid typed packages over locations and interfaces, general discrete subdistributions, heterogeneous heap semantics, sequential and parallel composition, identities and interchange, contextual advantage/reduction laws, and pRHL. These facilities are described in the versioned [SSProve guide](https://github.com/SSProve/ssprove/blob/v0.2.4/DOC.md) and the [SSProve paper](https://eprint.iacr.org/2021/397.pdf).
- Target C is the full multi-session, active, primitive-composed, extraction-linked milestone in the repository's computational-security plan rather than either framework's library surface.

The answer is “credible match after a local state-certificate layer” for Target A, “partial, not drop-in” for Target B, and “not yet achieved by either implementation” for Target C.

## Compile-checked native CTX reduction

[`CtxReduction.lean`](../../beaconcrypt-core/proofs/lean/BeaconcryptCore/Computational/CtxReduction.lean) defines a game directly over the merged ideal PQXDH record model. An adversary returns one arbitrary raw wire payload and two well-formed explanations containing message material, record associated data, and plaintext. `CtxMisattribution` holds exactly when the real ideal-model `Pqxdh.openRecord` parser and verifier accept both explanations and the explanations differ.

The deterministic theorem `Pqxdh.openRecord_double_opening_yields_ctx_collision` decodes the shared payload, uses its actual parsed Poly1305 tag, and proves that any two distinct successful openings expose unequal CTX preimages with equal `c.blake2b` outputs. The proof uses fixed-width transcript injectivity and the determinism of the same `aeadOpen` call; it assumes neither AEAD integrity nor AEAD key commitment.

`ctxCollisionReduction` runs the same probabilistic adversary and returns those two CTX preimages, using an equal fallback pair only for a payload that fails to parse. The checked capstone

```text
ctxMisattributionAdvantage c A
  ≤ CollisionResistance.crAdvantage c.blake2b (ctxCollisionReduction A)
```

has factor one, no additive loss, and no random-oracle idealization. It is a standard-model reduction conditional on collision resistance of the ideal model's pure BLAKE2b function. VCVio's `CRAdversary` does not encode a PPT cost proof, so polynomial-time preservation is an external inspection obligation; the reducer adds only deterministic parsing and transcript construction.

The first scheme-level capstone is now explicit rather than implicit in that stronger raw-payload game. `CtxFullCommitment` gives the adversary two complete well-formed inputs, runs the real ideal `sealRecord` algorithm on each, and tests whether distinct choices of key, nonce, associated-data bytes, sequence, sender identifier, or plaintext produce the same `C || T || T*` payload. `ctxFullCommitmentAdvantage_le_blake2b_cr` maps every such one-shot equal-seal win into raw-payload misattribution and then into BLAKE2b collision finding with factor one. The executable collision reducer computes the left base-AEAD tag and constructs the two BLAKE2b inputs without evaluating BLAKE2b itself. This is a direct computational full-commitment proof for BeaconCrypt's modified CTX scheme; the extracted transcript theorem is a subordinate production-correspondence result, not its replacement. It does not yet encode the paper's complete adaptive CAE oracle/history game with indexed keys, reveal/corruption status, and query accounting.

The first retained-tag freshness-projection step is separate and deliberately narrow. `CtxRetainedTagProjection.lean` compares one candidate raw forgery with one designated honest seal under fixed material and complete record context, proves pointwise that an accepted fresh `C || T || T*` opening projects to an accepted fresh retained base `C || T` opening, and lifts the implication to a factor-one probability inequality. The theorem is named as a same-view probability projection rather than an AEAD advantage bound because no hidden-key sampling or enforced encryption oracle constrains the attempt computation. Fixing `RecordAD` is necessary at this step: BeaconCrypt's base AEAD sees `ad.bytes`, while `seq` and `sid` occur only in `T*`, so a full-payload forgery under changed outer fields may reuse an earlier base ciphertext. The general authenticity game must split that context-alias replay branch and discharge it with an oracle-parametric secret-prefix-hash argument in addition to base AEAD authenticity.

The general same-view split is now checked in `CtxAuthClassification.lean`. Its history permits arbitrary protocol-width material, complete contexts, and plaintexts, and its full-fresh event compares the complete authentication tuple `(material, RecordAD, C || T || T*)`. Every accepted full-fresh forgery is classified as either a fresh accepted base projection `(material, ad.bytes, C || T)` or an accepted context-alias replay of an earlier base output under a different complete CTX context. `RecordWf` on every entry and target rules out semantic differences hidden by truncated `LE64`, and a separate theorem proves that every alias branch has distinct serialized outer-hash inputs. VCVio lifts the pointwise classification to `Pr[CTX forge] ≤ Pr[base projection] + Pr[context alias]` in the identical attempt computation.

The nonce-consistency step now sharpens the alias branch for the intended computational reduction. `CtxPerKeyNonceConsistent` permits repeated `(key, nonce)` entries only for identical complete context and plaintext, including harmless exact duplicates. Under that condition, every accepted alias replay's target `ctxPreimage` is fresh from all actual outer-hash inputs used by the designated honest seals. The composed factor-one inequality is `Pr[nonce-consistent CTX forge] ≤ Pr[nonce-consistent fresh base projection] + Pr[accepted alias at an honest-history-fresh outer input]`; retaining consistency on the base branch prepares it for a nonce-AEAD reduction. This is the exact structural premise needed for the next random-oracle query/guess hop, but it does not yet stop the adversary from querying that target input directly, sample or hide a key, enforce nonce discipline through an oracle, or reduce the base projection to AEAD authenticity.

The first enforced ROM hop is now checked in `CtxRomAuth.lean`. The game samples one hidden 32-byte key and gives an adaptive adversary a public exact-byte ROM plus a CTX seal oracle that rejects repeated 12-byte nonces. Every successful seal uses the actual ideal base `aeadSeal`, retains its 16-byte `T`, queries the exact `Pqxdh.ctxPreimage`, and returns an actual-shaped `C || T || T*` record; honest, public, and final verifier calls share one VCVio lazy cache. One explicit handler state records that cache, used nonces, successful seal witnesses, and public query inputs. Its inductive invariant proves cache provenance and successful-seal nonce uniqueness under every adaptive strategy. For a full context alias, exact transcript injectivity and nonce uniqueness exclude an honest target-cache source, and `outerInput_take_key` shows that the remaining public target query carries the hidden key in its first 32 bytes. The composed `ctxAliasGameProbability_le_secretPrefix_add_inv_512` theorem proves `Pr[accepted alias] ≤ Pr[public ROM query with hidden-key prefix] + 2^-512`; the prefix event must still be reduced through base-AEAD IND$ privacy because an arbitrary modeled AEAD could leak its key. The target is a typed well-formed record, and neither reverse normalization from every accepted arbitrary raw payload nor a checked composition from the earlier `CtxFreshTargetOuterHashAliasReplayProbability` game into this typed `ctxAliasGame` exists yet. Separate private coins, `qE`/`qH` bounds, ratchet-derived key distribution, and multi-key composition are also later game layers; the current theorem is a one-hidden-key classical-ROM component bound.

The canonical prefix-isolation hop is now checked in `CtxPrefixIsolation.lean`. A sticky flag records exactly whether an adaptive public query starts with the hidden key, and mapping away the flag recovers the current `ctxBeforeVerifyGame` rather than a separately modeled approximation. On the isolated side, only public prefix queries are independently resampled and written to the cache; therefore the handlers agree until bad, and VCVio's relational fundamental lemma plus data processing proves `Δ(ctxBeforeVerifyGame, ctxPrefixIsolatedGame) ≤ Pr[public ROM query with hidden-key prefix]`. Both games expose the same complete `CtxBeforeVerify × QueryCache` surface, including the target and histories needed by the final verifier. The later split-cache theorem uses the same exact bad event directly, so this standalone prefix-isolation bound is not added as a second loss in the key-free game chain.

The per-seal sampling premise for that hop is checked in `CtxSealSampling.lean`. On an invariant state with no recorded public key-prefix query, cache provenance leaves only an earlier honest seal as a possible source for the next outer input; an unused nonce and exact transcript injectivity rule that source out. The canonical cache query is therefore a miss, and the lazy-ROM sealing transition is exactly equal to direct uniform digest sampling and cache installation. This has zero loss and applies to every unused-nonce seal step satisfying the generated invariant. The direct-sampling transition still computes `outerInput key` to update the shared cache, so it is a local semantic bridge rather than the eventual key-free reducer.

The exact representation needed to remove that ghost key dependency is checked in `CtxSplitCache.lean`. It projects one canonical cache into a public complete-input cache outside the hidden-key-prefix domain and a secret-prefix cache indexed only by the suffix after the 32-byte key. Merging a projection recovers the canonical cache extensionally, and projecting a merged normalized split cache recovers both components exactly. Honest outer inputs project to the key-free suffix `N ‖ AD ‖ T ‖ LE64(seq) ‖ LE64(sid)`, with exact length 197 bytes for the retained 16-byte tag.

The full adaptive lift is checked in `CtxIndependentTags.lean`. Canonical public and seal transitions project exactly into the routed split handler, and VCVio's simulation theorem lifts those equalities through every adversary query. The operational independent handler is key-free at its cache boundary: all adversary ROM calls update only the complete-input public cache, while honest seals address only the suffix cache. The routed and independent flagged handlers agree on every non-bad transition; a prefix query sets the same sticky bad flag on both sides, and all later transitions preserve it. Exact flag erasure, projection to the common `CtxBeforeVerify × SplitCache` result, and uniform-key averaging yield `Δ(ctxSplitBeforeVerifyGame, ctxIndependentTagGame) ≤ Pr[public ROM query with hidden-key prefix]`. This is the only fundamental-lemma hop in that chain, so the bad event has coefficient one. The suffix oracle remains lazy on this intermediate proof surface.

The zero-loss sampling lift is checked in `CtxHonestTagSampling.lean`. The first 12 bytes of each honest suffix are its nonce, and the direct handler preserves an adaptive invariant stating that successful-seal nonces are marked used and pairwise unique and that every suffix-cache hit came from an exact earlier seal. An unused nonce therefore makes the next suffix query fresh. The invariant-gated simulation theorem proves exact equality between the complete lazy-suffix run and a handler that first computes the deterministic modeled base-AEAD result and then draws one uniform `CtxDigest` for every successful seal; reused nonces return `none` before any draw. The fixed-key and uniform-key pre-verification games are equal, so this step adds no statistical loss, preserves the one prefix-event charge, performs at most one internal digest sample per successful encryption query, and leaves adversary `qE`/`qH` counts unchanged.

The retained-base authenticity branch is checked in `CtxNonceAeadIntCtxt.lean`. It defines a nonce-rejecting modified nonce-AEAD INT-CTXT game whose freshness predicate covers the complete `(nonce, AD, ciphertext)` tuple and constructs a forger from the direct independent-tag CTX adversary. Public ROM calls use private uniform samples and make no primitive seal query; every fresh CTX seal makes exactly one primitive seal call and one private 512-bit commitment draw, while a repeated nonce makes neither. Exact state and history projections lift through the adaptive execution and uniform-key experiment, yielding a factor-one bound from fresh retained-base acceptance to the constructed primitive advantage. A separate query-tracking theorem proves that any source `qE` seal-query bound is preserved by the primitive forger. The final composition supplies exact uniform-byte accounting and connects this branch to the typed game.

The secret-prefix branch is checked in `CtxNonceAeadIndDollar.lean`. A bounded adversary carries separate `qH` public-ROM and `qE` sealing bounds, and every recorded public input contributes one optional 32-byte key candidate to a fixed `qH`-slot vector. Exact sticky-flag and direct-sampling equalities identify the canonical secret-prefix event with success in the real probe experiment. Its random nonce-AEAD world independently samples a plaintext-length body and 16-byte tag for each fresh nonce, then samples a ghost key after the adversary returns, making the candidate vector independent of that key and giving the upper bound `qH / 2^256` by a finite union bound. Thus the prefix probability is at most one modified nonce-AEAD key-probe IND$ advantage plus `qH / 2^256`; the reduction preserves the `qE` primitive-seal budget and the source total public/seal budget is `qH + qE`. This stronger key-probe result remains available as a tighter specialized alternative.

The conventional bridge is checked in `CtxNonceAeadIndDollarValidation.lean`. An adaptive length invariant proves that at most `qE < 2^96` source seals cannot exhaust the 96-bit nonce space. The reduction selects an unused nonce, makes one extra empty-message encryption, and compares the returned 128-bit tag with local encryption under all candidate keys. A real key hit validates, whereas a fresh random-world tag matches with probability at most `qH / 2^128`. Thus `Pr[prefix] ≤ ofReal(Adv_IND$) + qH / 2^128`, and the validation reduction makes at most `qE + 1` primitive seals. The selected nonce is justified extensionally, but VCVio does not encode an asymptotic efficiency proof for the search.

The final typed composition is checked in `CtxComputationalSecurity.lean`. An adaptive cache-value invariant proves that every successful honest commitment remains installed at its exact suffix, so actual typed full-fresh acceptance is contained in the retained-base/context-alias classification. The canonical-to-direct data-processing hop charges the existing secret-prefix event exactly once and the direct alias branch costs one fresh `2^-512` guess. Under `qE < 2^96`, conventional composition yields `Pr[typed forge] ≤ Adv_INT-CTXT + ofReal(Adv_IND$) + qH / 2^128 + 2^-512`; the specialized key-probe theorem retains the tighter `qH / 2^256` term. Query tracking proves source total `qH + qE`, gives the validation reduction `qE + 1` primitive seals, bounds its private uniform calls by `64(qH + qE)` bytes and its complete interface by `64qH + 65qE + 1` calls, accounts for 32 key bytes in real primitive games, and bounds the complete direct CTX game by `96 + 64(qH + qE)` uniform-byte calls. The conventional interface total excludes the random challenger's plaintext-length-dependent ciphertext sampling; a complete conventional-game coin bound additionally needs a total plaintext-length budget. This closes the typed single-key classical-ROM target, not raw-payload normalization, indexed multi-key CAE composition, adapter correspondence, or an asymptotic PPT theorem.

The checked relabelling specialization uses an honest `sealRecord` as the source payload and proves that acceptance under a distinct target context has the same factor-one reduction. Its pointwise wrong-sequence, wrong-sender, and cross-session corollaries return the exact two CTX transcripts that collide if a record is accepted under any of those changed fields. Separately named wrong-sequence, wrong-sender, and cross-session record-opening games now let an adversary choose an honest source explanation, independent target material and plaintext, and a distinct well-formed target field; their advantage theorems map those adversaries through the relabelling reduction and preserve the factor-one bound. The sender result is deliberately scoped to `openRecord`: `beaconFinish` rejects a mismatched pinned sender before invoking CTX, so its eventual protocol-transition theorem should have advantage zero rather than charge that rejection to BLAKE2b. “Cross-session” at this layer means different `RecordAD.bytes`; interpreting those bytes as identities and a session still relies on `assocData` refinement and field provenance.

The protocol-transition seam is explicit in `Acceptance.lean`. `BeaconRecordAdmitted` classifies exactly successful beacon processing plus `badPlaintext` and `keyIdMismatch`, the two failures reachable only after record opening; it excludes identity, KEM, DH, sender, zero-sequence, and `badRecord` failures. `HonestRun.beaconRecordAdmitted_elim` proves that every classified outcome passed the pinned-sender and nonzero-sequence checks and contains an actual successful `openRecord` call under the exact receive-ratchet material and frame context. `CtxTransitionReduction.lean` uses that eliminator for a game in which an adversary chooses a distinct 64-bit sequence for the exact honest first-record ciphertext; every winning admission exposes the exact two CTX transcripts, and `beaconWrongSequenceAdvantage_le_blake2b_cr` gives a factor-one bound for one fixed `HonestRun` under `HonestRun.Ok` and a 64-bit honest sender identifier. The claim deliberately permits sequence zero because that broader case cannot win at the beacon's precheck. A parallel wrong-sender transition game allows an arbitrary substituted frame whose numeric sender differs from the pinned identifier and proves `beaconWrongSenderAdvantage_eq_zero`: such a frame cannot reach CTX at all, so no primitive assumption or collision loss belongs in that theorem. Finally, the foreign-session game substitutes a well-formed ciphertext sealed under different 153-byte `RecordAD.bytes` while retaining the honest sequence and sender headers; `beaconCrossSessionAdvantage_le_blake2b_cr` maps every post-record admission to a collision with factor one. The claim's `RecordWf` supplies the sender bound; if the fixed honest sender identifier is not 64-bit, the claim type is uninhabited, so the theorem is intended only for protocol-well-formed runs. Interpreting the differing bytes as identity-bound sessions remains conditional on `assocData` field provenance.

The native theorem closure is admission-free. `#print axioms` reports only `propext` and `Quot.sound` for full-commitment-to-misattribution, collision extraction, the fixed-context retained-tag freshness projection, the alias distinct-preimage and nonce-consistent fresh-input witnesses, the three pointwise field specializations, the field-game pointwise implications, the beacon admission eliminator, both transition collision implications, wrong-sender impossibility, and the ROM-record parser round-trip. The general-history classification, audited probability inequalities, and exact-zero probability theorem additionally report `Classical.choice`; the prefix-isolation projection identities and total-variation inequalities have the same standard closure, and no audited theorem reports `sorryAx`.

The extracted-to-ideal builder bridge is now checked in `PqxdhCommitment.lean`. `commitment_encode_u64_le_abs` proves that the current extracted integer encoder returns exactly ideal `Pqxdh.LE64` bytes for every `u64`, and `build_commitment_transcript_abs` proves that the generated fixed-array builder returns exactly `Pqxdh.ctxPreimage` in the 32-byte key, 12-byte nonce, 153-byte associated data, 16-byte tag, 8-byte sequence, and 8-byte sender order. This does not cover the adapter's BLAKE2b call or field provenance, Hax/Rust semantic preservation, PPT/runtime preservation, or compiler correspondence.

A numerical ROM birthday corollary cannot be obtained by rewriting this theorem. `Pqxdh.openRecord` calls a pure `Bytes → Bytes` hash, whereas VCVio's ROM experiment uses monadic oracle queries and a finite output type. Such a corollary requires a separate oracle-parametric record verifier plus a checked correspondence theorem; the generic pilot below does not supply that bridge.

The remaining production bridge is also explicit. The reduction is over the handwritten ideal model, while the new refinement separately equates the current generated `build_commitment_transcript` result with `Pqxdh.ctxPreimage`. A later adapter theorem must connect the intended authenticated fields and returned bytes to the actual BLAKE2b call and ideal `Crypto.blake2b`; Hax/Rust and compiler correspondence also remain required before this supports a production-code claim.

## Earlier framework pilot

[`VCVioFeasibility.lean`](../../beaconcrypt-core/proofs/lean/BeaconcryptCore/Computational/VCVioFeasibility.lean) is imported by the maintained Lean root and contains no `sorry`, `admit`, local `axiom`, or `sorryAx` dependency.

The collision-layer portion instantiates VCVio's generic adaptive lazy-ROM commitment binding theorems with `Aeneas.Std.Array Aeneas.Std.U8 229#usize`, exactly the byte-field type in the Aeneas-extracted `commitment.CommitmentTranscript`, and `BitVec 512`, the production digest width. A checked injection from Aeneas `U8` into `BitVec 8` lets Mathlib's existing fixed-vector instance supply the required finite-type evidence. For any generic binding adversary with query budget `q` and `Unit` salt, `ctx_binding_bound_tight_512` checks VCVio's tight `(q(q - 1) + 2) / (2 · 2^512)` bound, while `ctx_binding_bound_512` also preserves the looser `(q + 2)(q + 1) / (2 · 2^512)` collision-resistance-chain route with the generic verifier's two opening queries made explicit. These remain useful numerical ROM results, but they are separate from the native standard-model CTX theorem because no checked oracle-parametric verifier connects `Pqxdh.openRecord` to `bindingGame`.

The generic pilot treats the 512-bit function as an ideal random oracle; it is not a standard-model BLAKE2b collision-resistance theorem and does not prove transformed-AEAD privacy or ordinary integrity. The new native reduction closes the ideal-model binding-to-collision step without routing through this generic game, while production correspondence, CTX privacy, and ordinary ciphertext integrity remain separate obligations.

The state portion defines a dependent private CKEY oracle with typed `put` and `take` results, an affine `empty/full/taken` store, and a public handler linked sequentially around the private provider. Four exact theorems check successful transfer and tombstoning, a call from an assumed tombstoned state, two sequential calls returning the value at most once, and the public observation after private state is discarded. This demonstrates basic `link`/`runState` behavior, but it does not yet match the accepted SSProve certificate: its hard-coded `Bool` key, one slot, and one `Unit` public operation omit authentication/provenance, role/session checks, paired sibling bodies, the joint sampler, false-provenance early return, the complete two-location observation-and-final-heap normal form, finite-source probability/advantage equality, full lifecycle history, and arbitrary contexts. Discarding state with `run` is definitional here and is not a contextual noninterference theorem.

`#print axioms` reports only `propext`, `Classical.choice`, and `Quot.sound` for the four probability-bound theorems and the extracted-constant theorem, and no axioms for the four exact state theorems. In particular, the imported proof path does not report `sorryAx`. The pinned VCVio tree does contain unrelated admitted modules, so this is a result for the pilot's theorem dependency closure, not a complete audit of every upstream module, `unsafe` declaration, or build option.

The accepted SSProve gate has a different reviewed trust policy: Rocq 9.0.0 and SSProve 0.2.4 are pinned, `coqchk` runs, proof-bypass syntax is rejected, and probabilistic modules are allowed exactly `boolp.propositional_extensionality`, `boolp.functional_extensionality_dep`, `boolp.constructive_indefinite_description`, and abstract real numbers `R`. The package-semantics proof deliberately avoids stock `Pr`, `Pr_op`, generic advantage, package-validity, and interchange routes whose dependency closure reaches the rejected infinite-sum interchange principle. Any cross-framework comparison therefore requires a documented no-stronger trust policy, not identical axiom names across Lean and Rocq.

## Historical framework-surface comparison

The following table records why VCVio was selected and which framework features remain available if a future native ideal-model reduction needs them. It is not a parity checklist or a requirement to port an SSProve module.

| Capability | Tracked beaconcrypt SSProve use | VCVio v4.31.0 assessment |
| --- | --- | --- |
| Finite randomized games and event probabilities | All accepted probabilistic capstones use finite sources and direct event probabilities. | Match for this finite layer. `OracleComp`/`ProbComp`, `evalDist`, event probabilities, monotonicity, and finite uniform sampling cover it directly. |
| Adaptive bounded random oracles | `BoundedRom.v` supplies explicit fuel exhaustion as `None`, a hidden finite table, chronological traces, exact count/consistency facts, and witness/extractor reductions. | Likely match after an exact semantic ledger. VCVio has random-oracle implementations, caching, logging, programming, pregenerated answers, and query-bound machinery, but the port must preserve observable exhaustion, trace order, and the exact query-count convention rather than merely rule overflow out. |
| CTX binding | `CtxEventReduction.v` and `CtxGame.v` convert the actual finite double-opening event to a bounded same-run explicit collision witness. | The native pure-hash ideal-model event and factor-one standard-model reduction are checked, and the current generated transcript builder now refines the ideal preimage exactly. The separate generic ROM pilot still lacks an oracle-parametric `openRecord` bridge; adapter hashing, field provenance, Hax/Rust semantics, and compiler correspondence remain open. |
| CTX privacy programming | `CtxPrivacy.v` reindexes a finite table and bounds the true/real hop by a hidden-transcript query event. | Likely match. VCVio's oracle programming, logged traces, distribution equivalences, hybrids, and identical-until-bad support the same proof shape, but this specific theorem has not yet been ported. |
| PQXDH/ratchet closed games and one-hidden-input hybrids | `PqxdhRatchetGames.v`, `PqxdhRatchetRom.v`, and `PqxdhHybridSecurity.v` use finite challenges, bounded queries, and bad-input events. | Match in expressiveness. These are ordinary oracle games and reductions; the substantive work is porting definitions and preserving the exact shared-label/prefix contract, not adding framework primitives. |
| Post-erasure forward secrecy | `RatchetForwardSecrecy.v` uses a table involution and an erased-predecessor bad query. | Match in expressiveness through couplings/distribution equivalence or identical-until-bad plus trace logging. No implementation erasure theorem is gained automatically. |
| Record integrity and fresh-guess bound | `RecordIntegrity.v` and `RecordIntegrityBound.v` partition prior queries from a fresh adaptive candidate and prove a one-bit bound. | Match in expressiveness; VCVio's logged/cached oracles and probability tools are designed for this pattern. The assumed AEAD+CTX composition remains an assumption. |
| Stateful private interfaces and one-call linking | `StateSeparatedComposition.v` hides CKEY, while `StateSeparatedPackageSemantics.v` certifies the exact restricted one-call observation and final heap and proves public-view probability/advantage equality. | Partial mechanism demonstrated, full accepted certificate not yet ported. `QueryImpl.Stateful`, typed dependent queries, `link`, parallel sums, lenses, and state-separating hybrid/equivalence APIs appear sufficient for a local one-call certificate layer. |
| General SSProve package algebra and heap validity | SSProve exposes valid packages, raw packages, location sets, heterogeneous heaps, link/parallel/identity/interchange, and contextual advantage laws. | Gap. VCVio has compositional handlers but no drop-in equivalent of the complete SSProve package record, validity judgment, or all algebraic laws over one shared heap. |
| Advantage, distance, hybrids, and reductions | SSProve supplies `AdvantageE`, reduction and triangle laws, and pRHL, although the accepted package certificate avoids dependency-tainted generic routes. | Match for Target A's finite probability equalities and hybrid mathematics through total variation/advantage, distribution equivalence, hybrid chains, couplings, and program logics. The full SSProve contextual package-reduction and pRHL surface remains part of the Target B gap. |
| Conventional PPT accounting | The repository's accepted SSProve suite is query-bounded and does not establish a full PPT implementation theorem. | No regression relative to Target A, but still incomplete for the end-to-end plan. VCVio v4.31.0 has limited asymptotic/cost scaffolding, its `secureAgainst` accepts a caller-supplied `isPPT`, and its README explicitly says computational complexity is not considered. |
| Aeneas/extracted Rust connection | Direct hax-to-SSProve import was rejected; production correspondence remains a cross-prover contract. | Better architectural fit but not automatic. Co-locating Aeneas-generated production types and VCVio in one Lean kernel reduces a representation seam; semantic refinement from Rust operations to games still needs explicit theorems/contracts. |

## Why parity is not the current goal

Reproducing the tracked SSProve module graph would optimize for framework comparison instead of the security properties exposed by the current ideal Lean models. The native CTX proof demonstrates the preferred unit of work: name a concrete bad event over a maintained model, extract a primitive-breaking witness, lift that implication to an advantage bound, and record the exact implementation-refinement and primitive assumptions that remain.

The same-kernel Aeneas/VCVio arrangement reduces one representation seam because a Lean theorem can mention both handwritten models and extracted types. It does not establish semantic correspondence automatically. For CTX, full commitment and collision extraction are proved natively for the ideal scheme and the current generated builder equals its transcript; the remaining bridge is an ordinary Lean refinement theorem from authenticated adapter inputs and the actual BLAKE2b call to that model.

The direct CTX reduction imports only VCVio's collision-resistance hardness-assumption module rather than the upstream example binding game. The exact SHA pin remains essential because VCVio's API and active development have moved beyond the 4.31-compatible release, and every production-relevant theorem still needs a transitive admission, `unsafe`, option, and axiom-closure audit.

## Acceptance path

1. Treat `ctxFullCommitmentAdvantage_le_blake2b_cr` as the first modified CTX scheme capstone: it is the direct one-shot full-control equal-encryption game, while the stronger raw-payload theorem and transition specializations explain deployment-relevant misattribution paths.
2. Complete the production bridge only as a separate corollary layer: byte representation, `LE64`, and the generated builder's exact six-field order refine `Pqxdh.ctxPreimage`; the adapter's BLAKE2b result representation, field provenance, Hax/Rust semantic preservation, and compiler correspondence remain.
3. Extend beyond the completed one-transition CTX suite only where it strengthens the scheme or composition claim: a `beaconRun` list lift merely restates that only the first `InitSent` response can reach record admission and is not a substitute for the full-commitment theorem.
4. Use the proved factor-one retained-base reduction to modified nonce-AEAD INT-CTXT and continue with the secret-prefix branch.
5. Use the conventional Boolean IND$ validation bridge under `qE < 2^96`, with one extra primitive seal and the `qH / 2^128` false-positive term; retain the tighter `qH / 2^256` key-probe theorem as a specialized alternative.
6. Use the completed typed full-fresh composition and its exact query-accounting record; retain raw-normalization, multi-key, PPT, and extracted-production gaps as explicit follow-on obligations, and audit the capstone's transitive Lean dependency closure.

Reassess the chosen game or framework if it requires a materially stronger assumption than the protocol claim, if the imported dependency closure cannot be kept admission-free, or if the project requires genuine QROM/QPT claims.
