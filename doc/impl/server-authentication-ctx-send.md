# Source-factor send through the selected CTX interface

`PqxdhServerAuthCtxSend.lean` adds twelve guarded statements for the actual selected-factor sending driver. The executable reuses `PqxdhServerAuthCtxCalls.step` and receives the 76-byte residual without a selected-message-key argument. Its hidden material goes to the ordinary selected CTX seal; concrete known material uses the existing local real seal and forwards its commitment query to the same component cache. Known material may have the selected key's bytes. No alias exclusion or key-independence premise is used.

`send_cases` evaluates the complete original send normalizer and derivation. Exhaustion returns without a component call. A reached seal retains the exact already-advanced kernel, source sequence and immutable context. Its result is `Option (Kernel × Option Encrypted)`: outer `none` is the explicit selected-nonce refusal, while an inner `none` is the actual optional source writer failure. The two outcomes are kept distinct.

`sealing_project` consumes the existing selected/known sealing theorem and preserves the original optional encrypted API reply, all unrelated auxiliary state and the shared commitment cache when the reached selected nonce is unused. `Repeated` names the precise omitted case: the reached material is a selected marker, its source associated data has width 153, and the selected challenger's nonce ledger already contains that nonce. `sealing_cases` proves the full case split, including known keys, invalid associated data, missing writer output and actual nonce refusal. A refusal retains the complete component state and source cache.

`source_cases` executes the unchanged source-side derivation and original optional seal callback. `send_source` combines the complete program with the explicit `Stops` test derived from that actual pending seal. It assumes no fresh-nonce invariant. Every non-stopping result is the source's complete advanced kernel, actual optional ciphertext and cache.

`native_sealing` identifies the callback with the literal existing native source sealing, commitment and writer interpreter. `send_material` applies the reviewed material-map driver to the existing `RawCtxSelectedChain.sendLabels` program under the exact 108-byte factor. `factor_send` combines both connections: material interpretation of the compiled stopped result equals the original full factor-side sender on the same complete state and cache, outside precisely the reported nonce stop. These equations retain the writer even when it fails; they do not infer a source publication log from a cryptographic seal.

`send_bound` proves at most one dynamic component request per send attempt. `send_other` gives zero selected raw-opening and zero uniform component requests for that send. `receive_other` and `raw_other` give zero selected sealing and zero uniform requests for the complete receive driver and arbitrary raw prelude from the companion module. Every unsuccessful attempt remains counted. Known local seals still contribute their actual shared hash query, and the separate source KDF cost is retained. These are oracle counts, not a claim that deterministic native computation is free.

The ordinary CTX endpoint starts from its own prescribed state and uniform key distribution. Applying it to the whole authentication experiment still requires the actual key-first factor supply, original shared-cache routing for all surrounding source operations, full logged Server build and Beacon sequence-one settlement, and the adaptive source event/observer connection. A one-use Server token bounds one session's build; it does not by itself bound selected seals across multiple matching sessions. The intended consumer must stop before a second hidden accept and prove that this loses no designated event using the actual source collision witnesses. This package neither assumes that argument nor supplies a global nonce-risk term. Serialization, persistence and primitive implementation proofs remain outside scope.
