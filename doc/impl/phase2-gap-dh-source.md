# Phase2 source embedding into the joint Gap-DH interface

This checkpoint connects an actual reached Beacon Phase2 prefix to the existing joint Gap-DH input recognizer. It establishes operational equality and exact root-input recognition. It does not establish pseudorandomness of the resulting root, authenticate a server response, or complete the common computational experiment.

The implementation reference is `beaconcrypt/src/beacon.rs`, in `finish_registration`: packed decoding and typed getters precede public Server identity conversion, private Beacon identity conversion, KEM decapsulation, DH1 through DH4, the assigned-ID getter, extracted preparation, and temporary-secret clearing. The exact pinned Ed25519 identity comparison occurs in extracted preparation after these native calls. This ordering matters on rejected responses: the reduction cannot skip the earlier decapsulation or DH effects merely because it already knows the response carries a different identity.

## Executable prefix and functional validation contract

`PqxdhPhase2GapDhSource.collect` retains the original twelve callback positions and every optional early exit. The simulator owns the Beacon identity, one-time key, and KEM material. It receives the selected Beacon prekey's public encoding and the selected pinned Server's public identity through the joint challenge. It does not receive either selected secret. The first and third DH results become private references containing their actual peer encodings; the remaining DH and KEM replies remain their actual source values.

The reference interpreter uses `PublicDomain` for the unavailable prekey's optional DH admission. This is an ordinary functional primitive contract: for every raw scalar input interpreted by the correct generated-scalar/clamping interface, whether scalar multiplication succeeds depends only on the checked public peer encoding; every successful result is nonzero. The predicate is the native public input domain, including the implementation's required point checks and its encoding semantics. It is not a claim that every 32-byte input is valid, that a length-only `from_bytes` constructor checks the point, or that differently encoded valid points have distinct DH outputs. The domain check is applied at the original scalar-multiplication call, after the preceding source work. Resource failures outside normal native execution remain outside this functional model. No scalar multiplication, point-validation algorithm, or primitive implementation is proved here.

The predicate contains no authentication or secrecy conclusion. It is a stronger explicit interface description than the earlier `DhInterface` record, which described only optional results and reciprocal agreement. Its use is conditional on the stated primitive correctness contract. If a concrete primitive interface admits secret-dependent optional failures beyond this contract, the public predicate must not be instantiated for that interface without accounting for those failures.

`selected_reply` proves exact equality of the optional native result under the mathematical materializer. `collect_realization` preserves the entire original effectful collection in any lawful monad. `collect_continuation` preserves every remaining computation. `prepare_continuation` specializes that equality to the complete callback poststate, then runs the original extracted preparation and erasure callback on both success and rejection. This last continuation is a mathematical native realization: it still materializes the unavailable DH values. It is not advertised as an executable root-output or secret-erasure simulator.

`collect_references` proves that every supported compiled success contains exactly its two actual selected-prekey references and successful public-domain checks. `collect_conversion` separately propagates the ordinary native public-conversion callback law through the complete optional source prefix. Neither property is supplied as an authentication premise.

## Exact source root address and decision continuation

`PqxdhPhase2GapDhInput.address` supplies the existing Gap-DH matcher with the selected Beacon prekey public encoding, the actual response ephemeral encoding, and the actual DH2, DH4, and KEM replies. This is private simulator data; calling the remaining coordinates known does not publish them or assume they are independent of the challenge.

`selected_value` and `source_coordinates` identify DH1 with the selected pinned Server's static DH against the selected Beacon prekey, using the existing joint interface's reciprocal agreement law. They identify DH3 with that same Beacon prekey's DH against the actual response ephemeral encoding. Arbitrary attacker-selected response encodings remain in the input; no discrete logarithm for the ephemeral is required.

`source_input` consumes a successful extracted root builder and proves that the address denotes exactly its 192 bytes: 32 bytes of `0xff`, followed by DH1, DH2, DH3, DH4, and the 32-byte KEM secret in source order. It does not replace any coordinate with a uniform value or move a source generator.

`pinned_conversion` consumes actual extracted preparation success, the exact pinned Ed25519 bytes, native public-conversion provenance, and `PqxdhPhase2JointIdentity.converted_public`. It derives the corresponding joint converted public point. This accounts for the Ed25519/X25519 related use through the existing same-seed functional interface. An altered raw response identity is not granted admission because it happens to convert to an equivalent point. Existing successful-preparation refinement supplies the exact raw identity equality.

`test` is executable using only the public challenge and retained prefix. `test_source` consumes the existing `PqxdhJointGapDh.testInput_continuation` and proves exact equality with a decision whether the candidate bytes equal the actual source root input. The complete prior history and both anchored decision entries survive; a failed first comparison does not suppress the second comparison. `prepared_test` discharges the reference, conversion, and constructed-root premises from a supported compiled prefix and actual extracted preparation, retaining its complete callback poststate in an arbitrary later continuation.

Successful extracted preparation is an operational branch condition in these statements. It is not a premise that the response was honestly generated, that a selected KEM key is honest, or that the subsequent application record is authentic. Failed preparation remains represented by `prepare_continuation` and carries its actual prior primitive work.

## Query accounting

`collect_bound` counts at most twelve source callbacks. `selected_bound` counts at most two selected-prekey call effects; `auxiliary_bound` counts at most ten other callbacks. Both quantify over every optional reply continuation, including later identity rejection. The original preparation's separately maintained bound is thirteen callbacks because temporary-secret clearing occurs after collection.

`interpreted_bound` charges the complete adaptive interpreter: if each auxiliary callback costs at most `qAux` queries of a chosen target class, and each selected-call effect costs at most `qVisit`, the collected prefix costs at most `10 * qAux + 2 * qVisit` queries of that class. This law applies separately to randomness, hashes, signatures, decapsulations, or other target classes supplied by the eventual interpreter. It does not declare opaque local work free. The post-collection erasure and root continuation need their own bills.

`test_bills` gives at most two ordinary anchored Gap-DH decision queries for each candidate input, zero signing queries, and zero explicit uniform queries. A malformed candidate causes no decision query. The maintained Gap-DH game separately samples the selected 32-byte identity seed and 32-byte prekey scalar, charging 64 byte-level uniform queries, and any later candidate scanner has its own existing decision allowance. This checkpoint introduces no identity, Beacon, session, or record-selection bound; those require the eventual common-experiment compiler and target selection theorem.

## Remaining cryptographic endpoint

The existing ordinary joint Gap-DH endpoint exposes the selected seed's Ed25519 signing interface and two anchored DH decision interfaces. Its winning event is recovery of the nonzero cross-DH value between the selected Server identity and Beacon prekey. Its exact same-seed signature/conversion use and actual scalar distribution are explicit. It does not return either secret, arbitrary raw target DH values, HKDF roots, or related derived outputs.

An input recognizer is insufficient to simulate the production Phase2 root and later record behavior. In particular, the unmodified fixed no-salt Extract is evaluated at a joint input containing both unavailable DH1 and DH3, together with the retained native DH2, DH4, and KEM values. CDH recovery hardness alone does not establish fixed-Extract pseudorandomness on this nonuniform joint input. Ordinary EUF-CMA, ML-KEM secrecy, or secret-key HMAC PRF security alone does not provide the missing related-input output interface either.

The subsequent construction must state an ordinary Extract/Expand endpoint on the actual joint distribution and permitted adaptive related-output context, or give a reduction that implements those outputs from already stated endpoints. It must preserve all other root evaluations, KEM operations, local identity reuse, reveals, failed attempts, and public fixed-HKDF evaluations. Neither a raw secret-dependent DH failure oracle nor a protocol-authentication conclusion has been inserted to supply that missing service. The public optional-admission seam is closed under the functional contract above; derived-output simulation and the resulting authentication advantage remain open.
