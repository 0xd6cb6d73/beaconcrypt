# Marker preservation before a later-record challenge

`PqxdhLaterChallengeMarkerPrefix` proves four support statements for the existing complete monitored wrapper. If a successful execution ends with no chosen challenge pair, it began with no chosen pair and preserves its incoming private marker. In particular, a prefix started at marker `none` still has marker `none` when it returns an unused wrapper. This is an operational invariant of the actual optional monitor; it does not assume that a selected cut is fresh or that two KDF addresses differ.

`callback_unmarked` first checks every reply path of the original wrapper callback. An ordinary request preserves the pair. A rejected challenge preserves it, while an admitted challenge always sets it; the admitted case is incompatible with a returned unused pair. The monitor's exact `record` function therefore preserves any incoming marker in the remaining cases, regardless of the selected-input predicate or the instrumented cryptographic state.

`query_unmarked` transports that fact through the actual saved compiler's optional source interpretation. Successful replies retain the full instrumented poststate and actual optional source reply. `program_unmarked` lifts it through the entire adaptive monitored program, including all callback work and the original stop-on-refusal behavior. It reasons backwards from the actual final unused pair, deriving the needed unused intermediate pair rather than assuming it for each step. A refusal cannot provide the successful return in the theorem, but it is still present in the unchanged program.

`evaluated_unmarked` applies the same implication after any stateful probabilistic component interpreter. Its premise retains that interpreter's complete initial and final state and the full returned monitored state. The conclusion transports a supported bookkeeping fact only; it gives no coupling, mass equality or independence claim for different interpreters. No program definition, query count, primitive advantage or statistical term changes.

This module supplies the marker invariant needed by a prefix consumer. The actual generated source cut still must be connected to a corresponding monitored prefix execution in the common experiment. It does not by itself prove that the monitor inserted into the complete generated sampler has reached that cut with marker `none`. The used-phase publication-trace join, inside-phase selected-input designation, two-world prefix coupling, raw cryptographic hop, freshness implications and final resource ledger remain separate obligations, as described in the [saved callback guide](later-challenge-compiler-support.md).

All four statements are checked directly with Lean 4.34.0 and guarded standard-axiom output.
