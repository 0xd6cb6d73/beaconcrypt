# Selected Beacon finish compiler

`PqxdhSelectedBeaconCompiler` closes the concrete Beacon continuation after the source preparation, private initializer and optional application getter have returned. Its executable input is their actual registration candidate, initialized opaque kernel and optional raw application bytes. The selected message key is absent. `after_application_source` compares every possible getter result to the exact source raw receive, preserving its entire owner result, optional challenger-produced plaintext, ambient state and shared cache. Missing application bytes and arbitrary malformed, empty or unaccepted raw strings remain source rejection paths.

`finish_application_source` then executes the original `afterOpening` and `finish`: sequence must be one; plaintext must contain the exact eight-byte authenticated registration binding and a nonempty suffix; registration authentication, pinned server ID and pinned server public key checks retain their original order. Success returns the original suffix and complete established Beacon state; failure returns the original aborted state. No plaintext is recovered locally or inserted into the adversary's raw message.

`native_after_application` connects the material-labelled driver to the native private kernel representation. `native_finish_application` composes that connection with the exact CTX compiler and source finish. The resulting equality includes the complete native Beacon state and the original shared state, projecting away only added CTX challenger bookkeeping. It has no success, authenticated-origin, source nonce-freshness or injectivity assumption. It is operational correspondence, not a standalone authentication conclusion.

`finish_queries` bounds this complete post-getter continuation by one dynamic CTX verification call. The private receive derivation still has its separate allowance of at most 51 retained-table lookups. The earlier preparation, initializer and getter costs are not included in this one-call bound; the common source experiment must retain and count those explicit operations before this continuation.

The source prefix, callbacks, saved descriptor consumer, original global `Gate`/`Fresh` decision and adaptive session/record selection losses remain separate composition obligations. This module does not assume that an arbitrary native callback is simulatable without its secret inputs. It changes no protocol admission rule, wire format, primitive contract or Rust source.
