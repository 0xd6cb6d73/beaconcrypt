# HB-83: general admission and parameterized bounded continuation

This unintegrated continuation topic starts from the published HB-89 corrected registration projection. It preserves production code and the maintained 14/8/18/27 gates, including the known later-record claimed/assigned-ID distinction and the original raw-encoding negative controls. Twenty-three checked operational lemmas cover admission, exact cache publication and removal, public sender evolution and material-parametric cached-target coverage. General symbolic authentication uses the eleven-field retained-value projection, excluding raw response encodings and pre-Extract input. The final family passes all 53 cases and 2,444 required classifications for initial admission and the parameterized cached/replay/immediate-future continuation. Arbitrary later receive schedules and the computational composition remain unfinished.

The candidate sender replaces the earlier expanded 52-record suffix with a private state token and a replicated worker. The server publishes the sequence-one response before emitting its sole initial token. Each worker consumes one token, receives only public application bytes, seals under the retained chain/sequence/associated data, emits actual record and plan-origin events, publishes the frame, and returns one evolved token. Its private history of earlier material is proof instrumentation for the initial-state correspondence, not production server storage and not a reveal interface. Source storage, erasure and permitted reveals must retain that distinction. This model includes arbitrarily many subsequent sends; matching finite production traces still respects source counter exhaustion and successful-seal/codec contracts.

The current sender correspondence concerns successful seals before source overflow. Production rejects an empty request before taking the ratchet; after sequence allocation, even a failed seal callback is passed to `finish(None)` and consumes the allocated material. Those distinct failure behaviors are not established by the successful-only worker theorem. The common sender experiment must expose the actual optional result and preserve that transition, or state a justified successful-input/codec contract for the exact executions it covers.

This continuation theorem concerns the actual extracted phase drivers; it does not replace the still-required common computational/symbolic experiment or prove new symbolic correspondences for unrestricted later traffic.

The receive-phase query counts are exact: an admitted initial target `n` makes `n` ratchet-derivation requests and one opening request; cached reception makes no derivation request; identical-frame replay rejects before derivation or opening; the immediate future path needs one derivation before opening. Targets zero and above 51 reject before those receive requests. These counts do not erase earlier Phase-2 work: production has already decoded the response, performed its KEM/DH operations and derived the root and initial chains before attempting the initial record. A short or wrong binding is checked only after authenticated opening and then aborts the whole registration owner. The common computational experiment must account separately for all earlier primitive calls and public evaluations.

## Symbolic boundary

`generate-general-registration.py` derives separate honest role templates from the reviewed existing Phase-1 and Phase-2 roles while preserving the old model verbatim. It emits all 51 prefix macros and a sender that publishes the original response and then accepts arbitrary application requests through the replicated sequential worker. The beacon receives an arbitrary candidate response from the attacker. Each case specializes only the expected initial frame sequence; the private admitted-state handoff carries the same session agreement, associated data, claimed ID, receive state and send chain for every successful case.

The initial family also needs to cover sessions choosing different admitted targets in the same execution. For an initial query whose antecedent belongs to a selected owner admitted at `n`, specialize that owner to `n` and replay the other owners’ unchanged public prefixes. Each Beacon publishes its signed bundle and registration continuation and inserts its honest-origin entry before the target-dependent response tail. The independent registration replay guard also precedes that tail. The remaining tail changes only local tests, events and an output-free owner handoff. Thus another owner’s different target may turn its tail into rejection without changing attacker knowledge, replay/table state or server sends. The selected query’s right-hand origin and plan events occur on the server or before those tails. The ordinary agreement product retains a separately fresh owner tag, so an erased other-owner handoff cannot feed the selected owner. These syntactic conditions and the reviewed trace projection justify the mixed-target initial family; they do not establish arbitrary post-registration event correspondences.

A `crypto_frame` term denotes the decoded ciphertext, tag, commitment, sequence and sender fields. Exact-record origin therefore concerns those authenticated fields and payload, not identical Cap'n Proto serialization bytes. Equivalent noncanonical encodings are represented by the same term; complete-input parsing and encoding equivalence remain part of the codec boundary.

`general-registration-continuation.pvl` consumes the actual private admitted-state handoff. Each fresh Beacon creates exactly one continuation tied to its agreement; this process structure represents the source ownership boundary and prevents a separate replicated consumer from duplicating an admitted owner in the symbolic approximation. The adversary can select any retained cached target or request immediate future reception. Cached success removes precisely that entry using the production last-slot swap. The generated ordered destructor cases cover every one of the fifty source cache positions. The source send chain, receive counter and live chain are carried from the selected admitted state. Thus the symbolic continuation is parameterized over every admitted counter and every retained target, instead of fixed cached-1 and future-4 constants. It remains a bounded continuation shape, not a theorem for arbitrary later symbolic schedules or reveals.

The admission-only query runs project away the receiver continuation; the continuation queries enable it. This projection uses more than event ordering: the continuation contains no output, table access, phase change, fresh allocation, shared write, reveal, or optional-plaintext oracle reply. Its only effects are continuation events and inputs from the public network and its own exact-agreement private handoff. Distinct fresh Beacon agreements cannot consume each other's handoffs. The private handoff producer has no following action in its parallel branch, so deleting its consumer can block only an output with no later initial event. Projecting a complete trace deletes those local continuation steps without changing any admission event, public output, or other owner's state. Conversely, an admission trace is a prefix of an enabled execution that schedules no continuation step; the adversary can retain and repeat public messages. Thus the initial-query event traces coincide. The runner checks the exact continuation macro inventory, absence of observable/shared effects, allowed input channels, agreement match, and event/call inventory before applying this law. This is a checked syntactic scope condition plus a reviewed trace argument, not a general erasure theorem for arbitrary protocol continuations. Adding a public plaintext result or shared persistence update invalidates this projection and fails the guard.

Immediate-future safety and its sequence guard use a separate stronger receiver projection.
