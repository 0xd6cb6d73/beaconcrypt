# Recover identities from actual associated data

`PqxdhServerAuthPublicationIdentity` recovers the ordered Server and Beacon raw identity arrays from the associated data used by actual registration candidates and selected records. It reuses the existing extracted-source proof `build_associated_data_abs`, the proved fixed-layout theorem `Pqxdh.assocData_inj` and the concrete byte-array abstraction. There is no new injectivity assumption about a cryptographic output, KEM shared secret, arbitrary message writer or decoder.

The source layout is `Tag_sig(Server identity) ++ Tag_sig(Beacon identity) ++ INFO_PQ ++ INFO_R`. Both raw identity arrays have exactly 32 bytes. In the extracted 153-byte output, their raw bytes occupy zero-based positions 1–32 and 34–65, respectively. The existing refinement proves this complete layout from the generated source implementation. `source_bytes` consumes an actual successful output of that implementation; `source_identities` then recovers equality of the native arrays from equality of two such outputs' byte abstractions.

`prepared_bytes` and `prepared_identities` consume actual successful `server_prepare_commit` equations. They reuse the generic `prepare_commit_fields` theorem already maintained in the negative-control module; that theorem itself has no negative-control, cryptographic or honest-input premise. It proves that candidate associated data comes from the current Server binding and the supplied pending registration's Beacon identity. `beacon_bytes` consumes the original Beacon associated-data construction. These source facts preserve the identity order and the claimed/current binding distinction.

`receipt_identities` consumes the published `BuiltRecord.At` receipt, whose selected input and first-record context came from the actual successful builder and its inner/outer writers. Given equality of the selected entry's AD bytes with the Beacon control's AD, it identifies the supplied pending Beacon identity and the pre-build Server identity with that control's two identities. `matched_identities` discharges this AD equality from the actual metadata admission equation, the reached `LocalTarget` and the existing same-full-tuple match. It retains these local operational premises explicitly; it does not claim to establish the whole adaptive run's admission or matching evidence by itself.

The seven statements add no queries, sampling, primitive assumptions or probability loss. They need no readback law and do not infer a session from equal roots or record bytes. Connecting the local admission/matching evidence to the final whole-source acceptance is a separate consumer. Linking the recovered raw identity to the retained signed Phase1 bundle and its prekey, one-time and KEM fields still needs the existing signature-origin/EUF analysis and actual source history. Thus the result does not yet identify the full eleven-field cryptographic session or establish a maintained ProVerif correspondence.

The module depends on the reviewed build-journal checkpoint `972af169dccc1bea4d0cc9bfa16154b1fd2d85e1` and unchanged source refinement dependencies. All seven statements carry checked axiom guards. Validation is scoped to this module in the pinned existing environment; no new aggregate build is claimed.
