# Exact functional KEM graph and adaptive call trace

The maintained symbolic KEM frontier needs to preserve both ordinary distinct public outputs and permitted byte aliases. The sibling HB-92 coin-only quotient forces equality for same coins under different keys and is only a diagnostic. This follow-on leaves all existing ProVerif files, queries, runners and controls unchanged. It supplies the bounded actual-value graph interface for a later serialized applied-pi service; it does not classify a persistent protocol query.

`KemFunctionalGraph.lean` has thirty-four guarded statements. Its complete addresses are public-key derivation from the supplied secret, encapsulation from the supplied public key and coins, and decapsulation from the supplied secret and ciphertext. Replies retain the actual public key, entire ciphertext/shared-secret pair, or actual optional decapsulation secret. No field is replaced by an owner/index constructor. `Pqxdh.Crypto` is the existing fixed functional interface with total encapsulation and matching-key correctness. Native optional public-key validation/encapsulation, source key generation and actual coin distributions are separate interfaces to instantiate; their rejection or random effects are not inferred from these equations.

`lookup_consistent`, `tableStep_reply` and `tableStep_consistent` prove that memoized evaluation returns the same actual answer and retains functional consistency. `lookup_append`, `tableStep_preserves` and `tableStep_lookup` preserve every earlier complete binding and store the returned answer. `tableStep_cases`, `tableStep_repeat`, `tableStep_extends` and `tableStep_length` identify the exact hit/miss alternatives: a repeated address leaves the whole graph unchanged, and an unseen address appends exactly its actual answer. No input or output injectivity is assumed. Public and private dispatch tags are outside the address, and `public_private_same` proves that both routes use the same computation. The tags record a caller category; they do not enforce native capability ownership or grant attacker access to a private source callback.

`same_key_ciphertext` derives the actual coupling required when two matching-key encapsulations return the same ciphertext: their shared secrets must agree because the same functional decapsulation cannot return two different answers. `decap_before_encap` preserves a prior successful answer when a later encapsulation uses that ciphertext. `decap_prior_reply` covers every prior Option, so a stored rejection is incompatible with a later matching ciphertext. These are consequences of the supplied matching-key correctness law, not assumptions excluding collisions. Wrong-key decapsulation remains its actual Option and may coincide with another operation's answer; no free ciphertext destructor forces rejection.

`table_step_erasure` and `table_execution_erasure` erase the private graph and obtain the exact original dependent reply, arbitrary adaptive client result and complete base-interpreter state. The base interpreter is arbitrary and stateful in any lawful target monad, so its actual random calls, effects and rejection branches remain. `classified_execution_erasure`, `classified_query_bounds` and `classified_supported_nodup` add the existing common actual-byte representative table without altering this result. Inputs and replies share one table. `observed_length` records at most four fields per KEM call, and `recorded_field` supplies a retained lookup for each actual field. Together with the previous same-table `branch_eq`, these facts preserve both equality and disequality choices after the relevant lookups are established.

The source-independent `Compatible` predicate states only necessary finite constraints: operation/answer shape; agreement of a stored public-key derivation, encapsulation and matching decapsulation; and agreement of two same-key encapsulated secrets when their ciphertext bytes coincide. `consistent_matches`, `consistent_decapsulation`, `consistent_ciphertexts` and `consistent_compatible` derive these conditions from the actual functional graph. `ValidExtension` permits either an exact cached answer or a new complete binding whose resulting table meets these constraints. `tableStep_extension` embeds every actual call in that relation. New outputs may be represented by previous byte classes or by new actual values. The relation is an overapproximation: it neither proves that every allowed finite graph extends to one global `Crypto` instance nor assigns probabilities to its choices. Matching-key constraints can become relevant when a public-key binding arrives later; actual consistent extensions satisfy them in every order.

The traced interpreter constructs the chronological list of actual public/private KEM request/reply events itself. Every repeat and optional rejection remains an event even though only misses grow the graph. Other base queries are forwarded unchanged and are outside this KEM-only call projection. `traced_step_reply`, `traced_execution_erasure` and `traced_fields_erasure` retain the original adaptive result and full primitive state. `source_supported_trace` starts from empty graph/classes and obtains one actual supported instrumented execution with that same complete outcome, a valid finite `Trace` from the empty table and unique byte representatives. This is not a trace guessed independently of the program or selected after changing its replies.

`Extension.length`, `Trace.length` and `Trace.preserves_lookup` show that every allowed finite trace retains its old bindings and grows by at most the number of calls. `traced_query_bounds` gives exact equivalence of every selective underlying-oracle cap for the complete transcript/class instrumentation. These statements count the actual base interpreter's oracle requests; fixed functional primitive evaluation, byte comparisons, scans, class insertion and log copying are real local work. No native runtime, constant-time or bit-work bound is asserted.

The graph contains secret input bytes, and its values, numerical classes and call history remain private ghost state, excluded from every network, reveal, snapshot and persistence interface. They are not public wire encodings, unguessable names or key handles with an injectivity guarantee. A public call that supplies a value previously represented privately must share that actual value's class. Conversely, an actual distinct value receives a different representative. This component does not expose those representatives to a reduction or adversary.

The next applied-pi service must serialize this one graph, retain complete source frontend arguments and original request-specific replies, and prove the actual event/observation projection from admitted source control through indefinitely repeated send/receive operations. It must retain public evaluations and permit later successful public guesses of hidden bytes through the same interpretation or identify them as an actual bad event with a computational bound. Merely replacing an unseen byte by a fresh symbolic name would exclude such guesses. Cross-owner key/context/material aliases can invalidate unconditional owner-origin correspondences; later protocol statements must preserve the actual origin alternative or explicitly derived alias, exposure, guess or primitive-forgery events. Those events cannot be assumed absent because a constructor is injective.

This functional graph does not establish a ProVerif process simulation, a source-free probabilistic scheduler for abstract choices, ordinary ML-KEM IND-CCA security, hidden-value collision/guessing bounds, persistent registration/record authentication or global confidentiality. The existing source consumed-position proofs and parameterized admitted poststates remain separate ingredients, as do native optional/error/coin/capability mapping, restoration/copy policy, source KDF/material interpretation and API plaintext declassification. No generic trace monotonicity transfers the prior quotient's results across changed equality/disequality branching.
