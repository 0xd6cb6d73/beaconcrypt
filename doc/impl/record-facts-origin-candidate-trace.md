# Candidate traces for adaptive source requests

`PqxdhRecordFactsOriginCandidateTrace` supplies the finite candidate family needed by the selected failed-writer guessing argument. It is generic instrumentation of the existing `ServiceSpec`, with no new primitive, decoder or security contract. Its extraction function examines a request and returns either one candidate digest or none; the actual raw-byte extraction and its relationship to a replay match are established separately.

`logger` forwards the exact original service request and returns its exact original reply. It appends the optional candidate to an analysis-only list. `traced_pure` and `traced_query_bind` expose these literal equations, including every reply branch of the original adaptive continuation. The list is not returned to that continuation and does not affect its choices. `traced_erase` proves that removing only the final analysis list recovers the original source program. `interpreted_erase` proves the same equality with any stateful probabilistic service interpreter, retaining its complete state, so caches, seal dictionaries, chains, seeds, counters and existing logs remain intact.

`traced_queries` preserves every original predicate query cap. In particular a zero cap on further selected seals stays zero; recording candidates adds no service call. `traced_fresh` separately preserves the existing history-annotated attempted-seal freshness rule, with the same sealing history and every possible reply. Neither theorem assumes a selected key is honest or exposes its secret material.

`traced_length` proves that the final list has at most its starting length plus the original counted-request cap. Its only bridge premise is that every request yielding a candidate is one of the requests counted by that cap. This is a syntactic query-accounting interface to be discharged by the actual extractor, not a cryptographic assumption. Requests yielding no candidate remain in the execution, and all original source costs remain counted by their existing bills. The theorem does not equate an erased experiment's costs to the original counted execution or waive opaque work.

`traced_prefix` retains the complete prior candidate list through every supported continuation. `traced_candidate` proves that the candidate extracted from the current query appears in every completed trace, regardless of that query's actual optional reply and the later adaptive schedule. These statements provide the prefix-to-final membership fact without changing or secretly filling an adversarial input.

`guess` pads the candidate list to a fixed `Fin cap` family using optional list lookup: unused indices return none and need no oracle query. `guess_complete` proves that every list member occurs at a finite index when the length is within the cap. `source_guess_complete` discharges that length condition directly from `traced_length` for an empty starting list. It introduces no probability loss; a consuming union bound must charge the explicit number of indices.

All eleven public statements have exact guarded axiom checks, with only ordinary Lean axioms. Direct single-module validation has no error or warning. The actual raw decoder candidate, its counted raw-request category, the selected replay-match inclusion, the earlier failed-seal ordinal and the final unpublished-origin bound remain consuming source joins. This generic trace module proves no unpublished-origin or secrecy probability by itself.
