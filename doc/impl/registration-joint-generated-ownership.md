## Scope and actual execution

`PqxdhRegistrationJointSchedule` runs the existing `PqxdhRegistrationSchedule.Spec`: uniform requests, typed Beacon creation, first-bundle attempts, arbitrary-byte Server acceptance, pending-token response building, arbitrary-byte Beacon finish, public HMAC, shared hash and current-kernel reads. This is one Server with many Beacons; it establishes no multi-Server or cross-Server imported pending-handle result. Public owner addresses, identity creation indices and KEM creation indices are separate values.

Each private analysis entry contains its original complete native owner and both creation indices. The private identity/KEM pools retain their entire histories. These fields are used in the representation proof; the public handler returns only the original reply type. No private-pool query or additional reveal capability is added. Existing current-kernel reads remain available through the original native interpreter.

Creation uses the existing `JointCreation.material` draw in identity → prekey → KEM order and installs the same values into both the source owner and the private service views. The later bundle call draws its one-time scalar only when the source Fresh phase requests it. All three signatures precede the optional writer, and their history survives writer failure. Finish runs the existing complete annotated native owner once, retaining every preparation, root, initializer, raw opening, sequence-one check, binding check, pin check, failure and publication effect. Only the selected owner is reinstalled. Other requests use the unchanged complete shared interpreter.

The `source` projection forgets only indices and private service annotations. It keeps every raw source owner, every native protocol field and both complete primitive caches. `program_source` proves equality of the whole evaluated oracle computation for any finite adaptive original client and any starting annotated state. Its result includes the arbitrary client result and full native poststate; it is stronger than equality of key marginals or public transcripts and can be composed with any continuation on those values. No invariant premise filters this source equality.

The starting `initial` state has no Beacon owners and accepts arbitrary existing private pools and a supplied native shared state. The cohort proves generation of Beacon slot ownership from that empty-owner start. Server construction, raw pin-width parsing and runtime initialization belong to the already modeled outer surface; this cohort does not replace their proofs or claim to have joined that outer surface to the new private-service scheduler.

## Ownership and selected finish

`Owned` requires the exact identity seed at an entry's identity index and the exact current KEM pair at its KEM index. The KEM requirement covers Fresh, FreshWithCoins and InitSent. Established and aborted owners have no live KEM field, so the invariant does not reconstruct one from the retained private pool. Equal public key encodings never identify or merge indices.

The source-generated invariant is preserved under every original request, including failed bundle writers, retained-coin retries, missing addresses, failed Server accepts/builds, unsuccessful Beacon finishes and operations after establishment. The supported-execution premises retain complete output and private state. They introduce no authentication, successful opening, fresh target, accepted record or independent-key assumption.

`generated_slots` applies the invariant to an arbitrary actual owner lookup after any supported adaptive prefix. It supplies the exact seed and InitSent KEM-slot conditions previously required by CompiledOwner8. `generated_finish` then compares the actual selected scheduler finish with the existing compiled private-service owner. Both sides retain the public optional reply, the complete encoded owner list, both creation indices for every entry, both entire private service pools, and the complete native shared poststate from the same run. Only the native identity/KEM representations are mapped to the established handle representation. The raw secret-bearing owner is not claimed to be recoverable from a handle. All other owners remain in this full comparison. Because the theorem is an oracle-computation equality, any continuation on that complete mapped result has the same evaluated distribution.

## Query accounting and contracts

For all-reply source-class caps `qCoin`, `qCreate`, `qBundle`, `qAccept`, `qBuild`, `qFinish`, `qHmac`, `qHash` and `qReveal`, `schedule_uniform` proves the typed schedule's uniform-query bound:

```text
qCoin + (64 + G)*qCreate + 32*qBundle
  + (96 + E)*qAccept + 64*qBuild
  + 69*max(64, D)*qFinish + 64*qHmac + 64*qHash
```

Here `G = keygenUniform + baseUniform*keygenBase`, `E = encapsUniform + baseUniform*encapsBase` and `D = decapsUniform + baseUniform*decapsBase`. Each cap quantifies all typed replies and counts attempted public calls. The current-kernel read has no uniform-oracle request in this interface; its local execution is retained. Deterministic signing, verification, conversion, local DH, codecs and public evaluations are actual local computations or existing contracts, rather than removed work. Runtime initialization and Server-seed generation are outside this typed schedule and retain their separate existing outer-surface bills.

For the compiled selected finish, `generated_compiled_resources` preserves the existing per-attempt bounds: at most one KEM decapsulation, one joint converted-identity DH, 56 native-tail requests, and zero other private service classes. Complete interpretation costs at most `69*max(64, D)` uniform requests, including KEM/base work and cache sampling on rejected calls. Creation and bundle keep their previous component bills: one identity creation, one KEM creation, 32 local prekey bytes; then at most one local one-time generation, three signing requests and one optional writer per bundle attempt. This cohort does not yet claim a global private-service reduction ledger for a compiled version of every scheduler operation.

The proof adds no cryptographic advantage term or statistical loss: its new results are exact representation equalities, support invariants and query upper bounds. The existing correct primitive/codec interfaces, exact joint Ed25519/X25519 contract, restricted programmable Extract model and shared classical CTX/BLAKE2b ROM remain explicit inherited contracts. No primitive algorithm or implementation is proved.
