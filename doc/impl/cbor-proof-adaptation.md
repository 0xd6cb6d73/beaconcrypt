# CBOR proof adaptation after upstream merge

This record concerns merge `11033723`, which merged upstream/main `0c629b1c` into `vcvio`. The executable extracted core is unchanged apart from a documentation comment; the adapter, parser, dependency configuration, bindings and proof-to-source checks changed.

## Changes relevant to verification

The three transport records are deterministic CBOR arrays with version 1 and distinct kind tags: `[1, 0, identity, prekey, one_time, pq]`, `[1, 1, identity, ephemeral, kem_ciphertext, application_ciphertext, assigned_id]` and `[1, 2, sequence, sender_id, ciphertext]`. Request key fields and response identity/ephemeral/KEM fields have exact schema widths. All three decoders reject trailing input, indefinite containers, wrong primitive types and messages larger than 33,554,432 bytes. Server routing uses the complete frame decoder before selecting a peer. The old partial-header reader remains a generic historical abstraction, rather than the production CBOR routing implementation.

The response application field is raw `C || T || U`. It contains no nested CryptoFrame and no encoded sequence or sender. Server registration seals with sequence 1 and its server ID; Beacon registration supplies sequence 1 and its pinned server ID before the ordinary CTX opening. The authenticated little-endian assigned-ID prefix and its verification remain unchanged. Ordinary established records still carry explicit sequence and sender fields. Their complete-message size preflight runs before taking the ratchet kernel or deriving a key; response size admission also precedes registration publication work. Writer allocation failure remains possible.

The old sequence-three registration experiment with its omitted post-open gate is retained as a historical counterfactual decoder experiment. It is no longer a witness obtainable by deleting only that gate in current production: the registration helper already supplies sequence 1 to CTX. The established sequence-three receive/cache continuation remains meaningful. The new `cbor-registration` ProVerif scenario strips logical frame metadata and restores only sequence 1 and the pin; it checks genuine opening, reachable later-sequence and other-sender attempts, and rejection of both authenticated context mismatches, even when all three fixtures deliberately reuse the same key material.

## Proof boundary

The existing reductions use logical decoded frames, and their codec laws are premises. The actual CBOR build uses a pure payload projection in place of the removed frame writer and passes raw protected bytes to the optional outer response writer. Finish is connected through explicit virtual-frame normalization: a successful response reader wraps its raw protected payload with sequence 1 and the pin. A separate normalized logical build removes that virtual wrapper before outer serialization; its relation to the actual raw build is stated separately. Raw payloads are never assumed to preserve arbitrary frame metadata. The new Lean modules isolate exact CBOR size arithmetic, full-decoder routing, the raw registration writer and this registration codec normalization. Generic historical source programs retain their own stated contracts; a normalized logical program must not be described as a literal execution of the removed Cap'n Proto calls.

The parser's F* generation provenance is a separate boundary. Its generated Rust, handwritten preflight/sizing code, Rust compilation, allocation behavior and correspondence to the Lean codec still require their documented contracts and executable checks. New theorem statements do not claim verification of EverCDDL's generated Rust or libsodium. The updated dependency pin is `libsodium-rs 0.3.0` with `libsodium-sys-stable 1.24.3`; changes to the native implementation remain outside the extracted-core proof. New Wasm hosting and persistence APIs do not extend the experiment's approved command set.

The fixed-codec representation uses `CborTaggedCodec`: an eight-byte public sender prefix around native response bytes, with exact inverse and read/application/write laws. This prefix is mathematical bookkeeping and has no message-size cap of its own; capping the envelope at the native maximum would incorrectly reject a native response that already fills the allowed message size. Native parsing still happens on the original bytes. The fixed codec retains the native Phase-2 read-back law under the stated virtual-frame round-trip contract, without requiring every Beacon to pin the same identifier.

`CborRawRegistrationBuild` proves that removing the ordinary-frame-writing capability yields exactly the raw seal program under arbitrary stateful optional AEAD/hash interpretations. Its pure virtual-render bridge changes only the returned representation. The supplied-root raw builder is independent of the ordinary encoder, and an outer-response failure keeps all reached primitive/cache/log effects while publishing no peer or control change. This isolates the removed allocation step without postulating its success.

`CborResponseWriterMap` proves that a pure encoding of the optional outer response changes only the returned serialized bytes. The initialized send tail, candidate tail and full supplied-root builder preserve the entire protocol state and arbitrary stateful probabilistic callback effects, including writer failure and Rust diagnostics. These laws are reusable representation steps; they do not assert that an arbitrary response writer is the current CBOR serializer.

`CborResponseRepresentation` proves response-representation naturality through Phase-2 collection, preparation, root consumption and the complete owner operation. `CborTaggedFinish` instantiates all callback relations for the actual native implementation and lifts the equality through the scheduler and deployment dispatcher. Its production theorem equates the actual CBOR finish with a fixed tagged-codec finish at the same complete state, including mismatching pins, malformed responses, inactive owners and primitive caches. It adds no cryptographic premise. This closes the local finish representation step, while the complete event and security-headline transfer remains a separate composition step.

`CborAdmissionSend` proves that both empty sends return `None` with exactly the original deployment state, for missing, inactive and established handles. `CborAdmissionSimulation` combines those results with the empty-build substitutions into a full handler equality and arbitrary adaptive execution equality, including the unchanged secrecy ledger above the replacement handler. Its guard still reads the complete internal state; these operational theorems do not claim that an adversary can inspect that state.

## Adaptive compiler and remaining security scope

`CborTaggedBuild`, `CborTaggedOther` and `CborTaggedSimulation` combine the response and finish representation laws for complete normalized logical executions. `CborLogPins` recovers active Beacon pins from successful public creation records under the existing compiler invariant. No global numeric pin restriction is introduced. These normalized executions retain the historical shared optional frame-writer interface. The actual CBOR build instead uses the separate pure raw writer; it must not be identified with that normalized model merely because their successful ciphertexts agree.

`CborAdmissionCompiler` implements exact complete-message admission in the existing source14 interface. It tracks the last public assignment and prefetches the existing peer or owner kernel once before send admission, caching it before the old local compiler runs. `CborAdmissionPreload`, the role-specific compiler modules and `CborAdmissionInvariant` preserve the full reconstruction invariant, public counter and merged deployment state. Oversized sends return before primitive work; oversized builds substitute `some []`, retaining moved-token consumption. Failed admitted nonempty sends still advance their kernel even when the optional physical writer returns `None`.

`CborAdmissionCompileStep` proves arbitrary adaptive simulation and invariant preservation. `CborAdmissionCompileGame` derives the initial allocation counter from the generated Server constructor and proves initialized source/game equalities. `CborAdmissionCompileBudget` retains the existing classwise costs and proves unbudgeted absence of identity, KEM, prekey and one-time field reads. `CborAdmissionCompileSecrecy` composes the unchanged secrecy ledger above the admission compiler, retaining the hidden test bit, fresh-message draws, transcript and complete states. Its full-interface budgets and unreadness use the same existing cost formulas. These are checked fixed-codec operational theorems; they do not silently change the original security headlines' compiled program.

Four obligations remain before claiming those headlines for physical raw-CBOR execution. The raw registration writer must be joined to a hybrid source14 implementation that keeps the physical optional writer for ordinary records without inventing an initial-frame allocation failure. The public-client step and adaptive correspondence must be assembled from the pin-selection invariant, tagging and stripping laws. The public tag/drop translation must preserve session designation, linkage, eligibility, target selection and each named win event, including Mode P observations and produced-frame origin. Finally the existing headline and record-lift chains, which hardcode the original `compileFull`, must be connected to the new certified compiled program. The current adapter transcription, local representation equalities and unchanged costs do not by themselves discharge these event and game equations. These are proof obligations, rather than added cryptographic assumptions or claimed results.
