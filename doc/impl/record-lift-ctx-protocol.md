# Global CTX source interpretation

`PqxdhRecordLiftCtxProtocol` connects the actual dynamic protocol program to the ordinary selected-key CTX interface. It proves exact operational equalities, including the continuation after every optional reply, and retains an explicit stop before a repeated selected nonce. It does not yet prove a global CTX security bound or remove that stop.

## Source admission and the reduction

`ownerReceive_admitted` derives the opening conditions from the actual empty-input check, frame decoder and `ValidFrame` branch. The emitted opening carries the original raw bytes, decoded frame, associated data and prepared sequence equal to that frame’s sequence. Cached and future paths use the existing `OpaqueDrivers` source discipline. Malformed input, invalid associated-data width, replay and state-machine failures remain the original branches. `schedule_admitted` proves this discipline for every adaptive `WorldSpec` client and every supplied control state; `program_admitted` specializes it to the frozen environment/adversary/ledger program in either mode. No honest sender or reachability premise is added.

`ctxInterpreter` handles the same ten private services as `Protocol`: seed allocation, public coin, public hash, effect charge, hidden coordinate lookup, labeled opening, labeled sealing, complete caller-known send, complete caller-known receive and tagged publication. The executable interpreter takes no selected message key. Its private `Secret` contains the actual lazy seed cache, a persistent table with the selected key32 projection omitted, the produced and pending writer logs and the effect ledger. Only the private interpreter reads those values. The source client keeps its original optional replies, control state, environment and world-owned test/fresh ledger.

Caller-known operations execute their complete original native programs. `knownRom_step`, `knownRom_program` and `knownProgram_source` retain real functional HKDF and AEAD, forward hash requests to the same shared BLAKE2b oracle and append the attempted frame even when the writer returns `None`. They impose no distinct-key or nonce premise on caller-known keys. Hidden opening returns exactly the ordinary CTX challenger’s optional plaintext through the existing native callback; no secretly recovered plaintext is inserted into an adversary target. Hidden sealing distinguishes an endpoint refusal from the source writer’s ordinary `None` result.

`query_source` and `global_source` prove equality for every service and its complete adaptive continuation, after retaining the source cache and selected nonce history and erasing only the unused endpoint bookkeeping. `reduction` is the actual `AdaptiveCtxDynamicKnownKeys.wrapped` client of the ordinary `ReceiveSpec` endpoint. `reduction_source` and `schedule_reduction_source` identify its real interpretation with the native comparator. The endpoint key occurs only in the proof-side interpretation and never in the reduction definition.

## Counter erasure and the literal source

`Bare` contains the full shared ROM cache, public-effect ledger, actual lazy seed cache and its own query/draw accounting, complete chain table and both writer logs. `erasePrivate` removes only the native primitive-call counters and uniform-draw counter from `Protocol.Private`. It removes no primitive evaluation, sampled byte, reply, table entry or source state decision. The erased counters cannot be reconstructed from an ordinary optional opening reply, since commitment and AEAD rejection take different internal paths.

`logged_effects_erasure`, `lookup_effects_erasure` and `sampled_bare` prove the concrete native, lookup and sampling projections. `bare_query` covers all ten services and `bare_schedule` preserves the whole returned `Result` through any adaptive service program. These equalities are independent of a selected key, target coordinate or mask. `program_bare` joins them to the complete initialized mixed `WorldCompiler.run`, including arbitrary environment state and the test/fresh ledger. They remain valid under every concrete mixed lookup selector. The original source counters and the reduction’s oracle bill are separate accounting obligations; counter erasure does not make either kind of work free.

## Selected stop and complete continuation

`CutState` adds only a selected coordinate, its nonce and an attempted-nonce list to the literal `Bare` state. `SelectedSeal` tests structural material-coordinate equality on a hidden sealing service with the actual associated-data width. Equal byte values at another coordinate or in a caller-known kernel do not select that service. All such aliases remain permitted throughout the source relation.

`stoppedBareInterpreter` performs the original bare operation unless the selected nonce has already been attempted. At that precise boundary it stops with the entire pre-operation state. On an allowed selected attempt it retains the real opening/sealing result, cache changes and writer log, and records the nonce even when the writer returns `None`. Unselected operations preserve the selected history and execute their complete native work.

`lookup_full_realization`, `sealing_cut` and `source_cut_query` restore the omitted message key only on the proof side and identify the native comparator with that literal stopped source. Their table condition is that the selected cache entry is already designated ideal by the supplied mixed selector. This is an explicit intermediate-game condition; it is not a claim that a network-selected identity is honest or that a real key is uniform. `source_cut_parameters` proves that this condition is stable through every supported service result. `source_cut_schedule` then proves the complete adaptive continuation equality, retaining the final error state when a refusal occurs.

`reduction_cut`, `schedule_reduction_cut` and `program_reduction_cut` combine those equalities with the constructed ordinary selected-key reduction. The last theorem covers both actual frozen mode programs, preserves their full returned environment/ledger/control and derives all raw-opening conditions from the source program. It still contains the explicit selected nonce stop.

## Contracts, counts and remaining joins

These statements use the already declared functional primitive and codec interfaces and make no cryptographic hardness assumption. They do not assume source reachability, independent record keys, absence of byte aliases, no selected-key reveals or final protocol authentication. The temporary selected-entry condition is stated in the relevant realization theorems. All primitive implementations remain trusted contracts.

The existing local CTX oracle bounds remain 76 uniform endpoint queries for a possible full76 lookup miss and at most one ordinary opening or sealing service query per callback. A hit reuses the retained sample; real KDF evaluation remains real. Allocation still runs the actual persistent 64-byte seed sampler, public coins and hashes execute their actual requests, and every caller-known native program remains present. This operational module does not claim the final global numerical reduction bill; the companion service-cost transfer must prove the bounds for those complete programs and connect them to the actual global source budget.

The remaining joins are the uniform selected-key cut and its actual input distribution, source query-cap transport, selected-history stop elimination before any refused reply, global record selection and final integrity/privacy events, and any alias probability terms in a target-key-free experiment. The separately proved source history is intended to remove the stop through pre-query freshness, not by conditioning on a successful stopped run. Later post-phase observers may retain the full returned environment and shared public cache; no theorem here permits them to observe omitted secret table state. No persistence, snapshots, storage or primitive implementation proof is introduced.
