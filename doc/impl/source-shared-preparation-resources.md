# Complete source preparation query accounting

The three resource modules consume the literal shared-ROM preparation and first-record prefix established by `PqxdhSourceSharedPreparation` and `PqxdhFirstSharedMessagePrefix`. They count every branch of those programs. A rejected, malformed, attacker-owned, or ineligible candidate is not deleted, and its original adaptive common decision is retained. The resource premises concern named generators, native callbacks, and source schedules; none assumes a bound on an opaque final observer or a security conclusion.

`PqxdhCommonSharedRegistrationResources.step` checks the actual registration compiler one native interface at a time. Its fixed-HKDF, known-key AEAD, frame encoding, identity validation, and logical erasure are deterministic at this interface. The commitment makes one shared hash request. Peer reservation, plaintext reservation, and the actual optional response writer pay separate bounds `qPeer`, `qPlaintext`, and `qResponseWrite` for their complete local probabilistic computations. `cost_sum` sums the existing nine-class native partition, and `build` consumes the original `AcceptedRegistration.buildReady_weighted` theorem. The resulting builder bounds are one hash and `qPeer + qPlaintext + qResponseWrite` local uniform calls, preserving failed allocations, failed writers, actual optional replies, and complete auxiliary state. The native operation ledger still counts the deterministic operations; these statements do not give a zero running-time bound for parsing, primitives, or serialization.

`PqxdhSourceSharedPreparationResources.coins` forwards a complete local probabilistic computation with no new hash request and its full original uniform bill. `completed` consumes the actual ordinary post scheduler. `accepted` composes the literal registration builder with that same scheduler for every possible builder reply. `afterEncapsulation` retains optional encapsulation failures and the source DH/root checks. `common` includes the consumed-registration test, actual ephemeral draw, optional native encapsulation, and whichever complete source continuation is reached. `dispatch` also includes the unchanged original signed-field filter and the eligible branch, including its real encapsulation on root failure. It adds at most one ephemeral draw and one encapsulation before the common continuation. No selected-KEM honesty premise or assumption that common decisions are false is used.

`run` adds the full generated identity/prekey/one-time prefix, three original signatures, optional Phase1 publication, and complete original adaptive main schedule. `prepare` then charges the actual outer KEM key generation and encapsulation. Write `T = 1 + qSelector + 69*qLocal`, where `qSelector` bounds the complete original interpreted identity/base/KEM selector callback and `qLocal` bounds each complete actual non-raw native callback. The existing native finish proof charges all 69 callbacks, including malformed and rejected paths. Uniform bounds for these callbacks hold for every sampled KEM secret. Their full base/primitive randomness is included; they are not zero-cost placeholders.

The complete `prepare` program has the following bounds:

- Shared hashes: `H = 69*qMain + 1 + 69*qPost`.
- Local uniform calls: `U = qKeygen + 32 + qPre + qOne + qPhase1Write + (qMain + qPost)*T + qEphemeral + 2*qEncaps + qPeer + qPlaintext + qResponseWrite`.

Here `qMain` and `qPost` bound the original adaptive source schedules, not just successful requests. `qPre` and `qOne` cover the complete original interpreted generators, and `qPhase1Write` covers the actual complete optional Phase1 writer. The identity seed costs 32 byte draws. The explicitly stated `qEncaps` cap applies separately to the actual total KEM encapsulator and the optional native encapsulator; it can be chosen as the maximum of their separate costs. There is at most one such call in candidate dispatch and one outer encapsulation, hence the coefficient two. Key generation has its own `qKeygen` cap. Every primitive remains the fixed correct implementation under its existing contract.

`PqxdhFirstSharedMessageResources.first` consumes that complete preparation theorem and the actual first-record source input projection, then adds the existing full64, nonce12, and next-chain32 draws. Its hash bound is still `H` and its local uniform bound is `U + 108`. This preserves the first-record hybrid's correlations and the shared initial64 output; it does not replace projections by unrelated samples. The selected message key's separate 32-byte challenger draw is not included in those 108 bytes.

`forwarded` proves that the complete first-record prefix uses at most `H` hash and `U + 108` uniform calls at the actual selected-key component interface, with zero selected seal and zero selected raw-opening calls before the cut. Source known-key seal/open work can still occur and remains real local computation; their commitments are in `H`. `evaluated` charges the ordinary shared-ROM interpreter at most `(U + 108) + 64*H` uniform calls, allowing a full 64-byte digest miss for every hash request while retaining the actual complete cache. Adding the separately sampled selected key costs another 32 calls.

It does not construct arbitrary supplied initial owner catalogues or identity histories, justify a compromised selected history, simulate the later native key-taking observer, or establish a global secrecy/authentication inequality. Dynamic source ownership/reveals, the selected-record continuation, event-specific symbolic correspondence, and all final reduction/selection losses remain consuming obligations. Fixed public HKDF evaluations remain real. Primitive implementations, snapshots, and persistence are outside this proof scope.
