# Dynamic generated-identity routing

This focused extension of HB-90 connects the on-demand generated-identity interface to the existing reveal-capable joint Ed25519/X25519 family reduction. It proves an indexed signature event with freshness through the final decision. The stronger joint-use weak-EUF contract is unchanged: its winning event remains an ordinary fresh-message signature forgery, while its auxiliary service returns actual optional converted-static-DH replies for chosen peer encodings. No secrecy conclusion is assumed for that raw-DH service, and no primitive algorithm or implementation is proved here.

`PublicState` contains only a created-index counter and the complete public query/reply transcript. `routeImpl` publishes the next reserved public identity on creation, forwards services and reveals only for already-created indices, and forwards explicit source uniform queries exactly. Requests for an uncreated index return outer `none`; a created identity's rejected DH request returns `some none`. Only the family interpreter owns reserved seeds. The terminal reconstruction of the created private prefix is an analysis projection, not an adversary interface. Future reserved public keys are available to the internal router but it publishes them only on the corresponding creation request.

`historyUpdate` records the actual returned signature, optional DH reply or revealed seed index. `historyImpl` forwards the source request before performing that pure update. In particular, attempting to reveal an index before creation does not mark its future identity compromised. `sourceWithHistory_run` retains the exact reply and source poststate before adding this public history instrumentation. The four projection theorems for creation, explicit coins, services and reveals equate complete source states and histories with the existing family interpreter. They include exhaustion and invalid-index rejection. The lookup and next-seed lemmas prove that an exposed index refers to the same element of the exact created prefix; they do not infer index equality from equal public bytes.

`routeImpl_preserves_count` proves that the counter never exceeds the reservation size under any possible oracle replies. `linked_preserves_count` carries that fact through the real family interpreter. `route_complete` lifts the per-query equalities to every adaptive continuation, preserving its full returned result, complete public transcript, every created private seed and all prior signing/DH/reveal histories. The initial history may be arbitrary; the equality does not discard earlier joint-use observations or retain only a marginal public-key distribution.

`historyRun_query_bound` preserves every declared source query class through instrumentation. `lazy_eager_history_complete` applies the earlier complete-distribution seed-reservation theorem to the entire instrumented continuation, keeping the actual global history jointly with all source state. `dynamic_reserved_complete` then connects the actual on-demand source, starting with no created identities, to a privately reserved family followed by the public router. The creation cap is quantified over the client's arbitrary possible replies. All unused reserved seeds are sampled and counted by the reduction even when the source stops early; they are never passed to the source client.

`DynamicForgery` permits any natural-number target choice. `DynamicEvent` requires a seed actually present at that generated index, a valid signature on a message absent from its signing history, and no successful reveal of that identity through the final decision. These are explicit event tests; the client is allowed to choose invalid or uncreated indices and to request every reveal. `dynamicEvent_implies_global` checks the exact source-prefix seed lookup and passes the unchanged candidate and complete history into the existing global signature event. `selectedForgery` uses a fixed ordinary fallback only for an index outside the reserved family. Extra fallback wins can only enlarge the upper bound. Choosing an uncreated but in-range index similarly cannot satisfy the source event, even if the family game could accept its candidate.

`reserved_event_le_global` connects the complete source execution to that ordinary family event with coefficient one. `dynamic_advantage_le_sum` then bounds the source event by the sum of the existing constructed `globalReduction` joint-use advantages over the `N` reserved generated indices. `dynamic_advantage_le_count` gives `N * epsilon` when each constructed reduction has advantage at most `epsilon`. There is no extra creation-time, session-position or invalid-index factor in this indexed interface. The zero-family event is false. This result does not identify a production identity by public bytes and does not eliminate a future collision or ownership term needed for native lookup.

The query ledger is explicit. `routeImpl_query_bound`, `routeRun_query_bound` and `routedAdversary_query_bound` preserve the source class caps, including attempted services on invalid indices. `dynamicReduction_query_bound` gives each selected reduction at most `qUniform + 32 * (N - 1)` uniform-oracle queries, `qSign` signing queries and `qDh` optional static-DH queries. Rejected DH replies occupy the DH cap. `dynamicReductionGame_uniform_bound` includes the challenger's own 32-byte seed and gives `32 * N + qUniform` for the full interpreted challenger. Each seed uses 32 byte-valued uniform queries; `qUniform` counts arbitrary finite source uniform requests in the library's units. `dynamicClass_uniform` proves that this is the same source uniform predicate used by the pool interface. `dynamicRun_uniform_bound` charges the actual on-demand source `32 * qCreate + qUniform`, where the actual source creation cap may be smaller than the reserved bound used for selection.

`dynamicRun_trace_bound` charges every request in any declared source class. In particular, separate create, sign, DH and reveal predicates give `qCreate`, `qSign`, `qDh` and `qReveal` attempt caps, including repetitions and invalid-index requests. A successful source reveal copies one 32-byte seed; a source creation computes one joint public map. Non-target local signing and DH evaluations in a selected reduction are still deterministic primitive work, bounded by the corresponding source service caps. Public routing and event verification perform index checks, history processing, list lookups and transcript appends; those operations depend on the source request count and current prefix/history lengths. These costs remain explicit local computation and are not made free by their absence from an oracle-query count. The file does not prove a machine-runtime complexity theorem.

This checkpoint does not instantiate native seed-to-secret generation, native optional DH errors, public-byte identity lookup, caller-supplied identities, attacker-owned registrations, dynamic session ownership, or native protocol acceptance-report points. Its new signature event uses final-decision freshness; the separately proved report-time family extension still needs its dynamic protocol wrapper before later compromise can be admitted after an earlier source acceptance event. Root, KEM, chain and skipped-key reveal policies and the common multi-session root/record experiment remain open. The new module introduces no custom axiom, primitive endpoint or protocol security conclusion as a premise, and it does not close the full computational-symbolic goal.
