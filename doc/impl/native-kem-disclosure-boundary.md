# Native KEM disclosure boundary

`PqxdhDynamicKemNativeRead` connects a modeled compromise request to the actual KEM field retained by a native Beacon. The request supplies only the installed native-owner index. The interpreter selects that owner, checks its current phase through `PqxdhLivePhase1State.privateKeys`, and uses its retained KEM creation index to read the existing private service. A missing owner or erased native field returns `none` before making a private-pool request. This is a compromise capability of the security experiment, not a new public production API.

`retained_known` consumes the native ownership relation established by actual indexed construction. Every still-retained handle resolves to its original private pool slot. No public-key byte uniqueness is required, and the native owner index remains distinct from the private identity and KEM creation indices. `allocated` proves that the exact owner installed by the original constructor requests its actual KEM creation index. `allocated_source` then returns the exact generated secret while retaining the actual prior creation records and complete joint identity state. The constructor's source-order and supported-output statements remain those already proved by `PqxdhLiveIndexedCreation`.

`source` gives the complete original-source interpreter equation for any native read, including optional rejection and full private poststate. `owned_source` derives the successful secret reply from actual retained ownership instead of assuming that reply or substituting a secret. `present` and `absent` identify the precise service request or the absence of any service request. These statements leave the native owner objects unchanged; the only source state update is the ordinary private read history, including a recorded lookup rejection. An outer public scheduler still records its own attempted API request and optional reply, including rejection; an absent native field is not an attempted lookup in the historical private pool.

`finished` uses the actual Phase2 `finish` operation. Both successful registration publication and terminal rejection leave no retained native KEM field, so a later read makes no pool request. `disposed` proves the same property for explicit native KEM deletion and preserves the entire earlier private history. This models logical access to currently retained fields. It neither resurrects disposed keys from the interpreter's historical table nor removes disclosures that occurred earlier.

`selected_source` connects that same native getter to the ordinary monitored joint source: it returns the real selected secret, appends the successful reveal and sets the disclosure monitor. The source continues normally afterward. `selected_pre` and `selected_post` prove that the executable CCA reduction instead stops precisely on that selected existing-field read, before returning an unavailable secret. Its complete unrelated joint/private state is retained. Missing or future handles remain governed by the already proved ordinary-rejection behavior. The postchallenge candidate and ciphertext do not change this reveal boundary.

`selected_disclosed` connects actual native compromise to the existing successful-reveal history predicate. A successful selected read makes that predicate true, regardless of the adversary's final decision. This supplies concrete evidence for a KEM-disclosure freshness policy in the common experiment. It does not claim that `RawCtxLiveLineage.Fresh` already expresses that policy: that existing predicate accounts for current chains, skipped message keys and explicitly supplied prior root/ancestor bytes. Identity and KEM disclosure records, their permitted timing, and the precise policy for each symbolic event still need their explicit common-experiment definitions. A policy can exclude actual successful selected KEM disclosure without assuming authentication or secrecy as a premise.

`read_queries` and `indexed_queries` count at most one private reveal request per native compromise attempt, with zero identity creations, explicit source coins and decapsulation attempts. Combined with the full joint CCA ledger, this adds no primitive or selected logical-decapsulation call. A missing owner or erased field makes zero private requests. These are oracle-query bounds, not a claim that native list lookup and field inspection take no computation.

The sixteen guarded statements establish this exact native exposure boundary and its connection to the ordinary source and both CCA phases. They add no cryptographic advantage, statistical term or selection factor. They do not finish the adaptive common scheduler, the event-specific compromise policy, or the actual target-root continuation's public nonexposure argument. Arbitrary supplied histories and equal secret bytes at other indices remain allowed. Primitive implementation correctness remains a contract; snapshot, persistence and restoration behavior are outside scope.
