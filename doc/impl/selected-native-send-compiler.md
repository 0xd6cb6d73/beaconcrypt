# Selected native send compiler

`RawCtxSelectedSendCompiler` compiles one complete actual source send into the ordinary selected CTX interface without giving the selected message key to the executable compiler. The source `normalBegin` and retained-table derivation decide whether the pending material is known or selected. Known material follows the original local encryption and writer, with its commitment lookup forwarded to the common public ROM. Selected material uses the selected sealing oracle. Public HKDF is unchanged.

`send_source` preserves exhaustion, the actual advanced kernel, inner optional writer failure, and the complete original ambient state and shared cache. `native_send` composes this equation with the extracted native send interpretation. These are evaluated distribution equalities, including the continuation's state; they are not marginal key-distribution claims. The mathematical interpreter alone receives the selected key. The private derivation and executable send receive only the retained table, predecessor descriptor, target chain, selected nonce and next chain.

The selected ordinary sealing oracle rejects nonce reuse, while the production local seal does not. The compiler therefore retains two option layers: the outer `none` is an explicit stopping event; an inner `none` is the unchanged native writer failure. `Stops` is computed from the actual source pending seal and the ordinary challenger's used-nonce ledger. `send_source` and `native_send` state the exact distribution on both sides of this test and have no nonce-freshness premise. On a stop the complete prior source state is retained. `sealing_cases` proves the test holds precisely for a selected material slot with the required 153-byte associated data and an already-used nonce. This event must still be charged in the global source experiment using actual owner, derivation and publication history. No zero-probability or per-session uniqueness assumption is introduced here.

The complete send makes at most one dynamic component query. A known seal pays one public shared-ROM lookup; a selected seal pays one selected sealing attempt, even when refused. The already proved component classification additionally gives zero raw verification calls and zero explicit uniform requests for sealing. The original private derivation has its separate one-retained-lookup allowance. Hash sampling and cryptographic work inside the component interpreter remain subject to the existing component query accounting. These counts do not declare local or ambient work free.

The module does not yet establish the whole adaptive mixed-family suffix, the exact global `Gate`/`Fresh` decision, or the probability of the source nonce-stop event. Those require the actual source role dispatcher and saved continuation descriptors. It changes no Rust source, wire format, primitive contract, freshness rule or registration admission rule.
