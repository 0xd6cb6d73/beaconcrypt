# Indexed KEM decapsulation routing

`PqxdhLiveKemRouting` uses the actual private KEM creation index to route a retained source handle. `redact` removes the selected slot's secret and keeps all other actual slots; it does not compare public-key or secret-key bytes. `selected_redacted` and `other_redacted` prove those exact lookups. Missing handles reject. All other created handles invoke their actual local decapsulation, with optional failure retained.

`pre_source`, `pre_source_state` and `pre_step` compare this executable prechallenge service to the original indexed private interpreter. The selected secret is a parameter only of ordinary CCA interpretation and private source-state reconstruction. `pre_interpreted` and `pre_complete` extend the equality through every adaptive decapsulation schedule with fixed existing key slots. They retain complete private pool reconstruction, all prior history and each new attempted query and optional reply, including rejection. No generator-order interchange, accepted-key honesty or marginal-only equality is used.

The prior history is an explicit input to this operational equation. It is not automatically a constructible reduction state: an arbitrary prior history could contain a prohibited selected-secret reveal. The dynamic source compiler must construct the admissible history using its actual creation/reveal schedule and freshness stop. That obligation is neither assumed away nor discharged by redacting the private key table. New creation interleaved with decapsulation is also outside this fixed-slot service theorem.

`post_origin` derives the exact source of every selected-origin tag: the actually present selected slot and its exact challenge ciphertext. The ordinary router never sends that ciphertext to the challenger. Other owners return known-tagged actual values; `known_not_challenge` is disjointness of provenance tags, not injectivity or inequality of shared-secret bytes. A separate postchallenge source-state interpretation, dynamic ownership consumer and target-selection reduction must still connect these tags to the full global protocol.

`ambient_no_decaps` charges zero selected-oracle requests to local primitive evaluation; it does not make that computation free. `pre_decaps` charges at most one selected request per actual source attempt, while `pre_ambient_bound` retains every original uniform or base request made by local other-key decapsulation. `pre_schedule_decaps` bounds an arbitrary q-attempt schedule by q selected requests, and `pre_schedule_ambient` bounds each local class by q*qLocal. The selected challenger's internal primitive work remains a separate runtime cost. `post_bound` states the corresponding per-attempt local-plus-selected bill, with the exact challenge branch contributing zero challenger requests and still counted as a source attempt. Public uniform and base classes remain separate; actual algorithm bounds must be supplied for them.

These fifteen statements add no primitive-security assumption, implementation proof, cross-key injectivity claim, snapshot or persistence behavior. They do not assert an IND-CCA advantage or complete the dynamic source compiler. All guarded dependencies are ordinary Lean axioms only.
