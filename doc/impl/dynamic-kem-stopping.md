# Exact selected-KEM disclosure stopping

`PqxdhDynamicKemStopping` closes the source-service stopping argument used by the dynamic CCA router. Its ordinary source actually answers every existing requested KEM secret, including the selected secret, and retains that exact successful reply in its history. Its private monitor marks a selected disclosure only after the actual indexed lookup succeeds. Missing or not-yet-created handles return ordinary rejection and do not mark disclosure.

The executable reduction stops before answering a successful selected-key reveal. This is justified through the event being measured, rather than by assuming the adversary stops or rejects after compromise. `normal_good` and `schedule_good` prove that an actual disclosure cannot be undone by any subsequent adaptive source program. `bad_output_zero` therefore gives zero probability to every complete output retaining the disclosure freshness condition after compromise. `output_good` compares the ordinary and stopped services pointwise on their entire final result, private history, activated-key count and stop flags. Its proof retains both possible optional replies and every continued adaptive branch. The stopped branch does not fabricate a secret, record an ordinary rejection, or insert secretly recovered bytes into an adversary-supplied target.

The freshness monitor is itself checked against actual observations. `normal_tracked` and `schedule_tracked` show that its value equals whether the complete original history contains a successful reveal at the selected creation index. `empty_tracked` initializes this equality from the real empty source. `history_event` thus preserves every event gated by absence of a successful selected disclosure in the actual ordinary history; `empty_history_event` discharges its initial tracking premise directly. Events may inspect the complete original result and retained state. There is no premise requiring the adversary's unqualified final decision to become false after compromise.

`pre_event` combines this exact original-history event with the executable prechallenge CCA router. `post_event` carries the complete earlier tracked state into the postchallenge suffix and consumes ordinary recipient correctness and the existing functional decapsulation interface on actual key-generation and encapsulation support. It uses the existing blocked postchallenge CCA interpreter. These are event equalities; they do not independently assert that a generic source client hides the supplied challenge candidate. The actual native protocol/adversary boundary must supply that fact, as recorded in [the router guide](dynamic-kem-router.md).

`normal_step_capacity` and `normal_capacity` prove that the original creation allowance prevents reservation exhaustion in the ordinary source as well as in the stopped source, including executions that continue after compromise. Source reveals do not generate primitive-oracle requests. The executable pre/post source retains the previously proved selected-decapsulation cap `qD` per phase and the complete local uniform/base bills. Actual key generation, outside source callbacks and the full native scheduler keep their separately stated charges. This stopping transformation adds no cryptographic advantage or statistical error.

The package contains seventeen guarded statements. The remaining protocol consumer must connect the actual native/joint source scheduler, owner-handle provenance, live erased-field read restriction and final protocol freshness event to this selected KEM disclosure history. In particular, this module does not infer whole-protocol freshness merely from the name of a monitor. It adds no public-key injectivity, no independent-secret-alias premise, no primitive implementation proof and no snapshot or persistence behavior.
