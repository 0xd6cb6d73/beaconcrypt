# HB-99: live native Beacon Phase2 adapter

The native Beacon Phase2 adapter models one live `finish_registration` call from its actual `InitSent` state. It retains opaque private identity, DH-pair and KEM handles, the original packed input and decoded response, every optional callback outcome, and one complete shared primitive state. A successful call publishes the actual returned ratchet kernel and assigned outer key ID. Any failure during an active call resets the outer ID to the pinned Server ID and terminally aborts registration. Calls in other phases reject without changing owner or primitive state.

`PqxdhBeaconPhase2Preparation` follows the native order: packed decoding; ciphertext, ephemeral and Server-identity conversion; public and private identity conversion; decapsulation; DH1 through DH4 with the original argument pairs; then the assigned-ID getter. Only after these twelve callbacks does the extracted `beacon_prepare_finish` run. The shared-secret erasure callback runs on both extracted preparation outcomes. The typed 32-byte outputs make the source fixed-length shared-secret conversion total in this representation; correspondence of these typed callbacks with native libraries remains an explicit implementation contract. Packed decoding does not assert full-input consumption.

`normalPrepare_exact` identifies the normalized core result with the actual extracted result. `abort_fields` and `owner_inactive` describe exact rejection fields. `afterInputs_complete`, `owner_complete` and `continueWith_complete` preserve arbitrary complete continuations and the same primitive poststate. `afterInputs_origin`, `prepare_origin` and `owner_success` derive the actual private candidate and original input provenance from a supported execution. `owner_failure` retains the real failed preparation effects before abort. `collect_bound`, `afterInputs_bound`, `prepare_bound`, `owner_bound` and `continueWith_bound` give the twelve-plus-one callback accounting; `owner_interpreted_bound` charges each callback's explicitly supplied selected work.

`PqxdhBeaconPhase2Publication` keeps the prepared response private until root derivation completes. The root callback represents optional Extract/Expand and unconditional clearing of the candidate's 192-byte root input. The same typed 64-byte ratchet initializer runs before the application-ciphertext getter. The actual raw receive wrapper then keeps source decoding, pinned sender, stored AD, cache behavior and every optional opening effect. A returned sequence other than one is rejected before plaintext length or binding inspection. A longer-than-eight-byte plaintext supplies the actual first-eight-byte binding to extracted authentication. Both final native Server pins are checked before publication. The plaintext suffix, assigned ID, extracted established control and actual returned kernel are published together; an advanced local candidate from any failure is discarded while the real primitive effects remain.

`normalInitial_exact`, `normalAuthenticate_exact` and `initial_request` identify the actual extracted callbacks and the fixed initial KDF request. `clearedCandidate_fields` preserves all candidate binding and AD fields while clearing its root input. `afterOpening_wrong_sequence` states the sequence-one policy at its actual location; `afterOpening_success` derives sequence one, length and extracted binding acceptance without a successful-decryption or correct-plaintext premise. `publish_fields`, `finish_failure`, `finish_success` and `owner_inactive` identify the exact outer publication or rejection. `afterRoot_complete`, `tail_complete` and `owner_complete` preserve full state and continuations through the original callback order. `afterRoot_supported`, `tail_supported`, `tail_sequence_one`, `owner_success` and `owner_failure` recover the same executed source path and final state from supported outcomes. Finally, `native_complete`, `native_success` and `native_failure` expand the original selected opening into its actual commitment hash and optional AEAD calls, retaining commitment mismatch and primitive failure effects. The raw wrapper's local attempt counter is a private analysis field; Phase2 preserves the separate outer native attempt field.

The adapter makes no new authentication, key independence or freshness assumption. Codec and primitive-library realization, source root derivation, physical erasure and target-challenge routing remain explicit interfaces. The next computational connection must retain decapsulation before the DH calls and represent an unavailable challenge shared secret through a private handle until root processing; it cannot defer decapsulation effects or expose a secret as an adversarial reply. This stage concerns live protocol state. Storage snapshots, persistence, restoration and their consequences are outside the requested proof scope.

`PqxdhBeaconPhase2Bounds` counts the actual executed callback program under all replies. `total_of_partition` and `query_union` combine shared structural allowances, including overlapping query classes; `simulate_total` preserves the count under exact one-query routing. `receive_total` and `raw_total` combine the existing 51-KDF and one-opening bounds into 52 logical callbacks. `native_raw_total` retains the same 51 KDF calls plus at most one commitment hash and one AEAD call, giving 53. Parsing and guards add local computation without additional callbacks.

`afterRoot_bound`, `tail_bound` and `owner_bound` give 54, 55 and 68 logical callbacks: initialization and app access precede raw receiving; root derivation adds one; preparation adds thirteen. `native_raw_lift` and `native_tail_lift` identify the exact composed native dispatch programs. `native_afterRoot_bound`, `native_tail_bound` and `native_owner_bound` give the corresponding 55, 56 and 69 native callback caps. These are conservative all-reply limits. In particular, a later sequence admitted by the generic receive window still performs its real KDF and opening work before the post-opening sequence-one policy rejects it.

`interpreted_total_bound` transfers a callback count into the same complete stateful interpreter using an explicit allowance for a chosen underlying query predicate. `native_interpreted_bound` yields `69 * qCall`; `native_continuation_bound` adds `qNext` for a private continuation receiving the actual optional plaintext, entire updated owner and primitive poststate. The product is a per-callback upper bound, not a claim that codec, hashing, key conversion or local byte work is free. These resource statements use exact program equations and structural query bounds, never evaluated-distribution equality. They introduce no new cryptographic advantage premise.

## Verification and remaining connection

The three modules contain 54 guarded statements: 16 for preparation, 21 for publication and 17 for callback accounting. Each directly checks against the maintained proof environment. Independent reviewers inspected the actual source order, theorem statements, complete primitive state, optional results, sequence-one policy and resource accounting. The complete guarded Lean gate passes all 3,360 jobs, and the reviewed inventory gate passes all 474 entries. Publication rechecks the exact integrated tree before comparing local, fetched and direct private-remote hashes. No Rust or ProVerif source change is included, so mutation testing is omitted under the user’s proof-only policy.

This operational boundary is the next interface used by the computational continuation; it does not extend HB-98’s one-private-root cap by itself. Connecting the original decapsulation point to the private challenge-secret family, compiling finish calls into the common live scheduler and charging every such attempt remain subsequent obligations. The independent evolving-key and symbolic lanes remain active.
