# Accepted-record receipts for publication analysis

`PqxdhServerAuthPublicationAcceptance` proves the accepted-record alternative needed by the stronger publication analysis. The existing B decision only tests W1/W2, so it cannot be used as a premise when an accepted cryptographic seal was never returned by the outer response writer. This module instead starts from the actual accepted snapshot, its actual owner coordinate, and the source's unchanged absence-of-refusal flag.

`accepted_input` consumes the complete factor-side source execution and the existing first-acceptance, touch and designation invariants. It identifies the hidden input with the actual Beacon input for arbitrary supplied factor output, without requiring W1/W2, an original-key invariant, or a caller-supplied designation witness. This is source control and input attribution, not a key-independence statement.

The local finish proof keeps the actual component raw request, actual optional plaintext, exact attempt-time seal history and matching earlier component record. `program_receipt` yields that complete witness or the existing ordinary authentication observer's win. `local_receipt` attaches its actual source session, input and seal context. The approved `ReadWritable` contract is used only for the concrete accepted matching frame to exclude that frame's inner-writer failure. The receipt retains the same partner-indexed snapshot seal and original accepted fields. It does not assert outer response serialization or publication, canonical wire bytes, or uniqueness of source sessions from equal key bytes.

`matching_hit` derives the publication capture's tag predicate from the exact complete CTX tuple. `receipt_hit` retains the real attempt and its earlier sealing occurrence; it does not select a record by decoding a writer result. `receipt_grows` retains that same frozen attempt-time history through later observer operations. These are occurrence witnesses in the actual run. Transport to the before-raw captured probability and association with the matching public build outcome remain separate consumers.

The remaining handler proofs execute the original finish preparation, selected or ordinary table derivation, optional getter/opening, registration gates and full source settlement. Rejection creates no acceptance. A reached ordinary root is retained as an explicit occupied-input alternative. Every other API operation preserves the first accepted snapshot and extends the actual attempt ledger. The original designation latch and second-session stop retain all work before refusal. `program_cover` proves the full adaptive statement; `initial_cover` and the maintained source/observer invariant discharge its induction hypotheses from the literal empty experiment.

`execution_receipt` is the concrete endpoint. Every normal accepted execution at its actual owner coordinate with no sticky refusal yields either the ordinary all-attempt CTX authentication event or the exact receipt described above. Actual designation and cache omission exclude the ordinary-root alternative. No caller seal-origin, tuple-freshness, first-acceptance, nonce, or winning-event premise remains. The existing abstract readable-frame contract stays explicit. No program or query count changes, no additional selection factor is introduced, and deterministic local work is not declared free.

The full publication bound still requires the exact successful or failed public build occurrence associated with this selected record, the killed-publication/reference coupling, capture-event inclusion, and the accepted-observation source/key-schedule transport. In particular, an owner-independent matching-field publication must not replace a cryptographic partner's actual publication. The existing B theorem and all maintained ProVerif queries remain unchanged.
