# Actual CTX services for labeled record callbacks

`PqxdhRecordLiftCtxServices` supplies the ordinary CTX service behind the source-shaped labeled opening and sealing requests. Its 38 checked statements establish deterministic routing, complete callback distribution equality and local oracle budgets. They do not establish the global security bound, target-key distribution, absence of nonce refusal or source reachability of an arbitrary supplied pending object.

The private `materialRoute` selects the unavailable message key by the original structural coordinate. It retains the selected output’s nonce and uses the actual cached material at every other coordinate. It never recovers a coordinate by comparing bytes. `materialRoute_real`, `chainRoute_real`, `openingRoute_getters` and `openingRoute_native` prove the exact material/chain interpretation and actual cached or future opening getter behavior. The selected key is absent from the service programs. Known key bytes may coincide with one another or with the selected key; these operational equations introduce no independence or injectivity premise. The global masked experiment must separately account for exposure and alias events.

`openingService_source` connects the labeled opening directly to `NativeAdapters.receiveOpen` under the actual source native interpreter. A malformed protected payload is rejected locally, just as `RawCtxSourceOpen.openInput` rejects it without a hash or AEAD call. Otherwise the service passes the original raw input and retained source context to the existing universal decoder and dynamic known-key component. Missing or mistagged cached material still returns the source `None`. The ordinary challenger’s actual optional plaintext is wrapped in the original API metadata; it is never inserted into an adversary-supplied target. The equation preserves the entire shared cache and existing pending frame list. Its nonempty-input, decoded-frame, frame-validation and prepared-sequence premises are source admission facts to be discharged by the global protocol compiler, not cryptographic assumptions. The payload need not parse successfully. Cached/future publication, rollback and replay control remain the literal OpaqueDrivers program.

`sealRom_typed`, `nativeSeal_step`, `nativeSeal_program`, `nativeSeal_typed` and `sendSeal_inner` connect the actual inner native seal and original API adapter to the typed CTX record. The AEAD output, commitment input, source sequence, sender, ciphertext and optional writer result are the original ones. The complete frame is appended to the pending writer log before returning the writer’s option, including a failed writer. Invalid associated-data width returns ordinary source failure without writing. `evaluateRom_bind` retains an arbitrary complete continuation and full cache/log state. `publicRom_complete` preserves all dynamic component histories for known-key local sealing; `publicRom_cache` drops only challenger bookkeeping while preserving the actual shared ROM cache and reply.

`sealCall_selected_fresh` and `sealingService_source` identify the selected ordinary seal with the original source callback before nonce reuse. This is an explicit branch condition, not an assumed protocol invariant. `sealCall_selected_repeat` and `sealingService_repeat` prove that a repeated selected nonce produces an outer `Except.error ()`, leaves the complete component state and pending log unchanged, and never becomes a fabricated native writer failure. A normal failed writer is `Except.ok none` and retains its attempted frame. Known-key sealing remains the native unchecked operation with forwarded public hashing; it does not inherit the selected-key oracle’s nonce gate. The global lift must derive the source nonce condition or charge the stop event. Equal nonce bytes under unrelated keys are not treated as reuse of the selected key.

`native_counts_erasure`, `logged_counts_erasure` and `native_unit_erasure` remove only the separate analysis counters or Unit wrapper from complete adaptive native executions. Actual shared-cache effects and attempted writer frames remain. `receive_log_program`, `receiveOpen_logged` and `receiveOpen_native` connect the source opening embeddings with the same untouched writer log. The simulator does not reconstruct secret-dependent native opening or ROM-miss counters from an optional plaintext reply and does not strengthen the primitive endpoint to return those counters. The global observation must exclude these private counters, while established source-budget theorems account for their upper bounds.

The explicit local bills are `openingService_total`, `openingService_routes`, `openingService_other`, `sealCall_total`, `sealCall_bills`, `sealCall_other`, `sealingService_total`, `sealingService_bills` and `sealingService_other`. One source opening issues at most one dynamic verification query, at most one selected raw verification and at most one forwarded known-key hash, with zero selected seals and zero explicit uniform queries. One source seal issues at most one component query: a selected seal has sealing cap one and public-hash cap zero; a known seal has public-hash cap one and selected-seal cap zero. Both sealing routes have raw-verification and explicit-uniform cap zero. A selected nonce refusal still consumes its attempted sealing query. Internal challenger ROM sampling and AEAD work retain the existing component ledgers; zero explicit uniform queries does not make that work free. Global session/record selection, repeated adaptive acceptances, total source budgets and advantage losses remain downstream obligations.
