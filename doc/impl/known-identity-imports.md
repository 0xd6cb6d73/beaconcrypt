# Known identity imports and generated-owner signature reports

This focused HB-90 extension adds attacker-known seed imports to the already checked dynamic identity/report interface. An arbitrary client can interleave honest creation, import any typed 32-byte seed selected from earlier observations, request signatures or optional static-DH replies, reveal identities and submit signature reports. It may continue after a report and compromise an identity later. The probability of a fresh valid report about a generated owner is bounded by the same sum of `N` constructed joint-use weak-EUF advantages for at most `N` honest creations. Neither imported handles nor report attempts add a probability selection factor. All their source work remains separately counted.

`Owner` records either the generated index and public identity returned by the actual honest source, or the exact seed supplied in an import request. `PublicState` contains that owner list and the complete outer query/reply transcript. The wrapper receives no private generated seed. The only seeds in this public wrapper are already client-supplied inputs. Honest creation publishes the next outer handle and stores the actual source-generated index behind it; known imports publish another outer handle and the same primitive joint public map of their supplied seed. These handles are internal generated-order bookkeeping, not native BeaconCrypt assigned IDs. No public-byte equality or distinct-key premise is used, and a supplied seed or its public values may collide with another entry.

`wrapper` forwards generated services and reveals to exactly the stored source index. Requests at an absent outer handle return `none`. At an imported handle, signing and optional DH are computed locally with `primitiveReply` on the exact imported seed. Thus the Ed25519 and converted-X25519 uses remain correlated, and DH rejection remains an actual optional response. Revealing an imported handle returns its already supplied seed. Every outer request and actual reply stays in the transcript, including locally processed imports, invalid indices, rejected DH, repeated reveals and reports that cannot win.

A report at a generated handle forwards its unchanged message and signature with only the explicit handle-to-generated-index translation. The existing report source checks the actual generated public key, signing history and successful prior reveals. An imported or absent handle cannot establish a fresh generated-owner signature event, so its report returns `Unit` locally and remains in the outer transcript. Imported owners are explicitly adversary-known at birth; this is the event's ownership scope, not a claim that their supplied bytes lack entropy. The inherited source still permits arbitrary subsequent creation, service calls and compromise, retaining earlier successful report events.

`sourceImpl` defines this composed joint-identity source by linking the public owner wrapper to the existing actual dynamic reporting interpreter. It retains the complete owner state alongside every generated private seed, original generated-source observation, per-identity history and report-time event. `run_complete` proves exact equality of the complete continued source run with the reporting experiment driven by `routedClient`, with only product reassociation. This is a checked oracle-link composition of the declared interfaces; it does not claim that a separately extracted native owner/lookup implementation already equals this wrapper. `run_event` transports the existing generated-owner report-time event through that full-state equality.

`source_pure_step` proves that any local wrapper step preserves the entire generated interpreter state. `import_source` specializes it to exact supplied-seed import and joint public-map publication. `imported_service_source` preserves all generated secrets and histories while returning the exact imported-seed signature or optional DH result. `imported_reveal_source` returns the supplied seed unchanged. `imported_report_source` retains the outer report while leaving the generated source's freshness histories and sticky event unchanged. These are full-state functional statements, not only reply or public-key marginal equalities.

`report_advantage_le_sum` applies the prior report-time reduction to the explicit composed `routedClient`. Each ordinary endpoint adversary is `globalReduction` of the previous dynamic `routedAdversary` and `reportExtractor` applied to this wrapper. No generated private seed is passed into that constructed adversary, and known seeds are never resampled or replaced. The sole source precondition for the family selection is the honest-creation cap over every possible client continuation. The previous unchanged-candidate extraction supplies the signature freshness event without requiring an honest-selected-target premise; imported and invalid selections simply do not satisfy this event. `report_advantage_le_count` gives `N * epsilon` when each constructed endpoint advantage is at most `epsilon`.

`Cost` distinguishes explicit uniform requests, honest creations, known imports, signing, optional DH, reveals and reports. `wrapper_query_step` proves that every request forwards at most one underlying request of the same class; known-input local work makes no hidden generated-key oracle request. `routedClient_query_bound` lifts that fact through arbitrary adaptive scheduling. `forwarded_create` and `forwarded_primitive` identify those predicates exactly with the earlier reporting source's creation and primitive classes. Every selected reduction has uniform cap `qUniform + 32*(N-1)`, signing cap `qSign` and optional-DH cap `qDh`. Rejected DH replies count. `reductionGame_uniform_bound` includes the target challenger's own seed, giving `32*N + qUniform`, including unused reservations. `run_uniform_bound` separately gives the actual source `32*qCreate + qUniform`; imported seeds use their actual supplied bytes and trigger no generator call. Seed generation uses 32 byte-valued uniform calls, while each explicit source uniform request may have an arbitrary finite range and counts once in these library units.

`wrapper_transcript` proves that every operation appends exactly its outer request and actual reply. `wrapper_trace_count` and `wrapperRun_trace_bound` charge each class in that complete history. `run_public_support` transfers actual interpreted source results into the same public wrapper support, without discarding the jointly retained generated source. `run_trace_bound` therefore charges all actual `qImport`, `qSign`, `qDh`, `qReveal` and `qReport` attempts, including those that cause zero underlying oracle calls. Known-owner signing and DH evaluations remain local deterministic primitive work bounded by their source classes. Each import computes one joint public map; each successful imported reveal copies the supplied 32-byte seed. Generated-owner report validation and all owner/history lookups, message processing, list appends and retained transcript work also remain actual computation. The absence of an oracle call does not make this work free. No machine-runtime or unbounded-input byte-complexity theorem is claimed.

The primitive contract remains the earlier explicit joint-use weak-EUF game. Its winning event is ordinary fresh-message signature forgery with an additional chosen-input optional converted-static-DH service, so its assumption is stronger than plain EUF-CMA. This component adds no primitive assumption and no raw-DH secrecy premise, and proves no primitive implementation. Native functional seed/public/conversion/error contracts remain unchanged. In particular, `Server::try_new` separately documents that a secret honest supplied seed must be uniformly generated 32-byte material. This module's known-import interface does not classify such secret honest supplied input as adversary-known or prove its distribution; an honest input-provider contract is still required.

Native byte-based identity lookup, imported registration ownership, rejection of malformed raw seed lengths, protocol acceptance-report points and exact session ownership remain separate source-boundary obligations. Public-key collisions have not been converted into identity-index equality, and native assigned-ID agreement is not claimed. Root/KEM/current-chain/skipped-key reveals, evolving record-key correlations, persistence and rollback rules, and the common global computational/symbolic experiment remain to be connected. This milestone adds a checked adversarial capability to the signature interface and retains its exact scope; it does not establish the full BeaconCrypt theorem.
