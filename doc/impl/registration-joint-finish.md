# Complete native finish through indexed private services

`PqxdhRegistrationJointFinish` extends the preparation representation to the whole Beacon registration owner and the original scheduler's finish operation. The client owner retains public identity and KEM material, private service indices, the actual local DH scalars and every original control, pin and ratchet field. Its interpreter state contains both complete private service pools and the complete existing native state. The original root, initial KDF, deferred application getter and raw receive tail operate on that same native state. The private service indices are independent of the public owner address.

This is equality inside the existing operational experiment. It inherits the approved programmable Extract random oracle restricted to 192-byte root inputs and the shared programmable classical CTX/BLAKE2b random oracle. It does not replace those idealizations with a new concrete-HKDF security claim. Public HMAC evaluation and the remaining source KDF/AEAD functional interfaces remain as modeled by the existing native interpreter. The abstract decoder and field/writer contracts remain the serialization boundary; this module proves no Cap'n Proto property, primitive implementation property, storage guarantee or restoration behavior.

The central `owner_source` statement compares the entire evaluated indexed client with an annotation of the original source owner, including all private histories, both shared primitive caches and the returned owner. It requires the exact private identity-slot lookup and, only when the owner is in InitSent, the exact active KEM-pair lookup. These are representation conditions. They do not assume a valid response, honest network origin, accepted root, successful opening, matching session or authenticated record. The complete scheduler still needs to establish them from actual creation and preserve them through its other operations.

Every inactive phase retains the original pure rejection. Active preparation can fail at any of its optional callbacks or extracted admission checks. A successful preparation feeds its exact output into the original tail. Root rejection, initial derivation, missing application bytes, raw parsing, commitment and AEAD rejection, the sequence-one check, binding authentication and final pin checks all retain their original control flow and effects. Terminal abort discards the original active owner material; publication installs the exact original established kernel and outer ID. The proof changes only the private representation of the returned owner. It does not strengthen later assigned-ID agreement.

The scheduler statement assumes only the actual present-slot lookup. The existing `RegistrationSchedule.finish_missing` result already handles absent slots by pure rejection before any callback. Neither lookup equates public and private indices. Annotation erasure is valid even without the local ownership conditions, because annotation records actual source replies and never controls admission; the indexed-client comparison is the statement that additionally requires exact private ownership.

The whole-owner uniform bound is intentionally conservative: every one of the existing 69 possible native callbacks receives the larger of the 64-byte shared-table allowance and the complete interpreted KEM decapsulation allowance. This retains every reached KEM base-oracle call and every root/hash sample, including work before failure. The separate preparation result gives the tighter logical bound of one decapsulation and one joint identity-DH request for that stage. The uniform ledger does not claim 69 decapsulations occur, count local CPU work as zero, or bound an unspecified external callback by fiat. Real deterministic derivation, conversion, indexing and decoding remain in the program.

The private annotation pools retain historical slots for proof interpretation; the live native owner still drops its active KEM/prekey/one-time fields on completion or abort. This is not a physical-erasure claim or a new reveal API. Correct routing of permitted reveals, preservation of ownership through the complete scheduler, the single global service compiler, adaptive target selection, total protocol query bounds and the common symbolic event transfer remain consuming obligations. These 15 statements introduce no new primitive security assumption or advantage term and do not discharge the earlier `noCreate`/`noSign` restrictions by themselves.
