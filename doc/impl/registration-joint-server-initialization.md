# Actual Server initialization and ordered joint-service prefix

This cohort connects actual generated or supplied Server initialization to the ordered raw Server root-preparation prefix through the existing indexed joint identity service. The executable client contains the initialized owner's public identity, original role state, consumed-registration state and origin, but no generated identity seed. Its complete interpreted distribution agrees with the actual native constructor followed by the actual native prefix. Actual initialization supplies the exact private-slot ownership needed for that equality; there is no honest-Server or successful-acceptance premise.

This remains an operational composition result for the one Server and many Beacons schedule. It does not yet compile the complete Server accept/root/pending-token/build continuation into the common service scheduler, replace a cryptographic component, establish freshness or prove a protocol advantage bound. The existing native Server macros remain the scheduler's current consumers until that continuation is joined.

## Exact initialization and retained origin

`PqxdhRegistrationJointServerBirth.client` first invokes the actual initialization callback. A false result rejects. A supplied byte string then undergoes the existing exact seed-length conversion: invalid input rejects; valid caller-known material is installed at the next identity index by a separate deterministic import request. An absent supplied string instead makes the existing joint identity service's ordinary create request, whose interpreter performs the existing 32-byte uniform seed sampler. Generator order is unchanged. A generated seed never needs to be recovered by the client from a public key or service handle.

The mathematical source constructor is the existing `PqxdhLiveServerConstruction.construct`. Its exact returned seed is installed in analysis state at the next slot; this installation records the ordinary create observation only for generated construction. Imported construction appends the known seed without claiming that a uniform create event occurred. This is an equality of operational representations, not a primitive assumption or a new secret oracle.

The seven statements in `PqxdhRegistrationJointServerBirth` have the following scope:

- `client_source` compares the complete optional constructor result, private pool and initialization runtime. Only the source representation's seed field is removed from the public client result.
- `source_constructor` traces every successful initialized owner to the same actual source execution and exact seed installation.
- `install_slot` and `install_arrays` identify the appended slot, retain every prior seed and retain all KEM pairs.
- `source_owned` proves that the returned owner's actual identity index contains its exact native seed. It derives this from successful source support, without an honesty assumption.
- `source_origin` retains the actual generated/imported branch and proves that imported seed bytes are exactly the caller's bytes. Imported identities cannot qualify as generated targets in later reductions.
- `client_uniform` charges the initialization callback and the generated branch's 32-byte sampler allowance. Deterministic installation adds no randomness; this is not a claim that initialization or parsing costs no computation.

The owner keeps its origin in every subsequent prefix result. The identity pool is not asserted to contain exclusively generated keys. A future joint-service security reduction must preserve this distinction and exclude caller-known imported material from any generated-secret target. No ordinary all-generated service endpoint is applied to the enlarged pool in this cohort.

## Ordered raw prefix and complete state

`PqxdhRegistrationJointServerPrefix.compiler` retains every ordinary source callback and rewrites only the Server static-DH callback to the indexed joint identity service. It accepts a private index and public callback inputs, not a Server seed. The actual `PqxdhServerRootPreparation.collect` preserves raw admission, attached signature verification, ephemeral generation, encapsulation, the four DH positions and all optional failures in their original order. This is the existing abstract codec/primitive boundary; no codec internals or primitive algorithms are reproved.

The eight prefix statements distinguish representation equality from annotation erasure. `query_source` proves one exact callback at the owned slot; `query_slots` preserves all seed and KEM arrays through every supported native callback. `program_source` propagates that fact through the entire adaptive continuation, retaining the full private history and auxiliary state. `query_projection` and `program_projection` erase only the private service annotations and recover the original native callback/program. `prefix_source` instantiates the actual raw collector, `prefix_native` recovers the actual native prefix and consumed-registration poststate, and `prefix_uniform` charges its real scalar and encapsulation/base randomness. These are full evaluated-program equalities, not comparisons of marginal key distributions or generator-order interchange assumptions.

`PqxdhRegistrationJointInitializedPrefix` is the actual consumer of both constructions. `body_source` connects the handle-based prefix to the exact source owner at an owned slot. `initialized_source` obtains that slot from the same constructor run and retains every constructor/prefix outcome, including an initialized owner whose raw prefix subsequently rejects. `body_projection` and `initialized_native` erase only the private pool and recover the actual original native construction and prefix, including the complete initialized owner, origin, consumed list and runtime. `native_body_uniform` and `initialized_uniform` account for the corresponding whole evaluated programs.

## Query accounting

All numbers are upper bounds, including failure paths. The three statements in `PqxdhRegistrationJointServerPrefixCosts` prove one compiler-step classification, exclusion of unrelated private capabilities and the complete raw-prefix cap for every typed reply. The constructor classifier in `PqxdhRegistrationJointServerBirthCosts.client_bound` likewise covers every typed reply, including an initialization failure or invalid imported length.

| Interface | Logical capability cap |
| --- | --- |
| Constructor initialization callback | 1 |

| Other constructor private capabilities | 0 |

The auxiliary count includes native parsing, checks, generation and cryptographic calls; it does not make their interpreted work free. Let `qInit` bound the initialization callback's complete uniform-query cost for every runtime and let `E = caps.encapsCost` be the existing actual encapsulation/base sampler bound under `PqxdhServerAuthSourceCosts.KemBound`. The entire constructor plus raw prefix is bounded by `(qInit + (supplied.isNone ? 32 : 0)) + (32 + E)` uniform queries. The constructor and prefix logical caps above are separate from that complete evaluated bill. There is no Extract, HMAC or security-advantage charge here because this cohort stops before the root and record consumers; it does not declare their later work free.
