## `PqxdhRecordLiftComposition` (7 guarded theorems)

(ctxReduction ...) chainBills ctxBills`, for every slot count, HMAC, forgery fallback and setup. `record_auth_lift_terms` gives the same statement for arbitrary alias and refusal terms, from `chain_lift_terms` and `ctxAuthLiftStatement`.

The privacy half `CtxPrivLiftStatement` is not on central yet. `ctx_lift_of_priv` (`CtxLiftTarget`), `record_lift_bool_of_priv` and `record_lift_of_priv` (`RecordLiftTarget`) take it as an explicit hypothesis parameter `privLift` for any privacy reduction family `privacy` and bills `privacyBills`, and use `ctxLiftBool_of_parts` and `recordLiftBool_of_parts`. ## `PqxdhRecordLiftHiding` (55 guarded theorems)

`idealRecords_hiding` proves `HidingStatement setup codec route serverKid bounds n` as defined, for every setup, codec, router, Server key ID, fresh bounds and slot count: for every environment and mode-P adversary (the target has no `Frame` or budget premise) and every length-preserving `replace`, the hiding projection `hidingView (ctxView result)` has the same law in `ctxRun (fun _ => .random) replace ...` as in `idealRecords ... .P`. The equality is between the mapped computations themselves, so it holds for every event and every decision of the hiding projection (`PqxdhRecordLiftIdeal.hiding_event`, `hiding_advantage`). `hiding_replace` is the same statement for any two replacements that agree on lengths.

The proof is a syntactic coupling. `Coupled Rr Ro x y` (an inductive predicate) holds when the two computations make the same queries in the same order, replies related by `Rr` lead to related continuations and the final values are related by `Ro`. Four generic facts carry it: `Coupled.bind` and `Coupled.map`; `Coupled.refl` and `Coupled.refl_weighted` (a computation is coupled with itself when its replies are compared by equality, or when every query it can make has equal related replies, which `refl_noOpening` gets from the existing raw-cost bound `PqxdhRecordLiftCtxBills.handler_categories`); `Coupled.simulateQ_run` and `Coupled.simulateQ` (simulation through implementations whose single queries are coupled preserves couplings); and `Coupled.map_eq` (with equal coin replies, maps that agree on related final values give equal computations).

The world is then coupled with itself layer by layer, the replacing world on the left and the identity world on the right:

| Layer | Lemma | Replies | States |
| --- | --- | --- | --- |
| CTX interpreter, random mode | `interpreter_couple` (`randomSeal_couple`, `keyed_seal_couple`, `sealing_couple`, `localRaw_couple`, `replay_isSome`, `keyed_couple`, `opening_couple`, `base_couple`) | equal coins; opening replies agree on success (`SuccessRel`), other replies equal (`ServiceRel`) | base state equal, CTX local states equal after erasing recorded seal plaintexts (`PrivRel`, `eraseEntry`) |
| compiled client | `handler_couple`, `schedule_couple` (`normalFinish_couple`, `receiveProgram_couple`, `kernelReceive_couple`, `ownerReceive_couple`, `ownerRun_raw_couple`) | raw-receive replies agree on success (`WorldRel`) | control state equal |
| environment and native commands | `native_couple`, `environmentStep_couple` | raw receives agree on success (`SpecRel`) | environment state equal |
| secrecy ledger | `ledger_couple` (`sameSession_view`, `view_spec`, `ledgerRel_record`, `drawBit_couple`, `uniformBytes_couple`, `send_couple`) | raw receives agree on success (`FullRel`) | same mode-P transcript view, test session (with its bit) and fresh messages (`LedgerRel`) |
| mode-P observation and adversary | `observeFull_couple`, `adversary_couple`, `wrap_couple` | equal | |

The facts behind the layers are: a random-mode seal reads only the plaintext's length, because its body and tag are fresh coins and its commitment is a lookup in the coordinate's private suffix dictionary, so with the same coins the record, the frame, the writer result and the state agree except for the plaintext recorded in the replay dictionary; replay acceptance compares nonce, associated data and encoded record, never the recorded plaintext, so openings succeed together and return the recorded (replaced or original) plaintext; the source receive's publication `finish` depends on the opening reply only through success (`normalFinish_couple`); the environment handler sees only registration effects; and the ledger's test-session check reads the transcript only through its mode-P view (`PqxdhDeploymentTranscript.designate_view`). `worldProgram_couple`, `program_couple` and `ctxRun_couple` assemble the layers, and `hidingView_rel` checks that the hiding projection reads only fields that agree on related results: the adversary's output, the transcript's mode-P view, the test session with its bit, the fresh messages, the environment state, the produced frames (equal base state), the raw counters and the handle-to-slot map (equal control state).

Contracts per theorem: none. No theorem has an assumption or contract hypothesis, and the per-theorem closure probe (`/tmp/bc-arc-scratch/items45/world/tools/ContractProbe.lean`, recorded in the receipt) finds no contract used as a proof step in any of the 55 theorems; fields of the primitive record (`dh_comm`, `xpub_length`, `x25519_length`, `hkdf_length`, `aeadSeal_tag_length`) are reached only inside definitions (the setup's DH interface, the KDF definitions and the real-mode CTX code inside the CTX interpreter's definition, which random mode never runs).

## Remaining work

Every remaining target was checked by reading against the definitions and the Rust-derived source model, and none was found false; none is proved yet. The precise remaining steps are these.

The full `record_lift` needs only the privacy half `CtxPrivLiftStatement` (the privacy track): once it is on central for explicit reductions `privacy` and bills `privacyBills`, `PqxdhRecordLiftComposition.record_lift_of_priv setup codec route serverKid bounds n hmac fallback privacy privacyBills proof` is `RecordLiftTarget` for those reductions, with no further argument. The final module name `PqxdhRecordLift` of the brief is left free for that assembly.

`OriginStatement`, structural conjuncts (no accepted target frame that its counterpart never produced, probability zero, in `idealAuth` and `idealRecords`). These need a joint invariant of the ledger, the control state and the private CTX state along the whole run, so first a flattened form of the CTX world: a composition lemma for the nested state-passing simulations (secrecy ledger over native commands over the compiled handler over the CTX interpreter) that turns `ctxRun` into one adversary-level simulation with the joint state. The invariant has four parts: the replay dictionary of every coordinate holds exactly seals whose frames `⟨sequence, sender, record.encode⟩` are in the produced log (or the pending writer log during a command) with the tag of the handle that holds the coordinate's slot in the sending role of the coordinate's direction; installed kernels are never removed or replaced and each slot is used at most once per role (the control-only facts of `PqxdhRecordLiftWorldProvenance` and `PqxdhRecordLiftProtocolHistory`, transferred through `ctxInterpreter_base`); Server peers send on direction false and receive on true and Beacons the converse (`PqxdhRecordLiftWorldProvenance.labeledKernel_oriented`); and a replay match at a coordinate equates the received frame with the sealed one (the universal decoder's target has the frame's sequence and sender in its associated data and the payload's slices as its record, so `RawCtxFrameDecoding.fromPayload_record` and `CtxRomAuth.decodeRecord_romRecord` give equality of sequence, sender and payload; no codec contract is needed for this part).

`OriginStatement`, publication conjuncts (`UnpublishedAccept` at most `guessTerm = 2·R·S/2^512` in `idealAuth`, `idealRecords` and `randomRecords`), and `BindingStatement` (`CrossAccept` at most `bindingTerm`). With `FrameReadBack`, an accepted frame that its counterpart did not publish before is a produced frame whose writer failed or whose send was not returned; its 64-byte commitment is a private-suffix value, uniform and never written to the shared cache, and the adversary learns at most the writer's success bit about it. Both bounds are bad-event bounds over the run: for `UnpublishedAccept` a union bound over at most `R` raw attempts and `S` hidden seals with the factor 2 for the writer bit, for `CrossAccept` the probability that a private commitment equals one of at most `R + S + H` shared-cache outputs (`PqxdhRecordLiftWorldBudget.run_hash`) or another private commitment. This needs new probabilistic infrastructure on the flattened world (a guessing lemma for lazily sampled private commitments under adaptive queries). Identifying the Server's receiving handle needs no contract: `PqxdhRecordLiftProtocol.serverStep` routes a raw receive with the same `route` that `receivingHandle` reads, so the receiving handle of an event is the handle that processed the attempt. `DecoderAgreement` (a premise of `OriginStatement`, not of `BindingStatement`) relates `route` to the sender that `codec.frameRead` decodes; the plan does not assume that either bound needs it.

`LorStatement` and `FreshGuessStatement`. Both are distributional statements about the mode-P `idealRecords`. Reading found neither false, and both are believed true because hidden seals read only plaintext lengths (the hiding coupling) and the secret values enter nothing else the adversary sees. They need the hiding coupling extended in three ways, on the flattened world: per-node coin permutations at the bottom with a distributional final lemma (the bit coin swapped for `LorStatement`; for `FreshGuessStatement`, the bytes of the `i`-th fresh message permuted, followed by an average over the permutation); heterogeneous queries (the two runs seal different plaintexts of equal length on hidden handles); and an escape when a test or fresh message goes to a handle holding a caller-known kernel, justified by the joint invariant that such a handle never holds a hidden slot later, so `TestsHidden` or `FreshHit` is false in both runs. For `FreshGuessStatement` the bound is then a weighted sum over the claimed index. For each `i`, the permutation argument shows that, given the adversary's view (so its claimed index and guess) and that the `i`-th fresh message went to a hidden handle, that message is uniform over its `length_i ≥ min` bytes, so `Pr[claimed index = i, message i on a hidden handle and equal to the guess] ≤ Pr[claimed index = i] · 256^-length_i ≤ Pr[claimed index = i] · 256^-min`; summing over `i` gives at most `256^-min · Σ_i Pr[claimed index = i] ≤ 256^-min ≤ 2^-min`. Bounding each index term by `2^-min` alone would give the number of fresh messages times `2^-min`, which is too weak.
