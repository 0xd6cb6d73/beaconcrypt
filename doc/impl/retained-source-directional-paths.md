# Retained source directional paths

`RawCtxRetainedFunctionalPath` connects the actual fixed retained private interpreter used by the selected-message source execution to the existing directional walk and collision classification. Its table is simply `some (prior address)` at each address. It is a mathematical view of the same complete private replies, including their correlations and repeated inputs. Public HKDF evaluations remain real, and this module performs no random-table replacement or probability hop.

`request_address` identifies the exact source ratchet domain and input bytes. `interpreted_chain` checks that decoding the complete retained response produces its second 32-byte coordinate as the next chain. `source_walk` then constructs the chronological input list of any source chain position under that same interpreter. The list retains repeated visits; its terminal is the actual iterated source chain.

`reachable_path` consumes the existing operational `RoleReachable` certificate and gives the source send path at the kernel's actual counter. `initialized_path` obtains this certificate from a successful literal `ConcreteRatchetKernel.new` call. Neither theorem assumes independent roots. An arbitrary supplied kernel does not acquire a certificate automatically: a consumer must retain its source construction and subsequent operational refinement.

`native_send_path` follows the complete original native send through the same primitive state and optional seal/writer result. `native_send_cycle` handles an admitted, nonexhausted send whose resulting chain equals its entry chain. It derives strict counter advancement from that actual execution and exposes a cycle in the same retained walk. A writer returning no frame is included because that source send still advances the chain. This is an event implication, with no claim that the event has small probability.

`stored_path` uses the original `Stored` sum: selected initialized owners carry their directional certificates, while other native owners remain unrestricted. `family_paths` states the corresponding property for selected stored owners in the complete role family. `native_family_paths` consumes the existing exact full-state interpreter equation and lifts each supported original adaptive LIVE result to a supported annotated run with those paths. It preserves the original optional replies, full role state, read history and shared primitive state. Its conclusion is support attribution; it does not transfer probabilities from the older mutable-table support replay or supply cryptographic freshness.

`stored_meeting` classifies equal sending inputs from two certified source owners. Its witness lists have exactly their actual send-counter lengths. The alternatives are equal initial roots, an actual reached output equal to the other root, or equal next-chain outputs at two distinct reached inputs. Equal roots remain an explicit alternative and do not identify owners, local installation occurrences or cryptographic sessions. No constructor injectivity or key independence is inferred.

The eleven statements add no primitive security contract or reduction loss. They are deterministic source correspondence and support results. They retain repeated chronological input occurrences rather than declaring cache hits or ambient work free. The source run's existing query accounting remains necessary; a walk length is an exact source position, not a new bound on all protocol or reduction work.

The next consumers must attach these certificates to actual pre-advance initializers, retain distinct local installation occurrences through original source scheduling, and connect ordered repeated sends to cycles or cross-installation meetings. Their probabilities require the actual joint sampler, source candidate counts and cryptographic reductions. Arbitrary initial roles may already alias and can make the repeated-input event certain. The Boolean initializer-coordinate marker does not establish installation uniqueness, identity/KEM freshness, secret-key nonexposure or the final symbolic session correspondence. Primitive internals, snapshots, persistence and restoration remain outside this work.
