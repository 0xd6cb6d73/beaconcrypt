# Native source counter order

`RawCtxNativeCounterOrder` proves chronological sending-counter facts about the original indexed record and reveal scheduler under any complete native backend. In particular, it applies to the fixed retained private interpreter used by the selected-message composition. It does not replace that interpreter, its optional replies or its shared state.

`receive_counter` derives exact sending-counter preservation from the original native receive program through its concrete adapters. `send_counter` derives nondecreasing counters from the original send program. The exhausted counter stays unchanged; an admitted send advances once even when sealing or its writer returns no frame. The backend is unrestricted because these properties follow from the source control flow, not from a cryptographic assumption about its replies.

The private invariant rules consume those two facts. Their shared-state relation is `True` because the invariant constrains only the role's sending counter; every backend effect is still executed in the same source program. `schedule_lower` applies those rules to the complete generic LIVE schedule with the original public services, owner lookups, raw delivery, optional plaintext and reveal history. A lower bound at a selected owner remains a lower bound whenever that owner is observed later.

`source_lower` uses the checked complete native representation equation to transport that result to the literal original protocol state. It derives both the initial and final selected-owner lookups through the original kernel mapping. No caller-provided receive/send simulation premise is added. `source_mono` then instantiates the lower bound with the actual initial counter, retaining the two concrete source kernel observations.

`after_send_strict` starts with a supported original admitted send and the actual resulting full backend state. The returned kernel is the selected owner in the subsequent source schedule. Combining exact advancement with the complete suffix's monotonicity gives a strict inequality between the earlier and later counters. It retains a missing ciphertext and failed writer, and it covers arbitrary subsequent raw inputs, sends, public queries and reveals in that original record scheduler.

The scope is one interval with no owner installation. The LIVE record scheduler in these statements has no registration/replacement operation. A later registration may install a different kernel at the same public route; the theorem does not equate those installation occurrences or order their counters. The global consumer must use the actual initializer/attempt trace to identify the appropriate interval.

These six guarded statements add no oracle request, security assumption or reduction loss. They preserve an existing source execution and its complete backend effects; they do not supply its query or runtime budget. They discharge the strict chronological-counter premise needed by the source cycle classification. Actual initialized paths, cross-installation meetings, source event probabilities, sampler reductions and the common symbolic experiment remain separate obligations. Snapshots, persistence, restoration and primitive internals remain outside the work.
