# Executable record world and the Beacon record projection

`PqxdhRecordLiftWorld` interprets the frozen v1 `WorldSpec` using a dynamic Server peer map, a dynamic owner list, the actual source record operations and one shared BLAKE2b random-oracle cache. It executes `PqxdhRecordLiftInterface.program`, including its unchanged CE secrecy wrapper and explicit Server key ID. This is an operational world for the record lift. It does not identify the CE ideal-key game with this world or prove a chain/CTX security bound.

The source Beacon contains private registration fields that `appendOwner` cannot supply. `PqxdhRecordLiftBeacon` gives the precise ordinary-record projection needed to avoid fabricating them. An inactive projected owner stores only its actual source phase tag. An established owner stores the outer sender ID, the established control, the stored 153-byte associated data and the complete ratchet kernel. The ghost raw-attempt counter remains separate. Ordinary record dispatch never reads inactive identity, pin, prekey, one-time key or KEM fields. On an established owner it reads the outer sender ID independently of the control's assigned ID, and uses the control's server-binding ID as the receive pin. No equality between those identifiers is assumed.

`step_project` proves that the projected native Beacon step is exactly the minimal handler, before any primitive interpreter is supplied. `step_putback` restores the minimal result into its original full native source frame and recovers the exact source step. `putback_project` and `putback_fields` preserve every original outer private field. `logged_putback` extends the equation through the actual deployment logger and any supplied primitive interpreter, retaining failed-writer frames and the complete primitive poststate. `handler_bound` proves the source primitive budgets for every minimal state, and `step_bound` specializes this to the exact source projection. These are ordinary-record equations for arbitrary source states; no registration metadata invariant or dummy private value is introduced. Registration publication must separately supply the exact established shell, and an inactive abort may change env-owned metadata that the record projection does not read.

The world stores an optional initialized Server with the constructor's actual outer sender, public identity and peer map. Its raw counter starts at the native experiment's zero. The private initialization request cannot reset an already initialized Server. Environments cannot issue this request. The four record operations call `RawCtxServerMixed.serverImpl` or the proved minimal Beacon handler under the existing `PqxdhDeploymentNative.logged` wrapper. Their tags and produced-frame append operation are unchanged. A writer failure can therefore leave a produced frame without a public ciphertext. An absent owner rejects without incrementing a ghost counter; an existing inactive owner rejects sends unchanged and increments its raw counter on every raw attempt.

Inactive append arguments belong to the environment's registration state. The record world erases the supplied sender and Server identity until an exact established shell is installed. The frozen append API returns a handle without a failure branch, so the generic interpreter accepts the requested inactive birth tag. CE's create correspondence must show that its environment requests `fresh`. The allowed subsequent phase edges are exactly the CE command edges `fresh → initSent`, `freshWithCoins → initSent`, and `initSent → aborted`. Unsupported and same-state advances reject. Establishment is possible only through installation from `initSent`; established and aborted owners cannot be revived or reinstalled. Raw counters survive phase changes and installation.

The named C2b predicates are `ServerVacant`, `BeaconReady`, `Unused`, `SeedsPersist` and `UsesPersist`. Server installation requires an existing Server and a vacant assigned key ID. Beacon installation requires an existing `initSent` owner. A hidden reference additionally requires an unused marker for its slot and operation-selected role. All admission checks occur before hidden resolution. A refused installation therefore neither draws a seed nor consumes a marker. Successful hidden installation sets precisely that slot/role marker, so moving the same hidden role to another handle cannot bypass the check. Known kernels remain exactly the caller-supplied kernels and consume no hidden slot.

Hidden resolution uses `PqxdhRecordLiftLazyTable` on `Seed = RootOutput × RootOutput`. Both roles access the same persistent table. `resolve_miss` identifies the first lookup with the actual seed sampler and its complete poststate: the exact sampled seed is cached, both table counters advance, the actual uniform counter is retained, and all other fields stay unchanged. `resolve_miss_kernel` projects this law to the kernel of one uniformly sampled seed. Kernel construction is total by the existing Server and Beacon source-constructor theorems, and `kernel_exact` identifies the resolved kernel with the frozen role-directed `hiddenKernel`. There is no seed-dependent refusal or fallback kernel. The lookup facts retain every earlier seed and all role, raw-counter, produced-log, CTX-cache, native-call and effect-counter fields. The other role's cache hit performs no new random draw. `handler_persists` and `schedule_persists` prove that every private/public request and every adaptive continuation preserve prior seeds and used markers. Successful-install marker facts and the used-role refusal equations establish the one-install rule operationally.

Instrumentation forwards all actual uniform queries unchanged, including startup, adversary and ledger coins, environment coins, seed-table misses and CTX-cache misses. `countCoin_forget` proves that dropping this counter restores the original computation exactly. Record primitive calls use the literal `PqxdhDeploymentNative.primitives` with the fixed source HKDF, functional AEAD and original optional frame writer. Every KDF, seal, open, hash and writer request is counted separately, and `primitives_forget` preserves the exact native reply and shared cache after removing instrumentation. Local deterministic primitive calls are not assigned zero work merely because they use no randomness. Parsing, map/list operations and byte work remain mathematical source operations, not a compiled running-time claim.

`Counts.effects` counts every `EnvEffects` request: startup, adversary and ledger coins, public adversary hashes, and environment coins, hashes and administrative requests, including refused ones. It does not give environment-only totals. Public hashes and record commitment hashes update the same CTX cache. The separately reviewed `PqxdhRecordLiftBudget`, pending publication together with this package, transports `Frame` and `Budget.Respects` to bounds on these open-program effect queries. Interpreter-internal record requests, seed allocation, native primitive work and cache-miss random draws remain separate costs. In particular, `uniform` includes the actual seed and digest samplers and is not a CE coin cap. No arbitrary backend callback is treated as an uncharged sampler.

`run` retains full private world state for distribution and simulation lemmas. Security observations cannot be arbitrary predicates over that state: a predicate inspecting hidden seeds or caches could recompute source derivations. `game` projects to the CE-shaped `Option (X × Ledger × produced)`. `analysis` additionally retains the Server and per-owner raw counters. Both preserve constructor failure as `none`. The CE ledger contains the mode-O transcript, test bit and fresh-message entries for analysis; it is not the mode-P adversary view. The eventual event definitions must respect the original CE observation and declassification rules. No post-phase or reveal operation receives the world state; the later-quantum extension remains separate.

The remaining CE obligations are explicit. C1 must connect the same adversary's original ideal-key game to this projected world, composing the outstanding failed-finish erasure equality C7 with the erased-game correspondence. C2c must identify the exact shells, known kernels and hidden entry references at installation. C3 must connect the one cache to CE's cache, and C6 must derive reveal only from env-owned data. The world does not assume those equalities. The chain-table/source join, global selected-key compiler, source nonce/refusal and alias bounds, ideal-world events and both two-sided security lifts also remain to be proved. No primitive contract or security assumption is added here.
