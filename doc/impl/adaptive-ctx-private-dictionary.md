# Adaptive CTX private-dictionary simulation

This HB-85 component connects the actual persistent private cache to a checked final-vector guessing bound. For an arbitrary adaptive one-key replay-only execution and a final vector of `q` unchanged target candidates, the probability of any eligible commitment guess is at most `q / 2^512`. Eligibility means the full CTX tuple was not previously sealed, while the underlying nonce/associated-data/ciphertext tuple was previously issued. The candidate selector receives the client's result; eligibility uses the successful public seal history. It does not receive the retained private table or inspect the reconstructed private cache.

This is a final-vector result in the replay-only comparison game. It does not yet bound every earlier acceptance in the actual adaptive receive game. The next composition step must connect the first discrepancy to a stopped raw request, apply the one-slot result to that stopped execution, and sum over all `qRaw` raw positions, or prove an equivalent complete trace argument. The final vector length `q` is therefore not silently identified with `qRaw`. The existing canonical-to-logged bound still contains one conventional IND$ advantage, `qHash / 2^128`, and twice the same indexed ordinary INT-CTXT advantage sum; neither integrity sum is removed here.

`AdaptiveCtxReplayDictionary` defines the exact replay-only response. `replayPlaintext` searches the successful full CTX tuples and returns only a plaintext supplied to a successful sealing request. Actual record decoding proves that a matching encoded record has the same typed fields and underlying base tuple. Ordinary functional opening correctness then identifies that plaintext with the prior challenger-produced log response. `replayPlaintext_exact` also proves that its issued commitment is already installed in the actual cache. Consequently, `replay_discrepancy_iff` characterizes the difference from the retained-base logged reply as exactly a fresh full-tuple acceptance, after the same actual private lookup. No hidden recovered plaintext is inserted into the adversary's input.

The same module factors the private lookup into `unifSpec + (FixedBytes 197 →ₒ CtxDigest)`. The 197-byte address is the exact nonce, associated data, base tag, sequence and sender suffix used by production CTX; it omits the hidden 32-byte key prefix already separated by the earlier prefix coupling. `abstractSuffix_projection` equates the complete actual cache step with a lazy finite dictionary query and a mirror update. Hits reinstall the same value and therefore leave the complete cache unchanged. Misses install the same returned digest in both views. All well-formed raw requests query this dictionary, including failed, repeated and replay-only rejected requests. Public hashes retain their separate real public cache and explicit uniform draws. Honest seals preserve the actual primitive arguments, nonce rejection, returned record and full state. `abstractRun_projection` lifts these query equalities through the entire adaptive continuation while projecting only the duplicate external dictionary.

`JointEagerTable` supplies an analysis law for a finite private dictionary. After the actual lazy client finishes, independently fill only its missing cells and retain the completed answer function jointly with the complete client result. `completedLazy_eq_eager` proves equality with sampling that same function before the deterministic client. `mixedCompletedLazy_eq_eager` additionally forwards every explicit uniform query in source order. Its public-coin case interchanges only independent samplers and quantifies over the complete following computation. Its private-miss case uses the joint updated-table law under the complete probabilistic continuation. These are joint distribution equalities, not equalities of reply marginals.

The total function has an enormous finite domain and is strictly an analysis device. No source program, adversary, constructed cryptographic reduction or claimed runtime implementation enumerates it. Concrete programs keep lazy dictionaries. The proof does not assign a polynomial runtime to exhaustive full-table sampling, and it does not replace public HKDF or public hash evaluation by private independent cells.

`AdaptiveCtxReplayTable` connects that generic law to the actual source state. `abstractRun_dictionary` proves that the duplicate dictionary is determined by the full source cache. `completedSource_eq_eager` therefore retains the same private answer table jointly with the complete actual replay-only source result, including every failed lookup, both caches, histories, counters and returned optional plaintext. `completedSource_initial_eq_uniform` specializes this to the real empty initial cache.

Under each fixed retained table, replay-only raw replies depend only on the public successful full-tuple history. `honestOnlyImpl` can omit those raw private queries while retaining every attempted private address in order. Honest sealing still obtains its commitment from the private dictionary, and public hashes and source coins remain actual. `tracedSuffixCache` reconstructs the persistent private cache by replaying the retained address history against that same table; repeated addresses reuse the same cell. `honestRaw_restore`, `honestSeal_restore` and `publicHash_restore` prove complete query equalities. `honestRun_restore` lifts them through arbitrary adaptive continuations. Its arbitrary-state statement explicitly starts the source side from the reconstructed prior state; it does not assert that an arbitrary cache already equals that reconstruction. The fresh-source specialization is exact. `completedSource_eq_honestCompletion` connects the actual source to the completed honest-sealing-only dictionary followed by full-cache reconstruction.

`AdaptiveCtxHonestCache` proves the previously missing final-cache premise. `honestNative_preserves` and `honestClient_cache_invariant` establish actual cached honest commitments, marked and unique seal nonces, ordinary base-opening correctness and honest-only suffix provenance after the checked raw-query removal. Provenance is not assumed for the original actual cache, which still includes failed raw lookups. `freshGuess_address_absent` derives absence from a successful eligible guess: if its cell were already cached, the actual issued commitment and unique nonce would force a full replay, contradicting freshness. This uses the earlier checked fixed-width preimage equality, not cryptographic constructor injectivity.

`JointTableFreshCandidates` conditions on the complete actual result and final honest-only cache, then applies the independent-tail coordinate law. Cache absence is part of its winning event, not an assumed secrecy interface. A vector union bound permits repeated addresses, repeated guesses and explicit `none` slots. The selector may depend on the complete result and cache, while the completion tail is sampled afterward independently. `guessEvent_implies_freshHit` supplies the derived actual-source absence fact. `honestCompletion_guess_bound` obtains `q / 2^512`; `completedSource_guess_bound` transfers it through the same-table, complete-state reconstruction to the actual replay-only source. Full private-cache restoration changes neither the unchanged target candidate nor its public-history eligibility test.

`AdaptiveCtxReplayQueryBounds` keeps concrete runtime accounting separate from the analysis table. The actual replay-only source has at most `qCoins + 64 * (qHash + qSeal + qRaw)` uniform-oracle calls from every prior state. Each source coin is an arbitrary finite uniform request; each digest miss uses 64 byte-valued uniform requests, and a hit reuses its value. The factored actual source makes at most `qSeal + qRaw` private dictionary queries, including failed raw lookups. The honest-only comparison makes at most `qSeal` private queries. Its direct source has the same explicit conservative uniform upper bound; the raw component of that bound overcounts its now-zero private randomness. These are source and dictionary query caps, not a machine-runtime theorem. Each source seal still performs the ordinary primitive sealing operation when its nonce is fresh; raw parsing, full/base log searches, eligibility tests, cache operations, history maintenance and terminal reconstruction are real local work. The existing sampled-key challenger separately pays its 32 byte-valued key-generation queries.

The maintained primitive boundary is unchanged. Ordinary nonce-AEAD functional correctness and the existing conventional IND$/INT-CTXT endpoints remain the cryptographic contracts. This component operates inside the already explicit classical random-oracle interpretation of the CTX commitment hash; collision resistance alone does not imply that interpretation. No BLAKE2b, AEAD or other primitive algorithm or implementation is proved. The native CryptoFrame decoder is still represented by the retained external `RawDecoder` boundary. Native adapter correspondence, replay-consuming ratchet transitions, failure rollback, correlated record keys, multiple sessions, permitted reveals and the common computational/symbolic experiment remain separate obligations. No new security assumption equivalent to protocol authentication is introduced.
