# Source input attribution for the nonce charge

`RawCtxSelectedSourceSendInputs` connects the repeated nonce event to repeated visits to the exact selected sending-chain input in the same source execution. Its proof derives source admission from actual role callbacks rather than assuming that arbitrary audit records are valid. It introduces no independence, constructor injectivity or source-path security premise.

`callback_routed` follows empty-send admission, every Beacon phase, Server associated-data and peer lookup, indexed family dispatch and live reveals. Each recorded seal comes from its actual admitted sending kernel and the resulting ready capability. Rejected and non-send branches supply no sealing event. `step_routed` and `program_routed` preserve this evidence in the very event history used by the nonce-probability comparison, including the augmented source callback after a refusal.

`selected_input` starts the event history empty and consumes the resulting concrete evidence. Every selected seal uses `concreteChain target` as its original sending input. If a retained predecessor exists, the theorem also proves that this input's request address differs from the predecessor address: the existing source rule gives the retained predecessor priority. The theorem requires no invariant on an arbitrary initial audit and no assumption that a selected key differs from known bytes.

`repeated_positions` extracts two strictly ordered positions from the original sealing history when selected nonce values repeat. The occurrence values, owner labels and sending kernels need not be unequal. `RepeatedInput` records two such positions whose sending inputs both equal the selected input. `repeated_input` derives this event for every supported complete source execution exhibiting the repeated nonce event; it does not replace that execution or reset its cache.

`nonce_input_bound` therefore proves `Pr[actual selected nonce refusal] ≤ Pr[RepeatedInput target in the actual source history]`, with coefficient one. `executable_distance` consumes that bound in the complete source-to-executable CTX comparison, retaining all optional replies, roles, private state and source cache. There is no additional oracle request or probability loss; the existing source and reduction query ledgers remain unchanged. Local audit computation still costs time.

The input event is an overapproximation and is not yet shown rare. Its probability needs the actual installation origins, directional root distributions, paths and chain cycles or crossings, permitted disclosures and target-selection factors. Arbitrary initial roles can make the event certain. The proof remains in the retained selected-KDF hybrid; all public HKDF evaluations stay real. The CTX hash does not: both compared executions model BLAKE2b as a programmable classical random oracle, and in each of them CTX commitments and the adversary's direct hash queries read and extend one lazily sampled cache. Known-key aliases still require their ordinary endpoint and source exposure accounting, and chain freshness does not establish identity or KEM freshness. No primitive implementation, snapshot, persistence or restoration proof is included.
