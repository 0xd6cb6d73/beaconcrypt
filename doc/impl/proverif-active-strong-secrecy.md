# Bounded active strong secrecy with observable receive results

This stage tests two symbolic chosen-plaintext experiments derived from the maintained free-schedule record models. The experiments retain the active network and publish the optional-result bit of every modeled receive and Beacon finish, correlated to its submitted input and caller-selected public label. Application plaintext remains private to the application. These are symbolic observational-equivalence targets; they are not the computational adaptive optional-plaintext receive experiment or an end-to-end computational bound.

The complete maintained six-target Make gate passed on the frozen source inputs. Beacon-to-server equivalence was TRUE in 1,426.45 seconds with peak RSS 2,078,204 KiB; server-to-beacon equivalence was TRUE in 16.64 seconds with peak RSS 123,004 KiB. All four fresh-secret controls returned exact FALSE verdicts with confirmed traces. The gate also passed 25 transcript-fidelity tests and twelve checker regressions; the separately run reviewed inventory gate passed. Independent semantic review checked the complete processes, transformation, interfaces, source bounds and selective-run receipts; the final full-run receipt is reviewed before publication. Full logs and input hashes are retained with the publication record.

## Exact experiments

Both directions retain replicated honest Beacons, replicated Server objects sharing the honest Server identity, attacker-created identities and bundles, public network scheduling, one registration/build per Server object, and two subsequent application sends. The maintained manifest presently bounds post-registration receive attempts to one per peer. The receive libraries preserve cached, future, old, replay, malformed, wrong-sender and failed-open branches and their entry-state continuations. At this one-attempt bound, a cache-hit or repeated-delivery history is not reachable; no multi-attempt conclusion follows. The larger ordinary correspondence group remains independently bounded and checked.

In the beacon-to-server experiment, every Beacon's pinned identity and pinned Server ID are attacker-selected. After the actual sequence-one finish, the attacker supplies two plaintext alternatives for each of the two sends. A Beacon pinning the honest Server identity encrypts the left or right alternatives according to the experiment's shared hidden bit. A Beacon with another pin encrypts the left alternative in both worlds. Eligibility does not require an assumed accepted origin, honest selected KEM key, private partner table or a premise that an honest Server accepted its bundle. The two worlds use the same protocol operations and public interface.

The server-to-beacon experiment retains the older honest-pin main process. At sequence two, each Server send worker receives a choice between an ordinary chosen message and a deferred challenge. The ordinary branch encrypts the left input. The challenge branch waits for an honest Beacon's private announcement of the same assigned identifier and root after its actual successful finish, then encrypts the selected alternative. Sequence three carries an ordinary attacker-chosen message. This is the OD5 eligible-test slot, not a production admission check or an API test oracle. A challenge selected on an unpartnered session waits indefinitely in that slot; the experiment does not return a rejected test or permit a subsequent ordinary-send retry in that worker. Other workers and their ordinary sends remain schedulable. No arbitrary-pin extension is inferred for this direction.

The plaintext interface abstracts nonempty application byte strings and requires equal-length challenge alternatives for its computational interpretation. Byte lengths and serialization are not encoded in this symbolic experiment. The channel reveals frame bytes and success/failure, including malformed inputs and finish rejection. It does not reveal the accepted application plaintext. There are no new compromise/reveal interfaces in this P5 model; the eventual global freshness experiment remains separate.

Each finish or record delivery supplies `(call_label, input)`, and every modeled result echoes both values. Labels distinguish repeated identical inputs when the environment chooses distinct labels. They are experiment metadata and never enter a parser, cryptographic transcript or state transition. They do not select or identify a particular replicated worker: workers still consume from the shared channel. Source API routing by object handle or per-object endpoint remains part of the explicit L2 abstraction obligation. No production wire-format change is proposed.

## Checked source transformations

The static `fs-strong-*` process files remain reviewable. `active-strong-secrecy-models.py` computes their expected derivatives without writing files, and `check-active-strong-secrecy.py` compares every process token. The original Server registration body, generator order, selected root inputs, associated data, ciphertext arguments and receive continuations are copied from the corresponding maintained fs source. The Beacon's pure finish computations become a `letfun`, allowing failure at any intermediate parser or destructor to produce a public false result. Success emits the original ghost events, then the public true result and the unchanged next process.

The server-to-beacon equivalence helper maps every non-one initial sequence directly to terminal rejection. In the underlying model, later-frame opening may succeed or fail internally, but both paths return the same public false result, produce no private partner announcement and terminate. This is an observable-process simplification only: it does not preserve primitive-call history, timing or computational query counts. The original correspondence process and its later-opening events remain unchanged. The folded later-frame branches, original abort hook and chosen-application send source have explicit token digests: a change requires source review and a changed derivative. These drift guards are not compiler-correctness or applied-pi simulation theorems. The inherited free-schedule/source abstraction obligations still apply, especially cross-object pending registrations, peer routing, both-direction composition and the far-record abstraction. The ongoing scheduler work is separate from these bounded experiments.

The theory remains `crypto.pvl`, including its role-asymmetric DH representation and stronger symbolic KEM binding/injectivity idealization. The separately checked primitive encoding profile is not silently substituted into these equivalence results. Likewise the symbolic fixed KDF and AEAD constructors do not supply computational reductions. The ordinary no-unification heuristic is extended with a two-world `choice[x25519_public(x),x25519_public(y)]` pattern to control resolution selection. It changes no equation, process capability or cryptographic assumption. The beacon-to-server derivative retains the source precision annotations. The server-to-beacon derivative retains `[precise]` only at the sequence-two test/challenge selection and uses `set simplifyProcess = false` to avoid optional simplification search after an unsuccessful primary analysis. The corresponding controls use the same selective input instrumentation. These settings change analysis strategy and precision, not process operations, bounds, challenge eligibility, or observable replies. Every occurrence is recorded in the declaration allowlist.

## Controls and validation gate

For each direction, two single-world controls replace the challenge with a newly generated private secret and query whether its generation event and attacker knowledge can occur together. One control discloses the selected plaintext; the other removes its eligibility condition. Each must return an exact FALSE reachability verdict with a reconstructed trace. The leakage control checks that the eligible send is reachable; the ungated control checks the secrecy boundary for attacker-owned receiving identities. These are fresh-secret disclosure controls, not observational-inequivalence results. ProVerif 2.05 reports equivalence failures as “cannot be proved,” even when it reconstructs a distinguishing trace; this gate never accepts that verdict. No primitive equation changes.

The new runner is serial and uses the shared ProVerif lock. Each target retains the owner-approved maximum of 1,800 seconds and 10 GiB address space. It rejects unproved results, unexpected warnings, mismatched or missing summaries, wrong result classes and missing or duplicated reconstructed traces. The existing 49-target correspondence group and its budget are unchanged. Focused checker tests remove result outputs, alter failure states, bypass eligibility, expose the private channel, drop challenge alternatives, change source branches and corrupt verifier receipts to check that the gate fails closed.

The initial maintained group failed because its server-to-beacon analysis timed out at 1,800 seconds. Keeping precise-action instrumentation only at its challenge-selection input and disabling optional simplification search made that identical process decidable. The initial timeout, an interrupted all-imprecise probe and earlier unlabelled diagnostics remain explicitly failed or exploratory records; none is substituted for a final maintained verdict. The successful probe and maintained sources preserve every protocol operation, bound, challenge gate and public reply. Final publication records bind the frozen solver inputs to the committed source; central metadata reconciliation and the eventual aggregate proof matrix remain separate. This stage adds no primitive advantage term or query allowance and does not discharge the common computational/symbolic experiment.
