# Returning from actual later-record saved callbacks

Five modules add 13 guarded statements joining the original generated callback chronology to the executable saved CTX compiler and its before-challenge monitor. They retain the existing sampler, complete private state, optional refusals, callback order and adversary interface. They add no cryptographic contract or reduction loss and do not establish a later-record confidentiality bound.

`PqxdhLaterChallengeCarriedChronology.carried_reaches` relates the generated sampler's explicitly carried selection to the original `SampleChronology.Reached` witness. It evaluates the complete sampler with `hashImpl` from the empty shared cache. The resulting witness retains the original prepared input, private KEM interpreter parameters, initial Builder reply, historical wrapper path, captured callback and both reached caches. It uses the same packet selection that supplies the adversary; it does not recover a continuation from a matching output or replace an interpreted history by syntactic support.

`PqxdhLaterSavedOutsideSupport.Returns` describes a property of every possible returned value of each explicitly stored outside program, for every reply to its saved request. `program_returns` derives this structural certificate for every descriptor generated by the actual source Post program, covering record callbacks, inactive and active Beacon finishes, all preparation/application refusals and every continuation. `scan_returns` gives the certificate to the literal descriptor returned by a supported source scan, retaining the scan's actual complete reached state. These are logical all-reply statements, not a claim that a modified backend reproduces the original prefix probability.

`PqxdhLaterSavedCompilerSupport.optional_support` and `interpreted_support` show that a successful optional compiler returns a value from the original all-reply program. Refusal stays refusal. `prepare_returns` examines the existing saved record, Beacon finish and Server Builder implementations; each executes its actual saved operation, including optional writer and publication effects, and returns one of its own explicit outside programs. `complete_returns` preserves the certificate through that complete program's existing stateful optional interpreter. Finally, `source_support` joins an actual source callback cut to a successful output of `PqxdhLaterSavedPostCompiler.complete`: the output belongs to the original callback's all-reply syntax. It needs no invented frame reply and makes no claim that the original prefix had the modified backend's probability or state. Full instrumented poststate remains in the successful-run premise.

`PqxdhLaterChallengeBeforeMonitor.callback_unused` checks the ordinary and immediately rejected request cases of the actual wrapper. A before-phase request leaves its challenge pair absent for every source reply. `cut_unused` transports this fact to the literal saved callback using `scan_returns`. `resume_pre` executes the same complete saved callback in both worlds, preserving refusal and poststate, then applies the existing `Monitor.program_pre` to the request's carried continuation. Its explicit `Returns` certificate is operational and is discharged by `cut_unused`; its target-versus-parent address inequality is the existing alias event, which still must be paid by the maintained correlated-sampler allowance.

`PqxdhLaterChallengeGeneratedBefore.unused` discharges that certificate for the same actual generated pending packet by consuming `carried_reaches`. Its `resume_pre` then establishes the two-world relation for that packet's monitored saved continuation with marker `none`. The generated pending descriptor, original callback, carried continuation, complete source execution and original query allowance remain the same. The callback allowance is the existing `Fits` certificate, not a security assumption; the maintained descriptor-resource theorems supply it to source consumers.

These statements do not add queries or modify any executable program. The previously checked `SavedMonitor.resume_budget` still preserves every weighted budget of the full saved compiler, including callback work before refusal and the entire outside continuation. The original source-prefix, base, uniform, KEM, hash, seal and raw-opening bills remain unchanged. Support inclusion cannot cancel any loss or remove opaque callback costs. In particular, the alias allowance `(8 + 67 * postCap) / 2^256` remains a separate term; no unconditional address separation is asserted.

The [generated-prefix join](later-challenge-generated-prefix.md) now derives marker preservation along the actual native source prefix of the same generated packet, including the literal initial `none`. Its application to the nonce-stopped executable prefix still requires the full state relation and refusal comparison. The [source-frame join](later-challenge-source-frame-join.md) excludes the used phase for the original comparison event; its lift to the executable event still retains the nonce-refusal and Good-event obligations. The inside phase still requires the actual pre-send counter and historical directional path at the same callback cache. The two-world prefix coupling, real/raw primitive hop, Fresh/event implication, selected finish/refusal accounting, owner/session/position selection factors and final resource ledger also remain open. No snapshot, persistence, serialization-implementation or primitive-implementation claim is made.

Each changed module is checked separately with Lean 4.34.0 under the shared lock and one Lean thread. Every new public statement has an exact axiom guard for `propext`, `Classical.choice` and `Quot.sound`. Central imports, checker and inventory integration are deferred to the reviewed integration step; no maintained gate is disabled. The lane-local proof and support changes do not modify Rust or ProVerif.
