# Local selected near-receive uniqueness in the exact T0 process

This is an auxiliary paper argument for the exact `probe-selected` process, pending independent review. The same-process Kr3 C3 solver query remains queued; no solver result is claimed here. It supplies only occurrence uniqueness and does not establish publication origin, plaintext secrecy, native byte equality or a computational collision bound.

Each `A1Accept` invocation reaching its pending continuation has evaluated the exact `registration_set_root` helper once. That invocation restricts its own fresh `kem_coins` atom after the ephemeral draw. Normalize the generated root definition in three steps. Its KEM term is `K = mlkem_shared_secret(pq, kem_coins)`. Its root input is `I = RootKeyInput_to_bitstring(RootKeyInput(pqxdh_root_input(padding, dh1, dh2, dh3, dh4, K)))`, using the actual extracted names for the wrapper and converter. Its root is `hkdf_first_32(hkdf_sha512_no_salt(I, pqxdh_domain()))`. All displayed constructor positions are free in the loaded T0 theory, apart from definitional type erasure and the root-input helper reduction that produce this normal form. Equality of two accept-produced roots therefore entails equality of their final KEM coin arguments. Each such coin is restricted at a distinct dynamic accept occurrence, so equal roots come from the same accept occurrence. This argument permits arbitrary candidate identity/public-key terms; it does not assume their keys honest or unknown. It relies explicitly on T0's HKDF and ML-KEM constructor injectivity, which is stronger than ordinary cryptographic guarantees and must not be imported as a zero-probability computational collision theorem.

That accept creates exactly one `A1Pending` invocation with its private root and fields. Its single, nonreplicated input consumes the pending continuation on every build path. Failure returns None and creates no worker; success installs exactly one `L2Recv1`. Repeated public token or builder labels cannot duplicate this private continuation. Every `FsReceived` in this process is emitted by one of those installed workers; none is emitted by disclosures, the send worker or a fabricated public event. Thus equality of receive-root fields identifies the same worker, even across arbitrary many accept invocations and repeated public labels.

For one worker, the Server identity, Beacon identity, assigned ID, root, associated data and two initial materials remain fixed through every continuation. Initially its state is `(r,cached1)=(0,false)`. Every attempted input also consumes one remaining Kr slot, including parser, route, replay and opening failures. The only successful near state transitions and sequence labels are:

| Before | Accepted target | After | Still acceptable near targets |
| --- | --- | --- | --- |
| `(0,false)` | 1 | `(1,false)` | 2 |
| `(0,false)` | 2 | `(2,true)` | 1 |
| `(1,false)` | 2 | `(2,false)` | none |
| `(2,true)` | 1 | `(2,false)` | none |

All other branches either return None with the same pair and fixed fields, or exhaust the remaining slot count. The reachable pairs are exactly the four displayed pairs; in particular `(1,true)` is unreachable. Assign remaining-target sets `{1,2}`, `{2}`, `{1}`, and `{}` to those pairs respectively. A successful transition accepts an element of its set and removes exactly that element. No transition adds a removed element. Induction over any finite number of remaining slots shows that a worker emits at most one successful near receive event at each of sequences one and two, independently of plaintext, raw frame, failure scheduling or attacker knowledge.

Combining root-occurrence uniqueness with that local state invariant proves the selected C3 formula: two receive occurrences with equal Server/Beacon identity, assigned ID, root and sequence have the same occurrence time, even when their plaintext variables differ. In fact the selected-identity marker is unnecessary for this local uniqueness fact. This is exactly the root-and-full-tuple equality required by the source paper's ordinary-origin-to-injective-origin composition, not same-ciphertext uniqueness.

The near-process far-shaped None branch is not used to model successful source far calls. The source paper's separately reviewed public-computation projection maps source traces up to first far success and preserves every selected near receive occurrence, including caller-associated optional plaintext. It therefore preserves a hypothetical pair violating uniqueness. Every deleted source attempt and primitive operation remains charged in the computational experiment. Neither this local symbolic induction nor the earlier root constructor argument supplies that computational accounting or the global source/cryptographic bridge.
