# Entry insertion in the same chronological source prefix

`PqxdhRecordFactsOriginOrdinalPathEntries` connects a retained seal dictionary entry to its actual earlier sealing callback in the exact prefix that reaches a later receive. It preserves the complete callback reply, states, saved continuation and before/after cut lists. It does not infer receive chronology from membership in a final dictionary or replace an execution with a different supported sibling.

`prefix_insertion` is a generic operational fact for the existing literal `Prefix` relation. If a state predicate is false initially and true at the given prefix, an actual callback transitions from false to true. The theorem retains the prefix before that transition, its supported complete reply, the literal suffix prefix to the current state and the exact concatenation of their cut lists. It does not require monotonicity and does not claim this is the earliest transition if the predicate can later become false.

`prefix_entry_sealing` applies that fact to membership of a literal `CtxSuccessfulSeal` in one material coordinate’s dictionary under the actual cache-erased service interpreter. The already checked service classification proves that insertion can only occur at a sealing callback with matching material. The returned `Cut` retains its exact pending input, state, attempted history and continuation; the actual optional writer reply and complete poststate remain unchanged. The same literal entry is present after this callback, and its subsequent prefix reaches the current state. The chronological list equality is `cuts = earlier ++ cut :: later`.

`prefix_length` proves that the number of cuts in a literal prefix exactly equals the increase in its attempted-label history length. It counts every source `.sealing` constructor, including real/known modes, before the reply. Failed writers and rejection after reaching the callback count; outer sends rejected before the callback do not. A later event may separately restrict the selected mode.

No environment frame, target honesty, writer success, final completion or extra cryptographic assumption is required for this structural fact. For receive chronology, the caller supplies the prefix immediately before the actual receive/opening and attaches its literal suffix `Path` using the existing `prefix_path` theorem. Thus the selected cut belongs to the same execution and lies before that receive. The module deliberately does not assume a ciphertext/parser constructor is injective, or assert equality of a received sequence with the selected material’s position.
