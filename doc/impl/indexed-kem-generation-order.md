# Complete indexed KEM reservation

`PqxdhLiveKemReservation.complete` proves the full generation-order comparison required before selecting an actual KEM creation ordinal. On the left, the original indexed service generates a private pair only when the source create operation occurs. On the right, a private interpreter first reserves at most the declared number of pairs using the identical fully interpreted KEM generator and supplies them in source creation order. Every future pair remains outside the source state until its own create request. Missing-handle queries still reject; decapsulation and reveals use only actually created source slots. The reservation is neither a public input nor a private state field given to the executable client.

The equality is between complete evaluated executions of any bounded adaptive program over the existing joint-identity/uniform/KEM interface. It includes the entire final client result, both private services, every actually created pair and both observation histories. Joint generation, correlated sign/DH services, local source coins, decapsulation and both service reveal operations retain their original behavior and order. The proof commutes a private future sampler only across a noncreation operation that cannot inspect it, and quantifies over the full continuation. It proves more than equality of marginal public-key distributions. Distinct public or shared-secret bytes are never assumed.

`source_create` and `reserved_create` establish the literal source append and reply. `noncreate_equal` and `noncreate_keys` preserve the actual private prefix while allowing replies, joint state and histories to change. `unused` integrates unused lossless samples out only under complete evaluated equality; it makes no runtime claim. `reservation_uniform` charges qKeygen times qCreate uniform requests for the private reserved prefix, including unused pairs, when qKeygen bounds the complete interpreted actual generator. The source creation bound is a separate logical query class. All later joint/prekey/local/decapsulation costs stay in the unchanged complete service execution; this module neither bounds that entire program by the reservation cost nor declares its work free. The reserved interpreter retains a source-sampling fallback on exhaustion; the bounded correspondence's induction consumes a nonempty reserved suffix on each creation and does not use that fallback.

This is an operational generation-order bridge, not the selected-key IND-CCA reduction. The next consumer must place an ordinary challenge public key at the selected creation slot, keep its secret exclusively inside the CCA interpreter, simulate permitted pre/post decapsulation, derive an actually available private history, and stop precisely at prohibited selected reveals according to the original target freshness. It must also prove native retained-field reveal routing and pay explicit selection factors. Actual source owner allocation and native callbacks remain the published indexed-ownership consumers. A retained proof-analysis table does not authorize disclosure of erased native fields. No primitive implementation, snapshot or persistence proof is introduced.

# Selecting the actual KEM creation ordinal

`PqxdhLiveKemSelection.source_target_first` consumes the complete on-demand/reserved comparison. It moves the exact selected future KEM pair draw to the front of the actual bounded joint/uniform/KEM service execution, retaining the full subsequent distribution. The selected index is an ordinal in the private future creation sequence, not a public-key byte comparison or an assumed honest accepted-network target. Every other pair is sampled in original index order and reinserted around that ordinal. The original already-created key prefix, full client result, complete joint/KEM states and both histories remain part of the equality. A selected ordinal that is never created stays private and unused.

`family_list` equates the list and finite-index reservation representations. `target_first` proves the ordering law for an arbitrary full evaluated continuation, not just a keypair marginal. `selected_index` identifies the actual selected source slot as the length of the prior created prefix plus the selected future ordinal. `other_index` retains the exact corresponding source slot of each unselected pair after that insertion. No injectivity of public keys, private keys or shared-secret bytes is assumed.

`family_uniform` charges qKeygen times count for all locally generated unselected pairs, using the complete actual interpreted KEM generator allowance. `selected_uniform` keeps the selected generator's additional qKeygen charge, for total qKeygen + qKeygen*count. The selected generator belongs to the ordinary challenger's bill in the later reduction; moving it does not remove its cost. All source joint/local/decapsulation and continuation work remains unchanged and separately charged. These statements neither give the whole execution this sampler-only budget nor introduce free ambient work.

This is the exact generator-order interface for a fixed selected creation ordinal. It does not yet derive an adaptive target-selection loss or prove that an arbitrary accepted candidate uses that key. The all-candidate source partition, selected-secret-free CCA router, concrete private-history construction, permitted pre/post decapsulation and exact prohibited-reveal stop must consume it. The chosen private pair occurs only in the mathematical interpreter side here; the next executable reduction must expose only its public key and keep the secret inside the CCA challenger. Native erased fields remain unavailable through production reveals regardless of proof-analysis state. No new security assumption, primitive implementation, snapshot or persistence model is added.
