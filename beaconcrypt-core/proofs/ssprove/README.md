# SSProve computational game suite

This directory contains repository-owned finite game proofs for the modified CTX transform and a bounded ideal model of beaconcrypt's PQXDH plus symmetric-ratchet protocol.

`ProtocolLabels.v` centralizes the exact production KDF labels, proves that `PQXDH_INFO` is the 46-byte string `BeaconcryptPqxdh_CURVE25519_SHA-512_ML-KEM-768` and `SYM_RATCHET_INFO` is the distinct 41-byte string `SymRatchet_HKDF_SHA-512_CHACHA20_POLY1305`, and ties the finite Boolean ROM tag to those exact strings. It also records the 32/64/76-byte KDF uses and proves that initial ratchet expansion and per-record steps deliberately share the symmetric domain. The closed game passes those typed uses to its KDF calls, and the attacker-facing ROM query constructors use the common tag. The module does not prove a contextual equivalence to a byte-string-indexed oracle or equality to the extracted Rust arrays; those bridges remain open.

`BoundedRom.v` defines a fuel-bounded adaptive classical random-oracle query tree whose complete finite function table remains hidden from the program and observation. It proves query-count, trace-consistency, same-run event-inclusion, and extractor-reduction rules.

`CtxEventReduction.v` retains the original generic same-execution event-inclusion theorem. `CtxGame.v` strengthens it to an executable hidden-ROM binding game: an arbitrary deterministic adversary receives a bounded oracle interface, returns one payload with two candidate explanations, and a two-query verifier checks both commitments. A successful distinct double opening yields an explicit unequal-input, equal-output collision witness without assuming AEAD key commitment or AEAD security. The checked reduction has at most the adversary's query budget plus two verifier queries; it does not prove a numerical collision bound for BLAKE2b-512.

`CtxPrivacy.v` gives the separate ROM-programming hop needed because the CTX digest hashes the secret record key as data. Over one jointly uniform hidden key, table, and digest source, `ctx_hidden_uniform_key_true_real_privacy_bound` proves that the absolute true-real versus fresh-ideal decision-probability gap is at most the probability that the ideal trace queries the hidden secret transcript. The proof uses direct finite-source reindexing and carries no admitted marginal-probability interchange dependency. This is a leakage-preservation hop conditional on ideal AEAD confidentiality, not a complete transformed-AEAD theorem, a numerical production-width bound, or a QROM result.

`PqxdhRatchetGames.v` models one PQXDH establishment followed by one abstract ideal symmetric-ratchet record at fixed sequence zero. It selects the second initial half, so this record is not the production registration response, which steps the server's first half at sequence one. The model preserves the production root-input order of four DH contributions followed by the ML-KEM contribution, treats the Ed25519 seed and converted X25519 identity as jointly compromised, and models the shared initial/step symmetric HKDF label with the required 64/76-byte prefix consistency. The active-classical theorem quantifies over explicit forward and replacement actions; ideal authentication makes tampering under the fixed intended verification key a challenge-independent failure. A self-consistent attacker-owned identity and signed bundle is outside that replacement action and remains acceptable in production because the advertised identity key is unsigned. The forward-only passive-classical and passive-quantum classical-query capability games also have zero distinguishing advantage. The expected active-quantum replacement has advantage one, with the attacker recomputing the record pad from the exact authenticated fixed substituted root input that represents an attacker-selected ML-KEM secret.

`StateSeparatedComposition.v` implements the first single-run state-separating slice. A private two-slot CKEY package accepts one role- and session-checked `PUT`, permits one destructive `TAKE`, replaces the payload with a cleared tombstone, and rejects overwrite, retake, cross-role, and cross-session use in the pure model. The keying and keyed packages are linked as siblings around that private provider, and the public package hides CKEY, setup, seal, open, raw chain payloads, the finite ROM tape, and the opened plaintext. Its exported `RUN` operation takes only `unit`, samples the complete eight-bit tape internally through one joint uniform operation, and returns `Some ciphertext` for the modeled honest response or `None` for rejected provenance. A challenge-indexed game pair and direct uniform-sample pushforward use that optional-ciphertext view. Closed capstones prove server chains `(L,R)`, beacon chains `(R,L)`, authenticated use of the shared left half for the production sequence-one response, explicit and challenge-independent false-provenance rejection, exact root/initial/step KDF labels and 32/64/76-byte requests, a single-run pointwise public-view equality with the monolithic calculation, and scenario facts for replay consumption before construction, failed construction, dropped-response asymmetry, successful counters, and terminal abort of a pending beacon without assuming server publication. The record operation is a one-bit XOR key-correctness harness: nonce, associated data, AEAD, CTX, identifier checks, and outer serialization are not composed into it. The lifecycle records are scenario snapshots, not reachability from the executable package.

`StateSeparatedPackageSemantics.v` adds a proof-carrying semantics certificate for exactly one call to that linked public `RUN` operation from the canonical empty heap. A restricted evaluator supplies one caller-indexed value to the operation's sole joint finite sampler and otherwise executes SSProve's actual raw code and heap reads and writes. Local checked bridges identify staged proof-erased raw projections with the computational fields of the exact linked package, and the certificate equates the evaluator's full optional observation-and-final-heap result with a concrete normal form. The authenticated certificate contains the same `Some ciphertext` public observation as the direct state-separated calculation and the complete `both_consumed_heap`; the false-provenance certificate returns `None` before sampling or core execution and retains the complete canonical empty heap. The reportable capstones then summarize those heaps to show both private CKEY slots `Taken` after authentication and both `Empty` after rejection. After discarding the private heap, the certified public observation agrees pointwise with the direct observation, and its uniform finite-source view probability and distinguishing advantage equal the existing direct view and advantage for every deterministic predicate. Because the evaluator executes the same keying and keyed bodies, it preserves the exact distinct PQXDH-root label, the shared initialization/step symmetric label, and the 32/64/76-byte uses checked by `ProtocolLabels.v` and `StateSeparatedComposition.v`; it adds no role, direction, sequence, or initialization-versus-step KDF tag.

`StateSeparatedIndexedSessions.v` gives the linked seam bounded repeated-call semantics over two Boolean session handles. Four private CKEY slots separate the two role pairs, while one outer cache stores the single complete finite ROM sample drawn by the first fresh authenticated handle; the other fresh handle reuses that sample without consuming another value, so equal root or symmetric queries cannot receive inconsistent answers across handles. Its stream evaluator and stateful reference agree on the first fresh call, a fresh call through the opposite handle, rejected authentication, and same-handle reuse, including exact optional observations, private heaps, and residual sample streams. The adaptive capstone lets a deterministic context select its second handle from the first public observation and proves equality with the reference experiment for every initial handle and sample stream. The handles are ghost routing indices for private slots and per-handle static parameters: they are not added to PQXDH root input, the shared symmetric input, direction, sequence, or any KDF domain label, so the linked bodies retain the exact distinct `PQXDH_INFO` domain, shared initialization/step `SYM_RATCHET_INFO` domain, and 32/64/76-byte uses.

These modules are not an unrestricted contextual or computational composition theorem. The indexed result closes the specific second-call mismatch by comparing the two-handle consuming package with a stateful two-handle reference under the one-global-sample finite abstraction; it does not turn the original one-shot package into a stateless repeated service or instantiate the state-separation paper's repeatable `GET`/`HON` CKEY. Handle reuse is a proof-side lifecycle event, not a theorem about production registration replay, replay identifiers, fork/rollback behavior, or an active registration, replacement, drop, delivery, reveal, or corruption interface. The accepted PQXDH inputs and provenance bits remain parameters rather than an intended-peer agreement theorem, and the two-bucket Boolean ROM abstraction still collapses arbitrary non-substituted inputs to its honest entry. Pinned SSProve 0.2.4 still makes generic package/raw-syntax contextual reporting traverse the repository-rejected infinite-sum interchange dependency, so stock `Pr`, `Pr_op`, package-validity, interchange, and unrestricted contextual-advantage paths remain outside the accepted boundary. Arbitrary multi-user sessions, the production-left-half confidentiality reduction, four-corner advantage bound, authenticity proof, production-width record interface, and extraction correspondence remain open.

`PqxdhRatchetRom.v` strengthens the three positive cases with a bounded adaptive classical-ROM interface. The four classical DH coordinates are fixed and guessable while the honest ML-KEM contribution and complete tagged root/symmetric table remain hidden. Every deterministic adversary receives the challenge ciphertext and makes at most `q` adaptive root or ratchet queries. `pqxdh_ratchet_bounded_rom_confidentiality_bound` reduces its distinguishing advantage to the probability that its trace queries the exact hidden ratchet-pad input. Active-classical forwarding, passive-classical forwarding, and passive-quantum classical-query forwarding inherit that bound; active-classical replacement remains an exact challenge-independent failure. A restricted scenario type proves the accepted root stays hidden and makes active-quantum replacement unrepresentable in this positive wrapper. The result supplies no numerical production-width bad-query estimate; because the abstract symmetric domain has two inputs, a two-query program can make the bad event certain.

`PqxdhHybridSecurity.v` isolates a hybrid-combiner hop. Any one of the ordered four DH contributions or the final ML-KEM contribution may be uniformly hidden while the other four are public. For every bounded adaptive classical-ROM program, `pqxdh_hybrid_one_hidden_contribution_confidentiality` bounds the advantage for a one-bit payload masked by the ideal root output by the probability of querying the modeled five-coordinate input containing that hidden contribution. Capability corollaries use the honest ML-KEM contribution for active-classical, passive-classical, and passive-quantum forwarding, while explicit lemmas record that passive quantum exposes all classical coordinates and active-quantum replacement leaves no hidden hybrid component. The model preserves contribution order and now uses `ProtocolLabels.v`'s proved-injective encoding of the exact production info strings, but it still collapses fixed padding and HKDF Extract/Expand into one ideal lookup; it adds no session tag and is not an extraction-linked KDF-output pseudorandomness theorem.

`RatchetForwardSecrecy.v` gives a one-step post-erasure game. The adversary receives the compromised next chain, prior challenge ciphertext, prior nonce, and bounded classical-ROM access, but not the erased predecessor chain or message key. A table involution flips only the erased step's message-key slot while preserving its next-chain and nonce slots. `ratchet_erasure_forward_secrecy_bad_query_bound` bounds challenge advantage by the probability of querying the exact erased predecessor-chain input, and the trace contains at most the supplied fuel. Its finite domain tag now comes from `ProtocolLabels.v`, separates only the genuinely distinct root and symmetric labels, and intentionally does not distinguish initial from per-record symmetric expansion. This is an erasure-conditioned one-step theorem with no session, direction, sequence, multi-step, or implementation-erasure proof.

`RecordIntegrity.v` assumes one ideal random-function authenticator for the combined acceptance behavior of a direction-specific AEAD key and the CTX commitment check; it does not prove that those two mechanisms compose. Its context includes the direction selector, associated data, CTX sender identifier, nonce, and sequence, without attributing sender or sequence binding to the AEAD tag alone. Active modifications are exactly partitioned into prior exact authenticator queries and fresh candidates, and the fresh-input/fresh-guess predicates are definitionally identical. Reuse of the same protected payload under a distinct context or sequence extracts a same-run unequal-input/equal-output table witness. The file models one honest record and one candidate; identical-context replay, a standalone collision game, and a general verification oracle are outside it.

`RecordIntegrityBound.v` strengthens the fresh branch for the uniformly sampled one-bit ideal authenticator. It evaluates the exact existing bounded verifier runner and uses a table-dependent involution at the completed candidate's unqueried input. The honest tag and adaptive adversary trace remain unchanged, acceptance toggles, and `record_uniform_one_bit_fresh_tag_guess_bound` proves probability at most `1 / 2`. The capstone is stated directly over uniform tables rather than through a checked distribution-level equality to `record_uniform_hidden_integrity_game`; it is not a production tag-width bound and does not discharge the assumed AEAD+CTX composition.

The protocol results remain finite ideal-game milestones. The original confidentiality games are single-session and one-record, the forward-or-replace action is selected statically outside the challenge game, and the ROM observer sees no actual registration-transcript API beyond hard-codeable fixed DH atoms and the challenge ciphertext. The state-separated modules now provide the one-way CKEY/lifecycle slice, its exact finite one-call certificate, and a bounded two-handle adaptive-context equality against a stateful reference with one globally cached sample. The [composition investigation](../../../doc/impl/ssprove-end-to-end-composition.md) records those milestones and specifies the remaining common experiment, exact shared-label HKDF contract, state-separating hybrid, and implementation phases. The suite does not yet prove an end-to-end computational bound or cover arbitrary multi-user sessions, general ratchet schedules, adaptive corruption, superposition queries, QPT adversaries, or composition of every hop with the extracted implementation. Those extensions require separate games and production-width bad-query or primitive-reduction bounds.

Implementation correctness remains outside these files. The handwritten finite games mirror the shapes of the named production operations `build_root_key_input`, `split_initial_ratchet_kdf_output`, `split_ratchet_kdf_output`, and the fixed CTX transcript; a reviewed representation bridge to the Lean/F* extraction boundary remains open. Direct hax-to-SSProve imports remain disabled because the pinned hax Hacspec aggregate transitively exposes a proof of `False` and the selected array extraction is incomplete. Importing that boundary would invalidate the proof.

Run `make verify` in this directory to enter the repository's locked Nix proof environment, compile every module under Rocq 9.0.0 and SSProve 0.2.4, exact-check each assumption report, and run `coqchk`. Compiled output is written only below `target/formal-verification/ssprove/`.
