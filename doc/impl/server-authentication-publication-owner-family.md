# Publication observations at the actual owner coordinate

`PqxdhServerAuthPublicationOwnerFamily` supplies eight statements for a family `observers : Fin (Q + 1) → Observer`. Each observer receives the same root-erased ghost and chronological public API query/reply journal as the reviewed observed-schedule interface. The actual source owner chooses which observer is tested. This permits a later publication predicate to require a successful build by that exact session; a different session with matching fields cannot substitute for it.

## Source event and partition

`Accepted` requires an actual acceptance and requires `observers j` whenever the existing source `entryOwner` is `some j`. If there is no owner, the second condition is vacuous: the accepted run remains in the event and must be charged by the original source bad-event partition. `accepted_cases` derives that partition from actual source support and the existing all-attempt accept bound. No owner-existence or source-origin premise is added.

`accepted_probability`, `accepted_decomposition` and `accepted_decomposition_real` retain the original disclosure and distinct-Server collision games with coefficient one, followed by the same finite sum over `Fin (Q + 1)`. Only the two charged bad branches discard the observation condition. Finiteness of all probabilities and the owner sum is established before conversion to real numbers.

`accepted_bound` applies the existing fixed-coordinate observed-schedule transport separately to `observers j`:

```text
Pr[accepted observation at the actual owner]
  ≤ Adv[original joint Gap-DH extractor]
    + choose(Q, 2) · 64 / 2^256
    + Σ j : Fin(Q+1),
        (Pr[uniform observed endpoint with observers j]
         + five newly constructed schedule losses for observers j).
```

The five distinguishers are constructed from the observer at that same coordinate. The proof does not reuse the old W1/W2 distinguishers for a changed event and does not add a raw-attempt selection factor. `Q` still counts all accept attempts, including rejections. The existing X25519 class/spread and source Extract/Expand wiring contracts remain unchanged.

## Native execution and resource ledger

`observation` is a mathematical source projection that uses the original seed/scalar only to evaluate the existing owner function. Those values are not new arguments of any primitive `Observer`; each member retains the root-erased ghost/API-journal interface. Arbitrary correlations, known byte aliases and values already present in actual replies remain allowed.

`ordered_source` identifies this event with the complete production-order native execution by the existing full-continuation source correspondence. `observed_bills` supplies the exact unchanged disclosure extractor and the new coordinate-specific schedule reductions. `ordered_bound_with_resources` combines that source equality, probability bound and complete ledger. The shared allowance is the existing `entryReductionBudget caps qCoin Q qHash qH`, including context sampling, KEM/base costs and original adversary work. The underlying HMAC challenge caps remain 1/1/2 and the real/random challenger draws remain those documented in the [observed partition guide](server-authentication-observed-partition.md). These are oracle ledgers, not zero-runtime claims for journal or predicate evaluation.
