# Native source execution with retained private audit

`RawCtxSelectedFamilySourceAudit` consumes the concrete family audit in the original native record/public API. `native_step` instantiates `RawCtxSelectedMessageFamily.frontend_source` with the actual private table and public services, then applies the checked source callback interpretation and audit erasure. `native_schedule` follows every adaptive source reply and complete reached role family. Their equalities keep all private auxiliary state and shared commitment-cache effects inside the same native interpreter. They neither replace public HKDF by a random table nor assume that arbitrary secret-reading native clients have a selected-key-free simulation.

The `observed` execution retains the actual private owner/derivation/seal event list using the existing optional audit interpreter. Its source callbacks use `lifted`, which wraps each complete native reply in an outer success without changing the native reply itself. `lifted_program` checks that this wrapping remains exact through the entire original service program. Native parser rejection, failed commitment or opening, and failed writer outcomes therefore keep their original inner option. They are not confused with an outer selected-nonce stop.

`observed_native` reconstructs the complete native result and role family from that retained audit execution, preserving the same primitive poststate. Only private owner annotations and the audit list are removed by the source projection; the audited computation itself keeps them. The statement starts from an explicit supplied correlated family and source state and covers the original record/public request interface. The native interpreter alone receives the selected message key. That parameter is absent from the executable audited frontend.

`observed_uniform` proves equality of the original and audited uniform-query allowances for every bound. It uses equality of the full oracle programs and result maps, so no callback work or rejected path disappears. This is not a primitive running-time assertion: list appends and bookkeeping still have their ordinary computation costs, and existing source/component ledgers retain the separate lookup, hash and primitive operation counts.

The five guarded statements add no security loss or cryptographic assumption. They supply the actual native execution needed for later source-event attribution; they do not prove that a route label is a unique installation, that the supplied catalogue was dynamically constructed, or that a repeated selected nonce is improbable. Live key reveals, attempted registrations, installation ancestry, stopped CTX comparison and the global computational-symbolic event map remain separate consumers. Primitive implementations, snapshots, persistence and restoration are outside scope.
