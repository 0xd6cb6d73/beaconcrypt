This implication is used only to prove a safety invariant of each projection, not to select separate contexts for the equivalence conclusion. The executable response-list search below remains the same public program in both projections.

Therefore taking the first matching occurrence is sound even if there are several identical responses. This uses an explicit symbolic constructor idealization, not generic IND-CCA/PRF or a computational collision theorem. It needs no inference from equal roots to equal KEM key-generation indices.

## Remaining proof boundary

The selected component has replicated arbitrary registration accepts/builds and arbitrary public scheduling within the stated serial host and near limits; it does not assume that every accepted candidate or selected KEM key is honest. It retains the exact source order and the protocol's Ed25519/X25519 related use at T0. This proof does not justify T0 constructor injectivity, fixed-HKDF ideal equations, cross-key ML-KEM uniqueness, related-key signatures/DH or a programmable hash model from ordinary primitive security. The computational experiment must discharge the required ideal interfaces with its explicit contracts and reductions.

There is no constant global primitive query budget here. The selected identity publishes its source-ordered three signatures, each retained worker has at most two send allocations and three receive attempts, and registrations remain replicated. Every omitted call, locally generated object, public recipe evaluation, context lookup and retained callback must be charged by the global computational source/reduction accounting. Identity/session/record selection, reveal/compromise profiles and arbitrary later evolving records remain separate. The two directions are separately proved selected components; no loss-free global composition between them is inferred.

The private application assumption is a deployment/experiment boundary for this theorem, not a patch to the public receive API. A caller who publishes an accepted challenge plaintext trivially distinguishes chosen alternatives. A public optional-plaintext confidentiality theorem instead needs the separately specified target-opening/release freshness policy, including cache and replay aliases. Snapshot/persistence behavior remains excluded, codec internals stay external under the existing abstract-message contract, and no primitive implementation proof is attempted.
