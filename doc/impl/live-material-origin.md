## Service and aliases

A public creation request installs a fresh secret symbolic key with a fresh public handle and endpoint. A public alias request installs another handle and endpoint for exactly the same existing key. Arbitrary public key values can also be imported. Import records `PS1PrimitiveReveal(key)` before installing the endpoint, so an imported value is classified as already known even if no separate reveal request occurs. The event therefore means prior actual-key knowledge at this interface, including explicit public import; it does not mean only a native compromise operation.

Each installed endpoint serves arbitrarily many seal, open and reveal requests. Nonce, associated data, sequence, sender, plaintext and raw input remain supplied by the requester; the service uses the existing `seal_frame` and `open_frame` definitions. A successful open records its actual plaintext and original symbolic frame before publicly returning `ps1_primitive_open_some(endpoint, original_request, plaintext)`. The plaintext is exactly the value returned by the actual `open_frame` destructor, never a separately chosen or substituted value. A failed destructor produces no successful-opening event and publicly returns `ps1_primitive_open_none(endpoint, original_request)`. Both tagged replies retain the endpoint and complete original request term, including nonce, AD, sequence, sender and frame, so each service-produced reply identifies its original request. These explicit optional replies still do not establish a native API/public-observation or source scheduling equivalence.

The private handle table retains live interface state. It is not a storage, snapshot or restoration service. Aliases reuse the actual key term, and imported public terms remain public. Fresh creation still uses the ideal theory's fresh symbolic names: this experiment does not prove a native finite-byte sampler correspondence, eliminate key collisions, or replace the source HKDF with fresh independent outputs. The explicit alias route prevents a distinct-endpoint-implies-distinct-key inference, but it supplies no computational collision probability by itself.
