## Smallest concrete abstraction

Define the relation between one reached source owner/kernel and its symbolic token: owner and role, configured peer/routing identifier, associated data, both counters/chains, exact active skipped-key entries in the existing newest-first representation, plus separate ghost session/publication and actual reveal history. No session or honest origin is inferred from equal key bytes.

The first useful checked consumer is the **complete one-raw-receive step from an arbitrary related valid committed kernel**. It must cover decoded-field validation and sender/AD routing, old-missing/replay rejection, cached lookup/last-slot removal, future derivation with `cacheLen + (target-counter-1) ≤ 50`, capacity/zero rejection, actual optional plaintext, and exact rollback on commitment/open failure. Failed native state publication must still retain actual primitive effects. Existing `RawCtxReceive.rawReceive_*`, `RawCtxOwnerProvenance.raw_success`, `RawCtxServerRouting.rawGame_cases/rawGame_failure_server/rawGame_success`, and `RawCtxBeaconLifecycle.source_step` supply those source boundaries. Then add send (including chain advancement on failed seal/writer), non-consuming live reads, U64 exhaustion, and lift the relation through the existing schedule interpreter. The relative future offset has a finite 1–51 bound per request; the number and ordering of requests is unrestricted. A generated relative-offset family needs this trace argument, not a claim that selected examples cover all schedules.

## Private state and the fourteen main queries

The newer `registration-beacon-admission.pvl:138` uses a private state token and replicated public requests; all failure branches reinstall the actual aborted/closed token. `registration-set-admission.pvl:84` uses a private mutex and per-owner consumed state; its origin lookup at line 77 runs only as a parallel observer after the actual reply, never as an admission guard. These are better reusable patterns than `environment.pvl:453`'s one-honest-bundle replay guard and `environment.pvl:875/1182`'s honest/malicious-origin dispatch. Keep mutable live kernels in consumed/reissued tokens, not append-only historical tables that can resurrect an older state. Private tokens preserve source ownership in process semantics, but do not by themselves prove Horn-level linearity or injective correspondences: the existing Beacon `ClosedRejected` history query remains explicitly unknown.

There is **no justification yet that replacing the main process preserves all fourteen results**. Preserve `queries.pvl` and the existing fourteen-query gate as regression fixtures; add the generalized process and prove its own results. To retain the same honest-origin event scope without an authorization guard, perform origin labelling as non-blocking observation, while unknown/attacker-owned identities execute the same actual protocol operations. A trace/event correspondence must show the original registration and record witnesses; merely suppressing events on hostile sessions is not a protocol proof. Claimed/assigned IDs and the eleven-field cryptographic-session projection remain distinct; no later assigned-ID equality may be added.

The first five main queries are unconditional secrecy of named messages in the no-compromise fixture; the record correspondence is also uncompromised in scope. Giving that same process unrestricted current-chain/skipped-key reveals can reveal those records and enable later authentic-looking records. Thus preserve the old no-reveal gate and state fresh-target/reveal-scoped properties separately for the extended experiment; do not silently retain its old conclusions. Returned local plaintext is an API observation, not automatically public network output. Byte parsing, constructor distinctions, joint primitive/ROM contracts and the shared dynamic registration process remain explicit boundaries. This map adds no snapshot or persistence semantics and does not duplicate the joint scheduler lane.
