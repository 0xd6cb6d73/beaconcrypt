# Exact far material for the bounded receive projection — review draft

This draft addresses L3's specific `fs_far_chain` gap. It changes no maintained model and makes no new source-security claim before review. The two scratch C4 probes use the existing T0 theory, unchanged registration/finish/send code and unchanged C4 formulas, with an exact finite family of repeated HKDF terms replacing the uninterpreted far constructor. Each has one later receive attempt, chosen record plaintexts and failure-interleaving continuation. The b2s probe is AnyPin; the s2b probe retains its existing honest-pin scope. Both gave their exact TRUE result under a 180-second/10-GiB cap. Their parsed inputs, logs, limits and times are recorded separately. Initial declaration-syntax failures are retained as diagnostics.

The proposed result is a claim-specific symbolic projection. It does not equate arbitrary public HKDF outputs to a table or assert that `fs_far_chain(a,t)` equals an iterated HKDF term. It does not prove E19, many-peer ID translation, arbitrary API replies or global computational composition. Those interfaces must be handled separately. Primitive implementation correctness, the T0 idealizations and the abstract decoded-message contract remain the same.

## Exact reached-state and material facts

Let `T` be the highest materialized receive position: 2 for b2s and 3 for s2b. Stop a direction at its first accepted receive with target greater than `T`, as required by the existing bounded deliverable. At every earlier receive entry, `r <= T`, because registration starts b2s receive at 0 and s2b receive at 1, a successful near receive installs its actual target no greater than `T`, a successful cached receive leaves `r` fixed, and a refused receive restores the entry state. The existing source refinement retains the cache set, exact materials and current chain; no cache uniqueness or rollback property is assumed merely from the model flags.

The checked extracted control theorem `beaconcrypt_core.ratchet.control.plan_receive_until_bound` proves that an admitted future target has at most 51 derivations and satisfies `cache_len + (derivations - 1) <= 50`, with `r + derivations = target`. Thus every admitted first far target is in the finite range `T+1 .. T+51`: 3..53 for b2s and 4..54 for s2b. Values above that bound are source admission rejections, before commitment or opening. The bound is an upper envelope across all reached caches, not the exact admission condition for each cache. No wraparound occurs at these small indices.

Write `N(x) = hkdf_second_32(hkdf_sha512_no_salt(x,symmetric_ratchet_domain()))`. With the original directional chain `c`, the chain at sequence `t` is `N^(t-1)(c)`, and its material is the exact original `ratchet_material` of that chain, retaining the first32/final12 projections of the same expansion. The model's existing `far_anchor` is literally `N^T(c)`. For any admitted far target, the chain is therefore `N^(t-(T+1))(far_anchor)`. This is the ordinary iteration identity, instantiated by the already checked source `Ratchet.msgKeyAt_chainAt`, current-chain relation and future-open `material_exact` theorem. It is not a primitive pseudorandomness premise. In particular, at the first far target the chain is the anchor itself: no extra step is inserted.

The probe implements this exact expression for every one of the 51 target values as a public deterministic destructor family. Each right-hand side contains only the actual public HKDF/projection constructors. The family is a finite executable notation for these existing public recipes; it grants no inverse, secret value or new cryptographic oracle. A maintenance generator must check every case, the zero-step anchor case, both endpoint values and absence of any other successful branch. This applies equally to secret and attacker-known anchors. Public known-root computations remain actual nested HKDF terms.

## Exact-material comparison process

Define an expanded receive process by using those expressions for first far targets and the existing materialized near paths. Its public initial registration and record outputs, adversary inputs, event parameters and literal root/identity/ID/AD terms remain unchanged. Keep actual source capacity rejection as a silent entry-state-preserving transition. Before the first far success its state relation is the existing cache-set/chain refinement: near and cached successful operations keep exact target material; refusals restore the same kernel; first far admitted opening uses the expression above. A far success ends the projected direction and emits its exact `FsFarAccepted` fields. No claim describes later operations in that direction.

For the C4 comparison alone, it is safe to broaden admission to every target in the finite range regardless of `r` and cache length. A refused source operation may be left unscheduled in the comparing process; its hidden reply contributes no attacker term and it has no queried event. Every actual far success is still admitted, uses the same material and produces the same event. This is a violation-preserving schedule map, not equality of admission, reply, state or primitive-call traces. Values outside the finite range need not be accepted in the comparison. A maintained fail-stop variant must distinguish a silent admission rejection, which continues, from an admitted failed open, whose model continuation may stop; the current probe is failure-interleaving, where both simply continue.

## Why one later receive attempt suffices for C4

Take a finite expanded trace violating the exact C4 query, through a selected first far acceptance. Keep every registration, initial Beacon finish, honest record allocation/output and attacker input to those operations in the same order, with the same names and terms. Remove all later receive steps of every receive worker except the selected far acceptance, and leave unused workers unscheduled. Initial finish is retained; it is not a later receive step for this construction.

In the existing direction-split processes, later receives output no value and allocate no fresh name. Their only effects are receive-local state and ghost events. No sender, registration operation or other receiver reads those receive fields. Thus deleting these steps loses no attacker knowledge or public honest output, changes no remaining send input/material, and changes no initial finish. This is checked from the exact worker definitions, not inferred from the label “receive.” Arbitrary copied or nested public terms remain the same terms; there is no recipe substitution or key renaming.

The selected raw frame remains attacker-derivable. Its target exceeds `T` and hence the untouched initial receive counter. The comparison's broadened finite admission accepts it. Its root, AD, assigned ID and far anchor are fixed by the unchanged registration/finish and do not depend on previous later receive operations. Consequently its exact key/nonce, cipher/tag/commitment validation and plaintext are identical, and it emits the same selected far event at the one receive slot. In b2s, the query's `attacker(k)` condition has exactly the same truth value because the attacker knowledge closure is unchanged, including compound candidate terms. In s2b the forbidden far-event occurrence itself is preserved. Neither query observes the deleted near/rejection events or receive-input labels, and no fairness rule forces an unscheduled worker to run.

This constructs a C4 violation in the exact-material one-attempt process from any violation in an arbitrary finite number of later receive attempts within this otherwise fixed bounded registration/send profile. It does not increase sends, relax target freshness or alter the pin scope. Conversely, the scratch TRUE C4 results, once maintained and reviewed with this construction, rule out the corresponding expanded-profile far violations: s2b has no far acceptance, and b2s far acceptance implies the exact stated identity-key knowledge condition. They do not by themselves prove any computational probability bound or broader source profile.

## Transfer of the other bounded record claims

For a formula observing only non-far events and attacker knowledge, compare a finite expanded trace with the original maintained fs process. Delete each later receive attempt whose target exceeds `T`. Before the first far success, every deleted operation was refused and preserved the entry state; it emitted no non-far event and output no term. If a first far success occurs, delete that step too and leave this receive worker unscheduled thereafter. The projected trace already ends that direction at its first far acceptance, so there is no later retained receive state to reconstruct. Other workers and all honest sends remain scheduled as before.

Reindex the remaining receive macro instances within each worker. There are at most the original number, and their complete entry fields are the same because only entry-preserving failures preceded them. Every retained near/cache input, test, opening and poststate therefore executes identically in the original fs process with the same near-path continuation profile. This step does not change failure-interleaving into fail-stop: transferring chosen C2 to its maintained fail-stop instance additionally uses the independently reviewed E21 failure-deletion argument and its exact hidden-reply query scope. The literal-family helper is a conservative definitional recipe extension of T0: before carrying an attacker recipe into the original process, replace each successful helper application at a permitted numeral by its exact nested public HKDF expression. Evaluation of that recipe yields the identical ground message value; failed private attacker computations send nothing and need no trace step. This local syntax normalization changes no ground input, equality test or attacker knowledge, and does not map any real key to an artificial constructor. No original far branch is executed by the constructed trace. Its artificial `fs_far_chain` value never needs a corresponding source key. All honest public outputs and attacker knowledge remain exactly equal, every observed non-far event retains its field tuple and occurrence multiplicity, and event order and equality of occurrence times among retained events are preserved. A source mismatch or missing injective match cannot acquire a matching event merely by deleting unobserved far steps.

This transfers the exact query formulas that do not mention `FsFarAccepted`, failed far-input consumption or later receive replies, with their existing send/receive bounds and pin scopes. It includes the existing C1/C2/C3 non-far correspondences and the existing weak secrecy/event formulas whose referenced events are retained. It does not transfer C4 (handled separately above), the FAR reachability witness, a strong-secrecy equivalence, an API rejection-bit test, a returned-plaintext test or a formula mentioning deleted event times. The maintained TRUE/FALSE classifications must remain separate; an unexecuted branch in this comparison does not turn a witness or definition into a security result.

A finite source trace maps first to the expanded process only under the stated local ratchet relation and the other pending source-profile obligations. This argument closes the far-material part of that decomposition; it does not supply the missing L1/L2/E19/global relation by itself. The comparison preserves every public HKDF expression actually used in a retained operation. All skipped derivations, commitment checks, opens, rejected attempts, cached effects and optional replies still belong to the computational source experiment and its query accounting. Their absence from this particular hidden-reply symbolic projection never makes that work free.

Independent review must check the full finite-family generator, actual source material/capacity references, receive output/state footprint, both exact C4 profiles, the query-by-query admissible event projection and negative controls. At least a public-far-key control must demonstrate that C4 detects a broken material boundary, and an attacker-owned b2s witness must show that literal far material is computable where permitted. The old 49 solver results and all their negative controls must remain unchanged. No source claim is based on a timeout, parse failure or a hand-picked far index.
