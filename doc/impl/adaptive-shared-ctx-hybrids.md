# Ordered CTX hybrids with one shared public cache

This milestone constructs the complete ordered integrity hybrid for an independently sampled finite family of CTX record keys. Each adjacent game runs the same original adaptive client, original key indices and public hash cache, and changes exactly one key from real CTX opening to the existing public-record replay simulation. The final finite sum is applied to these checked adjacent simulations. It does not idealize production evolving keys, establish their freshness under compromise, or complete the protocol's computational-symbolic bridge.

## The actual family experiment

There are K = N+1 original key indices. The source samples the entire function from indices to 32-byte keys, retains one public random-oracle cache and a separate local entry for each index, then interprets the original adaptive client. Queries carry their original index and either a caller uniform request, a public hash input, a sealing input or arbitrary raw receive bytes. Responses retain the actual dependent query type, including optional ciphertext and optional plaintext. The Boolean client result is the distinguishing event; private final state is retained for simulation proofs and is not an additional observation.

A real local entry performs the original fixed-key AEAD seal/open and public CTX hash operations. A replay entry retains its own consistent private suffix dictionary and the existing replay filter. A private dictionary hit reuses its previous digest; a miss samples 64 bytes. Raw parsing failure retains the actual rejection and attempt count. Reached private lookups happen before the replay reply, so failed or rejected attempts do not erase their primitive effects. Private input histories contain the existing key-free suffixes; actual real hash calls still use the full secret-key-prefixed input.

All public queries and all real-key private CTX queries use the same public cache, including queries made while simulating another key. Processed keys keep their private dictionaries across every later call. No key-value inequality or cross-key nonce inequality is assumed. Distinct indices may contain the same bytes. Per-index sealing retains the ordinary nonce-use gate and complete sealing log; source per-key nonce uniqueness, copied states and compromise are separate obligations when instantiating this family with evolving protocol keys.

Only then does `family_bound` apply `PqxdhComposition.finiteHybridBound_of_hop_bounds` to the same game family. There is no additional random target guess hidden in that sum.

For each original target j, let Cj be its constructed `clientReduction`, Vj its `validationReduction`, and Fj,i its `forgeryReduction` at raw-attempt index i. If hj, sj and rj bound its routed public hash queries, selected seals and selected raw attempts, and sj < 2^96, the bound is:

```text
Adv[all real CTX keys, all replay-filtered CTX keys]
  ≤ sum over j of (
      Adv[modified nonce-AEAD IND$, Vj]
      + hj / 2^128
      + 2 * sum over i < rj of Adv[modified nonce-AEAD INT-CTXT, Fj,i]
      + rj / 2^512).
```

`loss` spells out these exact ordinary advantages and statistical terms. Every adaptive raw attempt remains included, including malformed requests, failed commitment checks, failed openings, replays and multiple successful attempts. The constructed forger family uses challenger-produced optional plaintext through the existing receive wrapper; it does not insert a secretly recovered plaintext into an attacker-supplied target. The finite sum has K validation reductions and up to K times the global raw-attempt cap indexed integrity reductions, with coefficient two on the latter.

This milestone's family endpoint concerns integrity/replay simulation. The existing selected ciphertext-view reduction and its query bounds remain available, but an all-key ciphertext-randomization family is a further composition step. The final family bound here does not silently claim that additional privacy hop.

## Contracts and remaining protocol obligations

The ordinary modified nonce-AEAD INT-CTXT and IND$ endpoints, their exact key/nonce/message interfaces and the completed selected CTX proof remain the cryptographic contracts used here. The CTX hash interpretation uses the already explicit programmable classical random-oracle contract. It is stronger than BLAKE2b collision resistance. This milestone proves protocol-style oracle wiring, sampling order, full-state simulations and losses; it does not prove any primitive algorithm or implementation.

The keys in this experiment are sampled independently and remain hidden from the client. This does not yet prove the corresponding distribution of production 64/76-byte HKDF projections, repeated evolving chains or related source key material. Native material-label realization, both directional chains, copied/restored state, reveal freshness, dynamic sessions and identities, target-session/record selection, and the common ProVerif experiment still require their checked composition. In particular, current-chain compromise exposes descendants and supplies no post-compromise recovery. Public fixed HKDF evaluations remain real; this proof introduces no public-HKDF/random-table advantage or qRoot/2^256 production interpretation.

Compiler correctness, correct native primitives and checks, allocator/OS behavior, physical erasure and foreign-runtime copies remain external contracts. Persistence integrity, rollback resistance, linearizable CAS, crash behavior and ownership must be stated as deployment premises when connecting restored source states. An unkeyed snapshot digest does not provide those properties. No assigned-ID equality or global symbolic correspondence is inferred from this family result.
