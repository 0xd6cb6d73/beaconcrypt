# Symbolic fresh-name ordering in the record Server processes

The E20 argument concerns exactly `FsS2bServer` and `FsB2sServer` in the existing T0 symbolic record models. Each instance accepts one bundle. Its ephemeral secret and encapsulation coins are symbolic fresh names restricted before the bundle input. Moving these two restrictions to immediately before the first DH tuple preserves every finite observable trace, event occurrence and attacker deduction up to consistent renaming of the fresh pair. The complete subsequent process is retained, including acceptance, the delayed build input, root, response, publication events and record continuation.

This is a symbolic process argument, maintained by finite syntax checks and independent review. It is not a computational generator interchange theorem, a new primitive contract or a new solver result. The actual Rust program still samples in source order, including its actual rejection and failure paths; its computational interpreters must preserve and charge that work.

## Exact compared processes

Both macros first compute the same public Server identity. The early form then restricts `ephemeral_secret` followed by `kem_coins`. The crossed prefix is exactly one precise public bundle input followed by four pure let operations: parsing the signed tuple, verifying and parsing its three fields, constructing the verified input, and computing its registration identifier. Neither moved name occurs in that prefix. It contains no output, event, state operation, parallel spawn, additional input or explicit alternative continuation. A failed let stops the instance. All these conditions refer to the loaded symbolic process; they do not assert that all native primitive or codec failures are already modeled.

The late form retains that prefix and introduces the same fresh pair, in the same relative order, immediately before the first DH tuple. Its entire remaining token stream is identical to the original continuation. The checker renders this comparison in memory; it does not change the maintained `.pvl` files. The full model and theory token pins and the exact `server.rs` digest require renewed review if the relevant interpretation changes.

The source anchors are `Server::get_shared_secret`: the signature and verified-input checks precede the ephemeral generation at `server.rs:368` and KEM encapsulation at `server.rs:373`; conversion and DH follow. The late symbolic placement respects this visible dependency order. It does not reproduce random-byte consumption, implementation errors, allocation or private instrumentation. Production correctness remains the separate extracted-core/adapter and primitive-contract boundary.

## Relation on complete traces and knowledge

Take any finite execution in any surrounding symbolic context allowed by the model. Relate complete configurations, including all other concurrent sessions, their private names and state, the adversary's frame of output handles and every event occurrence. Keep a finite injective renaming of names that fixes the original free names and public constants. Each early-form instance still before its cut has one private, unexposed pair reserved for its own eventual late-form instance. Other processes cannot refer to that pair: it has not occurred in an output or other shared position, and fresh restriction allocates a name distinct from every existing name.

An input step uses a recipe in the current adversary frame. Such a recipe cannot mention that reserved pair. Therefore both instances receive the same term under the current renaming, and each crossed let succeeds with corresponding values or fails in both executions. Interleaved steps of any other session are preserved by the same relation; choosing fresh names for those sessions extends the renaming while keeping all reserved pairs distinct. This covers adversarial scheduling and arbitrary nesting of previously observed terms, rather than comparing just the two public-key distributions.

At the cut, the late process chooses its fresh pair. Extend the injective renaming to map the early reserved names to that pair, avoiding capture by every existing bound or free name. The two complete continuations are now the same process under that renaming. The loaded equations, constructor applications, destructor rules, equality tests and data projections are equivariant under renaming of these fresh names: the theory refers to fixed public symbols and variables, not to an instance's restricted names. Thus every subsequent transition and output is transported with its full term, and every successful or failing attacker recipe is transported too. An output containing a key, ciphertext, commitment or nested term remains the corresponding complete term; it is not replaced by an unrelated public value.

If an instance fails or never reaches the cut, its reserved early names occur in no observable frame, event or active continuation outside that stopped or waiting instance. They may be forgotten in the relation. The late side need not create them. Conversely, a late-form trace is reproduced by reserving its pair at the start of the corresponding early instance and transporting every later name choice consistently. Private name-allocation steps may stutter, but the ordered public actions and event occurrences are identical under the renaming.

This yields both trace directions, not only inclusion under a stronger adversary. Attacker deduction and nondeduction of corresponding terms are preserved because the entire frame and every recipe are renamed bijectively on their support. Each event occurrence has exactly one corresponding occurrence, so matching tuples, ordering and multiplicity are preserved. The existing reachability, secrecy and injective/noninjective correspondence formulas do not name these local restricted atoms directly, and hence their truth is invariant under this renaming. This argument does not by itself transfer a two-process diff-equivalence statement or supply any missing source schedule, ID/routing or direction-split abstraction.

Replication creates a separate restricted pair within each process instance. For any finite counterexample only finitely many instances matter, so the construction extends one instance at a time. It never moves a restriction outside the replicated Server call or shares coins between instances. The actual checked macro has one bundle attempt; a retrying process cannot reuse this result to justify moving one pair ahead of all retries. Such an extension would need a fresh pair and its own relation at every reached sampling point.

## Computational and validation boundary

The symbolic pair is an unguessable fresh-name abstraction under the already documented T0 idealizations. This proof does not show that finite bit strings never collide or that ML-KEM public keys have an injective shared-secret constructor. Those interpretations remain separate computational obligations. In particular, an early sampler can consume randomness on a branch where the production program returns before sampling. Its private log and query bill then differ. No equality of those complete computational states, no equality of marginal key distributions in place of a continuation proof, and no zero-cost failed work is claimed here. The Lean source interpreters retain their original generator order and explicit bills.

The finite checker pins both full record-process token streams, the T0 cryptographic and transcript theory, the common interface and the production source anchor. It audits the exact local restrictions and crossed prefix, and retains the complete late continuation in its comparison. Regression tests reject early use, input shadowing, output/event leakage, extra attempts, extra or missing restrictions, changed source generators and changed tail or theory. Both record Make targets run the checker and tests; the inventory and transcript-fidelity gates reject omission. These are maintenance checks for the reviewed arbitrary-trace argument, not a mechanical proof of that argument. All existing ProVerif process files, query files, controls, rosters and solver verdict expectations remain unchanged.
