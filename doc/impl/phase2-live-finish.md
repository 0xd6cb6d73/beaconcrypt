# Live Phase2 execution, provenance and correctness error (HB-106)

This milestone connects actual Beacon Phase2 execution to the live record/public/reveal scheduler and proves that its selected/prior KEM representation is reversible on the reached owner family. A concrete source-service compiler retains the joint identity service and shared CTX cache. Prechallenge execution runs immediately with its original unblocked decapsulation interface. Separate ordinary KEM correctness-error games replace a zero-error interpretation with a coefficient-one error term where their stopped-protocol comparison is instantiated. These are consuming interfaces for the ongoing authenticated-root and global hybrid proofs; this milestone does not claim those final compositions.

Snapshots, persistence, restoration and their consequences are excluded. Live failed-call rollback, replay, optional replies and previously revealed knowledge remain in scope. Physical erasure and correct primitive implementations remain external. No primitive internals are proved.

## Ordinary recipient correctness error

`PqxdhKemCorrectnessError` adds an ordinary KEM correctness-error experiment, separate from IND-CCA. The experiment runs the supplied scheme's actual key-generation program, encapsulates to the resulting public key, then decapsulates the resulting ciphertext with that sampled private key. It wins when the result is `None` or differs from the encapsulated shared secret. No proof of the KEM's internals or assumption that this probability is zero is introduced. The existing perfect-recipient-correctness results remain unchanged.

`error_functional` identifies that actual experiment with the error predicate on the complete sampled key/ciphertext/secret record under the existing `FunctionalDecapsulation` contract. `error_probability` gives the corresponding exact evaluated probability. This contract describes a fixed deterministic, effect-free oracle program for decapsulation; it does not cover fresh independent implementation faults on repeated calls. `good_agreement` derives the exact actual decapsulation program on each sample outside the error event.

`continuation_bound` averages exact agreement outside that event and obtains a coefficient-one total-variation bound for any complete mathematical continuation. Its sampled private key and shared secret belong to the challenger and proof context. They are not an executable adversary interface. `routed_bound` gives the concrete restriction: the `LocalPostSpec` client and its initial auxiliary state are constructed from the public key and ciphertext, while the secret key and shared secret occur only in their private interpreters. The equality used on good samples preserves the full optional result and auxiliary poststate. Every repeated matching private-root request uses the same encapsulated secret and the same correctness event, so this theorem does not multiply the error by the number of roots.

`sample_bound` charges the actual key-generation and encapsulation programs under an arbitrary selected-query predicate. `error_bound` additionally charges one actual decapsulation program. Their bounds are respectively `qKey + qEncapsulation` and `qKey + qEncapsulation + qDecapsulation`, with all-reply premises on the actual primitive programs. A functional decapsulation program may have zero queries to the modeled oracle; this does not make its local invocation or runtime free. ## Unconditioned stopped-protocol correctness bound

`PqxdhKemCorrectnessStopped` retains the actual source order when an adaptive prechallenge program may stop before encapsulation. Its client interface receives a public key, returns its complete permitted private `Context`, and decides whether to abort or continue. An abort executes the original prechallenge oracle program immediately. A continuation first executes actual encapsulation and then runs the original `LocalPostSpec` program with its public ciphertext and retained context. Neither client branch receives the sampled KEM private key or encapsulated secret.

`error_keygen` expresses the same ordinary correctness endpoint as actual key generation followed by that key's encapsulation/decapsulation error test. `after_bound` fixes the actual reached prechallenge context and bounds the difference between the complete actual and routed continuation by that key's ordinary correctness error. It covers both a literal unchanged abort and arbitrary repeated matching-root requests after continuation. `prepared_bound` averages the complete original prechallenge program. `stopped_bound` then averages actual key generation and obtains the single unconditioned ordinary error probability. There is no division by the probability of continuing and no authentication or honest-candidate premise. In particular, a prechallenge program may use its permitted oracle replies to decide whether to proceed; the bound retains that program and its context instead of assuming a separate independent context.

`stopped_branch` states the exact original abort program on a stopped branch, so neither a ciphertext nor a shared secret is sampled there. `after_query_bound` proves the structural selected-query bill `max qAbort (qEncapsulation + qResume)`. `main_query_bound` adds actual key generation and prechallenge work, giving `qKey + qPrepare + max qAbort (qEncapsulation + qResume)`. Each allowance concerns the actual interpreted program under every possible reply, including all later private-root and ordinary decapsulation work in `qResume`. The proof of this query bound uses the source syntax, independently of the evaluated probability comparison.

These modules use the existing fixed functional KEM and ordinary ambient probability model. Their result type and context can retain complete private client state, but they do not silently generalize the fixed ambient primitive interface to a different stateful primitive scheme. They provide the explicit correctness term and stopped-protocol comparison needed for a later concrete native scheduler instantiation. They do not themselves establish reached-state provenance, identity or KEM freshness under live compromise, source codec contracts, or the remaining global protocol security theorem. Storage, snapshots and restoration are outside the active scope.
