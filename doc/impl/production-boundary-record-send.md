# Source send execution and publication boundary

`PqxdhBoundaryRecordSend` connects the actual send driver shape to both frozen CE send commands. Its thirteen guarded statements preserve the same plaintext, target handle, encoded sender, associated data, complete ratchet, optional primitive and writer results, shared hash cache, frame log and live owner/peer maps. These are exact operational equations and source callback bounds; they add no cryptographic advantage or end-to-end security claim.

The production reference is `beaconcrypt/src/ratchet.rs:371` (`seal_frame`) and `:414` (`encrypt_message_with_ratchet`), with `beaconcrypt/src/server.rs:224` and `beaconcrypt/src/beacon.rs:152` supplying role dispatch. The driver and outer Rust adapter remain reviewed transcriptions (RT). The local begin, request, resume, sealing-capability getter and finish definitions come from the extracted core. This module does not claim extraction of the whole driver or public Rust methods. The existing slot/normal-return ownership boundary represents the Rust take/put lifecycle; compiler, allocator/runtime, codec internals and primitive implementations remain the existing external contracts. No saved-state, snapshot or persistence behavior is modeled.

`executeArguments_exact` proves that the three literal extracted getters return exactly the sealing capability's material, sequence and immutable context. `executeSend_exact` composes extracted begin, request, resume, those getters and finish with the existing `RawCtxSourceSeal.sealInput` program. It retains the original KDF request, actual response, AEAD call, AD/tag-width checks, commitment hash and optional writer in source order. Empty application input is checked by the owner before taking a send step; exhaustion returns the original kernel. The source sealing program's previously checked arguments include the exact commitment preimage and frame layout. Primitive evaluation and serialization themselves remain trusted interface calls.

`executeOwner_exact` reinstalls the complete returned kernel and preserves owner metadata and receive-attempt instrumentation. Its context keeps the target API handle separate from the sender encoded in the frame. `executeServer_exact` selects associated data from the requested peer, reads the immutable server sender ID and selects that same mutable peer before calling the owner. Missing peers reject. `executeBeacon_exact` admits only the established phase, uses its stored associated data and pinned control target, and obtains the sender from the actual outer identity ID. It assumes no equality between that outer ID and a server-assigned ID. Every inactive phase retains its actual private fields and absent reply.

`executeServerSend_exact` and `executeBeaconSend_exact` run these programs through the same native record interpreter and writer instrumentation as CE. They preserve every primitive poststate, shared-cache effect, attempted writer frame and complete live role state. A writer log is evidence that a frame reached the writer, including writer failure; it is not evidence that bytes were successfully published. `handler_serverSend` and `handler_beaconSend` identify those programs with the frozen CE commands on the same caller inputs. Successful bytes and absent replies remain the original optional results. No honest peer or successful-writer premise is needed.

`executeOwner_active` makes failure behavior explicit. For a nonempty send whose counter is not exhausted, every supported completed execution advances the send sequence exactly once, regardless of whether its optional seal/writer result is absent. Receive sequence, skipped-key cache, receive chain and receive slots are unchanged. The theorem retains the complete arbitrary primitive interpreter and its final state; it does not assume losslessness. This is the source behavior of finish and reinstallation, unlike the live receive rollback behavior handled by the separate receive boundary.

`executeOwner_bounds`, `executeServer_bounds` and `executeBeacon_bounds` carry the original separate source query caps through the equalities: at most one ratchet KDF callback, one AEAD seal, one commitment-hash callback and one frame-writer callback per send, and zero opening callbacks. The bounds include empty, exhausted, inactive, missing-peer, AEAD-failure and writer-failure cases. Routing and lifecycle selection add no primitive queries. These are callback counts, not running-time claims: lookup, byte copying, serialization, primitive work, the shared interpreter's base/uniform bills and all wider protocol/reduction costs remain separately accounted for. No opaque work is declared free and no cryptographic session/record selection loss is introduced by these equalities.

The ordinary-axiom guards allow only `propext`, `Classical.choice` and `Quot.sound`. The PB contamination checks separately inspect exact statement tokens and direct elaborated constant references, each with a deliberately failing liveness example. They do not certify the entire transitive import graph. The frozen interfaces, production Rust, wire format, primitive algorithms and public API are unchanged. Remaining registration/root, whole-schedule and maintained source-boundary joins are separate PB work.
