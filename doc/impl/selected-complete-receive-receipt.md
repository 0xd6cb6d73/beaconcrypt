# Complete raw receive attribution to the ordinary authentication observer

`RawCtxSelectedReceiveReceipt` follows one actual complete raw receive through the selected message-material compiler and the previously checked authentication observer. It removes the earlier requirement to begin at an already reached opening callback. The theorem covers cached receives, future receives with every skipped-key derivation, parser and validation rejection, the actual optional plaintext, and the original owner publication. It does not infer selected material or an authentication forgery from acceptance alone.

`derive_actual` identifies the exact retained-table derivation result used by the receive compiler, including predecessor priority. `program_terminal` follows the strictly decreasing source driver until it either rejects or reaches its one opening. This is a mathematical description of the existing execution, not an additional oracle or a claim that source derivation work is free. `terminal_scope` proves that every reached opening retains the original target sequence and immutable raw/frame/associated-data context through all skipped-key derivations.

`program_accepts` and `receive_accepts` show that an actual successful complete receive returns the optional plaintext from that reached callback through the original cached or future finish. They retain the resulting complete kernel. `service_input` then extracts the actual source material getter, returned plaintext, sender and sequence. `service_branch` and `receive_branch` explicitly distinguish known material from selected material. The selected case records the original privately framed raw request, the actual optional challenger plaintext and the sealing history from that attempt. Known material remains an allowed success branch; byte equality between a known key and the selected key is not excluded by these operational statements.

`raw_accepts` obtains nonempty input, the actual decoder result and the production frame validation from the literal raw owner prelude. The resulting owner is exactly the original owner with the returned kernel and the incremented raw-attempt counter. Metadata, expected sender and associated data remain unchanged. No acceptance premise is inserted into the executable receive program.

`SelectedFresh` names the exact source target event used in the authentication implication: the terminal opening's actual getter contains selected material, and the full nonce/typed-associated-data/encoded-record tuple is absent from the successful selected seals recorded before this attempt. It is an event restriction, not a primitive contract or a theorem that every accepted record is a forgery. `raw_selected_record` derives the payload slices and associated-data width from actual validation, obtains the reached opening and actual returned plaintext from complete execution, and constructs the existing `RecordEvent`. `raw_selected_wins` maps that event to the ordinary observer's executable winning decision. The existing persistence theorem for attempted receipts retains this win through any later component continuation, including later seals and adaptive stopping. Original Gate and byte-Fresh predicates can restrict this source event; they do not imply it on their own.

`native_raw_erase` erases only the added receipts and recovers the actual native raw receive distribution, complete native owner, ambient state and shared commitment cache for arbitrary input and optional output. Its backend is the already proved retained private KDF-table hybrid. Public HKDF evaluations remain real. The separate transition from real private HKDF to this selected-material distribution is not supplied by the erasure theorem.

`raw_queries` preserves the original allowance of at most one dynamic CTX call for every raw attempt. The observer makes no additional queries, and earlier generic query-preservation results retain every sharper per-class bound. The source's separate allowance of up to 51 private receive derivations is unchanged. Rejected and repeated attempts are counted by the source interface; attempts reaching selected raw verification enter the observer even when opening fails. Local known-key operations retain their original computation and forwarded hash/uniform costs.

The ordinary authentication endpoint remains the previously checked modified nonce-AEAD validation and attempt-indexed INT-CTXT reductions, with their explicit query and guessing terms. Known-key calls in that endpoint are executed with the actual supplied bytes and shared hash cache, so adaptive key candidates and accidental aliases remain representable. Applying this endpoint to the full protocol still requires the source distribution hop that supplies a uniform selected key independently of executable context, or the appropriate explicit source key-probe/alias loss. Absence of an explicit selected-key argument is not an independence theorem.

This file establishes one full raw owner execution. Attribution of the selected target to a particular session/record occurrence in the complete role, installation or saved continuation, the global Gate/Fresh mapping, nonce-refusal probability, and target-selection factors remain separate composition obligations. It neither considers saved-state restoration nor strengthens deployment assumptions.

Validation uses a direct Lean 4.34 module check and guarded axiom output for all thirteen theorems. No Rust or primitive implementation changes are involved; mutation testing is therefore not needed for this milestone. The central integration owns root imports, the trust-boundary inventory and complete Make verification.
