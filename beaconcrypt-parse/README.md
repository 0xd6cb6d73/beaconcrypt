# Beaconcrypt transport parser

Dependency-free `no_std` Rust codecs generated by EverCDDL/EverCBOR from [transport.cddl](schema/transport.cddl), with handwritten complete-input decoders, size-checked encoders, and exact encoded-length helpers. The `beaconcrypt` adapter uses this crate for all transport messages.

The inclusive limit is **32 MiB (33,554,432 bytes) per complete encoded message**, including CBOR framing, authentication tags, and commitments. It does not limit plaintext snapshots or JSON state. Registration responses carry raw `ciphertext || tag || commitment`, with implicit sequence `1` and the pinned numeric server ID.

Registration messages use wire version `2`. Requests encode `[2, 0, identity-key, pre-key, one-time-key, pq-key, mldsa-public-key, signature]`; responses encode `[2, 1, identity-key, ephemeral-key, kem-cipher-text, app-cipher-text, key-id, signature]`. Both are eight-element arrays. The ML-DSA-65 public key is exactly 1,952 bytes and each signature is exactly 3,309 bytes. These fields are mandatory generated CBOR fields; there is no external authentication envelope or version `1` registration fallback. Complete requests occupy 6,757 bytes. Data frames retain their existing wire version `1` encoding.

`encoded_init_len` takes six byte lengths in identity/prekey/one-time/PQ/ML-DSA/signature order. `encoded_response_len` takes five byte lengths in identity/ephemeral/KEM/application/signature order and a separate numeric key ID. These helpers include the authentication fields and all canonical CBOR headers in the complete-message limit. The parser checks syntax and fixed widths; callers verify signatures and cryptographic identities.

Decoders apply a bounded, nonallocating flat-shape check before generated validation. Encoders reject oversized results before writing; other failures may modify the caller's output buffer and return zero.

Run from the repository root:

```sh
cargo check -p beaconcrypt-parse --locked --offline
cargo test -p beaconcrypt-parse --locked --offline
cargo fmt --all -- --check
cargo clippy -p beaconcrypt-parse --all-targets --locked --offline -- -D warnings
cargo mutants -p beaconcrypt-parse -C=--locked -C=--offline
```

Generated files reside in `src/generated/`; [provenance and regeneration commands](generated/README.md) use the pinned tool bundle through `scripts/regenerate.py`. Normal builds require no generator. Workspace mutation configuration excludes imported generated sources and includes handwritten code.

Imported sources use [Apache-2.0](generated/LICENSE); handwritten files use [0BSD](LICENSE-0BSD).
