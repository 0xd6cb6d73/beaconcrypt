# HB-85 adaptive raw receive components

`Computational/AdaptiveRawNonceAead.lean` supplies the first adaptive receive layer above the retained modified nonce-AEAD integrity endpoint. It is a one-key component with an explicit raw decoder. It does not yet instantiate the production CryptoFrame decoder, CTX commitment, ratchet state, multiple sessions, evolving keys, or reveals. Those interfaces remain required before a protocol claim.

The ordinary primitive game exposes private randomness and nonce-respecting chosen-plaintext sealing, then checks one final ciphertext forgery. It does not expose a plaintext-returning opening oracle. The new actual experiment accepts arbitrary raw byte strings and returns the challenger's optional plaintext after decoding. The simulation records each successful sealing request and ciphertext. For a decoded tuple equal to a recorded nonce, associated data, and ciphertext, it returns that record's supplied plaintext. Otherwise it returns rejection. No recovered secret plaintext is inserted into an adversarial request.

`primitive_preserves_historyCorrect` proves from ordinary encryption correctness that every recorded plaintext agrees with challenger opening. `discrepancy_iff_fresh` then proves that any actual/simulated answer difference is exactly a fresh accepted ciphertext, with freshness evaluated against the successful encryption history at that attempt. Malformed inputs reject in both experiments.

The full experiment retains the adversary's result, complete encryption state, raw-attempt counter, and sticky discrepancy flag. `adaptiveGame_distance_le_discrepancy` uses an output-bad coupling: replies need agree only when the resulting flag remains false, so the first successful fresh ciphertext can produce a different reply. The actual branch returns the challenger's plaintext through the adversarial interface. Both branches continue after a discrepancy. Every raw request increments the counter, including parser failures, repeated candidates, and attempts after an earlier acceptance.

`stopAtRaw` constructs an indexed family of ordinary primitive forgers. It forwards every earlier primitive request, simulates earlier raw answers using only its public plaintext log, and stops immediately before the indexed raw answer would be required. It submits the decoded ciphertext unchanged. An invalid or absent target uses a fixed public fallback. The reduction has no key, opening function, or primitive-challenger plaintext. `stopAtRaw_query_bound` preserves any source bound on a chosen class of primitive queries, so uniform and seal queries are separately bounded without adding a target-selection query.

`firstDiscrepancy_le_indexed_sum` bounds the stopped monitor by the sum of the ordinary final-forgery success probabilities at indices `0` through `qRaw - 1`. The proof stops charging on the first discrepancy: that index already wins without requiring its plaintext. On histories without discrepancy, it continues with the exact logged optional reply. Primitive-query steps average over the challenger's full joint reply and updated log. The finite expectation argument does not silently replace a correlated history by an independent sample.

`simulated_bad_eq_firstDiscrepancy` proves that stopping the monitor leaves exactly the full simulator's bad-event probability. Every continuation after a raised flag retains it, and the probability monad has no failure mass. `adaptiveGame_bad_eq` proves equality of real and simulated bad marginals. After sampling the ordinary primitive key uniformly once, `uniformAdaptive_bad_le_intctxt_sum` identifies every summand with the existing ordinary nonce-AEAD INT-CTXT advantage. `uniformAdaptiveGame_distance_le_intctxt_sum` bounds the total-variation distance between the complete real and simulated output/state distributions by that same sum. `uniformAdaptiveGame_distance_le_raw_count` gives `qRaw * epsilon` when each explicitly constructed forger's ordinary advantage is bounded by `epsilon`.

`indexedReduction_query_bounds` states separate source and reduction caps. For each indexed forger, at most `qUniform` uniform queries and `qSeal` nonce-respecting seal queries are inherited from the source. It makes no opening-oracle query: the ordinary challenger performs one final verification of the submitted tuple. The actual adaptive experiment performs at most `qRaw` raw attempts under its stated query bound, including parsing failures, repeats, and multiple successful fresh attempts. There is no session-selection factor in this one-key theorem; the `qRaw` factor is attempt selection. A fixed index requires no random selector query. Evaluating every member of the family would require up to `qRaw` separate primitive experiments; the bound does not call those experiments free. Log search and update are executable list operations and introduce no primitive-key search or secret opening into the forger.

The ghost discrepancy flag uses the challenger's opening operation to state and couple the two experiments. This instrumentation is separate from the executable forger. It does not provide an opening oracle to that forger or to its simulated adversary. The actual adversary still receives the complete challenger-produced optional plaintext through every real receive reply.

The production lift must additionally prove exact decoding and validation, commitment checks, consumed-key replay behavior, failed-open rollback, session/record selection, correlated key handling, reveals, and global query accounting. This component's log-reply simulator permits repeated opening of an earlier sealed tuple; production consumption must be added by the ratchet adapter and proved to preserve the simulation. Per-key nonce rejection here does not assert that nonce bytes differ across independent keys. No production security conclusion is inferred from the component theorem alone.

## CTX targets without a plaintext claim

`Computational/CtxUnclaimedAcceptance.lean` removes the plaintext-claim requirement at the retained one-key CTX endpoint. Its adversarial `Target` contains only the nonce, complete record context, and ciphertext/tag/commitment. A pure compatibility map supplies the public constant empty byte string to the older transcript type. No new winning event consults that field, and no key or recovered plaintext is used by the map. Existing proof modules and their reductions remain unchanged.

`optionalOpen` performs the commitment comparison and then returns the base challenger's actual optional opening. `AcceptedAt` requires full tuple freshness and a non-rejecting optional result. The checked classification reuses the existing honest-cache invariant: accepted fresh retained bases are ordinary nonce-AEAD integrity wins; the other branch must be a full context alias with the expected outer commitment. Dropping the opening requirement from that second branch is an explicit upper bound, not a cryptographic assumption.

The direct alias proof reuses the existing honest suffix-freshness result and pays one 512-bit digest guess. `retainedProbability_eq_intctxtAdvantage` reuses the exact retained-base transcript simulation and now identifies its event with ordinary acceptance of any plaintext. The canonical-to-direct cache hop reuses the existing single secret-prefix charge. The final ciphertext-only bound therefore has the same constructed ordinary INT-CTXT reduction, Boolean IND$ reduction, `qHash / 2^128` validation false-positive term, and `1 / 2^512` commitment-guess term. It introduces no plaintext-guessing loss.

`openAndRetain` explicitly returns optional plaintext and the updated suffix cache. `canonicalOpenAndRetain` performs the same operation against the actual shared classical random oracle at the exact secret-prefixed CTX input. Their checked split-cache projection retains both the optional answer and complete resulting cache. The canonical final-forgery game is connected to the split-cache component game by exact equality. The random-oracle contract remains stronger than collision resistance; no claim about the internal security of BLAKE2b is introduced.

The pure compatibility map preserves the separate public-hash and seal query bounds. The checked `reduction_query_bounds` makes that inheritance explicit: retained integrity uses at most `qSeal` seal queries and `64 * (qHash + qSeal)` uniform byte queries; Boolean privacy uses at most `qSeal + 1` seal queries and the same uniform cap. `openAndRetain_uniform_query_bound` charges up to 64 additional uniform byte queries for the final private hash, including rejected opening. Existing total/interpreted challenger bounds remain available for the mapped strategy. The conventional privacy reduction retains its `qSeal < 2^96` nonce-space premise. The inherited fresh-nonce selector currently uses classical choice; a constructive bounded candidate search or an explicit algorithmic realization is still needed for a defensible runtime claim. Its query bound alone supplies no efficiency proof.

This closes the missing-plaintext issue for one final CTX target. It does not yet prove adaptive CTX receive: every earlier well-formed failed verification can populate the private hash cache. The adaptive lift must preserve those dictionary entries and their insertion order, reuse repeated entries, include all private verification/hash/base costs, and charge public queries matching a hidden key prefix. The checked adaptive AEAD component alone does not supply that hash-cache simulation or the production multi-session ratchet lift.
