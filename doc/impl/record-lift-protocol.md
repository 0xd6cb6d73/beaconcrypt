# Global record protocol client and private interpretation

`PqxdhRecordLiftProtocol` factors the actual dynamic record world into an adaptive source client and a private service interpreter. Its complete execution equals `PqxdhRecordLiftWorldCompiler` for every lookup policy, and its all-real initial execution equals the original `PqxdhRecordLiftWorld`. The equality retains the caller's optional replies, environment state `E`, private test/fresh ledger, dynamic records, source counters, sampled seeds, shared random-oracle cache and attempted writer frames. This is an executable source correspondence, not a cryptographic security theorem or a completed global masked-observer reduction.

The `Control` state contains the optional dynamic Server, its `U64` peer map, the owner list, independent raw-attempt counters and per-slot role-use bits. It reuses the reviewed compiler's `StoredKernel`: a caller-known record contains its supplied concrete kernel, while a hidden record contains its slot and actual source kernel over logical coordinates. Control is internal source state, not a new environment capability or a public security observation. The client takes no seed assignment, chain table, primitive cache or primitive-counter argument. Caller-known values and the source's public decoder/crypto parameters remain inputs; the types alone do not prove a statistical independence statement about arbitrary parameters or adaptive observations.

`Private` holds the actual persistent seed cache, full76 chain table, complete `World.Primitive`, tagged produced-frame log and a pending native writer log. The pending log is the exact per-owner frame list used by `WorldCompiler.ownerRun`; it is not a fabricated transcript. `Service.publish` receives the caller's `FrameTag`, appends every pending frame under that tag and clears the buffer. It returns only unit. A failed writer still leaves its attempted frame in the private log. There is no log or counter read in the private service replies.

The private request surface has explicit allocation, counted coins, shared hashing, effect charging, coordinate lookup, labeled opening, labeled sealing, caller-known send/receive and frame publication. Allocation and lookup return unit. Hidden opening returns the actual source `core.option.Option Decrypted`; hidden sealing returns the actual source `Option Encrypted`. The caller-known services return the updated caller-known kernel together with that same optional reply. No service returns an interpreted hidden kernel, seed half, full76 output, random-oracle cache or primitive counter. These services are compiler operations; the frozen environment still uses only its existing restricted `EnvEffects` boundary.

`kernelSend` and `kernelReceive` flatten the actual `OpaqueDrivers.admittedSend` and `admittedReceive` programs through `localLift`. The source control therefore retains material coordinates until the private opening or sealing callback. Receive recursion still uses the literal normal admission, resume and finish transitions. Send advancement precedes the sealing reply, including `none`. Known records execute the original concrete source adapters through the same native primitive interpreter and shared cache. This representation introduces neither an independently sampled fixed role family nor an inverse from byte strings to labels.

The global handler preserves the reviewed world's operational distinctions. Server header routing selects the peer before full frame decoding; immutable sender ID, assigned target ID and identity-ordered associated data remain separate. A missing Server or missing owner index has no raw attempt. A present Server with an unrouteable or absent peer increments its raw counter, and an existing inactive owner increments its independent counter for raw receive. Installation checks Server vacancy, the legal Beacon phase and the slot's unused role before allocation. Refused installation cannot sample a seed. Existing seed-cache entries are reused by the actual lazy sampler. Inactive registration metadata remains environment-owned and irrelevant to ordinary record dispatch; this component does not reconstruct erased registration secrets or prove the CE registration-to-shell installation obligation.

The proofs have three main layers:

- `local_query_factor`, `local_program_factor`, `kernelSend_factor`, `kernelReceive_factor` and the owner factors preserve complete local table, primitive state and writer-log distributions. Local factors allow an arbitrary pending log and require no reachability or real-lookup premise.
- `resolve_factor`, the installation/capability factors and the full `serverStep_factor`, `beaconStep_factor`, `effects_factor` and `handler_factor` join actual source control to private interpretation. Their request boundary uses `privateState`, whose pending log is empty. Their exact output is `splitResult` of the original complete poststate, so an empty buffer is a conclusion of every complete handler, not an assumption supplied for a later operation.
- `schedule_factor` composes those equalities through every adaptive `WorldSpec` continuation. `schedule_pending_empty` derives the buffer property for all supported completed schedules. `run_factor` applies the result to the unchanged frozen `Interface.program` in both modes, retaining `E` and the exact world-owned ledger. `initial_schedule_source` and `run_source` compose this factor with the reviewed all-real compiler erasure from the actual empty state.

The all-policy factor is an equality to the parameterized compiler, not an assertion that every lookup policy equals the real source. The original World equality uses `WorldCompiler.realPolicy`. Its operational invariant and source correspondence are already proved by the imported compiler. This module adds no assumption of source reachability, freshness, target-freeness, alias exclusion or secrecy. It does not alter the frozen interface or import CE's ideal-game or headline modules.

`observed` directly reads only the actual client result, world-owned ledger and tagged produced frames. `analysis` adds only the exact Server and owner raw-attempt counters. Their source equalities are proved separately from the internal full-state equation. Neither view reads private coordinates, seed bytes, the table, primitive counters or `E`. Arbitrary predicates over the private execution result are not claimed to be valid cryptographic events. Later post/reveal work must consume the retained `E` through its existing continuation before applying the final permitted observation; this module does not infer later security from the record-only view that discards `E`.

All probabilistic and primitive work remains explicit in the interpreter. Allocation uses the original paired-seed sampler and `countCoin`; public coins and random-oracle cache-miss draws use that same counted route. Every `EnvEffects` request is charged before dispatch, including startup, adversary, ledger, public and refused administrative effects. The actual native KDF, opening, sealing, writer and shared-hash work runs with its existing counters and cache. Only pure structural moves such as frame publication introduce no primitive query. The exact equations preserve these bills; they do not establish a new numerical global allowance or declare hidden services free. Additional random full76 misses under another lookup policy remain that policy's explicit work.

The remaining security joins include derived global role orientation and unique sender history, mixed-policy table/depth invariants, complete selected-input and observer masking across allocation and adaptive callbacks, known/hidden alias coupling, concrete selected CTX service composition and its explicit nonce-refusal event, finite ordered-hop losses, and permitted final events with their query bounds. The CE-side constructor/ledger identification, exact registration erasure including failed transient receive, installation-shell equality, C1/C5 and concrete reveal obligations remain separate. The callback labels exposed here support those joins; none is assumed as a new contract or inferred merely from the client type.
