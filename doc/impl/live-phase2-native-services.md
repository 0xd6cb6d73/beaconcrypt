# Live Phase2 native services

`PqxdhLivePhase2Aux` supplies the actual native Phase2 callback program with the live indexed joint-identity and KEM services. A local interface retains only response decoding and field extraction, public-point conversion, and DH with a privately owned prekey or one-time pair. Every original optional local callback retains its full state and source randomness. The identity representation is its creation index and public identity; converted static DH uses that exact index and peer encoding in the joint seed service. KEM decapsulation uses the actual creation index and ciphertext in the private pool, preserving missing-index and primitive rejection. Public-key byte equality never chooses a slot.

`local_source`, `dh_source`, `kem_source` and `raw_source` establish the complete source operations. Static DH preserves the joint request/reply history, including missing identity and invalid-peer rejection. KEM use preserves the complete private pool and decapsulation history. Raw receive uses the existing shared native handler with the real fixed-source HKDF and complete reached CTX cache. The local callbacks cannot silently create a new independent cache. `step_source` and `program_source` give exact program equalities, preserving result, local state, cache, identity state and KEM state through every adaptive continuation.

`dispatch` expands the actual native Phase2 preparation, root, initial-ratchet, raw receive and finish interfaces. `native_step_source` and `native_program_source` retain the same full-state equality. `owner_source` consumes the Lean program `PqxdhBeaconPhase2Publication.nativeOwner`, which calls the extracted `beacon_prepare_finish`, initial-ratchet functions and `authenticate_registration_key_id_binding` but publishes through the Lean `publish` (matched to `beacon_commit` by `publish_fields`) and opens the first record through `RawCtxSourceOpen.openInput` rather than the extracted `record.*` opening functions, so its original optional branches, sequence-one and registration binding gates, rollback, logical private-field disposal and final owner state remain present. The proof moves no generator or callback across a continuation. The production root and initial HKDF evaluations remain real fixed-source computations.

The compiler requires no selected KEM secret or supplied challenge candidate argument. That is an executable interface statement. Arbitrary callback closures, initial private histories and equal other-key bytes are not excluded by this module. It does not prove that an arbitrary auxiliary state is independent of a challenge candidate, or that an arbitrary source client cannot return a candidate. The next private-root consumer must combine the actual owner-handle encoding, indexed source construction and retained root coordinates with the private challenge-marker interface. Public observations must be projected from those concrete source results rather than given the full secret-bearing service history.

The source-to-native representation boundary still uses the existing joint identity conversion and wiring contract. Generated seed conversion is represented by its public indexed handle; this does not establish success of an arbitrary optional conversion callback. The primitive implementation performs its required validation. Concrete installed-owner identity/KEM provenance comes from `PqxdhLiveIndexedCreation` and `PqxdhLiveKemOwnership`; the source equality itself accepts arbitrary initial states and does not manufacture that provenance. Codec and local DH-pair callback correctness remain their stated adapter/primitive contracts. No new authentication or secrecy assumption is introduced.

`service_queries` gives each callback its exact nonuniform request bill. Static DH issues one request to its original joint interface, and indexed KEM decapsulation issues one request to its original private pool. Every local source coin remains explicit. `uniform_queries` consumes an actual local-callback cap `qLocal` and the existing 64-byte allowance of the raw shared commitment path, giving at most `max(qLocal, 64)` source uniform requests per callback. `auxiliary_service_caps` proves zero identity/KEM allocations and zero direct private-key reveals, and at most one indexed decapsulation per callback. These are syntactic query bounds, not deductions from distribution equality.

`dispatch_queries` preserves each supplied callback allowance. `owner_query_caps` consumes the independently proved 69-callback bound of the complete native Phase2 attempt, including work before abort. Its explicit conservative caps are zero allocations/reveals, zero new identities, at most 69 indexed decapsulation attempts, and at most `69 * max(qLocal, 64)` explicit source uniforms. The decapsulation cap intentionally uses the complete callback allowance; it is not a claim that the source performs 69 decapsulations. Existing private-marker preparation bounds can give the tighter one-decapsulation count in the next routed consumer. Evaluating the KEM callbacks still pays the joint router's separately proved ordinary `uDecap` uniform and `bDecap` base-query costs on every indexed attempt. Identity generation, reservation draws, challenger generation and prefix/suffix work retain their separate bounds. Fixed HKDF, codec and native computation are not assigned zero runtime cost by an oracle query count.

This module establishes the concrete native operational consumer and its resource interface. It does not yet supply the final ordinary CCA adversary, secret-input Extract/Expand joint sampler, original event-specific disclosure policy, or session/target selection factors. Chain-only `Fresh` does not imply the required identity/KEM policy. Public HKDF is not replaced by a random table. Snapshot and persistence behavior are outside scope.

Validation: direct Lean 4.34 module checking and 14 guarded axiom reports. No Rust or primitive implementation changed.
