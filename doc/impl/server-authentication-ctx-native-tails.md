# Concrete ordinary tails through the CTX interface

`PqxdhServerAuthCtxNative` compiles the ordinary Server response builder and Beacon post-root continuation against the same selected CTX component that supplies the selected seal/open services. Its local state holds the actual auxiliary data or seal log, while the component interpreter owns the shared commitment cache. The executable callbacks require no selected-key argument. Known keys may still have equal bytes; these operational equalities do not establish independence or nonexposure.

`lift_evaluate`, `native_source`, `aux_source` and `registration_source` connect the actual fixed-HKDF, known-key AEAD, frame-writer and registration callbacks to their original source counterparts. Identity checks, reservation outcomes, erasure and the Phase 2 writer keep their actual answers. Fixed HKDF stays real. A known native commitment request is forwarded through the common cache rather than evaluated against a separately initialized table.

`nativeTail_source` and `tail_source` preserve the complete native response-tail result and its successful-seal log. The log is appended only when the original inner frame writer returns a value. Failed frame writing remains an absent optional result, and a later Phase 2 writer failure does not undo an earlier log append. The source and compiler keep the same cache effects on all these branches. `build_source` lifts the equality through the entire actual registration builder, preserving its returned Server state, optional response, log and cache without a callback-simulation premise.

`beacon_source` preserves the original initial-KDF and application getter alongside the actual native opening callbacks. `beacon_after_source` consumes the literal post-root program for arbitrary delivered bytes, including missing application data, parser or sequence rejection, failed opening and the original optional plaintext. This is the ordinary known-root branch. It does not resolve hidden skipped material after an arbitrary selected-key receive or impose successful sequence-one admission as a premise.

These nine statements are complete functional source equalities. They add no primitive-security or event-origin assumption. The surrounding callback query counts are established in `PqxdhServerAuthCtxAmbient`; the earlier source modules separately bound the attempted build and receive operations. The remaining reduction must still compose those counts through the concrete adaptive scheduler, compile the selected branches, consume the actual factor distribution, account for its stopping conditions and relate the original acceptance event to the ordinary CTX observer. Local crypto and codec work is not treated as free computation, and this module makes no new runtime bound.
