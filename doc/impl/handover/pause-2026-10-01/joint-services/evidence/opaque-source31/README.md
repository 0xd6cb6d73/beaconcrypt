# Opaque KEM source continuation, revised

This archive covers the revised opaque-KEM cohort: seven modules, the guide `doc/impl/registration-opaque-kem-source.md` and one section of `doc/formal-verification-analysis.md`. The cohort has thirty-one statements, each with an exact standard-axiom guard. The seven modules were ported from the untracked work in the registration joint-service worktree onto the lane commit `1881878f`, which already contains the source-suffix cohort they import. That worktree was not edited.

The first independent review rejected the earlier twenty-two-statement version for one reason. `resume_native` only accepted prefix interpreters whose target is the native game. The actual private identity/KEM services and the KEM reduction run in other monads, so the theorem could not be applied to them. This revision adds `resume_lift`, which proves the same join for any outer monad that the native game maps into by a monad morphism, with any prefix interpreter in that monad. `resume_native` is now its identity-morphism case, and its statement is unchanged. Five instantiations follow. They cover the exposed encapsulation-cut client, the real encapsulator with open private services, the stateful private services of the actual accept state, the ordinary challenge reply of the saved `suffix_cut` continuation, and the interpreter chain used by `KemResume.post`. `finding-responses.json` lists each review finding and what was done about it. None of the twenty-two original statements was weakened or deleted.

The scope is unchanged: this is operational source correspondence. No Extract/HMAC hop, context secrecy, correlated sampler, freshness, target selection or global loss is claimed, and no statement charges an advantage. Two joins are still open. The first is showing that the scan of the complete source program reaches the accept-form continuation that `resume_reply` and `resume_post` are stated for; that is the raw-accept cut join. The second is carrying the existing prefix uniform charges over to the resumed program.

`review-manifest.json` records the Lean toolchain and flags, the lock, the proof root, the exact `LEAN_PATH` (also in `leanpath`), the scratch artifact prefix and the hash of every artifact and log. The direct checks ran one module at a time with `check.py`, and all seven final logs are empty. `axioms.log` is the actual output of `Axioms.lean`. `GuardLiveness.lean` is a negative control: its deliberately wrong guard fails, which shows the guards are enforced.

Following the lane process, parent integration adds root imports and reviewed-inventory rows. The lane's focused `check-inventory` and `check-lean-policy` targets fail on files already committed on the lane before this cohort, as recorded in their logs and in the manifest; the cohort's own files pass the same forbidden-token pattern. No full build, `make verify`, Rust, ProVerif or mutation run was performed. A fresh independent semantic review of this revision is pending.
