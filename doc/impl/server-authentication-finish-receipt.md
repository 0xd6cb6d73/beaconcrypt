# Accepted selected Beacon receipts and ordinary authentication events

`PqxdhServerAuthFinishReceipt` derives the selected opening receipt from the complete executable Beacon callback. It does not assume that a successful opening used selected material or that its target was fresh. The module preserves the actual application getter, original network bytes, frame validation, receive target, challenger-returned optional plaintext and post-opening sequence and binding checks.

`opening_input` evaluates the actual uncached material and sequence getters of the first receive. `execute_selected` follows the literal empty initial state through its single derivation and opening; the request goes to the selected raw interface and the original finish receives the actual optional reply. `raw_one` identifies the complete raw program on a validated sequence-one frame with that exact query followed by the unchanged registration observation. These are source equations, including both acceptance and rejection replies.

`raw_accepts` proves that a syntactically successful raw callback supplied a nonempty, decoded, validated sequence-one frame. It derives sequence one from the existing post-opening gate while retaining the original opening effects on other sequences. `monitored_raw` then consumes the actual executable authentication monitor. Its receipt contains the real component request, returned plaintext and the sealing history that existed before that attempt. `raw_target` identifies the original source-local target and the universal component decoder's target, together with the source registration observation and actual recorded attempt. The private framing contains only the nonce, associated data and original raw bytes; it contains no proposed or recovered plaintext and is not a production wire format.

`program_raw` recovers the actual optional application-getter result from a successful complete callback. `program_target` combines that result with the raw receipt. Both use the original cleared preparation and candidate. The selected-message-key argument remains absent from the executable program, and all arbitrary input aliases and correlations remain permitted; selected-key independence and its distribution are separate obligations.

`program_or_match` uses the real dynamic component interpretation and the existing correct-history invariant to establish a precise alternative. Either the ordinary authentication observer wins, or the accepted target matches a selected seal in the history before this attempt, and the actual accepted plaintext equals that seal's plaintext. This is the existing observer's decision, not a new private-state winning predicate. The starting invariant is explicitly required for an arbitrary prefix; `RawCtxSelectedPlaintextOrigins.initial_good` proves it for the empty ordinary endpoint, and `schedule_good` preserves it through every adaptive selected and known-key query. No protocol authentication conclusion is assumed in that invariant: it records ordinary seal correctness and the plaintext returned on a full-tuple match.

`matched_fields` connects a matching seal's actual source binding context to the accepted key ID, application payload and associated data. It uses the original authenticated eight-byte binding check and the supplied source context's checked binding property. It does not infer session identity from equal keys, ciphertexts or encoded bytes. The global source consumer must obtain that context and its session from the actual sealing execution and logs.

`matched_writable` applies the already approved abstract `ReadWritable` contract only to a seal frame that matches an actually decoded accepted target. Equality of the complete CTX tuple fixes the frame's sequence, sender and protected payload, so that particular frame's writer returns a value. This rules out the matching frame-writer-failure branch without assuming total writers, canonical serialization, equality of input and output wire bytes, or success of the later response writer. It is a use of the abstract message-model contract, not a proof about a native serialization library.

The observer instrumentation preserves the existing query interface and attempt history. This package adds no query, randomness, target-selection loss or extra raw-attempt factor. The per-callback bounds remain those proved by `FinishMaterial`: total component calls at most one, selected seal zero, hash at most one, raw opening at most one and uniform zero, with local source and interpreter work separately accounted. The actual global seal/session provenance, acceptance snapshot chronology, complete stopped-handler simulation, challenge distribution and final event-probability reduction remain separate consumers. No final authentication bound, general session-origin theorem or symbolic computational-soundness theorem is claimed here. Saved-state restoration and persistence remain outside the proof.
