# Private labeled receive and send programs

`PqxdhRecordLiftOpaqueDrivers` factors the established local source drivers into adaptive oracle programs whose private requests retain their material coordinates until interpretation. This is the interface needed to route a selected record to a challenger before erasing its key label. It proves exact operational equalities; it does not prove a cryptographic replacement or the global record-layer lift.

`ServiceSpec` has three private operations: coordinate lookup returns `Unit`, opening receives the complete labeled pending opening and returns the actual optional plaintext, and sealing receives the complete labeled pending seal and returns the actual optional output. Opening and sealing have separate context types. These are internal compiler services, not extra adversary capabilities. The source programs have no seed, table, concrete key interpretation, or full76 reply argument. Their generic contexts and slot type remain caller-supplied data; these types alone do not prove that a complete instantiated client is independent of a selected secret.

`receiveProgram` follows the literal receive effect. Rejection returns the entry kernel and no plaintext. Each derivation asks for the actual requested coordinate, discards the `Unit` reply, then resumes with the same successor-chain and material labels used by `ChainCompiler.receive`. An opening sends the whole labeled pending capability to the private opening service and passes its actual optional plaintext to `normalFinish`. This keeps cached and future paths, skipped labels, target consumption and failure rollback in the existing source control functions. No recovered plaintext is inserted into a target chosen by the adversary.

`sendProgram` follows the source exhaustion and requested-derivation branches. It asks for one coordinate, builds the exact labeled ready capability, calls the sealing service, and retains the advanced kernel even when the service returns no output, as the existing driver does. `admittedReceive` and `admittedSend` start with the actual `normalBegin` source decision and therefore include all rejected or exhausted entries and targets, with no successful-admission premise.

The private `interpreter` is the only new definition that reads the concrete seed/table interpretation. Lookup invokes the supplied actual lookup with its full state and erases only its unused output to `Unit`. Opening and sealing erase the complete pending capability using the current table, execute the supplied native callback, and return its real optional result together with all primitive effects. They retain the table verbatim. The state is exactly `Table Slot × PrimitiveState`; `PrimitiveState` may contain the shared ROM cache, counters and writer log. There is no fresh or projected primitive state.

`receive_interpretation` and `send_interpretation` prove equality of the complete evaluated distributions with `ChainCompiler.receive` and `ChainCompiler.send`. The receive proof follows the source rank through every recursive derivation. These theorems quantify over every lookup and native callback, so they specialize directly to the existing real or mixed `ChainOracle` interpreter. They need no table-validity, reachability, alias, freshness or cryptographic premise. `receive_continuation` and `send_continuation` extend equality through an arbitrary adaptive private oracle continuation evaluated at the actual full poststate, rather than only comparing terminal replies. The two admitted interpretation theorems expose the same result from the complete source entry points.

The factoring keeps all existing callback executions and their native state, including query counters, unchanged under the interpreter. It introduces no primitive advantage or reduction loss and does not declare ambient computation free. No new global query bound is asserted here. The selected challenger interpreter, exact masked read laws, dynamic global routing, source provenance, alias/refusal bounds, query accounting and final chain/CTX security inequalities remain separate joins.

All six theorem declarations have exact axiom guards allowing only `propext`, `Classical.choice` and `Quot.sound`. The focused guarded module check and independent semantic review are recorded with the publication receipt; full-proof verification is outside this additive source component.
