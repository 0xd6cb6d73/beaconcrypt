# Selected finite family compiler

`RawCtxSelectedFamilyCompiler` compiles the exact original record/public API for any finite numbers of Server and Beacon roles. Its executable `family` invokes the original generic family dispatcher, the checked selected CTX role calls and concrete public services. It receives no selected message key. `family_cases` retains the original selected index, updates only that role, preserves every other role and returns the actual optional source API result.

`family_source` gives the exact evaluated distribution of each complete original family request, retaining the full role family, all original ambient state and the common commitment cache. Its explicit `Stops` predicate follows the actual source role dispatch and can hold only on an admitted selected send using an already-used nonce. All other requests have the same original source distribution. The stop is an additional reduction event; it is neither a production rejection rule nor an assumed nonce-freshness condition.

`original_native` discharges the native representation boundary with the existing concrete selected-message driver source theorem. `native_family` therefore connects every original `RawCtxProtocolRoles.protocolImpl` request to the key-free CTX program, preserving the complete original native family state, optional plaintext or ciphertext API response, source state and cache. Additional CTX challenger bookkeeping alone is projected away. The theorem allows arbitrary family state and original selection; it does not assume an honest target, independent role keys or injective kernel interpretation.

`public_source` covers explicit caller coins, public BLAKE2b commitment queries and public fixed HKDF. Public HKDF always evaluates the actual source function, including when its address equals a private selected derivation address. Public commitment queries access the very same ordinary CTX cache. `original_public` proves that these public requests bypass every private retained-table choice. Known keys, aliases and correlations are handled by the existing dynamic known-key component interface; no public random-HKDF interpretation is introduced.

`family_queries` bounds each entire family request by one dynamic component query. `public_queries` includes the caller coin and shared-ROM requests; public HKDF makes no component query but remains local cryptographic work. Private receive/send retained-table lookups keep their separate bounds of 51 and one. Component-internal hash sampling, local primitives, routing, parser work and role publication are not made free by this interface count.

These statements are one-step source simulations, valid at arbitrary reached private states. The common adaptive experiment must still join them over the original client, retain reveal history and the original `Gate`/`Fresh` event, and charge selected nonce stopping using the actual source history. Target/session selection and candidate-guessing losses remain separate obligations. No Rust source or primitive implementation changes.
