# Source raw traces through position-based opening

`RawCtxPositionCapability` supplies a kernel-free receive abstraction for every supported execution of an arbitrary adaptive raw-only source client. The abstract receiver retains the original raw input, parser result, sender pin, associated data, exact directional material position, actual optional plaintext and complete primitive state. It replaces the concrete receive counter/cache with private successful-position history and a per-attempt admission choice. That choice is derived from actual source control before the opening reply, so the proof does not assume that an accepted record is authentic.

This is the next source trace boundary after [consumed-position rejection](source-consumption-gate.md) and [material provenance at every opening](source-positioned-opening.md). It does not classify a persistent ProVerif query or finish the global computational-symbolic bridge.

## Actual step and private consumption

`openPosition` reconstructs the existing material at the original directional chain and decoded sequence minus one, builds the unchanged opening context and calls the existing private primitive interface. It returns the actual optional plaintext wrapped with the original decoded metadata. `positionReceive` keeps all empty-input, pure decoding, sender and shape checks. Its Boolean can reject an otherwise validated input before any opening or allow that exact opening. `gatedPositionReceive` additionally rejects an already consumed position. Neither helper stores the concrete source kernel or introduces independent material labels.

`bare_prefix_complete` erases the finite actual source KDF prefix only after interpretation by the existing fixed pure callback. It does not erase arbitrary state-dependent oracle work. `opening_reply`, `arguments_exact` and `raw_prepared_reply` retain the source-selected opening input, optional reply and entire primitive poststate. `owner_reply_choice` and `raw_reply_choice` derive one admission Boolean from the original source phase, valid for every initial primitive state and all later replies. Zero, replay, cached, future, capacity and malformed raw branches remain represented. `positionReceive_false` records the complete no-callback branch.

The existing `ConsumedRefines` relation says that recorded successful positions are already behind the actual receive counter and absent from its cache, with ordinary source material provenance. `source_gated_reply_choice` uses the proved source rejection law on those consumed positions; it does not assume an authentication conclusion or key uniqueness. `source_capability_step` then gives exact projected oracle-program equality between the real source call and the chosen abstract call. Both retain the actual optional reply, complete primitive poststate and `recordReply` update. Failed hashes/openings keep their actual cache effects and leave successful-position history unchanged.

## Constructed adaptive source trace

`SourceTrace` records successive actual source raw calls and their supported results, including the full source owner, primitive state and private successful-position history. `CapabilityTrace` records the position receiver with an arbitrary Boolean at each step. `source_trace_capability` embeds every actual source trace with the same raw/optional-reply transcript and exact final primitive/history state, while preserving the source relation. Source ownership and the immutable sender/associated-data fields are established through the original operations.

The adaptive result does not assume that a caller already supplies such a trace. `loggedRaw` executes the original source call and privately records its actual input/reply after it returns. `logged_raw_erasure` and `logged_run_erasure` remove only that private transcript and consumption history, yielding the complete original computation and terminal client result. `logged_run_trace` constructs `SourceTrace` from every supported monitored run. `source_supported_capability` combines these facts: every supported original adaptive raw client execution has a matching capability trace, preserving all actual raw inputs, optional replies and final primitive effects.

The result is support inclusion. Although each source-selected step has exact projected oracle-program equality and the monitor has complete computation erasure, the theorem does not assert a probability equality for an arbitrary scheduler of the abstract Boolean. The matching source-side simulation may retain the original control state. Constructing an executable source-free scheduler, a coupling of complete distributions, and the actual persistent ProVerif process correspondence remain distinct obligations.

## Source history and costs

`SourceTrace.metadata` derives the exact raw-attempt increment from transcript length and preserves the sender pin, associated data and metadata. `SourceTrace.history_length` bounds private history growth by the actual number of raw calls. `source_capability_bounded` uses the original client's all-continuation `qRaw` bound to derive transcript length at most `qRaw`, history growth at most `qRaw`, and no repeated successful position. `initialized_capability` obtains the starting empty-history relation from either actual source initializer for the supplied root; it does not substitute for a complete registration/lifecycle handoff.

`logged_query_bounds` preserves every selective underlying uniform-query bound of the original source computation. It is a monitor-erasure statement, not a cost bound for an arbitrary stronger capability scheduler. Reconstructing a material from its original chain may require local HKDF/list work proportional to the index; repeated pure decoder/list work also remains real computation. No uniform-query equality makes deterministic work free or proves native parser traversal, allocation, timing, constant-time behavior or a tight runtime bound.

## Remaining composition

The theorem covers one uninterrupted established owner, arbitrary adaptive raw-only calls, the existing fixed functional KDF and actual source material relation. Distinct positions or origins may yield the same key/nonce bytes. The source's finite counter and exhaustion checks remain in the embedding. The stronger receiver can allow attempts that actual window/capacity control would reject, but the proof makes no security assertion about those additional traces.

Mixed sends, public primitive services, registration and lifecycle changes, multiple owners, reveals, restored or copied state and the network/privileged API distinction still need their own trace mappings and policies. Source origins, kernels and all proof histories stay private and are excluded from reveal, snapshot, persistence and network interfaces. Actual successful API plaintext remains in the reply; whether it is declassified is an outer experiment decision. No key-distribution replacement, cryptographic loss, authentication assumption, primitive/library implementation proof or global protocol closure is introduced by this component.
